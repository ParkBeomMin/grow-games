# 테스트 작성

테스트 러너가 없습니다. 각 파일이 그냥 node 스크립트예요.
**테스트는 항상 `beta/` 소스를 읽습니다.**

당신이 막아야 할 것은 버그가 아니라 **아무것도 안 지키면서 초록불인 검사**입니다.
이 저장소에서 여덟 번 넘게 나왔고 매번 모양이 달랐습니다.

## 반드시 지키는 다섯

1. **`new Function(...)` + `return`.** 직접 `eval` 금지
2. **산식은 소스에서 정규식으로 추출.** 값을 복사해 적지 않기
3. **게임 입구를 통해** 실제 버튼을 눌러 도달하기
4. **변이 검증** — 고치기 전에 빨간불이 뜨는지 반드시 확인. 안 잡히면 검사를 고칠 것
5. **실기기 이벤트 순서**를 그대로 보내기 (`pointerdown` → `pointerup` → `click`)

> **방향이 반대인 것 하나** — 산식은 소스에서 뜯어오고, **문턱은 테스트에 상수로 박습니다.**
> 문턱을 소스에서 읽어오면 상수를 바꿔도 검사가 따라가서 아무것도 안 잡혀요.

### 세 번째 축 — 종속값은 **관계로** 봅니다

어떤 값은 문턱도 산식도 아니라 **다른 값에서 따라오는 것**입니다.
그런 건 값으로 박으면 안 되고, **관계가 성립하는지**를 봐야 해요.

```js
❌  CARD_AGE === 17                          // 값이 바뀌면 검사만 고치면 됨
✅  CARD_AGE + 유스기간 === 데뷔나이(20)      // 따라 움직여야 할 게 안 움직이면 빨간불
```

⚽ 더 윙어 II에서 실제로 값을 했습니다 — 카드 나이를 18로 되돌렸을 때
*"카드 18세 + 유스 3년 = 데뷔 만 21세"*로 잡혔어요. 값으로 박았으면 그냥 통과했을 겁니다.

**종속값의 예**: 중립화 상수(총량이 같아야 함) · 한 벌로 움직이는 문턱과 가드 ·
정규화 계수(같은 밴드) · 다른 값에서 역산된 배수.

| 종류 | 어디에 두나 |
|---|---|
| **산식** | 소스에서 정규식으로 뜯어옴 |
| **문턱** | 검사에 상수로 박음 |
| **종속값** | **관계식으로** — 값이 아니라 "따라 움직였는가" |
| **모델로 잰 값** | **차이(Δ)로** — 절대값은 모델의 치우침을 물고 옵니다 |

### 🔒 네 번째 축 — **모델로 잰 값은 「절대값」이 아니라 「차이」만 계약입니다**

시뮬레이터로 잰 값(`E[s]`·수상률·평균 성장)을 **절대값으로 밴드에 박지 마세요.**
그 값에는 **조작자 모델·겨냥 전략의 치우침이 그대로 남아** 있습니다.

⚽ 더 윙어 II 🧱 차단에서 세 사람이 같은 코드를 재고 **0.537 / 0.5102 / 0.510**이 나왔어요.
*"어느 쪽이 맞나"*가 잘못된 물음이었습니다 — **셋 다 「그 모델」을 맞게 잰 값**이고,
**그중 무엇도 그 게임의 난이도가 아닙니다.**

```
❌  E[s] ∈ [0.52, 0.55]                        // 모델을 바꾸면 계약이 뒤집힘
✅  |E[s](바꾼 뒤) − E[s](바꾸기 전)| ≤ 0.005   // 같은 모델·같은 판(CRN)이면 치우침이 상쇄됨
```

**모델의 치우침은 절대값에는 그대로 남고, 차이에서는 상쇄됩니다.**
개편 전 형태를 **검사가 들고 있어야** 이 계약이 성립해요 — 폐기된 상수를 검사 안에
남기되, **되살리라는 뜻이 아니라는 걸 크게 적으세요.**

> ⚠️ **차이도 「어느 모델의 차이」인지 적으세요.** 위 계약은 **손이 무편향인 모델**에서만
> ±0.005 안이었습니다. 편향 있는 손으로 재면 **−0.024**로 벌어지는데, 그건 고장이 아니라
> 개편이 **둘째 층(손)을 새로 만든 결과**예요. 그걸 모르고 편향 모델로 밴드를 다시 맞추면
> 계수를 엉뚱한 쪽으로 밀게 됩니다.

### 📐 **여러 대상의 「형평」은 값이 아니라 구조로 지키세요**

*"넷의 평균이 서로 0.017 안"* 같은 문장도 **한 모델의 성질**입니다
(같은 코드를 다른 모델로 재니 **0.145**였어요). 이 자리는 **세 번** 뒤집혔습니다.

넷이 형평인 진짜 이유는 평균이 우연히 가까워서가 아니라 **같은 자를 쓰기 때문**이에요:

```js
① 넷의 s가 전부 **같은 한 함수**(sBar)를 지난다        ← 소스에서 정규식으로
② 넷의 판정 창이 전부 `상수 × mul` 꼴이다              ← mul에 같은 비율로 반응
③ 같은 비율(오차 ÷ 창)을 먹이면 **넷이 같은 값**을 낸다  ← 창 폭이 서로 달라도
```

**구조는 모델을 안 탑니다.** 곡선을 다시 재도 살아남아요.
🔴 다만 **③은 「넷이 같은 장르를 쓰는 세계」의 계약**입니다 — 한 종을 일부러 다른 장르로
바꾸는 판정이 나오면 ③부터 다시 보세요. 그 전제를 **검사 옆에 적어 두세요.**

## 표준형 (a) — 산식 검증

```js
 *   ① {단언 1}
 *   ② {단언 2}
 *

 * 초록이 뜬다. 직접 eval은 쓰지 않고 new Function으로 감싼다.

"use strict";
const fs = require("fs");
```

## 표준형 (b) — jsdom 부트스트랩

화면·배선·도달 가능성을 볼 때. `<script src>`를 인라인해 **로드 순서를 살립니다.**

```js
const { JSDOM } = require("/workspace/grow-games/tests/cloud/jsdom.js");
const PRE = `window.fetch=()=>Promise.reject(new Error("off"));`
  /* 🔴 rAF에 **0을 넘기면 움직이는 판이 얼어붙습니다** — 아래 「자가 복구」 절 참고 */
  + `window.requestAnimationFrame=(cb)=>setTimeout(()=>cb(performance.now()),0);window.scrollTo=()=>{};`
  + `window.alert=()=>{};window.confirm=()=>false;localStorage.setItem("grow-auto-mini","1");`;

let html = fs.readFileSync(path.join(DIR, "index.html"), "utf8")
  .replace(/<script src="([^"]+)"><\/script>/g, (m0, src) => {
    const p = path.resolve(DIR, src);
    return fs.existsSync(p) ? `<script>\n${fs.readFileSync(p, "utf8")}\n</script>` : "";
  });
html = html.replace("</head>", `<script>${PRE}</script></head>`)
  .replace("</body>", `<script>window.__get=(n)=>eval(n);window.__set=(n,v)=>{window.__v=v;eval(n+" = window.__v");};</script></body>`);

const dom = new JSDOM(html, { runScripts: "dangerously", pretendToBeVisual: true, url: "https://x.test/{game}/" });
const w = dom.window;
w.Ads = { display() {}, init() {} }; w.Stats = { log() {} };
const get = w.__get, set = w.__set;
```

**주의할 것들:**
- `__get`/`__set`은 **페이지 안에 심은** `eval`이라 최상위 `const`/`let`에 닿습니다.
  밖에서 `eval`하면 스코프가 달라 안 됩니다
- **jsdom URL이 중요합니다** — `https://x.test/{game}/`(접두사 없음) vs
  `https://x.test/beta/_check.html`(`beta::` 접두사). `env.js`가 이걸 보고 localStorage를
  감싸므로 어긋나면 조용히 실패합니다
- jsdom `localStorage`는 `Object.keys`로 안 훑어집니다 — `length`/`key(i)`로 읽으세요
- 🔴 **`requestAnimationFrame`에 `0`을 넘기지 마세요.** `dt = (t − last)/1000`으로 도는 판이
  **제자리에 얼어붙습니다** — 스스로 끝나야 할 판이 안 끝나고 판정이 늘 `s = 0`이 돼요.
  화면은 멀쩡히 그려져서 **아무 검사도 안 웁니다** (실측: pump가 12초를 헛돌았습니다)
- 페이지를 닫으면 `cloud.js`의 늦은 fetch 콜백이 사라진 document를 만져 터집니다 →
  **스택에 `x.test`가 있는 예외만** 삼키고 나머지는 그대로 죽이세요

## 실기기 이벤트 순서 — **개수 · 자리 · 시점 셋 다**

```js
const tap = (el) => {
  for (const type of ["pointerdown", "pointerup", "click"]) {
    el.dispatchEvent(new w.Event(type, { bubbles: true }));
  }
};
```

`pointerdown` 하나만 보내면 안 잡힙니다. 준비 화면 도입 때 **24개 케이스가 전부
초록불이었는데** 실기기에서는 탭이 두 번 먹히고 있었어요. 순서를 그대로 보내니
24개가 전부 빨간불이 됐습니다.

### 🔴 그런데 **개수만 맞추면 여전히 안 잡히는 자리가 둘** 있습니다

2026-09-01 🧱 차단 2단 국면에서 **둘 다 한꺼번에** 나왔어요 —
**둘을 다 고쳐야** 변이가 빨간불이 됐습니다. 하나만 고치면 계속 초록불이었습니다.

| | 무엇이 틀렸나 | 어떻게 됩니까 |
|---|---|---|
| **자리 (재타겟)** | 세 이벤트를 **같은 요소**에 보냄 | 브라우저는 손 뗄 때 `click`을 **「그 지점에 지금 있는 요소」**로 보냅니다. `pointerdown`이 화면을 갈아치웠으면 click은 **새 버튼**에게 가요 — 그 버튼의 `lastPointer`는 초기값이라 메아리 차단에 **안 걸립니다.** 같은 요소에만 보내면 이 경로가 **아예 재현이 안 돼요** |
| **시점** | 판정을 `cb`로 잼 | 결과 연출이 **620ms 뒤에** `cb`를 부릅니다. 그 시점엔 **변이해도 언제나 0회**라 초록불이에요. 판정이 **곧바로** 남기는 흔적(`.w2m-hit` · `button[disabled]`)으로 보세요 |

```js
/* ✅ 브라우저와 같은 자리 바꾸기 — pointerdown/up은 옛 요소에, click은 새 요소에 */
function pressRetarget(w, oldEl, root, newSel) {
  for (const t of ["pointerdown", "pointerup"]) {
    oldEl.dispatchEvent(new w.Event(t, { bubbles: true, cancelable: true }));
  }
  const fresh = root.querySelector(newSel);
  if (!fresh) throw new Error(`재타겟할 새 요소를 못 찾았어요 — ${newSel}`);   // 조용히 넘어가면 초록불이 돼요
  fresh.dispatchEvent(new w.Event("click", { bubbles: true, cancelable: true }));
  return fresh;
}
```

**🔒 「아무 일도 안 일어났다」를 통과로 세지 마세요.** 이중 탭 검사는 *"안 먹혀야 한다"*를
재는 검사라 **게임이 통째로 죽어 있어도 통과**합니다. 판마다 셋을 나란히 보세요 —
① 재타겟할 새 요소가 **실제로 생겼는가**(없으면 던지기) · ② 그 click이 **안 먹혔는가** ·
③ 🔑 **그 다음 진짜 탭은 먹히는가.**

**📮 `gate`처럼 여러 게임이 나눠 쓰는 자리는 검사도 따로 세우세요.** 한 게임의 검사에
끼워 넣으면 **그 게임을 고쳤을 때 나머지의 신호가 같이 사라집니다.**

## 남이 올린 값을 그리는 자리 (XSS)

변이 검증은 **그리는 길에서 이스케이프를 빼고 페이지를 다시 세워** 태그가 실제로
DOM에 들어가는지 봐야 합니다. "esc 함수가 이스케이프한다"만 보면
**부르지도 않는 esc**를 지키게 돼요.

## 시간이 지나면 틀려지는 검사

배포 시점에는 맞았는데 데이터가 자라면서 조용히 죽는 종류가 있습니다.
**의심할 자리: 고정 개수로 자르는 곳(상위 N), 문턱, 상한, 컷.**
분류가 걸린 값을 개수로 자르면 안 됩니다 — 분류 기준마다 뽑으세요.

## 변이가 소스에 안 걸리면 — 종료 코드를 셋으로 가르세요

**변이 검증은 소스 문자열을 정규식으로 잡아 바꿉니다. 구현이 그 문자열을 바꾸면 변이가
조용히 죽어요.** ⚽ 더 윙어 II에서 한 세션에 **두 번** 났습니다
(`ME_P : 1` → 모양 변경, `NPC_SPOT` → 숫자에서 객체로).

**"실패 1건"으로만 보이면 안 돈 것과 빨간불이 구분되지 않습니다.**

```
0  통과
1  빨간불 (검사가 무언가를 잡았다)
2  💥 죽음 (검사가 아예 안 돌았다)
```

그리고 **파일 맨 앞에 0번 「변이 등록 검사」**를 두세요 — 그 파일의 변이 정규식이
소스에 실제로 걸리는지 **다른 무엇보다 먼저** 대조합니다.
안 걸려도 죽지 말고, 그 줄만 ❌로 찍고 **나머지는 계속 돌게** 하세요.

```bash
red=0; dead=0
for t in tests/{game}/*-test.js; do
  node "$t" >/dev/null 2>&1
  case $? in
    0) ;;
    2) echo "💥 $(basename $t) — 안 돌았어요"; dead=$((dead+1)) ;;
    *) echo "❌ $(basename $t)"; red=$((red+1)) ;;
  esac
done
echo "빨간불 ${red}건 · 죽음 ${dead}건"
```

> **뿌리는 남습니다.** 정규식이 소스 문자열에 의존하는 한 구조적으로 반복돼요.
> 엔진이 **계수를 주입받는 형태**(`cfg`로만 받기)면 이 함정이 사라집니다 —
> 그게 안 되는 코드에서는 **"안 걸리는 순간 크게 보이게"까지가 한계**입니다.

## 🚨 자가 복구가 실패를 삼킵니다 — **도달만 재면 아무것도 안 눌러도 통과**

**검사가 「하기로 한 조작」을 안 해도, 타임아웃·기본값·폴백이 흐름을 끝까지 밀어 줍니다.**
흐름은 완주하고 화면은 다 그려지니 **초록불**이에요. 그 자리는 통째로 안 재진 겁니다.

2026-09-01 ⚽ 더 윙어 II 🧱 차단에서 났습니다 — 미니게임이 **2단 국면**이 되면서
2단계 버튼(`.w2m-blk-go`)이 생겼는데 검사의 셀렉터 목록에 **없었어요.**
그런데 **초록불이었습니다**: 2단계는 안 누르면 **~1.7초 뒤 상대가 지나가며 스스로 끝나고**
(s = 0) 경기가 그대로 흘러갑니다. **2단계를 한 번도 안 누르면서 통과**한 거예요.

> 🔑 **원칙 ⑫(폴백이 조작을 상쇄한다)의 검증판입니다.**
> 폴백이 조작을 상쇄하고 있었고, **조작을 지워도 폴백이 남았습니다.**

### 🔴 셀렉터에 더하기만 하면 **또 타임아웃이 삼킵니다**

**「도달했는가」와 「눌렀는가」를 따로 세지 않는 한, 목록을 고쳐도 같은 자리가 다시 납니다.**

```js
/* ① 화면에 「떴는지」는 pump가 아니라 **독립된 훑기**가 셉니다.
      pump가 세면, 목록에서 빠진 셀렉터가 "안 뜬 것"으로 둔갑해요 — 그게 그 버그입니다. */
const scan = () => { for (const s of SELS) if (doc.querySelector(s)) seen[s] += 1; };
const pump = () => {
  const el = doc.querySelector(SELS.join(", "));
  if (!el || el.disabled) return false;
  for (const s of SELS) if (el.matches(s)) { tapped[s] += 1; break; }
  press(el); return true;
};

/* ② 🔒 **떴는데 한 번도 안 눌린 셀렉터가 있으면 빨간불** */
const uncovered = SELS.filter((s) => seen[s] > 0 && tapped[s] === 0);
check(uncovered.length === 0, `화면에 뜬 셀렉터를 전부 눌렀다 — ${uncovered.join(" · ")}`);

/* ③ 🚧 안 뜬 것은 「통과」가 아니라 「미도달」입니다. 조용히 넘기지 마세요 */
const never = SELS.filter((s) => seen[s] === 0);
if (never.length) console.log(`🚧 이번 판에 안 나온 자리: ${never.join(" · ")} — **검증됨이 아닙니다**`);
```

### 🔒 목록 자체가 소스와 어긋나면 검사가 통째로 눈이 멉니다

목록에서 셀렉터를 **지워 버리면** ①②가 같이 눈이 멉니다. 그래서 **목록을 소스와 맞춰** 보세요 —
이건 「등록 지점」 검사와 같은 모양입니다.

```js
/* ㉮ 소스에 **직접 적힌** 탭 자리는 전부 목록에 있어야 한다 */
const lit = [...SRC.matchAll(/onTap\(\s*(?:\w+\.)?querySelector\(\s*[`"'](\.[\w-]+)/g)].map((m) => m[1]);
check(lit.every((x) => SELS.includes(x)), "소스의 탭 자리가 전부 등록돼 있다");
/* ㉯ 🔑 변수로 넘기는 자리는 ㉮로 못 뜯어요 — **호출 자리의 개수**를 검사에 박습니다
      (소스에서 세어 오면 늘어나도 따라가서 안 잡힙니다) */
const TAP_SITES = 6;
check((SRC.match(/\bonTap\(/g) || []).length - 1 === TAP_SITES, "탭 자리가 그대로다");
```

### ⚠️ 그리고 **커버리지가 난수에 걸려 있으면 방어가 아닙니다**

위 단언은 *"떴을 때만"* 물으므로, 그 화면이 **가끔만 뜨면 가끔만 지킵니다.**
실측했더니 🧱 차단(=`defend` 카드)은 **여섯 판에 한 번**이었어요 — 한 라운드로 끊으면
**6번 중 5번은 아무것도 안 지키는 초록불**이었습니다.

- **닿을 때까지 더 굴리세요** (라운드 상한을 두고). 못 닿으면 **빨간불이 아니라 🚧**로 —
  난수 탓에 빨간불이 뜨는 검사는 아무도 안 보게 됩니다
- 🔒 **상한에 걸려 끝날 때는 뒷정리를 하지 마세요.** 원인은 하나인데 뒤의 검사가
  줄줄이 빨간불이 되면 *"저건 원래 빨간불"*로 배웁니다 (실측: 6건 → 1건으로 줄였습니다)
- **결정론적인 방어는 따로 세우세요** — 그 화면을 직접 여는 단위 검사로요

### 🔴 harness의 가짜 `requestAnimationFrame`이 게임을 얼립니다

같은 라운드에서 나온 곁가지인데 **더 조용합니다.**

```js
window.requestAnimationFrame = (cb) => setTimeout(() => cb(0), 0);   // ❌
```

움직이는 판은 `dt = (t − last) / 1000`으로 갑니다. **`t`가 늘 0이면** 첫 프레임 `dt`가
큰 음수, 그 뒤로는 0이라 **상대가 제자리에 얼어붙어요.** 그러면
**스스로 끝나야 할 판이 안 끝나고**(pump가 12초를 헛돎), 판정도 늘 `s = 0`이 됩니다.
화면은 멀쩡히 그려지니 **아무 검사도 안 울어요.**

```js
window.requestAnimationFrame = (cb) => setTimeout(() =>
  cb(typeof performance !== "undefined" && performance.now ? performance.now() : Date.now()), 0);   // ✅
```

> **재는 대상이 시간을 쓰면, harness가 넘기는 시계부터 의심하세요.**

## 🚨 감도 검사 — 기준선을 **「변이를 넣은 소스」**로 둡니다

**방어가 겹치는 자리에서는, 단독 변이가 잡히는지만 보면 안 됩니다.**

이 저장소가 같은 형태에 **두 번** 걸렸어요:

| 언제 | 무엇이 겹쳤나 | 증상 |
|---|---|---|
| 재도전 가드 | 같은 것을 막는 **가드가 셋** | 하나를 빼도 **증상 0장** → 그 자리 검사가 통째로 죽어 있었음 |
| 📨 조기 제안 | 앞 화면이 남긴 **화면 상태** | 감추기 줄을 통째로 지워도 이미 감춰져 있어 **변이가 초록불로 통과** |

> **★ 형태:** *여러 자리가 같은 상태를 쓰는데 **뒤 자리가 앞 자리의 흔적을 못 지우면**,
> 앞 자리가 뒤 자리의 검사를 가립니다.*

**가리는 줄은 단독으로는 증상이 0장입니다.** 동작이 없으니 **동작 검사로는 원리적으로 못
잡아요** — 검사가 부족한 게 아니라 그 줄의 성질입니다. 그래서 **감도 자체를 검사**합니다.

```
⒜ 본 변이만        → 빨간불이어야 한다  (= 감도가 있다)
⒝ 가리는 줄 제거 + 본 변이 → 초록불이면 «가려진 것»
```

🔑 **이 검사만 기준선이 무변이 소스가 아니라 「본 변이를 넣은 소스」입니다** —
재는 것이 게임 동작이 아니라 **다른 검사의 감도**라서요. 파일에 그 점을 크게 적으세요.

```js
const solo  = run(MUT.M_BACK);                                   // ⒜
const combo = run({ "game.js": MUT.M_RESET["game.js"].concat(MUT.M_BACK["game.js"]) });  // ⒝
check(solo.hidden === false && combo.hidden === true,
  "감도 검사 — 「끄는 줄」이 본 검사를 떠받치고 있다");
```

**⒝(가려짐)를 단언하는 것은 「결함을 정답으로 단언」이 아닙니다.** *"①이 ②를 떠받친다"*는
**참인 구조적 성질**을 못 박는 거예요. 구조를 바꿔 «①이 없어도 ②가 잡히게» 만들면 이 줄이
빨간불이 되고, **그때 사람이 파일을 엽니다.** 그게 노리는 마찰입니다.

**그리고 「가리는 줄」이 아예 사라지면 — 0번 「변이 등록 검사」가 먼저 잡습니다.**
그 줄을 겨눈 변이 정규식이 소스에 안 걸려 ❌ 한 줄이 뜨거든요.
🔑 0번이 여기서 **두 몫**을 합니다: 「변이가 안 도는 걸 알리는 장치」이자 **「이 줄이 존재해야
한다」는 계약** 그 자체예요.

### 🔒 애초에 안 겹치게 — **render 맨 앞에 「끄는 줄」 하나. 계약마다 줄은 여럿으로.**

한 화면이 두 몫을 하면 **「켜는 줄」마다 「끄는 줄」**이 있어야 합니다.
그리는 함수 **맨 앞**에서 상태를 한 번 되돌리고, 계약은 **각자 자기 줄**로 두세요.

```js
if (el) el.classList.remove("hidden");                    // ① 먼저 되돌리기
if (el) el.classList.toggle("hidden", 최종의_계약);        // ② 계약 A
if (조기 && el) el.classList.add("hidden");                // ③ 계약 B
```

⚠️ **「②③을 한 줄로 합치기」는 하지 마세요.** 두 가지가 동시에 나빠집니다:
- **신호가 합쳐집니다** — 계약 A가 깨진 것과 B가 깨진 것이 구분이 안 돼요
- 🔴 **변이 정규식이 「부분식」을 겨누게 됩니다** — `|| playedStage("m")` 같은 조각은
  **구현 변경에 가장 잘 죽는 형태**이고, 이 저장소가 *"변이 정규식이 두 번 죽었는데
  「실패 1건」으로만 보임"*으로 데인 바로 그 자리입니다.
  **줄 단위 정규식은 튼튼하고 부분식은 안 튼튼합니다.**

### ⚠️ 대상이 사라지면 **인스턴스는 지우고 패턴만 남기세요**

감도 검사도 예외가 아닙니다. 지키던 줄이 삭제되면 **그 감도 검사도 같이 지웁니다** —
대상 없는 검사를 남기는 게 정확히 **「검사가 옛 계약을 지킴」**이에요.
🔑 **다만 형태는 이 문서에 남깁니다.** 인스턴스가 사라졌다고 도구까지 잃으면
같은 사고가 **세 번째** 납니다.

## 검사가 무엇을 재고 있는지 스스로 찍게 하세요

**측정 조건을 결과 줄에 함께 출력하세요.**

```
측정 조건: _t.skill = 0.5 · 명단에 me 없음(순수 산식) · 전력 70:70 · N=20000 · 시드 11/202/5150/31337
시드별 [-14.70 -14.62 -14.31 -14.63]
```

⚽ 더 윙어 II에서 이게 없었으면 더 늦게 알았을 것이 있습니다 —
**어떤 검사가 조작 실력(`skill`)을 아예 안 타고 있었어요.** 명단에 내 선수가 없어서
판정 함수가 불리지도 않았는데, 값만 보면 정상으로 보였습니다.

찍어야 할 것: **표본 수 · 시드 · 무엇을 고정했는지 · 명단/입력의 성격**.
특히 **"이 검사는 X를 안 본다"**가 의도라면 그것도 적으세요.

> 조건이 안 적혀 있으면, 나중에 값이 흔들릴 때
> **코드가 변한 건지 조건이 변한 건지 아무도 못 가립니다.**

같은 이유로, **하나의 검사가 두 가지를 재고 있으면 갈라 두세요** —
"순수 산식 대칭"과 "실제 플레이"는 다른 질문이고, 섞으면 어느 쪽이 깨졌는지 안 보입니다.

## 사람의 조작을 검사로 굳히지 마세요

미니게임처럼 **사람이 하는 것**을 시뮬레이션으로 재면, 검사가 **코드가 아니라
당신이 지어낸 조작자 모델**을 잽니다.

⚽ 더 윙어 II에서 실측으로 드러났습니다 — 같은 σ의 조작자를 **겨냥 전략만 바꿔** 다시 짜니:

| | 🏃 | 🥅 | 🎯 | 🧱 | 폭 |
|---|---|---|---|---|---|
| 첫 모델 | 0.522 | 0.522 | 0.521 | 0.537 | 0.017 |
| 다시 짠 모델 | 0.558 | **0.655** | 0.559 | 0.510 | **0.145** |

*"빈 곳 한가운데를 겨냥"*으로 바꾼 것 하나로 0.52가 **0.66**이 됐습니다.
밴드가 ±5%p인데 조작자 모델 하나가 그걸 통째로 넘나듭니다.

**대신 「유효 조건」을 지키세요:**

- 그 값을 만든 **상수들을 pin**하고, 움직이면 *"다시 재세요"*로 빨간불
- 값이 아니라 **관계·부등호**로 지킬 수 있으면 그쪽을 쓰세요
  (예: 두 신호가 갈리는 조건 `a × b > c`)
- 실측값은 **"측정"이 아니라 "기록"**이라고 파일에 적으세요

> 같은 이유로, **밸런스 실측값도 검사에 그대로 박지 마세요.**
> 그건 balancer가 잰 것이고, 검사가 재현하려면 시뮬레이터를 새로 짜야 하는데
> 그게 곧 **"경로가 다른 시뮬레이터"**입니다.

## 픽스처는 모양뿐 아니라 **시점**도 맞아야 합니다

실측 표에서 숫자를 가져올 때 **그 숫자가 언제의 값인지**를 보세요.

⚽ 더 윙어 II에서 났습니다 — 실측 표의 `71.9`가 **시즌 끝** 값인데 그걸
**시즌 내내**의 값으로 픽스처에 박았어요. 훈련 78턴이 경기 사이에 끼어 있어
개막전 값은 **46.9**였습니다. 그 차이 하나로 출전 수가 12.1 → 28.7이 됐고,
두 하네스가 서로 다른 판정을 냈습니다.

- 값 옆에 **"언제의 값인가"**를 적으세요 (개막전 / 시즌 끝 / 커리어 평균)
- 커리어 안에서 자라는 값은 **한 점으로 고정하면 안 됩니다** — 성장 경로를 태우세요
- 남의 표에서 가져온 값은 **그 표의 측정 조건**까지 함께 옮기세요

> `_load.js`의 SPREAD 함정과 같은 뿌리입니다 — **픽스처가 실제와 다른 세계를 만드는 것**.
> 거기는 분포가 달랐고 여기는 시점이 달랐어요.

## 픽스처가 기울어 있지 않은지 검사하세요

픽스처는 **한 겹만 고쳐서는 안 됩니다.** 같은 게임에서 두 겹이 나왔어요 —
고정 `SPREAD`를 무작위로 바꿨는데도 **내 자리 한 칸만 평평하게** 두어
골 에이스가 윙어 62.8%로 기울어 있었습니다(실제 50.1%).

**픽스처 건강 자체를 검사로 만드세요** — 픽스처가 만드는 분포가 실제 게임의 분포와
같은 자리인지. 안 그러면 검사는 초록불인데 **실제와 다른 세계를 재고 있습니다.**

## ⚠️ 실행할 때 종료 코드를 보세요

```bash
for t in tests/{game}/*.js; do node "$t" | tail -1; done

# ✅
red=0; for t in tests/{game}/*.js; do
  node "$t" >/dev/null 2>&1 || { echo "❌ $(basename $t)"; red=$((red+1)); }
done; echo "실패 ${red}건"
```

마지막 줄의 "✅ 통과"만 읽으면 **스택만 뱉고 죽은 검사가 조용히 지나갑니다.**
실제로 축구 검사 열 개가 여러 커밋 동안 죽어 있었어요.

칸이 겹치는지, 헤더가 세로로 쪼개지는지는 **폰으로 봐야 압니다.**
