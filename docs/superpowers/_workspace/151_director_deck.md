## 5. 👁️ 실기기로 봐야 하는 것 — **기계가 못 재는 자리**

1. 🏁 **0' 두 줄이 620ms 간격으로 흐르는 게 「두 문장」으로 읽히나, 「깜빡임」으로 읽히나.**
   버튼을 누르기 **전**에 흐르는 줄이라, 사람이 힌트를 읽는 사이에 지나갑니다 —
   *"뭐가 지나갔는데 못 읽었다"*가 되면 순서를 다시 봐야 해요.
2. ⏱️ **`FLOW_MS`(620ms) vs 결정 줄(900ms)의 차이가 손에 잡히나.**
   ②「밀도의 차이가 긴장을 만든다」가 실제로 서는지는 **눌러 봐야** 압니다.
3. 🧡 **60' 이름 줄이 «내가 한 일»로 읽히나, «배경음»으로 읽히나.**
   기하로는 결과 줄과 갈렸는데(회색 vs 초록/빨강), *"이게 내 얘긴가"*는 다른 문제예요.
4. 🌀 **84' `mid`에서 판이 «아무 일도 안 일어난 것»처럼 보이지 않나.**
   `BALL_FLOW.mid`는 폭이 12로 제일 넓은데, 90분 직전에 공만 흔들리면 김이 샐 수 있어요.
5. 📱 **12' 줄이 320px에서 두 줄로 접히는 것**(57px)이 답답한가 — 390px에선 한 줄입니다.

## 7. ⏸️ 미룬 결정 — **원인 확정 · 예산 대기**

> 📌 볼트 `백로그 — 미룬 결정`행. **「미정」이 아닙니다** — 원인도 고치는 법도 확정됐고,
> 예산(다시 재야 하는 범위)이 지금 안 맞아서 미룹니다.

### 무엇이 어긋나나

확인 화면의 드라이버(`w2Play`)가 🔥 순간 카드에 대해 **같은 객체를 두 번** `push` 합니다
(열기 → 미니게임 → 닫기). 그런데 덱 카드는 **`score`를 한 벌**밖에 못 들어요.
그래서 카드가 **열릴 때 스코어보드가 이미 「판정 뒤」 값**을 보여줍니다.

```
🌊 덱 68' 열림   문구 "🔥 골문 앞! 이걸 넣으면 동점입니다"   스코어보드 1 : 1   ← 이미 동점
🌊 덱 68' 닫힘   문구 "⚽ 골!! 김윙어, 그물을 흔듭니다!"      스코어보드 1 : 1
```

**실제 게임엔 없는 어긋남입니다.** `town.js`는 `draw(live)`(열기)와 `draw(live, done)`(닫기)에
**다른 `score`**를 넘겨요 — `land()`가 `hg`/`ag`를 갱신한 **뒤**에 닫기 값을 만듭니다.
즉 확인 화면만 「결과를 미리 아는 스코어보드」를 보여주고, 그 위에서 판단하게 됩니다.

### 왜 지금 안 하나

1. **범민 님이 지적한 축이 아닙니다.** 지금 쫓는 건 「90분 흐름의 밀도」예요.
2. **여섯 덱 전부에 닿습니다** — 🏟️ 프로 넷(tight·rout·decisive·quiet) 포함.
   그 넷은 오늘 아무도 다시 안 잰 자리입니다.
3. **하네스 구조를 바꾸는 일**이에요(덱이 스코어 한 벌만 든다는 전제). 픽스처 형식이 바뀌면
   `tests/check-page-test.js`도 같이 갑니다.

### 🔑 판단이 바뀌는 조건 — 다음 사람이 **확인할 수 있는 형태로**

아래 중 **하나라도** 참이 되면 그때 엽니다.

- ☐ **덱 카드가 열림/닫힘 두 벌의 `score`를 들 수 있게 되면**
  (예: `{ open: { score, stakeKey }, close: { score, result, text } }`, 또는 카드 두 장으로 분리).
  이건 형식 변경이라 **6개 덱 + `check-page-test`를 한 번에** 손봐야 합니다.
- ☐ **🏟️ 프로 넷을 어차피 다시 재는 작업이 생기면** — 그때 같은 왕복 안에서 처리하는 게
  제일 쌉니다(따로 하면 여섯 덱을 두 번 훑게 돼요).
- ☐ **확인 화면을 보고 「스코어보드가 이상하다」는 보고가 실기기에서 올라오면** — 그러면
  더 이상 「하네스만의 문제」가 아니라 **사람이 실제로 오독한 것**이라 우선순위가 올라갑니다.
