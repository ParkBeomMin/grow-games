## 2. 🖼️ 접히는 선 위에 무엇을 놓았나 — **이번 설계의 핵심**

조립대는 390px에서 **세로 1,300px이 넘습니다.** 3D를 어디에 두느냐가 아니라
**「무엇과 함께」 두느냐가 문제였어요.**

### 문제 — 🎲가 접히는 선 아래에 있었습니다

작업 전 실측 (390×844):

| 요소 | 문서 y | 접히는 선(844) |
|---|---|---|
| 🧒 실루엣(54×62) + 이름 | 145 | 위 |
| 📈 레이더 | 215~482 | 위 |
| 🌱 등급 여섯 줄 | 490~685 | 위 |
| 🎁 타고난 것 | 693~852 | 걸침 |
| **🎲 다시 뽑기** | **924** | **🔴 아래** |

*"🎲를 굴리면 체형이 바뀝니다"*인데 **굴리는 순간 캐릭터가 화면 밖**이면
아무 일도 안 일어난 것과 같습니다. 3D를 그냥 위에 얹으면 이 거리가 **더 벌어져요.**

### 해법 — 위는 맥락 고정, 아래는 행동 고정

세로 스포츠 UI의 검증된 형태를 그대로 씁니다.

```
🧬 선수 만들기                     32px
🎲는 몇 번이든 눌러도 돼요…         50px
┌───────────────────────────┐
│ 🧒 이름 · 🎂 17세 · 🦶 오른발 │  ← 무대 위 이름표(왼쪽 위)
│                           │
│        🧍 3D 선수          │  240px · position: sticky (top)
│              ⚽            │
│           🦶 오른발         │  ← 칩이 공 바로 아래
├───────────────────────────┤
│ 🌱 출발점 — 등급 여섯 줄    │  195px   ← 🎲가 바꾸는 것을 가장 곧게 읽는 자리
├───────────────────────────┤
│ 📈 지금 실력 (레이더)       │  267px   ← 접히는 선 아래
│ 🎁 타고난 것                │  159px
└───────────────────────────┘
🎲 다시 뽑기  ·  📊 표준과 견주기    ← position: sticky (bottom)
[ 이 선수로 시작 ]  /  ← 뒤로
```

**두 가지를 바꿨습니다:**

| | 바꾼 것 | 왜 |
|---|---|---|
| ① | 🌱 등급 여섯 줄을 **📈 레이더보다 위로** (`benchHTML`의 순서 · `data-slot` 1↔2) | 🎲가 굴리는 건 **📊 배분**이고 그걸 가장 곧게 읽는 게 여섯 줄이에요. 캐릭터와 숫자가 붙어 있어야 굴린 보람이 보입니다 |
| ② | 🧍 무대 `sticky top` · 🎲 줄 `sticky bottom` | **가운데를 아무리 스크롤해도 「캐릭터」와 「굴리는 손」이 한 화면에** 있습니다 |

> ⚠️ **CSS `order`로 눈속임하지 않았습니다.** DOM 순서를 실제로 바꿨어요 —
> `order`만 쓰면 낭독 순서가 화면과 어긋납니다.

**실측 (헤드리스 · 320 / 390px 둘 다):**

| 잰 것 | 320px | 390px |
|---|---|---|
| 🧍 무대 + 🌱 등급 여섯 줄이 접히는 선 안 | ✅ 등급 끝 **590px** | ✅ **580px** |
| 420px 스크롤 뒤 무대와 🎲가 함께 보임 | ✅ 무대 −2~188 · 🎲 676~736 | ✅ 무대 −2~238 · 🎲 675~735 |
| 가로 넘침 | ✅ 0px | ✅ 0px |
| 탭 칸 | ✅ 46 / 46 / 50 / 54px | ✅ 같음 |

**390×667(작은 폰)에도 제목 32 + 안내 50 + 무대 240 + 등급 195 = 517px가 들어옵니다.**

## 3. 🎲 굴리면 몸이 바뀝니다 — 어떤 칸이 어디에

**총합이 194로 고정**이라, 한 칸이 오르면 다른 칸이 내려갑니다. 그래서 **여섯 중 다섯을**
몸에 실었어요 — 한 칸만 쓰면 「내려간 칸」이 몸에 안 실려 **굴림이 한 방향으로만 보입니다.**

| 몸 | 어디서 오나 | 폭 |
|---|---|---|
| 몸통·어깨 두께 | 🛡️ 수비 + 🫀 체력 | 반지름 0.255 → 0.340 |
| 다리 길이 | ⚡ 스피드 + 🏃 드리블 | 0.52 → 0.72 |
| 다리 굵기 | ⚽ 슛 | 0.085 → 0.123 |
| 팔 길이 | 🎯 패스 | 0.40 → 0.50 |
| 머리 모양 · 머리색 · 피부색 | `shapeKey` (🎲가 같이 굴려요) | 3 × 6 × 4 |
| **🧒 머리 크기** | **아무것도 안 실립니다 (고정 0.385)** | — |

> 🔑 **머리를 고정한 게 중요합니다.** 여기가 흔들리면 🎲를 굴릴 때마다 **「다른 사람」**이 돼요.
> 조립대가 「내 선수를 다듬는 자리」이려면 **안 바뀌는 축이 있어야** 합니다
> (이름·나이·🎁 타고난 것과 같은 역할입니다).

**실측**: 🎲를 8번 눌러 **체형 8가지가 전부 다름** (`torsoRX|legLen` 조합 8/8).

## 4. 🦶 주발 — 거울이 한 번 뒤집힙니다 (가장 조심한 자리)

**캐릭터가 우리를 마주 보고 서 있어서, 캐릭터의 왼발은 화면 오른쪽에 보입니다.**

이건 예전에 실제로 낸 버그와 **같은 형태**예요 — 🦶 주발 표시의 색이 판정과 반대쪽이었고,
넓다고 색칠된 쪽이 실제로는 좁은 쪽이었습니다. ***"안 보이는 것"이 아니라 거짓말을 하고
있던 것***입니다.

**그래서 세 겹으로 막았습니다:**

| | 무엇 | 어디 |
|---|---|---|
| ① | 부호를 **한 곳에서만** 정합니다 (`side`) | `char3d.js` `shapeRig` |
| ② | `🦶 왼발` 칩을 **공 바로 아래**에 붙입니다 — 라벨이 물건 옆에 있으면 **좌우를 외울 필요가 없어져요** | `style.css` `.w2c-foot` |
| ③ | 렌더 검사가 **공의 화면 좌표**를 잽니다 | `scripts/w2-avatar-render.js` A절 |

**②는 손으로 %를 박다가 한 번 틀렸습니다.** 캐릭터를 오른쪽으로 비켜 세운 탓에
공의 화면 위치가 좌우 대칭이 아니었고, **왼발잡이에서 칩이 공을 덮었어요.**
→ **3D가 재서 CSS 변수로 넘기고**(`--ball-x` · `--ball-w` · `--ball-bot`),
CSS가 그 아래에 붙입니다. 무대 높이·카메라 거리·다리 굵기가 전부 이 위치를 움직이는데
**CSS는 그걸 모릅니다.**

**실측 (칩과 공의 네모 겹침을 2차원으로 확인):**

| 주발 | ⚽ 공 (무대 %) | 🦶 칩 | 판정 |
|---|---|---|---|
| 왼발 | x 71.3~79.3 · y 69.1~80.8 | x 67.2~83.2 · y **84~93.2** | ✅ 안 덮음 · 무대 안 |
| 오른발 | x 38.3~46.7 · y 70.2~82.6 | x 29.9~49.1 · y **85.3~94.4** | ✅ 안 덮음 · 무대 안 |

칩 글자(`🦶 왼발`)와 `.pb-meta`의 주발이 **같은 값인지도** 검사가 봅니다.

> 🔒 **변이 검증** — `side`의 부호를 뒤집으면 A절이 빨간불입니다(§8).

## 5. 🔴 검사를 안 죽이려고 한 것 — ES module + 폴백 위에 얹기

**jsdom에는 WebGL이 없습니다.** `tests/winger2/*`는 **게임 입구를 통해 실제 버튼을 눌러**
조립대까지 갑니다. 3D가 거기서 로드되면 12종이 통째로 죽어요.

| 장치 | 효과 |
|---|---|
| `<script type="module" src="char3d.js">` | jsdom은 module 스크립트를 **실행하지 않습니다.** 검사에서는 이 파일이 **없는 것과 같아요** |
| `_load.js`의 치환 정규식이 `<script src=`만 잡음 | `type="module"`이 먼저 오면 **안 걸립니다.** 그게 의도입니다 |
| `window.W2Char`가 **항상 늦게** 생김 | 모든 호출부가 "없는 순간"을 견디게 강제됩니다 — **제약이 아니라 폴백이 공짜로 생기는 구조** |
| `webglOK()`가 컨텍스트를 **실제로 만들어 봄** | 「있는지 묻기」가 아니라 「만들어 보기」. 가속 꺼진 기기·컨텍스트 상한 초과가 여기 걸립니다 |
| **폴백 위에 3D를 얹음** | `.pc-silhouette`이 무대 안에 **늘 깔려 있고** 3D가 그 위를 덮어요. 실패하면 아무것도 안 해도 실루엣이 보입니다 |

**폴백 실측** (WebGL을 막고 게임 입구로 진입):
캔버스 생성 0 · CSS 실루엣 **135×155px**로 무대를 채움 · 등급 6줄과 🦶 칩 **하나도 안 잃음** ·
페이지 에러 0.

## 6. 🔋 저사양·프레임 — 지킨 것

| 규칙 | 어떻게 | 실측 |
|---|---|---|
| **컨텍스트는 커리어당 1개** | 무대가 바뀌면 **캔버스만 옮겨 답니다**(`adopt`) | 🎲 8번 굴려도 `mounts = 1` |
| 화면 밖이면 루프 정지 | `IntersectionObserver` + `visibilitychange` | 화면을 감추면 `paused = true` |
| 화면을 떠나면 컨텍스트를 놓음 | 「이 선수로 시작」·「← 뒤로」에서 `dispose()` | 누른 뒤 `live = false` · 캔버스 0개 |
| `antialias: false` · `low-power` · `pixelRatio ≤ 2` · 그림자 없음 | | |
| `transform`/`opacity`만 움직임 | 숨쉬기·회전·공 회전 전부 Object3D transform | |
| 폴리 예산 | 구 12×8 · 눈 6×4 | **1,192 tri · 드로우콜 18** |

> ⚠️ **드로우콜은 설계 70번의 「≤ 12」를 넘겼습니다 (18).**
> 👀 눈 2 · 🧦 양말 2 · 👕 소매 2가 늘었어요. 셋 다 못 뺀다고 판단했습니다 —
> **눈이 없으면 마네킹**이고, **소매가 없으면 유니폼이 크롭탑으로 읽힙니다**(렌더에서 확인).
> 파츠가 전부 200 tri 미만이라 **폴리 예산은 오히려 줄었어요**(1,200 목표 대비 1,192).
> 넘긴 것을 숨기지 않고 적습니다 — 다음 사람이 여기에 더 얹을지 판단할 근거예요.

> 🔴 **🔥 순간 카드가 도는 동안 3D를 렌더하지 않습니다.** 이번엔 조립대에만 서 있어서
> 직접 부딪히진 않지만, `pause()`/`resume()`를 **공개 API로 뒀습니다.**
> 미니게임 화면에 3D를 얹는 사람이 나오면 그때 이 손잡이를 쓰세요 —
> 프레임이 떨어지면 판정이 나빠지고 `s` 분포가 내려가서, **곡선이 기기 성능에 의존**하게 됩니다.
> 밸런스 사고가 아니라 **밸런스를 잴 수 없게 되는 사고**예요.

## 7. 📦 첫 로딩이 얼마나 느려지나 — 재 봤습니다

**`three.module.min.js` = 675KB · gzip 168KB · brotli 136KB** (저장소 단일 최대 JS)
**`char3d.js` = 29KB · gzip 11KB**

### ① 타이틀 화면은 **한 푼도 안 냅니다**

`char3d.js`가 three.js를 **동적 `import()`**로 받습니다 — 🧬 조립대에 **처음 들어올 때**예요.

| CPU | 타이틀까지 (3D 없음 → 있음) |
|---|---|
| 보통 | 861 → **797ms** (차이 없음 · 노이즈) |
| ×4 느리게 | 1117 → **1057ms** (차이 없음) |

**타이틀에서 `three.module.min.js`를 받은 적 0회** — 5회 반복 확인.

### ② 조립대에서 얼마나 기다리나

`sw.js`의 `ASSETS`에 넣었더니 **서비스워커가 설치할 때 미리 받아 둡니다.**
이름 짓고 유스 고르고 포지션 고르는 동안(실제로 몇 초) 조용히 끝나요.

| 회선 (CPU ×4) | 🧍 3D가 서기까지 (포지션 누른 뒤) |
|---|---|
| 느린 4G · **SW 켬** | **1,036ms** |
| 3G · **SW 켬** | **1,055ms** |
| 느린 4G · SW 끔 (시크릿창 등) | 1,507ms |
| 3G · SW 끔 | **3,326ms** |

**그 사이 화면은 비어 있지 않습니다** — CSS 실루엣이 서 있다가 3D로 바뀝니다.
🔴 **그 전환이 덜컥거리는지는 기계로 못 잽니다 → 실기기 목록 ①번입니다.**

**비용**: 첫 방문에 백그라운드로 **168KB(gzip)**를 더 받습니다.
오프라인을 지키려면 `ASSETS`에 넣어야 하고, 안 넣으면 **온라인에선 멀쩡하고
오프라인에서만 3D가 안 뜹니다** — 그리고 실루엣으로 조용히 떨어져서 **아무도 눈치를 못 채요.**

## 10. 🔴 어긋난 것 하나 — `wiring-test.js` (고치지 않았습니다)

```
❌ ASSETS의 스크립트를 index.html이 다 받는다
   🔴 캐시에는 있는데 페이지가 안 받는 것: char3d.js, vendor/three.module.min.js
```

**나머지 11종 + `smoke-test` + `check-page-test`는 전부 초록불입니다.**

**이건 배선이 아니라 검사의 모형 문제입니다:**

| 파일 | 실제로 어떻게 실립니까 | 검사가 보는 것 |
|---|---|---|
| `char3d.js` | `<script type="module" src="char3d.js">` | `/<script src="…"><\/script>/` — **`type`이 먼저 오면 안 걸립니다** |
| `vendor/three.module.min.js` | `char3d.js` 안의 **동적 `import()`** | 스크립트 태그가 아예 없어요 |

**둘 다 실제로 실립니다 — 렌더로 확인했습니다** (3D가 뜨고, 타이틀에서는 안 받습니다).
`ASSETS`에 있어야 하는 것도 맞습니다(오프라인).

**그래서 손대지 않았습니다.** 이 검사는 *"캐시에는 있는데 페이지가 안 받는 것"*을 잡으려고
만든 것이고 그 취지는 지금도 옳아요. **모형이 자라야 합니다** —
`type="module"` 태그와 `import("…")` 지정자도 「페이지가 받는 것」에 세면 됩니다.
👉 **inspector 몫으로 넘깁니다.** (제가 정규식만 맞춰 통과시키면 그건 검사를 게임한 거예요.)
