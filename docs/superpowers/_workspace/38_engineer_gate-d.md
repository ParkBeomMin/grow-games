### 1번 — 죽은 인자를 남기지 않았습니다

### 5번 — 배선의 모양

```js
// career.js engRow — 🚨 나에게만. 이미 곱한 수로 넘겨요(엔진은 전역을 안 읽어요 §10-3b)
buff: x.me ? { g: buffMul("g"), a: buffMul("a"), d: buffMul("d") } : null,
```

## 🔴 3번(`ACE_POOL`) — 설계 근거가 코드와 다릅니다. 보고합니다

**시킨 대로 `wg`만 넣었습니다.** 다만 designer가 적은 **이유**가 코드에서 성립하지 않아요.

> designer: *"`wg`만 더하면 `GOAL_W[wg] 0.75 < GOAL_W[fw] 1.0`이라 **fw가 여전히 골 에이스가
> 되기 쉽습니다**"*

**`aceOf`는 `GOAL_W`를 보지 않습니다.** 능력치 최대 한 명을 그냥 고릅니다 —

```js
return list.reduce((a, b) => (abilityOf(a) >= abilityOf(b) ? a : b), list[0]);
```

포메이션이 fw 2 · wg 2라, 실제 명단 폭(`STR_SPREAD` ±14)에서 **골 에이스가 wg일 확률이 50.1%**입니다.
그리고 에이스 윙어의 무게는 `0.75 × 2.90 = 2.175`로 **비에이스 fw(1.000)를 넘습니다.**

**결론(fw가 위)은 그래도 지켜집니다** — 에이스가 아닌 나머지 fw가 `GOAL_W` 1.0을 계속 갖기 때문이에요.
실측 (실제 폭 ±14 무작위 · 4만 경기 · autoMatch):

| | fw | wg | mf | df |
|---|---|---|---|---|
| 되돌림 `goal: ["fw"]` | **54.0%** | 19.8% | 21.1% | 5.1% |
| 지금 `goal: ["fw","wg"]` | **42.6%** | 30.8% | 21.4% | 5.3% |

**fw 42.6% > wg 30.8% — 순서는 지켜집니다.** designer의 결론은 맞고 **근거만 틀렸어요.**
근거가 남아 있으면 다음 사람이 *"GOAL_W가 에이스 선택을 가른다"*고 믿게 되니 정정이 필요합니다.
