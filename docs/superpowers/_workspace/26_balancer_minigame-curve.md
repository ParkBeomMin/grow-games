## 중립 검증

### ① `s = 0.5`에서 자동 판정과 미니게임 경로가 **정의상** 같습니다

```js
// engine.js
function judgeAt(kind, s) { … return outcome(kind, cardP(autoP, ab, clamp(s, 0, 1))); }
const autoJudge = (kind) => judgeAt(kind, _skill == null ? 0.5 : _skill);
judgeFor: (s) => (pending ? judgeAt(pending.kind, s) : "miss"),
```

**둘이 같은 함수를 부릅니다.** `_skill`은 `_t.skill`(검사 훅)로만 설정되고
`beta/` 어디에서도 안 건드립니다(`grep` 확인) — 그래서 **실게임의 🤖 자동 진행은 정확히 `s = 0.500`**이에요.
미니게임이 제 손으로 판정을 만들지 않는 것도 확인했습니다(`winger-moment.js`는 `opts.judge(s)`로 되돌려 물어요).

### ② `cardP`는 `s`에 **정확히 선형**입니다 — 그래서 분포가 아니라 `E[s]`만 봅니다

| 능력치 | `half(a)` | `cardP(s=0, .25, .5, .75, 1)` | 측정 기울기 | 이론 `2·half(a)` |
|---|---|---|---|---|
| 70 | 0.185 | 0.2570 · 0.3495 · 0.4420 · 0.5345 · 0.6270 | **0.3700** | 0.370 ✅ |
| 110 | 0.198 | 0.4024 · 0.5011 · 0.5999 · 0.6986 · 0.7974 | **0.3950** | 0.395 ✅ |
| 150 | 0.200 | 0.5329 · 0.6329 · 0.7329 · 0.8329 · 0.9329 | **0.4000** | 0.400 ✅ |

시즌 생산량도 선형입니다 (fw110 · 단독 시즌 2,000회/칸):

```
s = 0.30 → 골 14.81 · 0.40 → 16.01 · 0.50 → 16.95 · 0.60 → 18.24 · 0.70 → 19.04
```

> 🔑 **그래서 `s`의 *분포*를 몰라도 됩니다.** clamp에 안 걸리는 한
> `E[P(s)] = P(E[s])`예요 — 겨냥 전략이 분산을 어떻게 바꾸든 **평균만 같으면 곡선이 같습니다.**
> (clamp가 걸리는 칸은 아래 §새 발견에서 따로 잽니다.)

### ③ 🫀 컨디션과 🦶 주발은 **기본값에서 중립**입니다 — 다만 경로가 둘씩입니다

| 축 | 경로 1 | 경로 2 (§2에서 새로) | 기본값에서 |
|---|---|---|---|
| 🫀 컨디션 | STEP 2 `isBig`의 `condMul` | 판정 창의 `condMul` | 컨디션 80 → **condMul 1.0000 정확** ✅ |
| 🦶 주발 | `w(i)`의 `foot` 배수 (±6%) | 판정 창 (`FOOT_WIN` ±25%) | 약발 5 → footMul **1.000** ✅ |

**기본 상태의 기댓값은 안 흔들립니다.** 다만 컨디션 60이면 두 경로가 곱해져
`0.94 × (판정 창 0.94를 지난 s의 손실)`이 됩니다 — **재기만 했고 판정은 designer 몫입니다**
(§2-7이 *"거는 곳은 두 곳"*이라고 적은 것과 같은 자리인지 확인이 필요해요).
