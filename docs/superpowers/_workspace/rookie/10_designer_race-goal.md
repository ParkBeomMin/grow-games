# 설계 — 🏅 개인 타이틀 레이스 목표판 (`beta/rookie/`)

2026-09-06 · **작성: Codex `gpt-6-astra`** · 구현: Claude
입력: 야구 도메인 스킬 · 저장소 규칙 · 통합 시뮬 설계 · `20_balancer_hits-anchor.md` · gpt-5.2의 앞선 진단

> ⚠️ 줄 번호는 아스트라가 **사본**을 읽고 적은 것이라, 구현 전에 실물과 대조했습니다 (아래 §대조 결과).

---

**1순위는 ‘개인 타이틀 레이스 목표판’입니다.** 기존 순위에 **선두와의 차이·바로 앞 선수·남은 경기·규정 충족까지 남은 기록**을 붙입니다. 수상 기준과 밸런스는 바꾸지 않습니다.

문서 5개는 지정 순서대로 읽었습니다. JS는 관련 호출 경로와 테스트 항목을 확인했으며, 전체 약 1만 2천 줄을 전행 정독한 것은 아닙니다. 파일은 수정하지 않았습니다.

**A. 무엇을 만들 것인가**

**1. 개인 타이틀 레이스 목표판.** 현재 `raceHTML()`은 상위 5명과 내 순위, 수상 안내만 보여줍니다. 선두 격차와 바로 앞 선수는 계산 가능한데 화면에 없습니다([career.js:511](`beta/rookie/career.js:511`)). 기존 `raceRank()`와 실제 개인 기록을 이용하면 짧은 세션마다 다음 목표를 보여줄 수 있습니다. 새 보상이나 난수를 추가하지 않고 완성할 수 있어 가장 먼저 합니다.

**2. 통합 기록의 연결 누락 보완.** 명단 화면에 앞서 해결할 기반 작업입니다. `moveTo()`는 시즌 중 이적 시 팀 승패와 `S.team`을 바꾸지만 로스터의 `me` 자리는 옮기지 않습니다([career.js:1900](`beta/rookie/career.js:1900`)). 또한 `lineupOf(false)`는 실제 상대가 아니라 첫 번째 다른 팀을 고릅니다([game.js:1274](`beta/rookie/game.js:1274`)). 내 경기의 `skipStats` 경로에서는 동료 도루·투구 기록이 빠지고, 등판 없는 날에는 타석 기록도 생성하지 않습니다(`sim.js:112`, `career.js:711`). 이 연결을 고치고 실제 시즌 경로로 재측정해야 팀 기록을 믿고 노출할 수 있습니다.

**3. 우리 팀 명단·개인 기록 카드.** 미완인 통합 시뮬 3단계를 구현합니다. 엔진은 이미 타자 9명·투수 6명을 생성하지만(`sim.js:59`), 프로 화면은 팀 순위와 개인 레이스만 붙입니다(`career.js:564`). 다만 2번을 먼저 완료합니다. 그다음 내 기록은 `S.season.stats`, 동료 기록은 현재 팀 로스터에서 읽고, 타자·투수 탭과 선수별 접이식 카드로 제공합니다. 배열 번호를 타순으로 표시하지 않습니다. 실제 보직은 `assignRole()`에서 별도로 정하기 때문입니다(`career.js:73`, `409`).

**4. 부문별 수상 확률 측정판.** 최다안타 약 3%라는 사용자 정정을 받아들입니다. 현재 검사는 라이벌 평균과 사람 기대치의 비율을 지키며, 실제 시즌별 공동 수상 여부의 분포를 측정하지 않습니다([sim-test.js:191](`tests/rookie/sim-test.js:191`)). 2번 보완 뒤 실제 자동 진행 경로에서 능력치·리그별 부문 수상률과 선두 격차 분포를 측정합니다. 측정 전에는 계수나 목표 밴드를 바꾸지 않습니다. 약 3%를 수위타자의 확률로도 일반화하지 않습니다.

**5. 고교 현재 지명 평가.** 고교 화면의 주목도와 종합 능력을 최종 지명 기준으로 연결합니다. `renderMain()`은 두 값을 따로 보여주지만(`game.js:972`), `showDraft()`는 `S.scout + overall() * 2`와 구간별 문턱으로 지명을 정합니다(`game.js:2303`). 같은 구간 판정 함수를 공유하여 ‘현재 기준 예상 지명’과 다음 구간까지의 평가 차이를 보여줍니다. 최종 지명 보장처럼 표현하지 않습니다.

**5.2와 다른 선택:** 명단 우선이라는 방향은 기록 연결이 온전할 때 타당합니다. 실제 소스에서 이적·상대 선택·기록 누락을 확인했으므로, 레이스 목표판을 먼저 만들고 명단 앞에 연결 보완을 추가했습니다. 팀 합산 분석은 그 뒤로 미룹니다.

**B. 1순위 구현 설계 — 개인 타이틀 레이스 목표판**

**1. 무엇을 푸는가**

지금은 내 순위가 보여도 다음 경기에서 무엇을 목표로 삼을지 직접 계산해야 합니다. 선택한 타이틀 부문마다 현재 위치와 다음 경쟁 상대를 짧게 보여줍니다. 비율 부문에서 순위에 들어가지 못한 선수에게는 순위 대신 규정 충족 목표를 제공합니다. 화면이 독자적인 순위나 예상 수상 확률을 만들지 않고, 기존 수상 판정이 읽는 순위에 설명을 붙이는 것이 핵심입니다.

**2. 데이터와 저장 정책**

**새 세이브 필드는 없습니다.** 기존 `raceKey`처럼 선택 상태는 `career.js`의 클로저에만 둡니다.

| 값 | 정본과 처리 |
|---|---|
| 선택 가능한 부문 | `myTitles()`의 반환 순서. 타자·선발·마무리 구분을 그대로 사용 |
| 선택 부문 | 기존 `raceKey`. 선택 불가한 값이면 첫 부문으로 초기화 |
| 경기 수 | `S.season.total || 144`. 기존 `raceRank()`·`titlesWon()`의 폴백과 동일하게 유지 |
| 완료 경기 | `S.season.game || 0` |
| 남은 경기 | `Math.max(0, total - game)` |
| 개인 기록 | `S.season.stats`. 로스터의 `me` 객체에서 읽지 않음 |
| 순위 | 해당 렌더에서 한 번 호출한 `raceRank(raceKey)` |
| 내 위치 | 반환 배열에서 `me === true`인 행의 인덱스 |
| 선두 | 반환 배열의 첫 행 |
| 바로 앞 선수 | 내 인덱스가 1 이상이면 바로 이전 행 |
| 규정 타율 기준 | 기존 판정과 동일한 `total * 2` **타수** |
| 규정 평균자책 기준 | 기존 판정과 동일한 `total * 0.9` 이닝 |
| 선수 식별 | 이름으로 찾지 않음. 내 선수는 `me`, 상대는 이번 순위 배열의 행 |

`S.season`이 없으면 기존처럼 순위 영역을 숨깁니다. `stats` 객체 자체가 없거나 깨졌다면 새 화면은 ‘개인 기록을 확인할 수 없어요’를 반환하고 `raceRank()`를 호출하지 않습니다. 객체가 있고 개별 누적 필드만 없으면 읽는 쪽에서 0으로 봅니다. 저장본에 기본값을 써 넣지 않습니다.

**중요한 기존 예외:** 평균자책 0인 사람은 현재 `raceRank()`와 `titlesWon()`에서 제외됩니다(`career.js:499`, `1338`). 일반적인 야구 규칙과 다르지만 이번 표시 기능에서 고치지 않습니다. 규정 이닝을 채웠어도 해당 조건이면 ‘무실점 기록은 현재 수상 집계에서 제외돼요’를 표시합니다. ‘실점하면 순위에 들어가요’ 같은 행동 목표는 만들지 않습니다.

**3. 함수 단위 설계**

아래 이름은 **새로 추가할 함수명**입니다. 줄 번호는 현재 파일의 삽입 기준입니다.

**① `raceMyEligibility(stats, metric, total)`**

삽입 위치: `career.js`의 `raceRank()` 바로 앞, 현재 476줄 주석 앞.

반환 형태:

```js
{
  eligible: true,
  reason: null,       // "ab" | "ip" | "zero-era"
  current: null,
  required: null,
  missing: 0,
  unit: null
}
```

동작을 다음으로 고정합니다.

- 누적 부문은 `eligible: true`.
- 타율은 `ab >= total * 2`일 때만 통과. 부족하면 `reason: "ab"`, 단위는 ‘타수’.
- 평균자책은 먼저 규정 이닝을 검사합니다. 부족하면 `reason: "ip"`.
- 규정 이닝을 채운 뒤 `titleMetric(stats, "era") <= 0`이면 `reason: "zero-era"`.
- 기존 수상 의미를 유지하기 위해 평균자책 값은 `titleMetric()`으로 계산합니다.
- 상태와 난수를 변경하지 않습니다.

**기존 함수 두 곳을 이 함수에 연결합니다.**

- `raceRank()`의 `myOk` 계산(`career.js:499`)을 이 함수의 `eligible`로 교체합니다.
- `titlesWon()`의 타율·평균자책 자격 검사 세 줄(`career.js:1336`)을 이 함수 호출로 교체합니다.
- NPC 규정 필터, 정렬, 동률 시 사람 우선, 수상 가치에는 손대지 않습니다.
- 두 함수의 `total || 144` 처리도 유지합니다.

표시와 수상에 규정 산식이 각각 생기는 것을 막는 작은 추출입니다. 정상 데이터에서 결과가 달라지면 구현 실패입니다.

**② `raceProgressOf(metric, ranked, eligibility, game, total)`**

삽입 위치: 기존 `RACE_UNIT` 선언 뒤, `raceHTML()` 앞(`career.js:508` 뒤).

순위 배열을 읽는 순수 함수입니다. 반환값은 다음 정보를 가집니다.

```js
{
  mode,              // "preseason" | "unqualified" | "empty" | "ranked"
  remaining,
  myIndex,
  leader,
  ahead,
  leaderGap,
  aheadGap,
  tiedFirst,
  soleEntrant
}
```

판정 순서:

1. `game === 0`이면 `preseason`. 0안타 공동 선두를 목표 달성처럼 표시하지 않습니다.
2. 자격 미달이면 `unqualified`.
3. 배열이 비었거나 내 행이 없으면 `empty`.
4. 나머지는 `ranked`.

`ranked` 계산은 다음과 같습니다.

- 현재 순위는 `myIndex + 1`. 별도의 공동 순위 체계를 만들지 않습니다.
- 선두가 나이면 `leaderGap = 0`.
- 내가 선두가 아니면, 누적·타율 부문은 `상대 값 - 내 값`, 평균자책은 `내 값 - 상대 값`.
- 바로 앞 선수 격차도 같은 방향으로 계산합니다.
- 내가 첫 행이고 같은 원값을 가진 NPC가 있으면 `tiedFirst: true`.
- 나만 순위 배열에 있으면 `soleEntrant: true`.
- 원본 배열에 `sort()`, `splice()`를 호출하지 않습니다.
- 값 비교는 반올림 전 원값으로 합니다.

**③ `raceGapText(metric, gap)`**

위 함수 다음에 추가합니다.

- 안타: `선두와 8안타 차이`
- 홈런: `선두와 3홈런 차이`
- 승수·탈삼진·세이브·도루도 기존 `RACE_UNIT`에 맞춥니다.
- 타율 격차는 소수 셋째 자리, 평균자책 격차는 소수 둘째 자리.
- 양수인데 반올림 결과가 0이면 각각 `0.001 미만 차이`, `0.01 미만 차이`.
- 정확한 동률만 `같은 기록이에요`.
- `안타 2개면 역전` 같은 예측으로 바꾸지 않습니다. 상대 기록과 타수가 함께 변하기 때문입니다.

**④ `raceEligibilityText(eligibility)`**

같은 위치에 추가합니다.

- 타수 부족: `순위 진입까지 38타수가 더 필요해요`.
- 이닝 부족: 아웃 단위로 올림한 부족 이닝을 표시합니다.
- 이닝 표기는 `12⅓이닝`, `12⅔이닝`처럼 씁니다. `12.1이닝`을 소수 12.1로 오해하게 하지 않습니다.
- 부족 아웃 수는 `Math.ceil(missing * 3 - 1e-9)`. 정수 경계의 부동소수 오차만 흡수합니다.
- `zero-era`는 앞서 정한 설명만 표시합니다.

규정에 도달했는지의 판정은 원래 실수 비교를 유지하고, **안내에 필요한 추가 이닝만** 아웃 단위로 올립니다.

**⑤ `raceProgressHTML(progress, eligibility, metric)`**

같은 위치에 추가합니다. 목표 카드 HTML만 반환합니다.

| 상태 | 표시 |
|---|---|
| 개막 전 | `첫 경기 후 순위가 쌓여요` |
| 규정 미달 | 내 규정 충족 현황과 필요한 타수·이닝 |
| 순위 데이터 없음 | `아직 비교할 순위 기록이 없어요` |
| 내가 선두 | `현재 선두예요` 또는 `현재 공동 선두예요` |
| 집계 대상이 나뿐 | `현재 집계 대상은 나뿐이에요`를 함께 표시 |
| 선두가 아님 | 내 순위, 선두 격차, 바로 앞 선수의 이름·구단·기록·격차 |
| 시즌 종료 | 남은 경기 대신 `정규시즌 기록 집계가 끝났어요` |

현재 선두라는 이유로 ‘수상 확정’을 표시하지 않습니다. 수상은 기존 결산 경로에서 정합니다.

**⑥ `raceHTML()` 변경**

현재 함수(`career.js:511`) 안에서 다음 순서로 처리합니다.

1. 시즌과 선택 가능한 부문을 확인합니다.
2. 화면 상태 문맥을 동기화하고 `raceKey`를 정합니다.
3. 로스터·개인 기록의 존재를 확인합니다.
4. 기존 `raceRank(raceKey)`를 **한 번만** 호출합니다.
5. `raceMyEligibility()`와 `raceProgressOf()`를 호출합니다.
6. **부문 탭 → 목표 카드 → 기존 상위 5명 표와 내 고정 행 → 수상 안내** 순서로 반환합니다.

현재 상위 5명·내 고정 행 규칙을 유지합니다. 내 바로 앞 선수가 표 밖에 있으면 목표 카드에서 확인할 수 있으므로 표의 행 수를 추가하지 않습니다.

로스터가 없을 때는 빈 표를 반환하지 않습니다.

- 시즌 중간: `이번 시즌은 개인 순위 기록이 없어요. 다음 시즌부터 볼 수 있어요`.
- 개막 전: 기존 `ensureRace()`가 생성에 성공하면 정상 표시합니다.
- 생성할 수 없는 상태: `개인 순위 정보를 준비하지 못했어요`.

현재 `raceRank()`가 호출하는 `ensureRace()`는 유지하지만, 새 목표 함수에서는 호출하지 않습니다. 시즌 중간 재시뮬레이션은 하지 않습니다.

**⑦ 문자열 출력 보호**

`raceHTML()`의 현재 선수명·구단명 직접 삽입(`career.js:520`)도 함께 고칩니다. 이 함수 근처에 `raceEscape(value)`를 추가하여 `& < > " '`를 HTML 엔티티로 변환하고, 기존 순위 행과 새 목표 카드의 동적 이름에 적용합니다. 이름은 외부 유저 풀에서도 오기 때문입니다(`career.js:363`).

이름을 `data-*` 식별자로 사용하지 않습니다.

**⑧ 화면 상태와 이벤트**

기존 `raceKey` 옆(`career.js:345`)에 `raceViewContext`를 추가합니다. 저장하지 않습니다.

문맥에는 `S` 객체 참조, 시즌 객체 참조, 리그 ID, 소속팀, 포지션, 보직을 보관합니다. 하나라도 달라지면 `raceKey`를 첫 번째 가능한 부문으로 초기화합니다. 경기 번호는 문맥에 넣지 않아 같은 시즌의 경기 사이에는 탭을 유지합니다.

- `syncRaceView()`를 `raceHTML()` 시작에서 호출합니다.
- `renderStandings()`의 시즌 없음 분기에서도 문맥을 비웁니다.
- `renderStandings()`의 기존 위임 이벤트(`career.js:566`)는 유지합니다.
- 클릭한 부문이 현재 `myTitles()`에 있는지 확인한 뒤 변경합니다.
- 재렌더 뒤 같은 탭 버튼으로 포커스를 복원합니다.
- 탭 클릭에서 `save()`, 훈련, 경기 진행을 호출하지 않습니다.
- 별도 추월 알림·타이머·결과 카드 연결은 이번 범위에 넣지 않습니다.

테스트 창구인 `Career._t`(`career.js:2902`)에는 `raceMyEligibility`, `raceProgressOf`, 두 포맷 함수만 추가합니다. 화면 검사는 실제 DOM 입구를 통해 수행합니다.

**4. 화면 배치**

기존 접이식 `#pro-standings` 안에 배치합니다. 위치는 이미 능력치·훈련 버튼 위입니다([index.html:181](`beta/rookie/index.html:181`)).

위 숫자와 이름은 화면 예시이며 밸런스 목표가 아닙니다.

- 접힘 상태는 기존 `<details>.open`에 둡니다. 새 저장 상태가 없습니다.
- 재렌더는 body만 교체하므로 펼침 상태를 유지합니다.
- 목표 카드는 세로 3~4줄, 긴 이름은 줄바꿈합니다.
- 탭은 2열 배치, 버튼 최소 높이 44px로 합니다.
- 버튼은 `type="button"`과 `aria-pressed`를 사용합니다.
- 목표 카드에 자동으로 읽히는 실시간 알림 속성을 붙이지 않습니다. 매 훈련 재렌더 때 반복 낭독되는 것을 피합니다.
- 가을야구에서는 기존 `renderPost()`가 같은 영역을 시리즈 현황으로 교체합니다(`career.js:1195`). 목표판을 따로 다시 그리지 않습니다.

새 스타일은 **신규 `beta/rookie/race.css`**에 `.rookie-race-*` 접두로 작성합니다. `index.html:25`의 기존 스타일 링크 다음에 로드합니다. `font: inherit`, `color: inherit`, `currentColor` 기반 테두리를 사용하여 확인하지 못한 테마 변수명을 지어내지 않습니다.

`sw.js:3`의 `ASSETS`에 `./race.css`를 추가하고 캐시 이름을 `rookie-v6`으로 올립니다. 공유 스타일과 스크립트는 수정하지 않습니다.

**7. 하지 않기로 한 것**

- **경기 결과의 추월 알림:** 이전 순위 스냅샷과 경기 종료 시점 연결이 필요합니다. 먼저 상시 목표판을 완성합니다.
- **상대보다 몇 안타 더 치면 역전하는지 예측:** 상대 성적과 분모가 함께 움직여 정확한 목표가 아닙니다.
- **수상 확률 표시:** 현재 평균 비율 검사만으로는 계산할 수 없습니다.
- **순위별 성장·돈 보상:** 경제와 성장 계약까지 넓어집니다.
- **규정 기준·동률·평균자책 0 처리 변경:** 표시 작업에 수상 규칙 변경을 섞지 않습니다.
- **팀 합산 기록·NPC 다년 커리어:** 기록 연결 보완과 별도의 데이터 설계가 먼저입니다.

**8. 계약에 닿는 위험**

가장 직접적으로 닿는 것은 **화면 순위와 실제 수상의 일치**입니다. 따라서 순위는 `raceRank()`에서 한 번 읽고, 내 규정 자격은 수상 함수와 같은 helper를 사용합니다.

세이브 계약은 새 저장 필드를 만들지 않고 지킵니다. 난수·밸런스 계약은 새 렌더 경로의 난수 소비와 상태 변경을 0으로 검증합니다. `PA_BASE`, `K_SHARE`, 타석 수, 성장·연봉 산식에는 변경이 없습니다.

마지막으로 이 목표판은 **현재 수상 집계의 설명**이지 통합 기록의 정확성을 새로 보증하는 기능은 아닙니다. A의 2번에서 확인한 연결 누락은 남아 있으며, 팀 명단과 상세 기록을 확대하기 전에 반드시 별도로 해결해야 합니다.
