## 1. 넣은 것

```js
const trainStep = (age, peak) =>
  age <= peak - 4 ? 1.1 : age <= peak + 1 ? 1.0 : age <= peak + 4 ? 0.7 : 0.45;

const TRAIN_NEUTRAL = { early: 1.226, normal: 1.000, late: 0.839 };

function trainMul(st) {
  const n = TRAIN_NEUTRAL[typeOf(st).id];
  return (n == null ? 1 : n) * trainStep(ageOf(st), peakAgeOf(st));
}
```

계단을 **`trainStep`으로 떼어 이름을 줬습니다.** 상수가 그 계단에서 역산되는 값이라,
둘이 붙어 있으면 종속 관계가 코드에서 안 보여요.

### 주석에 박아 둔 것 (원칙 ⑨)

| 무엇 | 어디에 |
|---|---|
| **중립화 상수지 트레이드오프 손잡이가 아니다** — *"만성이 세니까 ×0.7로"*가 정확히 하면 안 되는 일 | `TRAIN_NEUTRAL` 위 |
| **트레이드오프는 곡선이 맡는다** — 세기를 바꾸려면 `GROWTH_TYPES` 앵커를 옮겨라 | 〃 |
| **종속값이다** — 역산식 `Σstep(보통) ÷ Σstep(t)` (20~37세)을 적었고, 계단 눈금·구간·정점 나이를 바꾸면 **다시 재라** | 〃 |
| **왜 이름이 「훈련 상승폭」이 아닌가** — `train` 칸에 두었더니 트레이드오프로 읽혀서 지웠고, 지우자 계단 불균형(81.5/100/119.2)이 드러난 경위 | 〃 |
| `GROWTH_TYPES`에 **`train` 칸을 다시 만들지 말 것** | `GROWTH_TYPES` 위 |
| 면적 중립 창이 **데뷔~38세**이고, **은퇴 제안 나이로 끊지 말 것** (제안은 정보지 강제가 아니고, *선택의 결과*를 중립 대상으로 삼으면 원칙 ⑥의 반대 형태가 됨) | 〃 |

## 2. 🔴 측정 — 훈련 총량 (designer 목표 **±3%**)

**진짜 `trainMul`을 불러서** 쟀습니다 (계단·상수를 따로 베끼지 않았어요).

| 창 | 🌱 조숙 | 🌿 보통 | 🌳 만성 | 최대 편차 |
|---|---|---|---|---|
| ① 역산 창 그대로 (데뷔 20 ~ 37세) | 100.0 | 100.0 | 100.0 | **0.01%** ✅ |
| ② 새 면적 기준과 같은 창 (20 ~ 38세) | 100.7 | 100.0 | 99.5 | **0.64%** ✅ |
| ③ 데뷔 21세 (카드 18세) ~ 38세 | 99.8 | 100.0 | 100.8 | **0.61%** ✅ |
| ④ 데뷔 22세 (카드 19세) ~ 38세 | 98.7 | 100.0 | 102.4 | **2.02%** ✅ |
| ⑤ 카드 나이 17/18/19 균등 평균 | 99.8 | 100.0 | 100.8 | **0.61%** ✅ |

**모든 창에서 ±3% 통과.** 최악은 ④(데뷔 22세)의 **2.02%** — 카드 나이가 많을수록
조숙이 계단 아래쪽에서 시작해 조금 벌어집니다. 여유가 1%p라 계단을 만지면 다시 재세요.

**되돌림 대조** — `TRAIN_NEUTRAL`이 없었다면 (계단만, 20~37세):

| 🌱 조숙 | 🌿 보통 | 🌳 만성 | 최대 편차 |
|---|---|---|---|
| **81.5** | 100.0 | **119.2** | **18.90%** ❌ |

## 3. 🔴 inspector — 검사 38번이 **뒤집힌 계약을 지키고 있습니다**

원칙 ⑩대로 되돌려 봤더니, 이 저장소 표에 있는 *"버그를 정답으로 단언"*의 **거울상**이 나왔습니다.

### 지금 상태

```
기준선(코드 정상)                        → 38-1 ❌ · 38-2 ❌ · 38-변이 안 돎 ❌
변이(TRAIN_NEUTRAL 셋을 1.0으로 되돌림)   → 38-1 ✅ · 38-2 ✅
```

> 🚨 **폐기한 것을 되살리면 검사가 오히려 초록불이 됩니다.**

원인은 제 잘못이기도 합니다 — 56번 §7에서 제가 제안한 형태
(`trainMul(조숙 22세) === trainMul(보통 26세)`)는 **배수가 없는 세계의 계약**이었어요.
designer가 그 뒤 `TRAIN_NEUTRAL`을 되살리기로 하면서 **그 등식은 성립하면 안 되는** 것이
됐습니다. 지금 값으로는 1.226 ≠ 1.000 ≠ 0.839예요.

### 갈아 끼울 형태 셋 — 전부 확인해 봤습니다

**38-1 (교체) 「커리어 훈련 총량이 세 타입에서 같다」** ← 이게 `TRAIN_NEUTRAL`이 만드는 진짜 불변식

```js
const sum = (g) => { let t = 0; for (let a = 20; a <= 37; a++) t += P.trainMul({ age: a, growthType: g }); return t; };
const v = ["early", "normal", "late"].map(sum);
const m = (v[0] + v[1] + v[2]) / 3;
const worst = Math.max(...v.map((x) => Math.abs(x / m - 1) * 100));   // ≤ 3
```
- 지금: **0.01%** 🟢 · `TRAIN_NEUTRAL`을 1.0으로 되돌리면 **18.90%** 🔴 (확인함)
- **상수를 안 읽습니다** — *"세 값이 서로 같은가"*만 봐요. 계단을 바꾸고 상수를 다시
  역산하는 걸 잊으면 그때도 빨간불입니다(원하는 동작)

**38-2 (살릴 수 있음) 「계단은 거리만 본다」 — 등식이 아니라 *비가 일정한가*로**

```js
// 타입별 상수는 허용하되, 계단 자체가 타입을 보면 안 됩니다 (버려진 갈래 ①)
const r = (g, pk, d) => P.trainMul({ age: pk + d, growthType: g }) / P.trainMul({ age: 26 + d, growthType: "normal" });
// d = -8 … +9 전 구간에서 r가 **하나의 값**이어야 함
```
- 확인: 조숙/보통 비가 전 구간 **1.226 하나**, 만성/보통 **0.839 하나** 🟢
- 계단을 타입별로 쪼개면(갈래 ①) 비가 흔들려 빨간불

**38-3 (신설) 「상수가 계단의 종속값인가」** ← designer가 강조한 성격을 지키는 자리

```js
const st = P._t.trainStep, pk = { early: 22, normal: 26, late: 30 };
const S = (g) => { let t = 0; for (let a = 20; a <= 37; a++) t += st(a, pk[g]); return t; };
// |TRAIN_NEUTRAL[g] - S("normal") / S(g)| ≤ 0.005
```
- 확인: 조숙 1.226 vs 1.2262 (차 0.00024) · 보통 1.000 vs 1.0000 · 만성 0.839 vs 0.8390 🟢
- ⚠️ 이건 `_t.TRAIN_NEUTRAL`을 **읽습니다**. 하지만 *"문턱을 코드에서 읽어오는"* 함정이
  아니에요 — 소스의 상수를 **살아 있는 `trainStep`에서 계산한 값과 대조**하는 거라,
  둘 중 하나만 바뀌면 잡힙니다. 계단만 고치고 상수를 안 고치면 → 🔴

### 그리고 `BLOOM` 변이가 안 돌고 있습니다

정규식이 옛 `trainMul` 본문을 겨눕니다:
```
/ {4}return a <= p - 4 \? 1\.1 : a <= p \+ 1 \? 1\.0 : a <= p \+ 4 \? 0\.7 : 0\.45;/
```
그 줄은 `trainStep`으로 떼어냈어요. **지금의 진짜 되돌림 변이**는 이겁니다:

```js
NEUTRAL_OFF: { "prospect.js": [[
  /const TRAIN_NEUTRAL = \{[^}]*\};/,
  "const TRAIN_NEUTRAL = { early: 1, normal: 1, late: 1 };" ]] },
```
- 값을 정규식에 안 적었으니 **balancer가 상수를 재조정해도 안 죽습니다**
- 적중·치환 모두 확인했고, 걸면 38-1이 18.90%로 빨간불이 됩니다

`GROWTH_TYPES`에 `bloom` 칸을 심는 변이를 남기고 싶다면, 그건 이제
**"성장타입에 훈련 배수 칸을 다시 만들면 안 된다"**는 별개 계약이에요 —
`trainMul`이 그 칸을 안 보므로 지금 코드에서는 **효과가 없습니다**(변이가 안 걸리는 게 아니라
걸려도 아무 일이 안 나요). 그 계약을 지키려면 `GROWTH_TYPES`에 `train`/`bloom` 류 칸이
**없는지**를 직접 보는 편이 낫습니다.
