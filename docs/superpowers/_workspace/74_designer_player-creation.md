## 무엇을 푸는가

범민 님 제안:

> *"유망주 카드를 줘서 고르는 게 아니라 이름 내가 정하고 능력치, 키 랜덤으로 고를 수 있게 하고
> 주발 고르고 고유 특성 랜덤으로 고르고"*

**3택(견줌) → 굴리기(다시 뽑음)** 입니다. 얻는 것과 잃는 것이 분명합니다.

| | 3택 | 굴리기 |
|---|---|---|
| 감각 | *"주어진 셋 중 하나"* | **"내가 만든 선수"** — 애착이 큽니다 |
| 재미의 출처 | **견줌** (어느 게 나중에 좋을까) | **기대** (다음엔 더 좋을까) |
| 공정성 장치 | `잠재력 총합은 셋이 같아요` | 🔴 **통째로 사라집니다** |
| 최적화 | 셋 중 하나라 상한이 있음 | 🔴 **무제한이면 최고값까지 돕니다** |

### 🔑 그런데 위험의 정체가 「횟수」가 아닙니다

조율자님 걱정(*"무제한 리롤이면 곡선이 통째로 위로 밀린다"*)은 맞지만, **손잡이가 횟수가 아니에요.**

> **다시 굴려도 총합이 안 바뀌면, 몇 번을 굴려도 곡선이 안 밀립니다.**
> 바뀌는 건 **모양**뿐이니까요.
>
> 반대로 **총합이 흔들리면 리롤 1회도 곡선을 밉니다** — 기댓값이 `E[max of N+1]`이 되거든요.

**그래서 ②(총합 고정)를 먼저 정해야 ①(횟수)이 따라옵니다. 둘은 독립이 아닙니다.**

그리고 **이미 그 장치가 코드에 있습니다** — `prospect.js:171`

```js
const POOL = 194;                    // 세 장의 스탯 총합. 정확히 194로 고정
const STAT_LO = 18, STAT_HI = 54;
```

`spread()`가 반올림 우수리까지 되돌려 **총합을 정확히 194로 맞춥니다**(`prospect.js:417-431`).
주석에 이유가 적혀 있어요 — *"한 장만 1 높아도 「총합이 같다」는 약속이 깨집니다."*

### 🔴 그리고 지금 코드에 **이미 새는 자리**가 있습니다

```js
return { cards, talents: rollTalents(pos) };     // prospect.js:493
```

**⭐ 잠재력은 세 장이 공유합니다** — 어느 카드를 골라도 같아요. 그래서 3택 안에서는 중립입니다.
**그런데 🎲 리롤을 누르면 `rollCards`가 통째로 다시 불려서 잠재력도 같이 다시 굴러갑니다**
(`prospect.js:777`).

→ **현행 리롤 2회 = 잠재력을 3번 뽑아 가장 좋은 걸 고르기(`max of 3`)입니다.**
지금 곡선(5.8 / 24.6 / 63.6 / 91.0 / 99.0)은 그 상태에서 잰 값이에요.

**이게 새 설계의 기준선입니다.** 뒤의 「위험」과 balancer 항목이 여기서 나옵니다.

## 판정 — ①~⑤

### ② **총합은 고정합니다** (먼저 정해야 하는 것)

| 안 | 무엇 | 곡선 | 판정 |
|---|---|---|---|
| **총-1** ⭐ | **`POOL = 194` 고정 유지** — 다시 굴리면 **모양만** 바뀜 | 🟢 **0** | **권장** |
| 총-2 | 좁은 밴드 (±5%) — *"운 좋은 시작"*이 조금 | 🔴 리롤 횟수가 **곡선 손잡이**가 됩니다 | |
| 총-3 | 자유 | 🔴 곡선이 통째로 밀림 | 반대 |

**총-1을 권합니다.** *"운 좋은 시작"*의 재미는 **⭐ 잠재력과 ⭐ 특능의 모양**에서 이미 나옵니다 —
능력치 총합까지 흔들면 **재미가 아니라 뽑기가 되고**, 20시즌 곡선이 그 위에 서 있어요.

> 그리고 **총합 고정이 있어야 「다시 뽑기」를 마음 편히 줄 수 있습니다.**
> 이게 이 설계 전체를 지탱하는 한 줄입니다.

### ① 리롤 — **축마다 안전도가 다릅니다. 예산 하나로 묶어 플레이어가 씁니다**

| 축 | 다시 굴리면 | 곡선 |
|---|---|---|
| ✏️ 이름 | 값이 없음 | 🟢 0 |
| 🦶 주발 | **고르는 것**이라 리롤이 아님 | 🟢 0 |
| 📊 능력치 배분 | 총합 194 고정 → **모양만** | 🟢 **0** |
| 🧬 성장타입 | 커리어 총 면적 **±8% 중립화 완료** (실측 2.8%) | 🟡 거의 0 |
| ⭐ 특능 + 🩹 결함 | **값어치가 서로 다름** → 좋은 특능·가벼운 결함으로 수렴 | 🔴 **있음** |
| 📏 잠재력 (= 키) | `rand(0.8, 1.45)` × 6칸 → `max of N` | 🔴 **가장 큼** |

**→ 📏 잠재력은 첫 굴림에 확정하고 🔒 잠급니다. 나머지는 굴릴 수 있습니다.**

이게 ③의 *"생성된 키는 변경할 수 없습니다"*와 **정확히 같은 말**입니다 —
참고작이 키를 잠그는 건 인색해서가 아니라 **거기가 새는 자리**이기 때문이에요.

#### 🎲 다시 뽑기 — **예산 3회. 어디에 쓸지 플레이어가 정합니다** (제안)

횟수를 축마다 따로 주면 헷갈립니다. **하나의 예산**으로 묶으면 그게 **첫 결정**이 돼요 —
*"능력치 모양을 더 볼까, 재능을 더 볼까"*. 원칙 ⑦·⑧에 둘 다 좋습니다.

- **↩️ 직전 것으로 되돌리기는 예산을 안 씁니다** (직전 하나만 · 스택 아님)
- 되돌리기를 안 두면 플레이어가 **리롤을 안 씁니다** (잃을까 봐). 안 쓰는 손잡이는 없는 것과 같아요(원칙 ③)
- 되돌리기가 있으면 실질이 `max of (N+1)`이라, 🔴 **balancer는 그 기준으로 재야 합니다**

#### 🔴 새 방식은 현행보다 **덜 고를 수 있게** 됩니다 — 이게 중요합니다

| | 현행 (3택 + 리롤 2) | 새 방식 (🎲 3 + 되돌리기) |
|---|---|---|
| ⭐ 특능·🩹 결함 | 3장 × 3뽑기 ≈ **9개 중 1개** | **`max of 4`** |
| 📏 잠재력 | **`max of 3`** | 🔒 **1회 굴림** |

**둘 다 줄어듭니다 → 곡선이 「내려갈」 수 있습니다.**
원칙 ④는 *"새 축을 얹는 것만으로 세지면 안 된다"*인데 여기는 **약해지는 쪽**이라 사고는 아니지만,
**얼마나 내려가는지는 반드시 재야 합니다.** 목표 곡선이 5.8 / 24.6 / 63.6 / 91.0 / 99.0이에요.

> 🔒 **잠재력을 잠그면서 곡선을 맞추는 손잡이는 `rollTalents`의 범위입니다** —
> `rand(0.8, 1.45)`의 **하한**을 올리면 `max of 3` 없이도 기댓값이 회복됩니다.
> ⚠️ **다른 축의 손잡이를 쓰지 마세요**(원칙 ⑪) — 훈련 효율·`POOL`·등급 문턱은 이 축이 아닙니다.

### ③ 📏 키 — **넣습니다** (범민 님 확정). 형태는 **「⭐ 잠재력의 모양」**입니다

> ✅ **2026-08-30 — 범민 님이 *"키도 넣자!"*로 확정.** 아래는 **어떤 형태로**의 판정입니다.

#### 먼저 — 우리 코드에서 「성장 성향」은 **이미 있는 축**입니다

`game.js:1638`

```js
let gain = rand(2.2, 4.2) * S.talents[def.key] * m.growth * condMod * buffMod;
```

**`S.talents[칸]`이 그 칸의 훈련 배수입니다.** 즉 참고작의
`피지컬 성장 ↑ · 스피드 성장 ↓ · 드리블 성장 ↓` 배지 셋은
**우리 화면에서 이미 `⭐ 잠재력`으로 돌고 있어요.**

**그리고 `talents`는 이미 두 경로로 닿습니다** — 훈련 배수 + 클러치 보정(±6%).
`game.js:831-834`에 그 이중 계상을 의식해 폭을 좁혔다는 기록이 있습니다:

> *"재능은 훈련 속도뿐 아니라 '큰 순간'에도 작용해요 (클러치 보정).
> **스탯에 이미 반영된 걸 또 곱하는 이중 이득이 되지 않게 폭을 좁혔어요**"*

#### 형태 판정 — a·b·c·d

| | 형태 | 판정 | 왜 |
|---|---|---|---|
| **a** | **7번째 스탯** | 🔴 **반대** | ↓ 아래 세 가지 |
| **b** | **성장 성향 배지** (훈련 배수) | ⚠️ **뜻은 맞지만 새 축으로 만들면 안 됩니다** | 그 축이 **이미 `talents`입니다.** 새로 만들면 `talents`와 같은 층에 둘이 되어, 나중에 *"성장이 이상하다"*가 났을 때 **어느 축인지 못 가립니다**(원칙 ⑪) |
| **c** | **판정에 직접** | 🔴 **반대** | ↓ 아래 「엔진의 계약」 |
| **★ b′** | **b를 새 축이 아니라 `talents` 모양으로 표현** | ✅ **권장** | 배지 셋이 그대로 서고 **새 축이 0개 늘어납니다** |

**a(7번째 스탯)를 반대하는 이유 셋:**

1. 🔴 **`BLEND`가 6칸 위에 서 있습니다** (`engine.js:134-140`).
   7번째를 넣으면 `blend = S1×0.60 + S2×0.25 + S3×0.15`의 가중을 포지션마다 다시 잡아야 하고,
   **검사 304개 + 등급 38개가 그 위에 있습니다**
2. 🔴 **키는 훈련으로 안 오릅니다.** 능력치 화면에서 **유일하게 안 움직이는 줄**이 돼요 —
   그런데 그 화면의 정체가 *"내가 키운 것"*입니다
3. 🔴 **방금 확정한 등급 7단계·XP 바 문법에 안 맞습니다.** `183cm`의 등급이 `C`인가요?
   `다음 승급까지 12cm`인가요? **말이 안 됩니다**

#### ★ b′ — 키가 정하는 것은 **`talents` 6칸의 모양**입니다

```
📏 183cm
  🫀 체력  성장 ↑      🛡️ 수비  성장 ↑
  ⚡ 스피드 성장 ↓      🏃 드리블 성장 ↓
  ⚽ 슛 · 🎯 패스 — 영향 없음
```

**화면은 참고작과 같고, 축은 하나도 안 늘어납니다.**
그리고 지금 `⭐`가 *"왜 이 칸이 높은지"*를 못 말하는데, **키가 그 이유가 됩니다.**

| | |
|---|---|
| 산식 | `talents[k] ← talents[k] × HEIGHT_SHAPE[k](키)` |
| 중립 | **6칸 배수의 평균이 정확히 1** — 둘 올리고 둘 내리고 둘은 1.0 |
| 이름 | 🔴 **`HEIGHT_SHAPE`** — `HEIGHT_BONUS`라고 붙이면 다음 사람이 **밸런스 손잡이로 씁니다**(원칙 ⑨). *"평균이 1이 되도록 방향을 짝지은 모양 값"*이라고 바로 옆에 적으세요 |

#### 🔒 왜 c(판정에 직접)가 위험한가 — **키는 이미 판정에 닿아 있습니다**

```
키 → HEIGHT_SHAPE → talents → ① 훈련 배수 → S.stats → blend → sc(me) → autoP
                            └→ ② 클러치 보정 (±6%)
```

**키가 큰 선수는 🛡️ 수비·🫀 체력이 잘 커서 🧱 수비 카드의 `autoP`가 실제로 높습니다.**
경로가 이미 둘 있고, 코드는 그 둘이 이중 계상되지 않게 폭까지 좁혀 뒀어요.
**세 번째 경로를 만들 이유가 없습니다.**

그리고 순간 카드 엔진의 계약은 이렇습니다:

```
P(사건 | 카드) = clamp( autoP(me) + 2·half(a)·(s − 0.5), 0, 1 )
                 └ s = 0.5 에서 P = autoP(me).  **정의상 성립**
```

**여기에 키를 더하면 그 「정의상」이 깨집니다.**
카드 갈래와 자동 갈래가 어긋나요 — §2-6이 고친 **바로 그 자리**입니다
(🅰️ 전개 도움 **4~6배** · 🧱 수비 실점 **−9.8%**). 곡선이 아니라 **엔진의 계약**이 깨집니다.

**대신 연출로 씁니다 — 판정 뒤에 문구를 고릅니다.**

| 키 | 골이 났을 때 |
|---|---|
| 크면 | `🙆 높이 솟아 헤딩으로 밀어 넣었어요` |
| 작으면 | `🦶 낮게 파고들어 발끝으로 밀어 넣었어요` |

**판정에 안 닿고 서사만 삽니다.** 3D 캐릭터의 비율도 여기서 살아요.

#### ① 「잠재력 총합 고정」과 어떻게 만나나 — **키는 총합 밖입니다**

⚠️ 먼저 정정 — **`talents`는 총합이 고정이 아닙니다.**
`rollTalents`는 칸마다 `rand(0.8, 1.45)`를 독립으로 굴려요(`prospect.js:438-445`).
고정인 것은 **능력치 배분(`POOL = 194`)**뿐입니다.

**그래서 키를 이렇게 겁니다:**

| | |
|---|---|
| 🚫 총합에 **포함하지 않습니다** | 포함하면 *"키를 얻으려면 다른 걸 버린다"*가 되는데, **키는 못 고르는 값**이라 그 교환이 성립하지 않아요 |
| 🚫 **공짜로도 두지 않습니다** | 그러면 큰 키가 무조건 이득이고 🎲로 큰 키만 뽑습니다 |
| ✅ **모양 배수** — 평균 1 | 큰 키는 **체력·수비를 얻고 스피드·드리블을 잃습니다.** 얻는 만큼 잃어요 |

**이게 ①의 답입니다.** 키는 `talents`의 **크기가 아니라 방향**을 정합니다.

#### ② 🔒 **잠급니다** — 참고작과 같습니다

*"생성된 키는 변경할 수 없습니다."* 우리도 그렇게 합니다. **이유가 인색함이 아니에요:**

- 🎲로 키를 굴리면 = **`talents` 모양을 굴리는 것** = 리롤 축이 하나 더 늘어납니다
- 그리고 `talents` **자체가 이미 리롤 대상에서 빼야 할 축**입니다(①의 표) —
  키를 굴리면 그 잠금이 뒷문으로 풀립니다
- **📏 키 화면에서 `talents`를 한 번 굴리고 그대로 잠급니다.** 하나의 잠금이 둘을 덮어요

> 🔴 **engineer 항목** — `rollTalents`를 `rollCards` 밖으로 빼야 이게 성립합니다.
> 지금은 안에 있어서 🎲마다 같이 굴러가요(`prospect.js:493`).

#### ③ 🎯 포지션과의 관계 — **키를 포지션보다 먼저 굴립니다**

키를 포지션 뒤에 굴리면 **포지션마다 유불리가 생깁니다.** `BLEND`가 이렇거든요:

| 포지션 | S1 · S2 · S3 | 키 큰 선수는 |
|---|---|---|
| df | 수비 · **체력** · 스피드 | **이득** (S1·S2 둘 다 ↑) |
| mf | 패스 · 드리블↓ · **체력↑** | 상쇄 |
| fw | 슛 · **스피드↓** · **드리블↓** | **손해** |
| wg | 드리블↓ · **스피드↓** · 패스 | **손해** |

**포지션을 이미 골랐는데 키가 손해로 나오면, 그건 잠글 수 없는 값입니다** — 반드시 다시 굴리게 돼요.

**→ 순서를 바꿉니다: 📏 키 → 🎯 포지션.**
