## 1. 무엇이 문제였나 — 확인과 쓰기 **사이**

```js
// 고치기 전 (town.js)
queue = queue.then(() => {
  if (myGen !== sceneGen) return null;     // ← 확인
  …
  return Scene.push(c);                    // ← 쓰기
});
```

이 두 줄 **사이가 벌어지는 순간** 확인이 무의미해집니다. 확인은 「지금 세대가 맞다」를
말할 뿐이고, **실제로 쓰는 건 그 뒤**니까요. `push`는 `await`를 지나며 씁니다.

`push` 안에는 `alive(my)`가 있지만 그건 **들어온 뒤** 갈린 경우만 봅니다.
**들어올 때 이미 갈려 있으면** `my = S`가 **새 경기**를 잡아 버려요 —
옛 카드가 새 피드를 자기 것으로 알고 그립니다. 그게 inspector가 본
**중등 피드의 `30'`**(초등부 2장의 분은 30·60, 중·고등 3장은 23·45·68)입니다.

## 2. 🔧 고친 방식 — **세대의 소유자는 화면입니다**

### `match-scene.js`

```js
let _gen = 0;                              // mount()마다 하나씩

function mount(host, cfg) { _gen += 1; … } // 옛 세대의 남은 그리기는 이 순간 무효

async function push(card, g) {
  if (g != null && g !== _gen) return;     // 🎬 끄는 줄 — 여기 하나뿐입니다
  if (!S || !card) return;
  const my = S;                            // (그 뒤는 예전 그대로 alive(my))
```

`gen()`을 내보내고, `push(card, g)`는 **`g`를 안 주면 예전 그대로** 돕니다
(프로 경기처럼 카드를 한 장씩 순서대로 그리는 갈래 — 읽는 쪽 기본값이에요).

### `town.js`

```js
let myGen = null;                          // 소유자는 화면. 여기선 받아만 둡니다
if (Scene) {
  Scene.mount(sceneHost, { … });
  myGen = Scene.gen ? Scene.gen() : null;  // 낡은 화면이면 null → 옛 동작 그대로
}
…
queue = queue.then(() => {
  if (done) { … }
  return Scene.push(c, myGen);             // ← 확인은 「쓰기 직전」에 화면이 합니다
});
```

🔴 **`sceneGen`/`myGen !== sceneGen`을 지웠습니다.** 남기면 designer가 못박은 그 자리예요 —
*"같은 결과를 내는 줄이 둘이면 하나를 지워도 증상이 0장"*. 실제로 그렇습니다:
town의 확인과 push의 확인 **사이에 async가 없어서** 둘은 정확히 같은 판단을 냅니다.

### 🔒 두 줄이 왜 안 겹치나 (`push`의 `g` ↔ `alive`)

| 창 | 언제 갈리나 | 막는 줄 | 지우면 |
|---|---|---|---|
| ① 들어오기 **전** | `push`에 닿기 전에 다음 경기가 깔림 | `push` 맨 앞 `g !== _gen` | 옛 카드가 **새 피드 맨 위에** |
| ② 들어온 **뒤** | `await` 도중에 다음 경기가 깔림 | `await` 뒤마다 `alive(my)` | 같은 증상이 **줄 중간부터** |

①을 지우면 ②가 못 잡습니다(옛 카드가 새 `S`를 자기 것으로 잡으니 `alive`가 늘 참).
②를 지우면 ①이 못 잡습니다(진입할 땐 세대가 맞았으니까요). **각각 한 줄, 각각 다른 계약.**

🔒 **옛 주석을 새 규칙으로 다시 썼습니다**(원칙 ⑨) — `match-scene.js`의 `alive` 머리말이
이제 「창이 둘」이라고 말하고, `town.js`의 `♻️ 단계가 바뀌면` 주석은
**「확인을 여기서 하면 늦다」**로 바뀌었습니다.

## 7. 🚧 이 자리는 **검사가 안 지킵니다** — 그대로입니다

inspector의 판정(109번 §6)이 제 수정 뒤에도 유효합니다. 제 재현기는 **260ms 지연을 심어야**

아무것도 안 지키고**, 지연을 심은 검사는 *"코드가 아니라 검사가 만든 지연"*을 재게 됩니다.

📌 **결정적으로 검사할 수 있게 되는 조건**은 이겁니다:
**`push`가 「그린 카드」를 셀 수 있게 되면** 지연 없이도 잴 수 있어요 —
`push`가 세대 불일치로 버린 횟수를 세는 창구가 있으면,
「단계가 바뀌는 순간 남은 그리기가 몇 장이었나」를 **확률이 아니라 수로** 볼 수 있습니다.
지금은 그 창구를 안 만들었습니다(요청 밖 · 화면에 안 쓰이는 계수기를 남기고 싶지 않아서).
**inspector가 필요하다고 하면 한 줄로 냅니다.**

그때까지는 **재현 방법이 `match-scene.js`의 `alive` 머리말에 살아 있습니다** —
`scratchpad/`는 사라지지만 그 주석은 안 사라져요.
