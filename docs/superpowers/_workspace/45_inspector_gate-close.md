## 2. 🛡️ **"또 나면 어떻게 빨리 아는가"** — 두 겹으로 막았습니다

이번 세션에서 **세 번째**입니다(`ME_P : 1` · `NPC_SPOT : 1` · 그전 축구 검사 10개).
변이 정규식이 소스 **문자열**에 의존하는 한 구조적으로 반복돼요. 그래서 두 가지를 넣었습니다.

### ① 종료 코드로 **"안 돈 것"과 "빨간불"을 가릅니다** — `_load.js` (전 파일 자동 적용)

```
0 = 통과 · 1 = 빨간불(검사가 돌았고 계약이 깨짐) · 2 = 💥 죽음(안 돌았음)
```

`_load.js`에 `uncaughtException`·`unhandledRejection` 훅을 달았습니다.
**`_load.js`를 부르는 모든 winger2 검사에 자동으로 걸립니다** — 새 파일도, 앞으로 생길 파일도요.

```bash
red=0; dead=0
for t in tests/winger2/*-test.js; do
  node "$t" >/dev/null 2>&1; c=$?
  [ $c -eq 1 ] && { echo "❌ $(basename $t)";            red=$((red+1)); }
  [ $c -ge 2 ] && { echo "💥 $(basename $t) — 안 돌았어요"; dead=$((dead+1)); }
done; echo "빨간불 ${red}건 · 죽음 ${dead}건"
```

이 스니펫을 `_load.js` 머리 주석에 적어 뒀습니다.

### ② **0번 검사** — 변이 정규식이 지금 소스에 걸리나 (다섯 파일 전부)

각 파일이 쓰는 변이를 **표 하나에 모으고**, 다른 무엇보다 먼저 소스와 대조합니다.
안 걸리면 **죽는 대신 ❌ 한 줄**로 떠요.

```
✅ 0. 변이 정규식 8개가 지금 beta/winger2/engine.js에 전부 걸린다   (mutation-test)
✅ 0. 변이 정규식 4개 …                                          (award-test)
✅ 0. 변이 정규식 3개 …                                          (league-test)
✅ 0. 변이 정규식 2개 …                                          (neutral-test)
✅ 0. 변이 정규식 1개 …                                          (engine-test)
```

**정말 도는지 확인했습니다** — 정규식 하나를 일부러 깨뜨린 사본:

```
❌ 0. 변이 정규식 8개가 … 전부 걸린다
     🔴 **안 걸린 것 1개 — 그 변이 검사는 지금 "안 도는" 상태입니다** (초록불이 아니에요)
       · SPOT1: /const SPOT = 9\.99;/
✅ A. 능력치 130 시즌 생산량 …                            ← 나머지는 계속 돕니다
❌ A(SPOT1)-변이가 **안 돌았습니다** — 정규식이 지금 소스와 안 맞아요 (0번 참고)
❌ 2건 실패                                                [exit 1]  ← 죽지 않고 빨간불
```

**깨진 변이는 건너뛰지 않고 그 자리에서 ❌를 냅니다.** 조용히 통과하면
*"변이 검증이 있다"*는 거짓말이 남으니까요. 대신 **죽지 않아서 나머지는 계속 돕니다.**

> 📌 남은 한계 — 정규식이 **소스 문자열에 의존한다**는 뿌리는 그대로입니다.
> 없애려면 엔진이 계수를 주입받는 형태(`createMatch(cfg, K)`)여야 하는데 그건 구현 결정이에요.
> 지금 구조에서 할 수 있는 건 **"안 걸리는 순간 크게 보이게"**까지입니다.

## 4. 31b 승격 판정 — **승격하지 않았습니다**

양방향 표시는 의도대로 울렸습니다(`❌ 🎉 목표를 달성했어요! … 31로 승격하세요`).
**하지만 승격이 옳지 않다고 판단했습니다.**

### 시드 넷으로 다시 쟀습니다

| 시드 | 실점 차 | 밴드까지 여유 |
|---|---|---|
| 11 | −14.79% | 0.21%p |
| 202 | **−14.96%** | **0.04%p** |
| 5150 | −14.89% | 0.11%p |
| 31337 | −14.76% | 0.24%p |

**여유 0.04~0.24%p.** 제가 §6에서 `AFTER_RATIO_MIN`의 여유 0.4%를 *"너무 붙었다"*고 내렸는데,
이건 그보다 **열 배 더 붙어** 있습니다.

### 승격하면 안 되는 이유 셋

1. **승격 = `goal` → `reg`.** 다음 계수 조정 한 번에 **상시 빨간불**이 됩니다
2. **근본 원인이 그대로**입니다 — `CON 1.111 × 0.5 = 0.5555` vs `FIN 0.884 × 0.5 = 0.4420`, 차 **25.7%**.
   밴드에 닿은 건 `NPC_SPOT.assist 5.80`이 전개 주인공을 능력치 높은 도움 에이스로 더 자주
   뽑아 `pFinish`가 오른 **부수 효과**예요. 고친 게 아닙니다
3. **같은 뿌리인 무실점은 여전히 +26~28%**로 크게 미달입니다.
   한쪽만 승격하면 *"고쳤다"*는 잘못된 신호가 남아요

### 그래서 — **신호를 죽이지 않고** 히스테리시스를 넣었습니다

```js
const PROMOTE_MARGIN = 3;   // %p — 승격은 SYM_BAND - 3 (= 12%) 안쪽일 때만
```

*"밴드에 겨우 닿은 것"*과 *"밴드 안에 들어온 것"*을 가릅니다. 2차의 「칸마다 관점 굴리기」가
들어오면 원인이 사라지므로 **여유 있게 통과**할 거예요. 지금 상태는 이렇게 보입니다:

```
🚧 31b. 실점은 아직 같은 산식이 아니다 — 차 -14.8% (밴드 ±15% · **승격 ±12%**)
        ← 밴드에는 닿았지만 여유가 0.2%p뿐이라 승격 안 합니다 (위 주석)
```

UNMET 설명에도 *"지금 −14.8%로 밴드 가장자리에 걸쳐 있고, 부수 효과이며, 25.7% 차는 그대로"*를
적어 뒀습니다.

## 7. 🔥 픽스처 함정 — **두 겹이었고, 둘 다 없앴습니다**

|---|---|---|
