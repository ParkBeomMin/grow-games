## 1. 🔑 실측 하네스에 빠져 있던 한 줄

inspector 102번이 짚은 대로였습니다. 시드를 **두 군데** 겁니다:

```js
W.Math.random = mulberry32(seed);                  // town.js deal/shakeBy · winger-moment
if (W.WingerEngine && W.WingerEngine._t) W.WingerEngine._t.seed(seed);   // ← 이게 빠져 있었어요
```

`engine.js:32`의 `let _rng = Math.random;`이 **로드 시점에 함수를 잡아 둡니다.**
뒤에 `W.Math.random`을 갈아도 판정은 옛 함수를 계속 봅니다.

| | 같은 시드 3회 |
|---|---|
| `Math.random`만 | 🔴 `pmpmmmpp` · `pooommmp` · `moopmpop` — **매번 다름** |
| ✅ `+ _t.seed(n)` | `ppmmmoop` × 3 — **비트 단위 재현** |

> 🔑 ***"제 드라이버가 결정적이지 않습니다"*의 원인이 이것이었습니다.**
> `scratchpad/eng104/probe-pair.js`에 그 한 줄이 들어가 있고, 그래서 아래 짝비교가 성립합니다.

## 3. 🏟️ 무엇을 붙였나

### 3-1. `town.js` — 판정을 **읽기만** 하는 두 표

```js
const GOAL_BY = { g: { perfect: "us" }, a: { perfect: "us" }, d: { miss: "them" } };
```

| 카드 | 판정 | 스코어 |
|---|---|---|
| ⚽ 결정 | `perfect` | 우리 +1 (내 골) |
| 🅰️ 전개 | `perfect` | 우리 +1 (동료 골 · 내 도움) |
| 🧱 수비 | `miss` | 상대 +1 (실점) |
| 그 밖 | — | 안 움직임 |

🔒 **`PTS`와 다른 표입니다.** `PTS`는 편차 `d`(밴드)로 가고 이건 **화면에만** 갑니다.
🔴 **상대 팀을 따로 굴리지 않습니다** — 실점은 **내 🧱 카드의 `miss`**뿐이에요.

`CALL`은 판정 → `[W2Scene이 읽는 result, 중계 줄]`입니다. `{me}`가 내 이름 자리예요
(`game.js`의 `openStage(… , name: chosenName)` 한 줄이 새로 넘깁니다 — 🔒 판정엔 안 닿고,
화면이 그릴 때 `W2Scene.esc`가 이스케이프합니다).

### 3-2. 난수를 **한 톨도 안 쓰는** 연출값

| | 어떻게 |
|---|---|
| ⏱️ 시계 | `minAt(i, n) = round(90(i+1)/(n+1))` — 2장이면 30·60, 3장이면 23·45·68 |
| 🏟️ 상대 이름 | 🗺️ **지역 문자열 해시 + 단계 번호**로 `OPP` 8개 중 하나. 🔴 **전부 가상 이름**입니다 |
| 🏠 우리 이름 | 초등 「우리 동네」 · 중·고 「우리 학교」 |
| 🗣️ 무엇이 걸렸나 | `stakeOf(kind, hg−ag)` → `W2Scene`의 `STAKE_TAIL` **코드**(한국어 비교 안 함) |

> 🔴 **여기에 `Math.random()`을 한 번이라도 쓰면** 난수를 몇 번 쓰는지가 **카드 성적을 타서**
> 뒤 카드의 굴림이 통째로 밀립니다. 조기 제안에서 이미 데인 자리예요(§18-5).

### 3-3. `match-scene.js` — `lite` (🏫 학교 모드) · 연출 전용 난수 · 화면 교체 가드

`mount(host, { home, away, myName, lite })` — 🔒 **`lite`를 안 주면 프로 경기는 한 줄도 안 바뀝니다.**

| `lite`가 끄는 것 | 왜 |
|---|---|
| 🅶🅾🅰🅻 배너 · 🏆 결승골 축포 | 학교는 **단계 하나짜리 대항전**이지 90분 경기가 아니에요 (설계 §3-5) |
| 🎉 `Fx.burst`/`confetti` | 🔴 **취향이 아니라 난수입니다** — 입자마다 `Math.random()`을 씁니다 |
| ⌨️ 타이핑 | ⏱️ 카드가 여덟 장이라 단계마다 몇 초씩 붙어요. **밀도의 차이는 프로의 것**이고 학교는 카드가 **전부** 🔥 내 순간입니다 |
| 🔥 내 순간 N회 | 카드가 전부 내 순간이라 *"2판 중 2회"*가 아무 말도 안 해요 |

**남는 것**: 스코어보드 · 시계 · 흐름 막대 · 피드 카드 · 스코어 bump · 플래시 · 흔들림 · 진동.

새로 넣은 **연출 전용 난수원**(`fxRnd`)은 타이핑 지연 흔들림(40~60ms)에만 씁니다 —
`Math.random`도 엔진의 `_rng`도 **한 번도 안 부릅니다.** 보이는 것은 그대로예요.

### 3-4. 🚨 화면이 갈리면 **이어 그리지 않습니다** (`alive`)

**이번 작업에서 실제로 난 버그입니다.**

```
── data-stage=m (🏫 중등부 첫 카드)
   스코어보드: 우리 학교 0:0 아라 중등부 ⏱ 60'      ← 🔴 60'은 초등의 시계예요
   피드: · 60' 🧱 상대 에이스가 달려듭니다…          ← 🔴 초등 마지막 카드
```

`openMoment`가 `await wait(delayOf())`를 기다리는 사이 다음 단계가 `mount()`를 부르면
`S`가 새로 만들어지는데, **깨어난 옛 카드가 새 `S`의 피드에 이어 그렸습니다.**

```js
const alive = (my) => S === my;      // await 뒤마다 확인합니다
```

🔴 **`W2Scene` 자체의 구멍이라 프로 경기에도 있던 자리**입니다 — 다음 경기가 바로 이어지면
지난 경기 줄이 새 피드에 섞였을 거예요.

## 6. 📮 grow-inspector — **검사가 없는 자리 셋**

🔑 **제가 검사를 만들지 않았습니다** (`tests/`를 건드리지 말라는 지시 + 변이 검증 없는 검사를

### ⓐ 🔴 **스코어가 편차 `d`에 스며들어도 안 잡힙니다** (가장 중요)

```
M-D:  state.score += p;   →   state.score += p + (골이면 1);
      → school ✅ · town ✅ · town-neutral ✅ · youth-moment ✅   🔴 전부 초록불
```

`town-neutral-test`가 `E[spotMul] = 1.000`을 지키는데 **안 잡혔습니다** —
그 검사가 `_t.judgeFor`·`_t.PTS`로 아크를 **재구성**하고 `land()`를 안 지나기 때문입니다.
🔑 **설계 §3-3의 못**(*"스코어와 승패는 `spotMul`에 한 톨도 안 닿는다"*)을 **지키는 검사가 0건**이에요.
⚠️ *"이겼는데 아무 일도 없다"*는 압박이 **반드시** 옵니다. 그때 이 자리가 비어 있으면
**아무도 안 보는 사이에 승패가 `d`로 샙니다.**

★ 제안: **게임 입구로 아크를 굴린 뒤** `WingerTown.deviation()`이 **스코어를 흔들어도
비트 단위로 같은지.** (`probe-pair.js`가 그 모양입니다 — 시드 짝비교 + `rows()` 시그니처)

### ⓑ 🔴 **화면이 갈린 뒤 피드가 섞여도 안 잡힙니다**

```
M-F:  alive(my) 가드 제거   →   4종 전부 초록불
```

**이번에 실제로 난 버그**입니다(§3-4). 초등 카드가 중등 피드 맨 위에 떴고 시계가 60'으로
되돌아갔는데 **검사는 전부 초록불**이었어요. 🔑 **피드 내용을 읽는 검사가 한 건도 없습니다.**

★ 제안: 아크를 지나며 **`#town-scene .w2-feed`의 `.w2-min`이 단계 안에서 단조 증가**하는지,
그리고 **단계가 바뀌면 피드가 비는지**.

### ⓒ 🟡 **단계 스코어가 0으로 안 돌아가도 안 잡힙니다**

```
M-G:  let hg = 0  →  let hg = state.cards   →   4종 전부 초록불
```

🏁 「3 : 1 승」이 초·중·고 누적이 되어도 아무도 안 봅니다. (표시값이라 우선순위는 ⓐ·ⓑ 다음)

### ⓓ 🟡 **타이핑 갈래를 도는 검사가 0건**

검사가 늘 🤖 자동(=`fast`)이라 `type()`이 **한 번도 안 돕니다.**
`fxRnd`를 `Math.random`으로 되돌려도 안 잡혀요. 🔑 **자동을 끄고 도는 갈래가 필요합니다**
(`youth-moment-test`가 진짜 미니게임을 쓰듯이).

## 8. 📮 grow-designer — 되묻는 것 없음 · 알려드리는 것 둘

1. 🟡 **`momentSlot()`을 미니게임 host로 안 썼습니다.** 보이는 모양은 설계 그대로예요 —
   이유가 DOM 소유 경합이라 §4에 적었습니다. **설계 판단을 바꾼 게 아니라 배선을 바꿨습니다.**
2. 🟡 **§3-4 검산 ①의 답**: `W2Scene`의 연출 난수는 **전역 `Math.random`이었지만 안전하지 않았습니다.**
   실측 하네스와 검사가 **`W.Math.random`을 갈아 끼우기** 때문이에요 —
   그래서 *"전역이면 안전하다"*가 아니라 **「연출용 난수원을 따로 둔다」**로 갔습니다.
   🔑 §18-5의 다음 줄을 이렇게 적어 두면 좋겠습니다:
   > **「보여주기만 하는 굴림은 판정 난수원을 쓰지 마세요 — 전역 `Math.random`도 판정 난수원입니다.」**
