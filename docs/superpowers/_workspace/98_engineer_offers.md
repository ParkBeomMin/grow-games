## 1. 🔴 먼저 잰 것 — **승낙이 항상 이득인가**

> 조율자님 지시: *"4번 들어갈 때 이걸 먼저 재세요."* 그대로 **코드를 쓰기 전에** 쟀습니다.
> ⚠️ 시드 하나로 안 쟀습니다 — **시드 5개 × 20,000판**, `_t.deal`·`_t.judgeFor`·`_t.rollOffers`
> **게임의 그 함수**를 그대로 불렀어요(산식 사본 없음).

```
🙅 거절 (5곳 중 최고)  1.03592     ← 설계 §17-5의 기준선 1.03593과 **일치**합니다
🤝 승낙 (+1 확정)      1.04680  →  +1.089%p   🔴 §11 실측 2번(≤1%)을 넘습니다
🤝 승낙 (위로만 50%)   1.02392  →  −1.199%p   🔴 **반대편으로** 넘습니다
```

**🔑 설계가 지정한 대비책의 「방향」은 맞고 「폭」이 지나쳤습니다.**
`[0, p], [+1, 1−p]`라는 **같은 형태**에서 `p(+1)`만 쓸어 봤어요:

| `p(+1)` | 0.50 | 0.60 | 0.70 | **0.75** | **0.80** | 0.90 | 1.00 |
|---|---|---|---|---|---|---|---|
| 차이 | −1.20%p 🔴 | −0.76%p | −0.29%p | **−0.05%p** | **+0.18%p** | +0.63%p | +1.09%p 🔴 |

### ★ `p(+1) = 0.80`을 골랐습니다 — **0.75(정확히 0)가 아닌 이유**

| | |
|---|---|
| 🔴 **0.75는 다른 방향의 「더미 결정」입니다** | `spotMul`이 정확히 같으면 **거절이 항상 이득**이에요 — 거절하면 **5곳 중 고를 자유**를 덤으로 받으니까요. 설계 §6-3이 승-2를 폐기한 근거(*"−0.76칸 손해라 아무도 안 누릅니다"*)가 **부호만 바뀌어 그대로** 섭니다 |
| ✅ **0.80 = +0.18%p** | 아주 조금 위여야 **「고를 자유」와 「세게 부르는 팀」이 맞바꿔집니다.** 어느 쪽도 정답이 아니에요 |
| 🟢 **덤** | `+1`이 확정이 아니라 원칙 ⑧(모른다)이 승낙 쪽에도 한 뼘 남습니다 |

**구현된 함수(`_t.rollSigned` · `_t.rollOffers`)로 다시 쟀습니다:**

```
🙅 거절 1.03564 · 🤝 승낙 1.03730 · 차이 +0.166%p   ✅ 목표 ≤ 1%
시드별 +0.188 / +0.172 / +0.145 / +0.165 / +0.158 %p
```

> 🔴 **designer 확인 요청 ①** — 설계가 *"넘으면 `[0, 0.5], [+1, 0.5]`로 낮추세요"*라고
> **값까지 지정**했는데, 그 값이 목표를 반대편으로 넘습니다. 저는 **형태를 그대로 두고
> 확률만** 맞췄어요(`SHAKE`·`OFFER`·`BAND_EDGE` 불변 · 원칙 ⑪ 유지). **형태를 바꾼 게
> 아니라 폭을 맞춘 것**이라 판단했지만, 계수 확정은 designer/balancer의 자리입니다.

## 3. 🔑 설계에서 「형태」로 읽은 것 셋

### 3-1. `fit`과 `d`를 다른 표로 — **이름이 아니라 형태로 갈랐습니다**

```js
const FIT = { jp: "a", br: "g", eu: "d", af: FIT_ALL };   // 🎯 누가
const FIT_EDGE = { kind: 1, all: 2 };                     // 🎯 얼마나 잘하면 손을 드나
const BAND_EDGE = [-4, -2, 2, 4];                         // 📏 몇 등급인가  ← 안 건드렸습니다
```

🔴 **`FIT_EDGE`를 `BAND_EDGE` 옆에 두지 않았습니다.** 둘이 한 표에 있으면 다음 사람이
*"🇮🇹가 잘 안 온다"*를 등급 표에서 고칩니다 — `NPC_SPOT_D`로 철벽상을 고치려던 그 자리예요.
**주석에 그 문장을 그대로 남겼습니다.**

### 3-2. 초등 문턱과 중등 문턱이 **한 줄로 같습니다**

설계 §8-2가 초등은 *"그 종류 전부 `perfect`"*, 중등은 *"점수 ≥ 카드 수 + 1"*로 적었는데,
**초등은 종류마다 카드가 0~1장**이라 「1장 perfect」 = 「편차 +1」로 **같은 말**입니다.
→ 두 문턱을 `dev(종류) ≥ 1` **한 줄**로 씁니다. 🔑 표가 갈라지지 않아요.

### 3-3. 🚨 조기 제안은 **난수를 한 톨도 안 씁니다** — 이게 핵심 결정입니다

처음엔 `rollOffers`로 조기 제안도 흔들었습니다. **두 가지가 동시에 깨졌어요:**

| | 무슨 일이 |
|---|---|
| 🔴 **난수 소비량이 `fit` 결과를 탑니다** | 손 든 곳만 굴리면 **몇 번 굴리는지가 카드 성적에 따라 달라져서**, 뒤에 오는 카드 순서가 통째로 어긋납니다. `youth-moment` **B-0**(*"같은 시드에서 🦶만 뒤집으면 카드 순서가 같다"*)이 실제로 갈렸어요 |
| 🔴 **쓰이지 않는 값 때문이었습니다** | 조기 등급은 **아무 데도 안 쓰입니다** — 승낙하면 최종 편차로 다시 굴고(§6-3), 거절하면 사라지고(§6-1 ②), 화면에도 ⭐를 안 적어요(§6-4) |

**★ 그래서 조기 제안은 `tierOfD(그 시점 편차)`만 봅니다. 흔들기 없음 · 난수 0.**

> 🟢 **덤 셋:**
> ① 뒤에 오는 모든 카드 순서가 **📨 화면이 생기기 전과 완전히 같습니다**(검사 재현성)
> ② 🔑 **「`fit`은 등급에 안 닿는다」가 구조가 됩니다** — 등급이 먼저 정해지고 명단은 **고르기만** 해요
> ③ 원칙 ⑧(모른다)은 **다른 자리**가 맡습니다 — 조기의 「모른다」는 *"이번엔 누가 손을 들까"*지
>    *"몇 등급일까"*가 아니에요. 🎲 `SHAKE`는 **최종 등급**의 것입니다

## 4. 🔒 조작적 정의를 지킨 자리 넷

### 4-1. ⑤ 거절 ≠ 재도전 — **가드가 둘인데 겹치지 않습니다**

```js
function goEarly(id, after) {
  if (!window.WingerTown) { after(); return; }
  if (WingerTown.decidedEarly(id)) { after(); return; }   // ♻️ 이 판을 이미 정했나
  if (WingerTown.signed()) { after(); return; }           // 🤝 이미 계약했나
  ...
}
```

| 정의 | 어디서 지키나 | 확인 |
|---|---|---|
| ① 굴린 카드는 다시 안 굴림 | `goSchool`의 `playedStage` **한 줄**(96번 ⓔ 그대로) | T-6a ✅ |
| ② 거절한 등급은 사라짐 | 조기 등급이 **어디에도 안 실립니다**(§3-3) | 구조 |
| ③ 다시 들어와도 재굴림 없음 | `state.early[id]` 메모 + `decidedEarly` | 🧪 M-REDECIDE ✅ |
| ④ 승낙해도 남은 대항전을 뜀 | `goEarly`가 `after()`로 **흐름을 그대로** 잇습니다 | 🧪 M-SKIPCARD ✅ (변이 시 8장 → **2장**) |
| ⑤ 뛴 뒤엔 뛸 때 쓴 값을 못 바꿈 | 조기 화면에서 `btn-back-first` **감춤** | 🧪 M-EARLYBACK ✅ |

🔴 **그리고 「이미 정한 판을 다시 묻는 것」도 ②의 형태입니다** — 뒤 판 결과를 보고 앞 판
결정을 바꾸는 건 *"이미 나온 걸 버리고 앞으로"*가 아니라 **「이미 나온 걸 다시 고르기」**예요.
🧪 `M-REDECIDE`(가드 한 줄 제거)로 **되감기 뒤 조기 제안이 다시 뜨는 것**을 확인했습니다.

### 4-2. 🚨 `showOffers`의 인자를 **믿지 않습니다**

`prospect.js:1082`가 취소 콜백을 **`onBack(e)`로 부릅니다 — 클릭 이벤트를 실어 보내요.**
`showOffers`를 그대로 콜백으로 넘기면 조립대에서 돌아올 때 **📨 조기 제안 화면이 뜹니다.**

```js
const early = (stage === "e" || stage === "m") ? stage : null;   // 단계 id 둘만
```

🔒 그리고 `openBench(… showOffers)` 줄은 **글자 그대로 뒀습니다** — `town-test`의
`M_BENCH_BACK` 변이가 그 줄을 잡고 있어요.

### 4-3. 🤝 승낙은 **손을 든 곳으로만**

```js
if (marketId && e.offers[marketId]) { … }   // 안 온 유스 id는 조용히 거절로
```
화면이 애초에 안 그리지만, **판정은 `WingerTown`이 합니다** — 화면은 무엇을 눌렀는지만 넘겨요.

### 4-4. ♻️ 뒤로 가기로 **이미 정한 조기 화면에 다시 선 자리**

`screen-agency`는 `BACK_SAFE`라 🎯 자리에서 브라우저 뒤로 가기로 조기 화면에 **다시 설 수

됩니다 — *"왜 안 되지"*의 자리예요. 앞으로 보내기만 합니다:


## 5. 🚨 원칙 ⑩ — **되돌려 보다가 제가 만든 「가리는 버그」를 잡았습니다**

> **초록불은 두 가지 뜻입니다 — "고쳐졌다" 또는 "아무도 안 보고 있다."**

첫 구현에서 `showOffers`를 이렇게 썼습니다:

```js
if (back) back.classList.toggle("hidden", !!(… playedStage("m")));   // 🏟️ 최종의 계약
if (early && back) back.classList.add("hidden");                     // 📨 조기의 계약
```

**`town-test`의 변이 M-BACK(위 `toggle` 줄 제거)이 초록불로 통과했습니다.**
조기 제안이 **이미 감춰 놓은 상태**가 최종까지 남아서, 감추기 줄을 통째로 지워도
**증상이 0장**이었어요.

🔑 **96번 ⓔ(가드 셋이 서로를 덮던 자리)와 정확히 같은 형태**입니다 — 이번엔 가드가 아니라
**「화면 상태」**가 겹쳤습니다.

**고침 — 「켜는 줄」마다 「끄는 줄」:**

```js
if (back) back.classList.remove("hidden");                           // 🚨 먼저 되돌립니다
if (back) back.classList.toggle("hidden", !!(… playedStage("m")));
if (early && back) back.classList.add("hidden");
```

```
고치기 전 · M-BACK → hidden true  (🔴 초록불 — 아무것도 안 지킴)
고친 뒤   · M-BACK → hidden false (✅ T-6b 빨간불)
```

> 🚨 **inspector에게 — 이 「끄는 줄」을 지키는 검사가 없습니다.**
> `M-RESET`(`remove("hidden")` 한 줄 제거)만 넣으면 **증상이 0장**이에요 —
> **M-BACK과 함께 넣어야** 비로소 «M-BACK이 안 잡히는» 것으로 드러납니다.
> 🔑 이건 **「검사를 가리는 변이」**라 단독 판정이 안 됩니다. 둘 중 하나를 권합니다:
> ① `M-RESET + M-BACK`을 **한 벌로** 넣고 *"T-6b가 여전히 빨간불인가"*를 보는 검사
> ② 아니면 한 줄로 합치기(`toggle("hidden", !!early || playedStage("m"))`) —
>    이 경우 **`M_BACK_SHOW` 정규식을 같이 고쳐야** 합니다
