## 1. 🔴 D-2 — 운을 재던 검사를 뽑기 겨누기로

### 무엇이 문제였나

```
❌ D-2. ⚔️ 시드 3판에서 경기 성격 셋이 다 나온다
     🚧 안 나온 것: 중원 장악 — 시드를 늘려 다시 보세요
```

`playEvalStage`는 3경기 중 셋째만 고정이라 **자유 추첨이 판당 2번**입니다.
시드 3판 = **6번**이고, 셋 중 하나가 안 나올 확률이 **26%**예요.
🏘️ 동네가 들어오면서 `rollOffers`가 유스마다 `Math.random()`을 5회 쓰자 흐름이 밀렸고,
**경기 성격 코드는 한 글자도 안 바뀌었는데** 빨간불이 됐습니다.

### 어떻게 다시 겨눴나 — **표본을 늘리지 않았습니다**

시드를 8개로 늘리는 것도 답이지만 그건 여전히 **운을 재는 검사**예요
(확률만 낮아집니다). 대신 **뽑기 자체를 겨눕니다.**

`pick(arr)`은 `arr[Math.floor(Math.random() * arr.length)]`입니다. 그러니
**클릭 핸들러가 도는 동안만** `Math.random`을 상수 `c`로 고정하면,
그게 **몇 번째 난수든** `pick([0,1,2])`는 언제나 `floor(c·3)`번 칸을 집어요.

```
c = 0.10 → 0번 칸    c = 0.50 → 1번 칸    c = 0.90 → 2번 칸
```

- **게임 입구를 통해** 갑니다 — 타이틀부터 눌러 🏆 대회 출전까지 걸어가요
- 고정은 **그 한 번의 클릭 동안만**입니다 (누른 직후 원래 난수로 되돌림)
- 기대 성격 셋은 **검사에 박습니다** (`STAGE_TYPES`에서 안 읽어요)
- `c`와 칸의 **짝은 안 박습니다** — 표 순서가 바뀌어도 계약은 "셋이 다 나온다"

### 🔬 정말 안 흔들리는지 실측했습니다

난수 소비량을 크게 흔드는 변이 둘 × 시드 4개:

| 난수 소비 | 시드 11 | 시드 23 | 시드 37 | 시드 101 |
|---|---|---|---|---|
| **무변이** | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 |
| **`rollOffers` 소비 0** | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 |
| **`rollOffers` 소비 ×7** | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 | 공격/중원/수비 |

🔑 **engineer가 §6에서 "고정값으로 바꾸면 초록불이 된다"고 확인한 그 조작**을 그대로 걸어도
결과가 안 움직입니다. 앞으로 누가 난수를 몇 개 더 쓰든 D-2는 그대로예요.

**🧪 변이(M4):** `STAGE_TYPES[pick([0, 1, 2])]` → `pick([0])`
→ 세 `c` 전부 「공격 전개」 → **D-2 빨간불** ✅ (D-1은 그대로 초록불 — 나오는 한 종류는 여전히 맞으니까요)

## 2. 🔴 「기준선이 초록불인지 먼저」를 절차로 박았습니다

engineer의 발견이 정확했습니다 — **이미 빨간불인 검사는 남의 변이 신호를 통째로 먹습니다.**
여섯 변이가 전부 「잡힘」으로 보였는데, 사실은 전부 D-2 하나를 다시 빨간불로 만들고 있었어요.

CLAUDE.md의 *"빨간불인데 그냥 두는 검사"* 는 **신호를 잃는다**까지 적혀 있었는데,
**남의 신호까지 먹는다**는 한 겹이 더 있었습니다.

그래서 **변이 절 앞에 게이트를 박았습니다.** 새 검사 3종과 `youth-moment-test`가 전부
변이를 돌리기 **전에** 이 줄을 찍습니다:

```
── 🧪 변이 검증 (고치기 전에 빨간불이 뜨는지) ──
   ✔ 기준선(무변이) 전부 초록불 — 아래 빨간불은 **변이가 만든 것**이 맞습니다.
```

기준선이 하나라도 빨간불이면 대신 이렇게 찍습니다:

```
   ⚠️ **기준선이 이미 N건 빨간불입니다** — 아래 변이 판정은 그 신호를 먹을 수 있어요.
      먼저 위 ❌를 없앤 다음 변이 결과를 믿으세요.
```

> 📮 **하네스에 올릴 원칙:** *"변이 검증은 기준선이 초록불일 때만 뜻이 있습니다.
> 빨간불 하나가 서 있으면 그 파일의 변이 결과는 **전부 무효**로 읽으세요."*

## 6. 🔴 발견 — `bootPage`가 `index.html` 변이를 **조용히 안 걸고 있었습니다**

T-7a의 변이(🏘️ 동네에 `btn-town-skip`을 붙임)를 넣었더니 **초록불**이 나왔습니다.
코드는 맞아 보이는데요. 파 보니:

| | |
|---|---|
| `pageMutsOK({ "index.html": … })` | 디스크에서 읽어 **"걸린다"고 답합니다** → **0번 등록 검사 초록불** |
| `bootPage({ muts: { "index.html": … } })` | `<script src>`로 실린 **.js만** 갈아치웁니다 → **마크업 변이는 아무 일도 안 일어남** |

🚨 **이게 정확히 「초록불인데 아무것도 안 지키는 검사」의 새 모양입니다** —
0번 등록 검사까지 통과하는데 변이가 통째로 죽어요.
*"변이했는데 초록불"* 을 막으려고 만든 `mutsOK` 계열이 **이 조합에서는 거짓말을 합니다.**

**고친 것:** `_load.js`의 `bootPage`가 스크립트를 인라인으로 바꾸기 **전에**
`index.html` 자신에도 변이를 걸고, 안 걸리면 던집니다. 다섯 줄이에요.

```
🧪 M-G(town) 변이 → 화면 직속 조작: btn-town-skip · btn-town-next  → T-7a 빨간불 ✅
```

> 📮 **다른 게임 검사에도 같은 구멍이 있는지 봐야 합니다.** `bootPage`류를 쓰는
> 검사가 마크업 변이를 넘기고 있다면 **지금 안 돌고 있을 수 있어요.**
