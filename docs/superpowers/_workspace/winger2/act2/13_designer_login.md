## 1. 무엇을 푸는가

### 1-1. 결정 L

사용자 원문(`../15_decisions.md:95`): **선택 로그인**(로그인 안 해도 지금처럼 · 하면 세이브가 계정을 따라다님 · 8종 공통) — *「1번으로 하는데 명예의 전당은 캐릭터 이름이야」* → **명전에는 캐릭터 이름**(계정 이름 아님).

### 1-2. 지금의 구조 — 기기 토큰 + 익명 계정 + 연동 코드

| 무엇 | 지금 | 어디 |
|---|---|---|
| 신원 | 기기 토큰(128비트 무작위 · `grow-cloud-token`) — DB엔 **SHA-256 해시만** | `beta/cloud.js` · `cloud-schema.sql` |
| 계정 | `cloud_account` — **사용자에게 안 보이는 내부 개념** · 세이브의 주인 | 설계 문서 §4 |
| 기기 여러 대 | **연동 코드**(24자 · 해시로만 저장 · 재발급 전까지 재사용) → 그 기기가 같은 계정에 붙음 | `cloud-reusable.sql` |
| 접근 규칙 | 네 표 모두 RLS 켜고 **정책 0** → 표 직접 접근 불가 · `security definer` 함수로만 | `cloud-schema.sql:30-34` |
| 충돌 | 서버 시각 + 기기별 미전송 표시 + 마지막으로 올린 기기(`writer`) · **사람이 고름**(자동 병합 없음) | `cloud-writer.sql` · 설계 문서 §5 |
| 베타 | 로컬은 `beta::`로 갈리고 게임은 `beta:` 꼬리표 → 계정도 따로 | 설계 문서 §5.6 |

### 1-3. 지금의 한계 — 설계 문서가 스스로 적은 것 → 로그인이 푸는 것

| 한계(설계 문서 §7) | 로그인한 사람에겐 |
|---|---|
| **코드를 발급하지 않은 사용자는 복구할 수 없다** | 어느 기기에서든 로그인하면 되찾음 |
| **코드를 잃으면 끝이다** | 계정이 열쇠 |
| 연결을 끊는 기능이 없다 · 토큰 탈취 시 무효화 없음 | **로그아웃 = 이 기기를 계정에서 뗌** · 계정 삭제 |
| (배경) iOS 사파리가 7일 미방문 사이트 데이터를 지울 수 있음(ITP) | 다시 로그인하면 받음 |

### 1-4. 원래 설계의 「비목표」를 바꾸는 근거

2026-07-27 설계는 *「계정 · 로그인 · 이메일. 도입하지 않는다」*였고, 익명 인증은 *「토큰 탈취 위험이 리프레시 토큰과 동일한데 복잡도만 증가」*로 뺐습니다. 이번엔 **사용자 결정 L**이 근거이고, **선택** 로그인이라 로그인 안 하는 사람에겐 원래 설계가 그대로 섭니다. 익명 인증은 여전히 쓰지 않습니다(§10).

## 2. 구조 — 「로그인 = 이 기기를 내 계정에 붙이는 열쇠」

### 2-1. 한 장 그림

```
[기기 A] 토큰 a ─┐                                  ┌─ cloud_save (계정 × 게임마다 한 줄)
[기기 B] 토큰 b ─┼─▶ cloud_device ──▶ cloud_account ─┤
                 │    (토큰 해시)          ▲          └─ cloud_code (연동 코드 — 지금 그대로)
                 │                          │
       로그인 ───┴──▶ cloud_identity ───────┘   ← 새 표 하나: (로그인 신원 · 환경) → 계정
                      (auth.users.id · prod|beta)
```

- 🔑 **세이브를 올리고 받는 길은 그대로 「기기 토큰」**입니다. 로그인은 그 기기가 **어느 계정에 붙는지**만 바꿉니다 — 연동 코드가 하던 일을 로그인이 대신합니다
- 그래서 8종 게임의 `Cloud.init` · `Cloud.touch` · `Cloud.mark` 호출은 **한 줄도 안 바뀝니다**

### 2-2. 고르는 것 / 자동인 것

| 자리 | 사람이 | 자동 |
|---|---|---|
| 🔗 기록 연동 모달 | 「만 14세 이상이에요」 확인 · 「구글로 계속」 / 「카카오로 계속」(L1) | 돌아오면 이 기기를 내 계정에 붙임(§2-3) |
| 처음 로그인 | — | 이 기기의 지금 계정이 **내 계정이 됨**(기록이 그대로) |
| 다른 기기에서 로그인 | 게임마다 충돌이면 고름(**지금의 충돌 화면**) | 그 기기가 내 계정에 붙고 받기 |
| 로그아웃 | 「이 기기의 기록도 지우기」(L3) | 이 기기를 계정에서 떼고 토큰을 새로 만듦 |
| 계정 삭제 | 두 번 확인 | 서버의 세이브 · 기기 · 코드 · 신원 · 로그인 계정 삭제 — 이 기기의 로컬 기록은 남음 |

### 2-3. 로그인했을 때 — 경우 넷 (서버 `cloud_login_bind`가 판정)

| 경우 | 판정 | 화면 |
|---|---|---|
| ① 이 사람의 **첫 로그인** · 이 기기의 계정이 아직 누구의 것도 아님 | **adopted** — 이 기기의 계정 = 내 계정 | 「🔐 로그인했어요 — 이 기기의 기록이 이제 계정을 따라다녀요」 |
| ② 이미 내 계정에 붙은 기기 | **same** | 그대로 |
| ③ 내 계정이 있고, 이 기기는 다른(익명) 계정 | **joined** — 기기를 내 계정으로 옮김(연동 코드 연결과 같은 일) | **지금의 「코드 연결 뒤」 길 그대로** — 받기 → 게임마다 충돌이면 고르기 |
| ④ 첫 로그인인데 이 기기의 계정이 **이미 다른 사람의 것**(로그아웃 안 하고 넘긴 공용 기기) | **fresh** — 새 계정을 만들어 붙임 · 이 기기의 로컬 기록은 **자동으로 안 올림** | 「이 기기의 기록은 다른 사람의 것일 수 있어요 — 내 계정으로 올릴까요?」 고르기 |

- 🔒 ③에서 고르기 전에는 **양쪽 다 안 바뀜**(지금 충돌 화면의 규칙 — 설계 문서 §9 「충돌 화면」)
- ③의 이 기기 옛 계정은 기기가 하나도 안 남으면 고아가 됨 — 지금 코드 연결에서도 생기는 일이고, 정리는 설계 문서의 「나중에」 그대로(90일 이상 · 기기 0)

### 2-4. 로그인 안 하는 사람

**지금 그대로** — 기기 토큰 · 자동 백업 · 연동 코드(발급 · 입력) · 충돌 화면. 화면에서 로그인은 모달 안의 **한 칸**일 뿐 조르지 않습니다.

### 3-2. `auth.js`가 하는 일 (라이브러리 없이 `fetch` — 클라우드 · 명전과 같은 결)

| 일 | 어떻게(구현 때 GoTrue 문서로 확인) |
|---|---|
| 로그인 시작 | PKCE 검증자를 만들어 로컬에 두고(`crypto.getRandomValues` · 도전값은 `crypto.subtle` SHA-256) → `…/auth/v1/authorize?provider=<공급자>&redirect_to=<지금 주소>&code_challenge=…&code_challenge_method=s256`로 보냄 |
| 돌아옴 | 주소에 `code`가 있으면 → `…/auth/v1/token?grant_type=pkce`로 교환 → 세션(`access_token` · `refresh_token` · 만료 시각)을 로컬 `grow-auth-v1`에(베타는 `env.js`가 `beta::`로 자동 격리) → **주소에서 `code`를 지움**(`history.replaceState`) → `cloud_login_bind` |
| 갱신 | 만료 전에 `grant_type=refresh_token` — 실패하면 로그아웃 상태로(게임은 계속) |
| 로그아웃 | `…/auth/v1/logout` + `cloud_logout` + **기기 토큰을 새로 만듦** |
| 함수 부르기 | 🔴 **새 함수 셋만** `Authorization: Bearer <사용자 access_token>` — **기존 `cloud_*` 함수는 지금처럼 anon 키로**(§4-2) |
| 실패 | **전부 삼킴** — 게임 진행을 절대 막지 않음(클라우드 설계 §5.5) · 모달에 한 줄 |

- 🔑 **왜 라이브러리를 안 쓰나** — 필요한 끝점이 넷뿐이고, 저장소는 클라우드 · 명전을 이미 `fetch`로 짰습니다. 외부 스크립트 0 · 내려받기 0(코드는 최소한으로)
- 🔑 **왜 PKCE인가** — 토큰이 주소 조각(`#access_token=`)으로 오는 암묵 흐름보다 안전합니다(주소창 · 방문 기록 · 다른 스크립트에 토큰이 안 남음). `code`는 한 번 쓰면 끝

### 3-3. 돌아오는 주소

- 로그인을 누른 **그 게임 페이지**로 돌아옵니다(`…/grow-games/<게임>/` · 베타 `…/grow-games/beta/<게임>/`)
- Supabase의 **Redirect URLs 허용 목록**은 사이트 아래 경로 한 줄(와일드카드) — 실제 주소는 설정 때. 허용 목록 밖으로는 안 돌려보냄(남의 사이트로 튀기 — open redirect 막음)

│ ─────────── 또는 ───────────         │

│ 📜 개인정보처리방침                   │

로그인 뒤:  🔐 로그인됨 · ab***@… · [로그아웃] · [계정 삭제]   (코드 칸은 접힘 — L2)

## 4. 서버 — 표 · 함수 · 접근 규칙(RLS)

### 4-1. 지금 규칙을 그대로 지킨다

- 표는 **RLS 켜고 정책 0** → `anon` · `authenticated` 어느 쪽도 표에 직접 접근 불가 · **`security definer` 함수로만**
- 함수는 만들 때 `PUBLIC`에 붙는 실행 권한을 **먼저 회수**(`cloud-schema.sql` 끝 주석과 같은 까닭)
- 토큰 · 코드는 **해시로만**

### 4-2. 새로 · 그대로

| 무엇 | 누가 부르나 | 하는 일 |
|---|---|---|
| 표 **`cloud_identity(user_id, env, account_id)`** | — | 로그인 신원 ↔ 계정 · **환경(`prod` · `beta`)마다 하나** — 베타 로그인이 운영 계정에 안 붙게(지금 베타 격리와 같은 결) · RLS 켬 · 정책 0 |
| **`cloud_login_bind(p_token, p_env)`** | `authenticated` | §2-3의 넷 — `auth.uid()`로 본인 · 토큰은 해시로만 |
| **`cloud_logout(p_token)`** | `authenticated` | 이 기기를 **내** 계정에서 뗌(기기 행 삭제) |
| **`cloud_delete_me()`** | `authenticated` | 내 계정의 세이브 · 기기 · 코드(cascade) · 신원 · 로그인 계정 삭제 |
| 기존 `cloud_push` · `cloud_pull` · `cloud_meta` · `cloud_issue` · `cloud_claim` | `anon` — **그대로** | 바뀌지 않음 — 로그인한 기기도 **기기 토큰으로** 올리고 받음 |

- 🔴 **기존 함수를 사용자 토큰으로 부르면 거절됩니다** — `cloud-writer.sql`이 `cloud_meta` · `cloud_pull`의 `PUBLIC` 실행 권한을 회수하고 `anon`에만 열었습니다. 사용자 토큰으로 부르면 역할이 `authenticated`라 권한이 없습니다. 그래서 **기존 함수는 계속 anon 키로, 새 함수 셋만 사용자 토큰으로** 부릅니다(`auth.js`가 갈라 부름 — 검사로 굳힘)
- 🔑 **위협 모델은 그대로** — 기기 토큰을 가진 사람은 지금도 그 세이브를 읽을 수 있습니다. `cloud_login_bind`가 토큰을 받아도 새 노출은 없습니다(토큰이 비밀이라는 전제 그대로)

### 4-3. SQL 초안 — 파일(제안) `docs/superpowers/sql/cloud-login.sql` · **적용은 사용자 승인 뒤**

```sql
-- ============================================================================
-- 🔐 선택 로그인 — 초안 (검토용 · 운영 DB 적용은 사용자 승인 뒤)
-- ============================================================================

-- 0) 적용 전 확인 — 지금 DB가 저장소 SQL과 같은가
select proname, pg_get_function_identity_arguments(oid) as args
  from pg_proc where proname like 'cloud\_%' order by 1;
select prosrc from pg_proc where proname = 'cloud_push';        -- 허용 목록에 winger2가 있는가
select tablename, policyname from pg_policies where tablename like 'cloud\_%';  -- 정책 0이어야

-- 1) 로그인 신원 ↔ 계정 — 환경마다 하나
create table if not exists public.cloud_identity (
  user_id    uuid not null references auth.users(id) on delete cascade,
  env        text not null check (env in ('prod', 'beta')),
  account_id uuid not null references public.cloud_account(id) on delete cascade,
  created    timestamptz not null default now(),
  primary key (user_id, env),
  unique (account_id)
);
alter table public.cloud_identity enable row level security;   -- 정책 없음 → 함수로만

-- 2) 로그인으로 이 기기를 내 계정에 붙인다 (연동 코드를 대신)
create or replace function public.cloud_login_bind(p_token text, p_env text)
returns jsonb
language plpgsql security definer
set search_path = public, extensions
as $$
declare
  v_uid  uuid := auth.uid();
  v_dev  text;
  v_cur  uuid;   -- 이 기기가 지금 붙어 있는 계정
  v_mine uuid;   -- 이 사람의 계정
begin
  if v_uid is null then return jsonb_build_object('ok', false, 'reason', 'no_login'); end if;
  if p_env is null or p_env not in ('prod', 'beta') then return jsonb_build_object('ok', false, 'reason', 'bad_env'); end if;
  if p_token is null or length(p_token) < 16 then return jsonb_build_object('ok', false, 'reason', 'bad_token'); end if;
  v_dev := encode(digest(p_token, 'sha256'), 'hex');
  v_cur := public.cloud_account_of(p_token);            -- 처음 보는 토큰이면 지금 규칙대로 계정을 만듦
  select account_id into v_mine from public.cloud_identity where user_id = v_uid and env = p_env;

  if v_mine is null then
    if exists (select 1 from public.cloud_identity where account_id = v_cur) then
      -- ④ 공용 기기: 이 기기의 계정이 이미 다른 사람의 것 → 새 계정을 만들어 붙임
      insert into public.cloud_account default values returning id into v_mine;
      update public.cloud_device set account_id = v_mine, seen = now() where token_hash = v_dev;
      insert into public.cloud_identity(user_id, env, account_id) values (v_uid, p_env, v_mine);
      return jsonb_build_object('ok', true, 'mode', 'fresh');
    end if;
    -- ① 첫 로그인: 이 기기의 계정이 곧 내 계정 — 기록이 그대로 따라온다
    insert into public.cloud_identity(user_id, env, account_id) values (v_uid, p_env, v_cur);
    return jsonb_build_object('ok', true, 'mode', 'adopted');
  end if;

  if v_mine = v_cur then
    return jsonb_build_object('ok', true, 'mode', 'same');                -- ②
  end if;
  update public.cloud_device set account_id = v_mine, seen = now() where token_hash = v_dev;
  return jsonb_build_object('ok', true, 'mode', 'joined');                -- ③ 코드 연결과 같은 일
end;
$$;

-- 3) 로그아웃: 이 기기를 내 계정에서 뗀다 (클라이언트는 토큰을 새로 만든다)
create or replace function public.cloud_logout(p_token text)
returns boolean
language plpgsql security definer
set search_path = public, extensions
as $$
declare v_n int;
begin
  if auth.uid() is null or p_token is null or length(p_token) < 16 then return false; end if;
  delete from public.cloud_device d
   using public.cloud_identity i
   where d.token_hash = encode(digest(p_token, 'sha256'), 'hex')
     and d.account_id = i.account_id
     and i.user_id = auth.uid();
  get diagnostics v_n = row_count;
  return v_n > 0;
end;
$$;

-- 4) 계정 삭제: 서버의 세이브 · 기기 · 코드 · 신원 · 로그인 계정 (기기의 로컬 기록은 그대로)
create or replace function public.cloud_delete_me()
returns boolean
language plpgsql security definer
set search_path = public, extensions
as $$
declare v_uid uuid := auth.uid();
begin
  if v_uid is null then return false; end if;
  delete from public.cloud_account a
   using public.cloud_identity i
   where a.id = i.account_id and i.user_id = v_uid;      -- 세이브 · 기기 · 코드 · 신원은 cascade
  delete from auth.users where id = v_uid;                -- ⚠️ 권한을 실제로 확인 — 막히면 Edge Function(서비스 키)으로
  return true;
end;
$$;

-- 5) 권한 — PUBLIC에 붙은 실행 권한부터 회수
revoke all on function public.cloud_login_bind(text, text) from public, anon;
revoke all on function public.cloud_logout(text)           from public, anon;
revoke all on function public.cloud_delete_me()            from public, anon;
grant execute on function public.cloud_login_bind(text, text) to authenticated;
grant execute on function public.cloud_logout(text)           to authenticated;
grant execute on function public.cloud_delete_me()            to authenticated;

-- 6) (0번에서 빠져 있으면) cloud_push 허용 목록에 'winger2' — cloud-writer.sql 본문 그대로 + 한 단어

```

| 지금의 사람 | 로그인하면 | 잃는 것 |

| 기기마다 따로 계정(코드를 안 씀) | 기기 A 로그인(①) → 기기 B 로그인(③ joined) → **게임마다 충돌 화면에서 고름** | 고르지 않은 쪽(지금 충돌 규칙 그대로) · B의 옛 계정은 고아 |

| 베타 사용자 | 환경이 갈려 **베타 계정은 따로**(`env = beta`) | 0 |

- 🔑 **세이브를 옮기는 일이 없습니다** — 계정이 그대로 주인이고, 로그인은 기기를 어느 계정에 붙일지만 정합니다. 그래서 「이행 작업」(일괄 변환 · 서버 배치)이 없습니다

- 지워지는 것: 서버의 세이브 · 기기 연결 · 연동 코드 · 로그인 신원 · 로그인 계정 / **안 지워지는 것**: 이 기기의 로컬 기록 · **명예의 전당**(계정과 이어져 있지 않음 — 캐릭터 이름 기준이라. 가리기는 문의로 — 지금의 「한마디 가리기」 운영 도구)
- 카카오는 탈퇴할 때 공급자 쪽 **「연결 끊기」** 처리가 필요한지 설정 때 확인

### 8-2. 검사 (inspector)

| 검사 | 무엇 |
|---|---|
| 로그인 흐름 | 가짜 인증 응답으로 — `?code=` 교환 · 주소에서 `code` 지움 · 갱신 · **실패를 삼키고 게임은 계속** |

| 떼기 · 삭제 | 로그아웃 뒤 토큰이 바뀌고 서버에 그 기기 0 · 삭제 뒤 서버에 내 계정 0 · 로컬 기록은 남음 |

| 보안 변이 | 그리는 길에서 `esc`를 빼면 태그가 DOM에 들어감(빨간불) · `redirect_to`가 지금 주소만 |
| 접근 규칙(실제 호출 — 승인 뒤) | `anon` · `authenticated`로 다섯 표 직접 SELECT · INSERT 전부 거부 · 남의 계정 떼기 · 삭제 거부 |
| 베타 격리 | 베타 세션 · 신원이 `env = beta`로만 · 운영 계정에 안 붙음 |
| 회귀 | 지금의 클라우드 검사(연동 코드 · 충돌 · 오프라인) 전부 초록 |

## 9. 판단 지점 — 사용자에게 여쭐 것

### L1 — 로그인 공급자

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| (가) **구글 + 카카오** | 국내 모바일 사용자 대부분이 둘 중 하나는 있음 · 둘 다 Supabase가 기본으로 지원 · **카카오톡 안 브라우저**에서 구글이 막혀도(§11) 카카오로 됨 | 콘솔 설정 두 벌 · 카카오 앱 설정 · 동의 항목 조건 확인 |
| (나) **구글만** | 가장 빠름(설정 한 벌) | 카카오톡 · SNS 앱의 안 브라우저로 들어온 사람은 로그인이 막힐 수 있음 · 구글 계정이 낯선 사람 |
| (다) **카카오만** | 국내에서 가장 친숙 · 카카오톡 안 브라우저에서도 됨 | 카카오 계정이 없는 사람 · 해외 사용자 |
| (라) **이메일 링크**(비밀번호 없는 메일 로그인) | 공급자 없음 | 메일 발송 설정(발송 한도 · 스팸함) · 입력 마찰 · 메일 주소를 직접 받음 |
| (마) **(가) + 애플** | 아이폰 사용자 | 유료 개발자 계정 · 설정 한 벌 더 |

**추천 (가)** — 순서는 **구글을 먼저 켜고 카카오를 같은 코드에 붙임**(공급자는 버튼 하나 · 매개변수 하나라 코드가 갈리지 않음).

### L2 — 기존 사용자 이행: 연동 코드의 앞날

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| (가) **둘 다 유지** — 로그인은 선택 · 코드는 로그인 안 한 사람에게 그대로 · 로그인한 기기에선 코드 칸을 접고 「🔐 로그인으로 연결됨」 | 결정 L 「안 해도 지금처럼」 그대로 · 이행 작업 0 · 잃는 사람 0 | 두 길을 계속 유지(검사 · 화면) |
| (나) **새 코드 발급 중단**(이미 발급된 코드는 유효) | 길이 하나로 모임 | 로그인 싫은 사람이 **새 기기로 옮길 길**이 사라짐 — 결정 L과 부딪힘 |
| (다) **일정 기간 뒤 코드 폐지** | 유지 비용 ↓ | 로그인 강제에 가까움 |

**추천 (가).**

### L3 — 로그아웃할 때 이 기기의 기록

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| (가) **남김 + 「이 기기의 기록도 지우기」 칸(기본 꺼짐)** | 내 기기면 편함(로그아웃해도 계속 플레이 — 새 익명 계정으로 백업) · 공용 기기면 칸을 켜면 됨 | 칸을 안 켜고 넘기면 다음 사람이 내 선수를 봄(로그인 계정은 안 넘어감) |
| (나) **늘 지움** | 공용 기기에 가장 안전 | 실수로 로그아웃하면 이 기기의 기록이 사라짐(다시 로그인하면 서버에서 되찾음) |
| (다) **매번 묻기** | 둘 다 | 로그아웃할 때마다 한 번 더 |

**추천 (가).**

### L4 — 보관 기한과 방침에 적을 정보

| 선택지 | 얻는 것 | 잃는 것 |
|---|---|---|
| (가) **마지막 접속 뒤 3년 안 쓴 계정은 서버 기록 삭제**(방침에 적음) | 쓰지 않는 개인정보를 오래 안 쥠 · 정리 배치가 고아 계정까지 같이 | 알릴 메일이 없어 조용히 지워짐(방침 · 모달에 미리 적음) |
