## 1. 무엇을 푸는가

- **지금 판**(`winger-moment.js` `runShotGrid`): 키퍼가 미끄러지며 각을 지우고, 칸의 **밝기가 곧 `s`**(「지금 누르면 나올 값」)입니다. 고르기 전에 정답이 칠해져 있고, 「빨리 차라」 — **타이밍**을 잽니다(`ONE_WIN` · `tight` · `life` 3.4초).
- **사용자가 원하는 판**: 6칸 중 하나를 **고르고**, 그 **다음에** 키퍼가 움직이고, 결과가 드러납니다(승부차기의 결) — 「고른 뒤에 드러나는 판」.
- **함정 둘**(오케스트레이터)
  - **그냥 찍기**가 되면 — 6칸이 다 같으면 `s`가 판마다 운이고, 🎮 솜씨 칸과 결정 G(키운 만큼)의 「솜씨」가 무너집니다
  - **확인 버튼**이 되면 — 칸마다 확률을 다 보여 주면 가장 큰 칸만 누릅니다
- **이력이 정한 조건**(12번 §4-1 a~g · `winger-moment.js` 머리말): 골문 6칸만큼 한눈에 · 구체적 순간 · 공격 화면에 수비를 얹지 않음 · **폐기된 형태 넷 금지**(⑴ 칩 둘 읽기 ⑵ 세기에 따라 정답이 뒤집힘 ⑶ 2단 국면 ⑷ 띠) · **`s`는 화면에 보이는 것만으로**(조작과 결과 사이에 난수를 한 겹 더 넣지 않음) · 판은 `s`만, 판정은 엔진이 · 🧱 = 🥅의 `E[s]`
- 사용자 이력: *「미니게임들 다 뭘 어떻게 하라는지 모르겠다니까ㅜㅠㅜ 없애줘 … 골대를 배경으로 6칸 만들어서 어디로 공 찰지 선택하는 미니게임 하자」* — **한눈에 읽히는 한 탭**

## 2. 구조 — 단서 하나: 「🧤 키퍼가 몸을 실은 구석」

### 2-1. 판 한 장의 흐름

| 단계 | 화면 | 정해지는 것 |
|---|---|---|
| ① 열림 | 상대 골문 6칸(**3열 × 2행** — 왼 · 가운데 · 오른 × 위 · 아래) · 🧤 키퍼의 **준비 자세** · 🦶 주발 쪽 · 약발 쪽 표시 · 머리에 「기본 승산 39%(🤖과 같음)」 | 판 모양(키퍼가 실은 구석 · 세기) — 판의 연출 난수에서 한 번 |
| ② 고름 | 칸 하나를 탭(최대 **4초** · ♿ 5.2초) — 키퍼가 3초쯤부터 한 걸음 다가옴(재촉의 그림 — 판정 0) | **`s` = 고른 칸의 좋음**(보이는 것만으로 · 아래 §2-3) |
| ③ 승산 | 「🎯 이 구석이면 57%」 한 줄(J4 (가)) | 엔진에 `judge(s)` — **굴림 한 번**(결과가 정해짐) |
| ④ 모션 | 공이 고른 칸으로 날아가고 키퍼가 몸을 던짐 — 닿음 / 못 닿음 | 그림만(결과를 그림) |
| ⑤ 결과 · 해설 | 「⚽ 골!」 · 「🧤 선방」 · 「빗나감」 + **「가장 좋았던 칸」 테두리 · 「🧤 키퍼는 ↙ 왼쪽 아래에 몸을 실었어요」** | 없음(가르침) |

### 2-2. 단서 — 하나 · 늘 참 · 세기 셋

- **키퍼의 준비 자세가 한 구석을 가리킵니다** — 몸이 기운 쪽(왼 · 오른)과 손이 내려간 높이(위 · 아래)가 **한 자세**로 「저 구석으로 뜰 준비」를 말합니다. 규칙은 한 줄: **「키퍼가 몸을 실은 구석의 반대 구석이 비어요」**
- **세기 셋**: 똑바로(0 — 몸을 안 실음) · 살짝(1) · 크게(2) — 판마다 굴림(제안 **20 · 40 · 40%**) · 구석은 넷 중 고르게(주발과 무관 — 왼발 · 오른발 거울)
- 키퍼가 똑바로 서 있으면(세기 0) 구석 넷이 같고 **🦶 주발 쪽 구석**이 가장 좋음 — 「단서가 없으면 내 발」
- 🔒 **늘 참** — 자세가 가리키는 대로 칸의 좋음이 정해지고(§2-3), 숨은 값이 없습니다(조건 e). 「살짝」이 「크게」보다 덜 좋을 뿐 **방향이 뒤집히지 않습니다**(폐기 형태 ⑵ 없음)
- 🔒 **하나** — 기울기와 높이를 **두 칩으로 따로 띄우지 않고** 한 몸의 자세로 그립니다(폐기 형태 ⑴ 없음). 준비 화면(처음 세 번 전문)에서 「자세 → 구석」 넷을 한 번 보여 줌
- 그림: 자세 **아홉**(구석 4 × 세기 2 + 똑바로 1) — CSS 실루엣의 기울기 · 반 걸음 · 손 높이(§6 · 그림 0장)

### 2-3. 칸의 좋음 — `q` → `s`

```
q(칸) = 0.5 + 세기 × (A × 가로 + B × 세로) + C × 열
   가로  = 키퍼가 실은 쪽의 반대 열 +1 · 같은 열 −1 · 가운데 열 0
   세로  = 키퍼가 실은 높이의 반대 행 +1 · 같은 행 −1
   열    = 양옆 열 +½ · 가운데 열 −1(키퍼가 서 있는 자리 — 세 열의 평균 0)
s(칸) = clamp( q × 주발(칸) × 컨디션, 0, 1 )
   주발 = 주발 쪽 · 가운데 열 1 · 약발 쪽 0.75 → 0.85 → 0.95(약발 0 · 1 · 2단계 — P2 (가))
   컨디션 = condMul(경기 날 컨디션)   (51에서 1 — 엔진 중립과 같은 자)
A 0.13 · B 0.09 · C 0.08(제안)
```

**예**(오른발 · 약발 0 · 컨디션 보통 · 키퍼가 **왼쪽 아래**에 몸을 실음)

| 세기 | 위 행: 왼 · 가운데 · 오른 | 아래 행: 왼 · 가운데 · 오른 | 최선 |
|---|---|---|---|
| 크게(2) | 0.35 · 0.60 · **0.98** | 0.08 · 0.24 · 0.62 | 오른쪽 위(반대 구석) |
| 살짝(1) | 0.38 · 0.51 · **0.76** | 0.24 · 0.33 · 0.58 | 오른쪽 위 |
| 똑바로(0) | 0.41 · 0.42 · **0.54** | 0.41 · 0.42 · **0.54** | 오른쪽(주발) |

키퍼가 **주발 쪽(오른쪽 아래)**에 실으면 반대 구석이 약발 쪽 — 크게: 왼쪽 위 **0.74**(약발 2단계면 **0.93**) · 살짝: **0.57**(→ **0.72**). 약발이 약하면 읽고도 덜 받고, 키우면 골문 절반이 열립니다.

- 🔒 **뒤집힘 0**(스크립트로 모든 판 모양 확인): 세기 1 · 2에서 최선은 늘 반대 구석 — 약발 0단계에서도 차이 ≥ **0.06**. 그래서 「세기에 따라 정답이 뒤집힘」이 구조적으로 없음(inspector 검사 §9-0)
- 🔒 무작위로 고른 판의 평균 = `0.5 × (주발 · 약발 몫)`(약발 0에서 0.455 · 2에서 0.491) — 🤖(0.5)는 **약발 걱정이 없는 보통의 한 수**

### 2-4. 「찍기」와 「확인 버튼」 사이 — 어디에 섰나

| | 찍기(6칸이 같음) | **이 판** | 확인 버튼(칸마다 % 표시) |
|---|---|---|---|
| 고르기 전에 보이는 것 | 없음 | 키퍼의 자세 하나 · 내 발 · 컨디션 · 기본 승산(모든 칸 같은 값) | 칸마다 승산 |
| 읽는 일 | 없음 | 「자세 → 반대 구석」 한 걸음 · 세기가 살짝이면 놓치기 쉬움 · 4초 | 가장 큰 숫자 찾기 |
| `s`의 폭(어림 · 약발 0) | 0.5 고정 | 무작위 **0.455** ↔ 읽기 **0.704** ↔ 최선 **0.717** | 늘 최선 |
| 솜씨 칸(10 × (s̄ − 0.30)/0.50) | 4.0 고정 | 3.1 ↔ 8.1 ↔ 8.3(🤖 4.0) | 늘 꼭대기 |

- 옛 자리표(서툰 0.43 · 보통 0.57 · 능숙 0.70)가 **이 폭 안에** 들어옵니다 — 조작자 모델을 새로 짜도(§4-3) 「보통 판」의 눈금이 크게 안 흔들릴 공산이 큼
- 🔑 **배움이 솜씨가 됩니다** — 판 끝의 「가장 좋았던 칸 · 키퍼는 ↙에 실었어요」가 규칙을 가르쳐, 해 볼수록 0.455 → 0.70으로 올라감(112번이 걱정한 「안다/모른다 계단」을 **판이 스스로 가르쳐** 계단을 짧게). 4초와 「살짝」(세기 1 — 판의 40%)이 다 배운 뒤에도 실수의 자리를 남김
- 🔒 칸마다 숫자는 **고른 뒤에만**(③ 승산 줄) — 고르기 전 숫자는 모든 칸에 같은 「기본 승산」 하나

### 2-5. 이력이 정한 조건 · 폐기된 형태와 대조

| 조건(12번 §4-1) | 이 판 |
|---|---|
| a 골문 6칸만큼 한눈에 · 한 번 탭 | ✅ 6칸 · 규칙 한 줄 · 탭 한 번. ⚠️ 「밝은 칸 = 지금 누르면 좋은 곳」은 **사용자 새 방향이 바꿈**(고르기 전에 정답을 칠하지 않음) |
| b 구체적 순간 | ✅ 키퍼와 일대일(승부차기의 결) |
| c 공격 화면에 수비를 얹지 않음 | ✅ 🧱는 우리 골문(§5) |
| d 폐기 형태 넷 | ✅ ⑴ 단서는 한 몸의 자세(칩 둘 아님) · ⑵ 세기가 크기만 바꾸고 방향은 안 뒤집음(검사) · ⑶ 한 국면(고름 → 드러남) · ⑷ 띠 없음(4초는 재촉일 뿐 판정 창이 아님 — 시간에 따라 칸 값이 안 변함) |
| e `s`는 화면에 보이는 것만으로 | ✅ 자세 · 발 · 컨디션 표시가 `s`의 전부 — 숨은 값 0 |
| f 판은 `s`만 · 판정은 엔진 | ✅ `judge(s)` 한 번(§4) |
| g 🧱 = 🥅 `E[s]` | ✅ 같은 함수(거울 — §5) |

## 3. 육성 · 주발 · 컨디션이 닿는 자리

| 무엇 | 어디에 닿나 | 화면에 보이는 것 | 까닭 |
|---|---|---|---|
| **능력치**(주 능력치 blend) | **엔진 그대로** — 모든 칸의 승산 바닥(`autoP` · `sc`)과 조작 폭(`half`) | 판 머리 **「🎯 기본 승산 39% — 🤖 자동과 같아요」** · 고른 뒤 「이 구석이면 57%」 — 키우면 두 숫자가 다 오름 | 🔴 능력치를 `s`에 넣으면 **세 번째 길** — `s = 0.5` 중립이 능력치마다 깨짐(`winger-moment.js` 머리말 「능력치는 판정 창을 넓히지 않습니다」 · 12번 §4-5). 그래서 **값은 엔진이, 보이는 것은 판이** |

| **♿ 판정 넓게**(공유 키 `grow-wide-judge`) | **고를 시간 +30%**(4 → 5.2초) — 점수 0 | 설정 문구를 「♿ 고를 시간 넉넉히(+30%)」로(29번 §4-1 셋째 칸 — 키 이름은 그대로) | 새 판엔 좁힐 「창」이 없음 — 손이 느린 사람이 잃는 것은 **시간**이라 시간을 줌 |

## 4. 엔진과의 배선 — 창구는 그대로, 부르는 때만

### 4-1. 판은 여전히 `s` 하나를 냅니다

| | 지금 판 | 새 판 |
|---|---|---|
| `s`의 뜻 | 손(겨눔 + 타이밍) — 누른 칸 · 누른 때의 오차 | **읽기 — 고른 칸의 좋음**(§2-3) |
| 판정 | 엔진 `cardP = autoP + 2·half·(s − 0.5)` → 굴림 | **같음** |
| `judge(s)`를 부르는 때 | 판 끝(620ms 뒤) | **고른 순간**(결과를 알아야 키퍼 모션을 그림) → 끝에 `cb(판정, detail)` — 🔒 **굴림은 판마다 여전히 한 번**, 엔진 난수의 순서도 그대로(드라이버가 판을 기다린 뒤에야 다음 카드를 굴림) |
| 🤖 자동 | 판을 안 엶 · `s = 0.5` | **같음** — 「보통의 한 수」 = 약발 걱정 없는 무작위 한 칸의 기댓값(§2-3) |
| 🧱 = 🥅(R4) | 같은 산식(거울) | **같은 함수**(§5) — 보통 조작자의 짝지은 차이가 구성으로 0 |
| 시간 초과 | `life` 지나면 `s = 0` | 4초(♿ 5.2) 지나면 `s = 0` — 「🧤 키퍼가 먼저 덮쳤어요」 |

### 4-2. 승산 % — 엔진 0줄

- 판에 `odds(s)` 하나를 넘깁니다 — 드라이버(`live.js`)가 **29번이 내놓는 `m.autoP(kind, 능력치)`**와 이미 내놓은 `WingerEngine.cardP`로 만듦: `odds(s) = cardP(autoP, 능력치, s)`. 기술 테스트 · 승부차기는 각자의 중심으로 `cardP(중심, blend, s)`
- 「기본 승산」 = `odds(0.5)`(= 🤖이 받는 확률) · 「이 구석이면」 = `odds(s)` — **판정이 쓰는 그 숫자**(보이는 값 = 판정 값)
- 🔒 판은 이 숫자를 **판정에 안 씀** — 판정은 `judge(s)` 하나(엔진)

### 4-3. 무엇이 움직이나 — 사슬과 조작자 모델

| 자리 | 닿나 | 까닭 |
|---|---|---|
| `ACT1_SPOT`(판 수) · `RATE_B`(R7) · R13 · Mₑ · R11 · R12 · R14 | ❌ | 판 수 · `s = 0.5` · 이벤트에서 잰 값 |
| `n_pos`(R6 · R5) | 재는 판의 조작이 🤖(0.5)면 ❌ · 조작자 모델이면 ✅ | 28번 장치의 `r6b`가 무엇으로 재는지 따라 |
| **조작자 모델** | ✅ **새로** — 옛 R4 모델(판단 시각 τ + 칸 고름 잡음)은 타이밍 판의 것 | 새 판은 **고르는 모델**: 칸을 고를 확률 ∝ exp(β × s(칸)) — β로 자리표에 맞춤(어림: 서툰 β 0 = 무작위 0.455 · **보통 β 3.4 → 0.57 · 능숙 β 17.5 → 0.70** — 약발 0 · 컨디션 51 · 🥅). 같은 β라도 약발이 오르면 `s`가 오름 = 약발의 값 |
| T · K1~K3 · R19 | ✅(보통 판 · 잘함 판의 조작이 새 모델) | 자리표에 맞추면 크게 안 움직일 공산 — 그래도 `s`의 **퍼짐**(판마다 0.08~0.98)이 지금 판과 달라 다시 잼 |
| R3(조작 영향력) | 엔진 값(`s` 1 ↔ 0)은 그대로 · **판이 낼 수 있는 폭**은 새로 | 보고: 판마다 최선 · 최악 `s` · 「보통 ↔ 🤖」의 경기당 득실차 |
| 🎮 솜씨 칸(`SKILL_LO` 0.30 · `SPAN` 0.50) | 그대로 두고 보고 | 새 폭(0.455 ~ 0.72)이 칸의 3.1 ~ 8.4에 앉음 — 지금 판(서툰 2.6 · 능숙 8.0)과 비슷 |
| 사람 s̄ 재보정 | 실기기 뒤(그대로) | 새 판의 사람 s̄가 오면 **보통 판의 조작만** 그 값으로(21번 §3-5 규칙) |

|---|---|---|

`ONE_WIN` · `CELL_FLOOR` · `ONE_CLOSE` · `PERFECT_OF_CEIL` · `TIER_IN` · `ONE`(`off` · `slide` · `cov0` · `cov1` · `grow` · `life` · `look`) · `oneRoll` · `oneAt` · `cellS` · `boardCeil` · 미래 예고 띠 · 키퍼 자취 — 전부 **「고르기 전에 정답을 칠하고 타이밍을 잰다」**의 부품입니다. 새 판에 「밝은 칸」이나 「줄어드는 테두리」를 다시 붙이면 사용자가 버린 판이 돌아옵니다. `FOOT_WIN` · `WIDE` · `condOf` · 준비 화면 · `onTap` · `gate` · 세 줄 위계 · `ender`의 닫힘은 **살립니다**(새 뜻 — §3).

## 9. 📮 재실측 요청 — 범위(사전등록)
