## 4. 🟡 `fw` 4명 / 2자리 — **부수 효과입니다. 다만 지금 안 고칩니다.**

### 4-1. 원인은 확정입니다

```js
// squad.js:26 · 90 · 180
const FORMATION = { fw: 2, wg: 2, mf: 4, df: 3 };   // 합 11
const BENCH = 5;
const POS_KEYS = ["fw", "wg", "mf", "df"];
for (let i = 0; i < BENCH; i++) need[POS_KEYS[i % POS_KEYS.length]] += 1;
```

**5는 4로 안 나눠떨어지고, 나머지 하나가 인덱스 0(`fw`)에 떨어집니다** (i=0, i=4).

| 자리 | 자리 수 | 명단 | 경쟁률 |
|---|---|---|---|
| `fw` | 2 | **4** | 🔴 **2.00** |
| `wg` | 2 | 3 | 1.50 |
| `df` | 3 | 4 | 1.33 |
| `mf` | 4 | 5 | 🟢 **1.25** |

**`fw` ÷ `mf` = 1.60배.** 바로 위 줄의 주석이 *"벤치 몫은 포지션에 **고르게** 흩뿌려요"*라고
말합니다 — **선언과 결과가 다릅니다.** 의도가 아니에요.

### 4-2. 🔴 왜 이게 나쁜가 — 원칙 ④

🎯 자리는 플레이어의 **첫 정체성 선택**입니다. 그런데 지금은
**`fw`를 고르는 것만으로 난이도가 오릅니다.** 새 축을 얹는 것만으로 세지거나 약해지면 안 돼요.

🔑 그리고 이건 **포지션 경쟁률 축**입니다 — CLAUDE.md 원칙 ⑪ 표에 이미 적힌 그 축이에요
(`YOUTH_BONUS`가 **안 닿았던** 자리). 🔴 **계수가 아니라 `BENCH` 배분이 맞습니다. balancer가 옳습니다.**

### 4-3. 🔴 그런데 **지금 안 고칩니다** — 「미정」이 아니라 「예산 대기」

바꾸는 순간 **위 측정을 전부 다시** 재야 하고(balancer), **K-1 격자가 그 자리 수 위에 서 있습니다**(inspector).
지금은 engineer·director가 멈춰 있고 inspector가 `tests/`를 잡고 있어요. **움직이는 표적이 됩니다.**

👉 **판정은 났습니다: 부수 효과 · 고쳐야 함.** 미정인 것은 **어느 안으로, 언제**입니다.

| 안 | 배분 | 결과 경쟁률 | 대가 |
|---|---|---|---|
| **(가)** 남는 1을 **경쟁률이 가장 낮은 자리**로 (지금은 `mf`) | `fw`3 `wg`3 `mf`6 `df`4 | 1.50 / 1.50 / 1.50 / 1.33 | 🟢 **스쿼드 16명 유지** · 한 줄 변경 · 재측정 필요 |
| (나) `BENCH` 5 → 4 | `fw`3 `wg`3 `mf`5 `df`4 | 1.50 / 1.50 / 1.25 / 1.33 | 스쿼드 15명 — **명단 크기가 바뀝니다**(화면·기록이 따라옴) |
| (다) `need[p] = ceil(FORMATION[p] × R)` | — | 완전 균일 | 🔴 **새 손잡이를 만드는 것.** 지금 예산으로 감당 못 합니다 |

📌 **(가)를 권합니다.** 다만 🔴 **제 권고는 실측 전까지 제안입니다** — balancer가 재고 나서 확정합니다.

### 4-4. 🔑 덤 — **`squad.js:181`은 지금 죽은 줄입니다**

```js
if (mine) need[S.pos] = Math.max(need[S.pos], FORMATION[S.pos] + 1);   // 내 자리엔 경쟁자가 있어야 해요
```
