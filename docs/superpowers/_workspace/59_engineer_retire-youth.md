## 1. 넣은 것 셋

### ① 🕯️ 은퇴 제안 — 문턱과 방향 가드를 **한 벌로**

```js
const RETIRE_CURVE = 0.78;                    // 0.75 → 0.78
const suggestRetire = (st) =>
  !mustRetire(st)
  && ageOf(st) > peakAgeOf(st)                // 🔴 내리막에서만 — 방향 가드
  && ageMul(st) < RETIRE_CURVE
  && ((st && st.lowApps) || 0) >= LOW_RUN;
```

### ② 🌱 `YOUTH_BONUS` — 선발 경쟁 무게에만 (`squad.js`)

```js
const YOUTH_BONUS = { 18: 0.18, 19: 0.14, 20: 0.09, 21: 0.05 };
const rowAge   = (x) => (x.me ? WingerProspect.ageOf(S) : x.age);
const pickWeight = (x) => x.str * youthMul(x);          // 🔑 감독이 보는 무게 — 여기 한 곳
const lineupScore = (x) => pickWeight(x) + rand(-FORM_SWING, FORM_SWING) + (x.me ? myBonus().total : 0);
```

🚨 **NPC에게도 똑같이 걸었습니다.** 걸린 자리 둘 — 우리 팀 `rollLineup`(→`lineupScore`)과
**다른 팀 `startingXIOf`**(`b.str - a.str` → `pickWeight(b) - pickWeight(a)`).
둘이 다른 자를 쓰면 그게 *"나와 경쟁자가 다른 자"*예요.

- ⚠️ **`assignSlots`에는 안 걸었습니다** — 거기는 뽑힌 뒤 좋은 자리를 실력 순으로 나누는
  자리라 성격이 다릅니다 (설계: *"선발 경쟁 무게에만"*).
- 🖥️ 스쿼드 표의 `tag()`가 **내 줄에도 나이와 🌱을 찍습니다.** 여태 `x.me`면 빈칸이었어요 —
  이제 나에게도 실제로 걸리니, 표시가 없으면 *"왜 내가 뽑혔지/밀렸지"*의 이유가
  화면에서 사라집니다. designer가 말한 *"보이는 것과 하는 일을 맞추는 자리"*의 나머지 반쪽이에요.
- 내 줄에는 나이 칸을 **안 만들었습니다.** `S.squads`는 세이브에 들어가는데 거기에
  내 나이를 또 두면 `S.age`와 두 곳이 돼요 — `rowAge`가 그때그때 물어봅니다.

### ③ 🎂 카드 나이 폐기 — 셋 다 18세

`CARD_AGE_LO/HI = 17/19` → `CARD_AGE = 18`. **ⓑ(정점 기준값 × 곡선)는 유지**했습니다.

확인: 3000판 × 세 장이 **전부 18세** · 정점 기준값 총합은 여전히 **194 하나**(원칙 ④ 유지) ·
같은 18세인데 레이더 총합이 **조숙 163 · 보통 136 · 만성 109 (1.50배)** —
**반대급부가 나이 칸에서 성장타입 칸으로 그대로 옮겨갔습니다.**

> ⚠️ **`ageNote()`를 지웠습니다** (§5-③ 참고). 셋 다 18세가 되면서 카드마다 다른 나이
> 문구를 낼 게 없어졌어요 — 늘 같은 문자열을 뱉는 함수는 *"배너만 뜨고 아무 일도 안 하는"* 자리입니다.
> 원칙 ③(*"왜 이 카드만 약하지?"가 노이즈가 되면 안 된다*)은 **화면 문구로 옮겨** 지켰습니다:
>
> > `{유스} 스카우트가 열여덟 살 셋을 데려왔어요. 잠재 총합은 셋이 같아요 —`
> > `레이더는 **지금 실력**이라, 늦게 피는 선수일수록 지금은 작아 보입니다.`
>
> 성장타입 자체는 여전히 말하지 않아요. 흐릿함은 스카우트 코멘트가 맡습니다.

### 주석에 박아 둔 것 (원칙 ⑨)

| 무엇 | 어디 |
|---|---|
| **문턱과 가드는 한 벌** — 하나만 넣으면 각각 다르게 고장난다(가드만 → 만성이 영영 못 받음 / 문턱만 → 오르막이 23세까지) | `suggestRetire` 위 |

| `YOUTH_BONUS`는 **세게 만드는 게 아니라 기회를 주는 것** · 생산량은 곡선이 정하니 성적은 그대로 나쁘다 · **NPC에게도 건다** · `assignSlots`에는 안 건다 | `YOUTH_BONUS` 위 |
| 카드 나이 폐기 이유(**시간은 다른 무엇으로도 못 산다**) · **카드가 밋밋해지지 않는 이유**(성장타입이 다양성을 만든다) · ⓑ는 유지 | `CARD_AGE` 위 |

# 追記 (2026-08-29) — 🎂 카드 나이 **18 → 17**

**근거**: designer 정정 (*"유스 3년이라 `카드 나이 + 3 = 데뷔`인 걸 안 따졌습니다"*)
**바꾼 것**: `prospect.js`의 `CARD_AGE` 한 값 + 딸린 문구 셋. **다른 건 안 건드렸습니다.**

## 1. 무엇을 바꿨나

```js
const CARD_AGE = 17;      // 18 → 17. 셋 다 같은 나이인 것은 그대로
```

원칙 ⑨로 함께 고친 문구 셋 (전부 *"18세"*를 말하고 있었어요):

| 어디 | 무엇 |
|---|---|
| `prospect.js` `CARD_AGE` 위 | **왜 18이 아니라 17인가** — 유스 3년 → `카드 + 3 = 데뷔`. 18이면 데뷔 만 21세라 실제 프로 데뷔(18~20세)보다 늦고 **balancer 측정이 전부 만 20세 기준**이라 다시 재야 함. **이 값을 옮기면 데뷔 나이가 통째로 따라 움직인다**는 경고도 함께 |
| `prospect.js` 카드 화면 문구 | *"열여덟 살 셋"* → *"열일곱 살 셋"* |
| `game.js` `newState` 주석 | *"카드가 정해요(17~19)"* → *"셋 다 17세 — 유스 3년을 지나 만 20세에 데뷔합니다"* |
| `squad.js` `rowAge` 주석 | *"카드 나이가 18이라 안 생깁니다"* → *"데뷔가 만 20세라 안 생기지만, 표에 없는 나이가 들어와도 보너스가 0으로 뚝 떨어지지 않게 하는 자리"* |

## 2. 🔴 확인 — **게임 입구를 통해** 실제 버튼을 눌러 도달했습니다

`btn-new` → 유스 카드 → 포지션 카드 → 유망주 카드 → `btn-start` → 진짜 `advanceMonth` 35번 → `enterCareer`.

## 3. 🟠 커리어 길이 — designer 표와 **한 살씩** 다릅니다 (경계 세는 법)

같은 실행에서 계속 굴려 본 값입니다:

| | designer 표 | **실측** | 차 |
|---|---|---|---|
| 강제 은퇴까지 | 18시즌 | **19시즌** | +1 |
| 은퇴 제안 수락 시 🌱 조숙 | 14 | **15** | +1 |
| 〃 🌿 보통 | 16 | **17** | +1 |
| 〃 🌳 만성 | 17 | **18** | +1 |

원인은 **양끝 포함(inclusive) 여부**입니다 — `38 − 20 = 18`이 아니라
**만 20세부터 만 38세까지 = 19시즌**을 실제로 뜁니다.
`mustRetire`는 `age >= 38`이고 그 판정은 **그 시즌을 치른 뒤 결산에서** 나기 때문에,
만 38세 시즌은 뛰고 나서 끝나요. 은퇴 제안도 같습니다 — 첫 제안이 뜨는 시즌은 이미 치른 뒤라
조숙은 만 34세 시즌까지 **15시즌**을 뜁니다.

> **코드는 안 건드렸습니다** (이번 범위 밖이고, 어느 쪽이 의도인지는 designer 자리예요).
> 둘 중 하나입니다 — ⓐ 문서를 19 / 15·17·18로 고치거나,
> ⓑ 만 38세 시즌을 안 뛰게 하려면 `RETIRE_AGE`를 37로 내리면 됩니다
> (그러면 18시즌 / 14·16·17이 되어 표와 맞습니다).
> ⚠️ ⓑ는 **커리어 길이를 실제로 한 시즌 줄이는 밸런스 변경**이라 재측정이 따라옵니다.
