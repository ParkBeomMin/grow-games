## ① `.w2m-cell-in` — 가운데 점 하나

```css
.w2m-cell-in::after {
  content: "";
  position: absolute; left: 50%; top: 50%; transform: translate(-50%, -50%);
  width: 5px; height: 5px; border-radius: 50%;
  background: var(--m-mark);
  box-shadow: 0 0 0 1px rgba(0, 0, 0, .8);
  pointer-events: none;
}
```

### 왜 이 모양인가

**칸 한가운데를 「상태 칸」 하나로 씁니다.** 셋이 한 자리를 나눠 써서 눈이 한 군데만 봐요.

| 상태 | 가운데 | 칸 테두리 | 뜻 |
|---|---|---|---|
| 🔦 `hot` | **◎ 큰 링** | **2px 링** | `s ≥ perfect` |
| · `in` | **● 5px 점** | 없음 | `s > 0` |
| (클래스 없음) | **빈칸** | 없음 | `s = 0` |

- 🔴 **`in`은 눈에 띄려고 있는 게 아닙니다.** designer의 문장 그대로 —
  초보자에게 필요한 건 정답이 아니라 **「이 칸은 0점」**이고, 그건 **점이 없는 칸**이 말합니다.
  `in`은 그 대조를 세우는 쪽이라 **작고 조용**합니다. **키우면 `◎`를 가립니다.**
- ⚽ `perfect`가 판 천장의 종속값이 되면 `◎`가 **두 배로 자주** 뜬다는 것을 감안한 크기예요.
  ● 5px은 `◎`(12.3×14.1px)의 **1/6 면적**입니다.
- 🕶️ 점 바깥의 1px 어두운 테는 **밝은 칸에서 크림색이 앰버에 붙지 않게** 하는 것뿐이에요.
- ⛔ 글자 `·` 대신 **그린 원**을 씁니다 — 글꼴에 따라 위치·크기가 달라지고, 렌더로 재려면
  좌표가 결정적이어야 합니다.

## ② 곁가지로 잡은 것 — 🔴 표시가 무채색이 아니었습니다

`.w2m-cell-lit`(밝기 칠)은 칸의 **자식**입니다. 그런데 `::before`와 `box-shadow: inset`은
**박스 장식**이라 자식보다 **아래**로 깔려요. 그래서 **정작 제일 밝은 `hot` 칸**에서
`◎`와 링이 앰버 칠에 덮여 있었습니다.

같은 프레임을 얼려 놓고 **A/B로 잰 값**입니다(폭 390 · 키퍼 숨김):

| | `◎`의 제일 밝은 픽셀 | 잉크(가운데 19×19) | 칸 바탕 대비 |
|---|---|---|---|
| `::before` (예전) | `rgb(244,226,177)` 🟠 | 42px | 2.82:1 |
| `::after` (지금) | `rgb(234,240,255)` ⚪ | 45px | 3.21:1 |

링도 같았습니다 — 테두리 1px 안쪽의 제일 밝은 픽셀이
`rgb(247,224,160)` → **`rgb(234,240,255)`**(= `--m-mark` 정확값)로 돌아왔어요.

> 🔑 **이건 밝기 문제가 아니라 ♿ 문제입니다.** 이 화면은 색을 **한 축(앰버 주발 ↔ 회색 약발)**에만
> 씁니다. 표시가 앰버로 그려지면 그 규칙이 그 자리에서 깨져요. 그래서 옮겼습니다.

```css
.w2m-cell-hot { border-radius: 5px; box-shadow: inset 0 0 10px rgba(0, 0, 0, .4); }  /* 그늘만 남김 */
.w2m-cell-hot::after {
  content: "◎";
  position: absolute; top: 0; right: 0; bottom: 0; left: 0;
  display: flex; align-items: center; justify-content: center;
  border: 2px solid var(--m-mark); border-radius: 5px;
  font-size: .88rem; line-height: 1; color: var(--m-mark);
  text-shadow: 0 1px 3px rgba(0, 0, 0, .85);
  pointer-events: none;
}
```

**링과 조준점이 한 겹**이 되어, 칸은 여전히 🧤 키퍼 **아래**에 있고 표시만 칠 **위**로 옵니다.

## 👁️ 렌더 검증 — 무엇을 어떻게 쟀나

**격자**: 폭 {320, 390} × 모션 {기본, reduce} × 시야 {정상, 완전 흑백, 적록 색약(2형)} = **12판**
**경로**: `beta/_check.html` → 「🎮 미니게임 2종 바로 해보기」의 **진짜 버튼을 눌러** 도달.
API로 건너뛰지 않았고, 탭 횟수를 셌습니다(판마다 2회 — 목록 + ▶️ 시작).

**얼리는 법**: 칸의 `requestAnimationFrame`을 감싸 두고, **`hot`·`in`·빈칸이 한 프레임에 다 있는 순간**
같은 프레임 안에서 rAF를 무력화했습니다. 읽기와 얼리기가 한 프레임이라 그 사이에 판이 안 움직여요.
(판은 매번 달라서 셋이 안 뜨는 판이 있습니다 — 🔁 다시 하기로 최대 8판까지 봅니다.
 iframe이 통째로 새로 만들어져서 **판마다 갈고리를 다시** 겁니다.)

**측정 함정 하나** — 처음엔 칸 가운데에서 15px 옆의 **한 점**을 바탕으로 삼았는데,
🧤 키퍼가 그 점을 덮는 순간 **빈칸이 잉크 441px**으로 읽혔습니다. 상자 안 **가운데값(median)**
기준으로 바꾸고, 판별 측정은 키퍼를 숨긴 판에서 했어요(변수 하나만 남기려고).

### 셋이 갈리는가 — 12판 전부 같은 결론

| | 가운데 잉크(19×19px 상자) | 테두리 1~2px의 크림 픽셀 | 표시 색 |
|---|---|---|---|
| ◎ `hot` | **44 ~ 90px** | **45 ~ 108 / 102 ~ 114** | `rgb(234,240,255)` |
| ● `in` | **35 ~ 39px** | **0** | `rgb(234,240,255)` |
| 빈칸 | **0px** | **0** | — |

- ✅ **빈칸은 정상·흑백·색약 12판 전부에서 잉크 0**입니다. 「이 칸은 0점」이 **비어 있음**으로 읽혀요.
- ✅ **`in` 대비 3.4 ~ 9.2 : 1** (자기 칸 바탕 기준). 어두운 칸에서 9.0, 제일 밝은 칸에서 3.4예요.
- ✅ **링은 `hot`에만** 있습니다 — `in`·빈칸의 테두리 크림 픽셀이 **0**. 가운데를 놓쳐도 남는 **둘째 채널**입니다.
- ✅ **완전 흑백에서도** 같은 순서(0 → 36 → 56~76px). 색이 한 톨도 안 실려 있어요.
- ✅ 적록 색약(2형, feColorMatrix)에서도 같은 순서 — **애초에 무채색이라 필터가 안 건드립니다.**

## 📱 실기기에서 봐 주세요 — 기계가 못 잰 것

기하는 위에서 다 쟀습니다. **아래는 재지 못했고, 폰으로 눌러 봐야 압니다.**

1. 🔴 **320px 폭(작은 폰·분할 화면)에서 칸이 정말 44px인가** — 위는 **추정**이에요.
   진짜 경기 중에 🥅 판을 띄워 **엄지로 옆 칸이 안 눌리는지** 봐 주세요.
2. 🔴 **`·`가 3.4초 안에 읽히는가** — 밝기가 아니라 **크기** 문제입니다. 5px이 폰에서 작으면
   6px까지는 올려도 `◎`를 안 가립니다(그 위는 가립니다).
3. 🔴 **`◎`가 두 배로 자주 뜬 뒤에도 특별한가** — engineer의 `perfect ⟺ s ≥ boardCeil × 0.9478`이
   들어가면 **주발·약발 양쪽에서** 뜹니다. 흔해진 `◎` 옆에서 `·`가 **덜 중요하게** 보이는지.
4. 🟡 **가운데 한 자리에서 ◎ ↔ ● 가 프레임마다 뒤집힐 때** — 문턱 언저리에서는 깜빡입니다.
   그게 「지금 문턱에 걸쳐 있다」로 읽히는지, 그냥 거슬리는지.
5. 🟡 **🧤 키퍼가 칸을 반쯤 덮은 자리에서 점이 보이는가** — 키퍼는 반투명이라
   그 위에서도 점이 서는지는 **눈으로만** 알 수 있어요(실측에선 키퍼를 숨기고 쟀습니다).
6. 🟡 **iOS 저사양 기기** — 이 판엔 애니메이션이 한 개도 없어서 버벅일 자리는 없지만,
   `::after`가 6칸에 매 프레임 붙었다 떨어졌다 합니다. 스크롤 중에 끊기는지.
