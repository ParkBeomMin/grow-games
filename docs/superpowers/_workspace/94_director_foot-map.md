### 2-2. 🔴 **좌우를 여기서 다시 판단하지 않았습니다**

CLAUDE.md 2026-08-29 항목이 *"🦶 주발 표시 색이 판정과 반대"*를 적어 뒀고,
설계 93번도 *"**같은 자리입니다**"*라고 못 박았습니다. 그래서 **판정 줄을 베끼지 않고
같은 모양으로** 씁니다:

```js
// winger-moment.js  runCutin / runOneone
const right = ctx.foot !== "L";
lanes = [ { x: 26, strong: !right }, { x: 74, strong: right } ];

// intro.js  gateHTML  ← 글자 그대로 같은 모양
const right = foot !== "L";
const lanes = [ { side: "left", strong: !right }, { side: "right", strong: right } ];
```

폭도 상수에서 옵니다 — `flex: (1 ± FOOT_WIN)`이고 `FOOT_WIN`은
`W2Moment._t.K.FOOT_WIN`에서 **읽어 옵니다.** 숫자를 베껴 적으면 상수를 바꾼 날
**화면만 옛말**을 하게 되니까요.

**🖥️ 헤드리스 렌더로 잰 값 (390px):**

| 카드 | 왼쪽 칸 | 오른쪽 칸 | 비율 | 넓은 쪽 색 |
|---|---|---|---|---|
| **왼발** | **94.4px** (강) | 56.6px (약) | **1.668** | `--m-strong` (앰버) |
| **오른발** | 56.6px (약) | **94.4px** (강) | **1.668** | `--m-strong` (앰버) |

산식이 요구하는 값은 `1.25 ÷ 0.75 = 1.6667`. **렌더가 1.668입니다.**
320px에서도 72.5 / 43.5 = **1.667**.
그리고 **넓은 칸에 칠해진 색이 판정에서 넓은 쪽과 같습니다** — 이번엔 안 뒤집혔어요.

### 2-3. 🖼️ 두 발 그림이 **정말 다른지** 픽셀로 확인

처음 그린 발은 좌우 반전을 걸어도 **두 카드가 똑같아 보였습니다** — 모양이 거의
대칭이라 `scaleX(-1)`이 눈에 안 보였어요. 그러면 「왼발/오른발」이 **글자로만** 남습니다.
`clip-path`로 **앞코가 뻗은 축구화 옆모습**을 다시 그리고,
`.foot-art`만 잘라 두 장을 **바이트로 비교**했습니다 — ✅ **다릅니다** (5,671 vs 9,486 바이트).

> 🔴 계산된 스타일로는 못 보는 종류예요. `transform`은 둘 다 `scale(±1.2, 1.2)`라
> **값만 보면 정상**입니다. 잘라서 비교해야 잡힙니다.

### 2-4. ⏳ 탭하고 320ms

발을 탭하면 `.on`이 붙어 **⚽ 공이 그 발 앞으로 굴러들어오고**, 그 뒤에 다음 화면으로 갑니다.
디자이너 그림의 *"선택한 쪽에만 ⚽ 공이 붙습니다"*가 **보이려면 그 순간이 있어야** 해서요.

♿ **`prefers-reduced-motion: reduce`면 기다리지 않고 바로 넘어갑니다.**
연출이 진행을 붙잡으면 그건 연출이 아니라 지연이에요.
(⚠️ 이 320ms가 검사 하나를 비동기로 만듭니다 — §6-1)

## 3. ② 🗺️ 동네 지도

### 3-1. 🖐️ 가장 어려웠던 것 — **광역시는 지도에서 못 누릅니다**

경위도를 그대로 투영하면(y 66.7단위/도 · x는 `cos 37.5° = 0.793`배)
**서울 ↔ 인천이 16단위**, **세종 ↔ 대전이 10단위**입니다.
390px 화면에서 그건 **점 하나 크기**예요. ≥44px 탭 칸은 물리적으로 불가능합니다.

그래서 **17개를 성격으로 갈랐습니다:**

| | 어디서 고르나 | 잰 탭 칸(390 / 320) |
|---|---|---|
| 🏞️ **도 9곳** | **지도 폴리곤을 직접 탭** | 최소 **69.8 × 50.6px** (제주) |
| 🏙️ **특별시·광역시 8곳** | 지도에는 **핀만**, 탭은 **오른쪽 목록** | **160 × 44.9px** / **90 × 44.9px** |

🔑 **핀에 `pointer-events: none`을 건 건 의도입니다** — 히트 원을 주는 순간
세종과 대전이 **서로를 먹습니다.** 겹친 히트 영역은 「눌렀는데 다른 게 골라지는」
가장 나쁜 종류의 버그예요.
대신 **고른 순간 그 핀에 이름표가 뜨고**(평소엔 숨김 — 8개를 늘 띄우면 서울·인천이 겹쳐 못 읽어요),
핀이 커지며 색이 앰버로 바뀝니다. *어디인지*는 지도가, *누르는 것*은 목록이 맡아요.

### 3-2. 🏝️ 제주는 **확대 상자**

실제 크기로 그리면 탭 칸이 **40 × 25px**입니다. `translate(…) scale(2)`로 키워
**80 × 51px**이 됐어요. 한국 지도의 흔한 관례이기도 하고, 자리가 남해 아래 빈 칸이라
**본토를 한 곳도 안 가립니다.** 점선 상자로 *"여긴 축척이 다르다"*를 표시했습니다.

### 3-3. 🖥️ 잰 것 — 폭 {390, 320} × 모션 {기본, reduce} 네 판

| 검사 | 결과 |
|---|---|
| 콘솔 오류 | ✅ **0건** (네 판 모두 · `file://` 서비스워커 등록 실패는 렌더 환경 탓) |
| 가로 넘침 | ✅ **없음** — `scrollWidth == clientWidth` (390/390 · 320/320) |
| 요소 겹침·잘림 | ✅ 없음 |
| 🏞️ 도 라벨이 **제 폴리곤 안에** 있나 | ✅ 9/9 — `isPointInFill`로 확인 (눈대중 아님) |
| 🏙️ 탭 칸 ≥ 44px | ✅ 8/8 — 최소 **44.9px** (390·320 공통) |
| ♿ reduce 판이 **정보를 잃나** | ✅ **안 잃습니다** — 색·테두리·판정 창 폭·스토리 전부 그대로. 끄는 건 이동·전환뿐 |
| 🗺️ → 🎯 자리로 넘어가나 | ✅ 네 판 모두 `screen-position` 도달 |

> ⚠️ **처음 판에서 두 가지가 걸렸고 고쳤습니다.**
> ① 🏝️ 제주 탭 칸이 40 × 25px (→ 확대 상자로 80 × 51)
> ② 지도를 마우스로 고르면 폴리곤 위에 **네모난 기본 포커스 테두리**가 남았어요
> (모양을 안 따라가서 흰 사각형으로 보입니다). `:focus`의 outline만 지우고
> **⌨️ `:focus-visible`에는 하늘색 굵은 외곽선을 남겼습니다** — 접근성은 축약 대상이 아니에요.
> Tab 키로 폴리곤에 초점이 가는 것도 확인했습니다(첫 Tab → 「경상북도」).

### 3-4. 🔒 지역은 산식에 안 닿습니다

`intro.js`가 지역으로 바꾸는 것은 **📖 스토리 한 줄**과 **🏛️ 지역 기록**뿐입니다.

그 문장을 **파일 머리 주석에 못 박아 뒀습니다** — 79번이 예고한
*"고르는데 효과가 없다"*는 압박이 올 자리라서요.

## 5. 🎨 CSS가 안 붙어 있던 두 자리 — 하나는 **실제로 뒤집혀 있었습니다**

### 5-1. 🏘️ `.town-dot` — 점이 아니라 **칩**이었습니다

`town.js`는 `<span class="town-dot hit">⚽</span>`처럼 **카드 이모지를 안에** 넣습니다.
12px 점으로 만들었더니 **이모지가 밖으로 삐져나왔어요**(렌더로 봤습니다).
38px 원형 칩으로 다시 그렸습니다.

| 클래스 | town.js의 판정 | 색 | ♿ 표식 |
|---|---|---|---|
| `now` | 지금 뛸 판 | 앰버 테두리 + 링 | — |
| `hit` | `res === "perfect"` | 초록 | **✓** |
| `mid` | `res === "ok"` | 앰버 | **·** |
| `bad` | 그 외(miss) | 붉은색 | **✕** |
| (없음) | 아직 안 뛴 판 | 회색·흐림 | — |

♿ **색만으로 말하지 않습니다** — 색각 이상이면 초록/빨강이 같은 회색이라
결과마다 글자 표식을 하나씩 달았습니다.
실제 판을 굴려 확인했어요: `hit → rgb(110,231,160)` · `mid → rgb(255,159,69)` ·
`bad → rgb(255,77,109)`, 그리고 마지막 결과판이 `town-res bad`.

### 5-2. 🔴 🏟️ `.offer-t0~t4` — **색이 판정과 반대였습니다**

처음엔 t2를 하늘색, t3을 앰버로 뒀습니다. 그럴듯해 보였는데 **렌더로 재 보니:**

```
offer-t2 · ⭐⭐ 입단 제안 · 테두리 rgb(111,201,255) 밝기 185.8
offer-t3 · ⭐⭐⭐ 정식 제안 · 테두리 rgb(255,159,69) 밝기 172.9
등급이 오를수록 밝아지나: 🔴 아니오 — 색이 판정과 반대입니다
```

**중립 등급이 그 위 등급보다 밝았습니다.** 색상을 섞으면 밝기 순서가 뒤집혀요 —
🦶 주발 사고와 **같은 형태**입니다(*"넓다고 색칠된 쪽이 실제로는 좁은 쪽"*).

한 색 계열(회색 → 금색)로 다시 잡고 **다섯 등급을 전부 세워** 다시 쟀습니다:

| | t0 ☆ 관찰 대상 ×0.90 | t1 ⭐ 후보 등록 ×0.95 | t2 ⭐⭐ 입단 제안 ×1.00 | t3 ⭐⭐⭐ 정식 제안 ×1.05 | t4 ⭐⭐⭐⭐ 특급 영입 ×1.10 |
|---|---|---|---|---|---|
| 테두리 | `#3d4a44` | `#6b6a4e` | `#9a8a52` | `#ffd166` | `#fff0bd` + 발광 |
