## 1. 👕 유니폼의 일생 — **이 판은 ①②만, ③은 자리만**

```
① 조립대 처음      무지 — 아무것도 안 적힌 유니폼      ✅ 됩니다
② 이름·번호        그 자리에 새겨집니다 (실시간)        ✅ 됩니다
③ 팀 입단          그 팀의 색·무늬로                    🔴 이번 범위 아님 — 자리만
```

### ③을 위해 **색을 코드에서 전부 뺐습니다**

```js
W2Char.show(stage, { name, number, foot, kit })
W2Char.set({ name, number, kit })     // 서 있는 유니폼만 갈아입혀요
kit = { body, sleeve, trim, text, pattern }
```

`kit`을 안 주면 무대의 CSS 변수를 읽습니다 — `--kit-body` `--kit-sleeve` `--kit-trim` `--kit-text`.
**`char3d.js`에 유니폼 절대색이 한 개도 없습니다.** 팀 색이 생기면
`paintChar()`에 `kit: {…}` 한 줄이면 끝이에요. 셰이더도 지오메트리도 안 건드립니다.

> ⚠️ **딱 하나 예외**: ⚽ 공은 흰색을 박았습니다. 공은 **팀 물건이 아니에요** —
> 킷을 갈면 공까지 팀 색이 되는 게 오히려 사고입니다.

### 무늬는 **일부러 안 만들었습니다**

`kit.pattern`은 받되 지금은 `"solid"`만 그리고, 모르는 값은 조용히 무지로 떨어집니다.
붙일 자리는 **`paintKit()` 한 곳**이에요 (몸통은 원통 UV라 `wrapS = RepeatWrapping`이면
세로줄이 자연스럽게 돌아갑니다 — 주석에 적어 뒀습니다).

> 🔑 **왜 지금 안 만드나**: 클럽 색 데이터가 없어서, 무늬만 먼저 넣으면
> **무늬가 무슨 뜻인지 아무도 모르는 상태**가 됩니다. 장식이 되고, 장식은 나중에 지우기 어려워요.

## 2. 🔴 가장 크게 바꾼 판단 — **🎲가 유니폼을 안 바꿉니다**

캐릭터판은 🎲가 체형을 바꿨습니다(배분 여섯 칸 중 다섯이 몸에 실렸어요 · 78번 §3).
**유니폼은 안 바뀝니다.** 이건 축소가 아니라 판단입니다.

| 왜 | |
|---|---|
| ① | **배분을 유니폼에 실으면 「색·무늬로 능력치를 읽는 화면」이 됩니다.** 그건 🌱 등급 여섯 줄이 하는 말이에요. **두 번 말하면 하나는 반드시 거짓말을 합니다** |
| ② | 👕 유니폼은 **안 바뀌는 축**입니다 — 이름·번호가 거기 있으니까요. 조립대가 *"내 선수를 다듬는 자리"*이려면 안 바뀌는 축이 있어야 해요 (78번 §3에서 머리 크기를 고정한 것과 같은 이유) |
| ③ | 조율자 지시가 **킷은 「팀 입단」에 바뀐다**고 못박았습니다. 🎲가 킷을 굴리면 ③의 사건이 미리 소모돼요 |

### 그럼 🎲는 화면에서 뭘 하나

**🌱 등급 여섯 줄이 무대 바로 아래**에 있고, 거기서 값이 바뀝니다.
78번 §2에서 **그러라고 실측해서 올려놓은 자리**예요 — 무대 `sticky top` · 🎲 줄 `sticky bottom`,
가운데만 스크롤. 이 배치가 이번에도 그대로입니다(§7).

그리고 **손에는 대답합니다** — `W2Char.nudge()`. 굴린 순간 유니폼이 **한 번 흔들려요**(0.62초 감쇠 진동).
**아무것도 뜻하지 않는 흔들림이라 거짓말을 할 수가 없습니다.**

> 🔒 **검사가 양쪽을 다 지킵니다** (B절):
> `🎲 8번에도 킷·이름·번호가 1가지` **그리고** `🌱 등급 여섯 줄은 8/8 달라짐`.
> 앞의 것만 재면 **🎲가 죽어도 초록불**이에요 — 그래서 둘을 붙여 놨습니다.

## 3. 🦶 주발 — **거울을 지웠습니다** (검사가 반대 방향으로 뒤집힌 자리)

캐릭터판에서 가장 조심했던 자리가 여기였어요. 캐릭터가 우리를 마주 보니
**캐릭터의 왼발이 화면 오른쪽**이라 거울이 한 번 뒤집혔고, 세 겹으로 막았습니다(78번 §4).

**🔴 유니폼은 돌아갑니다.** 앞을 보면 착용자의 왼쪽이 화면 오른쪽이고, 뒤를 보면 화면 왼쪽이에요.
**안정된 좌우가 없습니다.** 그런데 공을 한쪽에 놓으면 — **반 바퀴마다 거짓말**입니다.
이 저장소가 한 번 데인 그 형태예요: *"안 보이는 것"이 아니라 **거짓말을 하고 있던 것***.

### ✅ 그래서 공을 **가운데**로 옮기고, 🦶는 **글자 칩**이 말합니다

`root`에는 공이, `shirt` 그룹에는 유니폼이 매달려 있고 **`shirt`만 돕니다.**
공은 바닥에 그대로 있어서, 돌려도 위치가 안 바뀝니다.

### 🔁 그래서 **검사가 재는 방향이 뒤집혔습니다**

| | 캐릭터판 A절 | 유니폼판 A절 |
|---|---|---|
| 재는 것 | *"공이 **주발 쪽**인가"* | *"공이 **어느 쪽도 아닌가**"* |
| 판정 | `sign(ball.x − root.x) === (왼발 ? +1 : −1)` | `ball.x === 0` · **왼발판과 오른발판의 화면 x가 같다** |
| 지키는 것 | 방향이 **맞다** | 방향을 **안 쓴다** |

**실측**: 왼발 50.0% · 오른발 50.0% — 두 판이 **정확히 같습니다.**
공을 다시 주발 쪽으로 옮기면 이 줄이 빨간불이에요.

> 🔑 이게 이번 작업에서 제일 마음에 드는 부분입니다. **거짓말할 수 있는 장치를 지운 것**을
> 기계가 지키게 만들었어요. 「올바른 방향」을 지키는 검사보다 강합니다 —
> 방향이 아예 없으면 틀릴 수가 없으니까요.

## 4. 🖨️ 등판 — 🇰🇷 **한글이 들어가야 해서** 캔버스로 갔습니다

3D 폰트 자산으로 한글을 넣으려면 글리프가 **11,172자**예요. 오프라인 PWA에 얹을 수 없습니다.

**그래서 2D 캔버스에 페이지 폰트(Jua)로 그려서 `CanvasTexture`로 씁니다.**
폰트 파일을 **한 개도 안 받아요** — 페이지가 이미 쓰는 폰트를 캔버스가 그대로 씁니다.

| 장치 | 왜 |
|---|---|
| 캔버스 **1024²** (DPR ≤ 1.5면 512²) + 이방성 4 | 캐릭터판에서 아낀 폴리 예산을 여기 썼습니다 |
| `document.fonts.ready`에 **한 번 더** 그림 | 웹폰트는 늦게 옵니다. 안 그리면 **대체 폰트로 굳어요** |
| 라틴만 **대문자**로 (한글은 그대로) | 유니폼 관례. 섞여 있어도 안 깨집니다 |
| `ctx.letterSpacing` (있으면) | 등판 글씨는 붙으면 뭉쳐 보여요. 모르는 브라우저면 그냥 안 벌어집니다 |
| 폭을 **실제로 재서** 줄임 (`fitText`) | 🇰🇷 한글 세 글자와 라틴 세 글자는 폭이 두 배 가까이 달라요 — **글자 수로 자르면 틀립니다** |

**실측 (390px · 1024² 캔버스 · 폭 상한 881px):**

| 이름 | 글자 크기 | 실제 폭 | 판정 |
|---|---|---|---|
| `김하늘` (세 글자) | 210px | **546 / 881px** | ✅ 여유 있게 들어감 |
| `남궁도영훈` (다섯 글자) | **193px** | **879 / 881px** | ✅ 줄어서 들어감 · 안 잘림 |
| 등번호 `9` | 553px | — | ✅ 이름보다 2.6배 큼 (유니폼 관례) |

> 🔴 **여기서 검사를 한 번 잘못 적었습니다.** 긴 이름이 줄었는지를 `namePx < 캔버스×0.185`
> 라는 **손으로 적은 문턱**으로 쟀는데, 시작 크기를 0.185 → 0.205로 한 번 올리자
> **줄었는데도 빨간불**이 됐어요(193 > 189.4). 지금은 **세 글자 이름과의 관계**로 잽니다 —
> `긴 이름 < 세 글자 이름`. 종속값은 문턱이 아니라 관계로 재야 합니다.

### 📐 등판을 **살짝 굽은 판**으로 만든 이유 — 두 번 틀렸습니다

| 시도 | 무슨 일이 |
|---|---|
| ① **평평한 판** | 납작한 통이라 등이 완전 평면이 아니에요 — 가운데가 옷 밖으로 튀고 가장자리는 옷 속에 묻힙니다 |
| ② **원통 조각** | 곡률은 맞는데 **글자가 가장자리에서 늘어납니다** (u가 각도에 비례하니까요) |
| ✅ **x는 균등 · z만 타원을 따라** | 뒤에서 보면 글자가 **한 점도 안 늘어나고**, 옆에서 보면 옷에 붙어 있습니다 |

그리고 **정사각 판 + 정사각 캔버스**입니다. 직사각으로 두면 캔버스 비율만큼 글자가 늘어붙어요.

## 5. 👀 기본 자세는 **등**입니다

이 화면의 사건이 *"내 이름이 새겨졌다"*라서, **쉴 때 등이 카메라를 봅니다**(`REST = π`).
앞(깔끔한 면)은 **끌어서 돌려야** 나와요 — 그게 보상입니다.

**실측**: 쉴 때 `facing = 0.975` · 반 바퀴 끌면 `facing = −0.989`(앞면).
♿ reduced-motion에서도 `facing = 0.991` — **멈춰도 이름·번호는 정면에서 읽힙니다.**

> 🔴 **조명을 앞에만 뒀다가 첫 렌더에서 회색 옷이 됐습니다.** 기본 자세가 등인데
> 광원이 앞에만 있으면 **이름·번호가 있는 면이 통째로 그늘**이에요.
> 앞뒤로 하나씩 뒀습니다 — 드로우콜은 안 늘어납니다.

## 6. 🔢 등번호 — **없던 데이터입니다**

### 판단: 포지션 관례 **셋 중에서 고르기** (자유 입력이 아님)

| 포지션 | 후보 (첫째가 기본) |
|---|---|
| 공격수 `fw` | **9** · 10 · 19 |
| 윙어 `wg` | **7** · 11 · 17 |
| 미드필더 `mf` | **8** · 10 · 6 |
| 수비수 `df` | **4** · 5 · 3 |

**자유 입력을 안 한 이유**: 등번호는 **고르는 재미**지 채우는 칸이 아니에요.
자유 입력이면 검증(0? 100? 빈칸? 이모지?)과 키보드가 붙고, 세로 화면이 한 칸 더 길어집니다.
셋이면 탭 세 번이고 **전부 그럴듯한 번호**예요.

### ⚠️ 세이브 — **마이그레이션 안 합니다**

```js
S0.shirtNo = Number(card.shirtNo) || defaultNo(S0.pos);      // applyCard
const shirtNoOf = (st) => (Number(st.shirtNo)) || defaultNo(st.pos);   // 읽는 쪽
```

`WingerProspect.shirtNoOf` · `defaultShirtNo` · `shirtNosOf` · `SHIRT_NOS`를 공개했습니다 —
**다음 화면(HUD·프로필·유니폼)이 전부 같은 자리에서 읽으면** 옛 세이브가 조용히 갈리지 않아요.

### 🔑 번호를 누르면 **화면을 다시 안 그립니다**

`render()`를 부르면 `innerHTML`이 통째로 새로 그려지고 🎬 슬롯 연출이 세 칸 다시 돕니다.
번호 하나 바꾸는 데 화면이 깜빡이면 **고르는 맛이 사라져요.**
그래서 `setShirtNo()`가 ① 3D는 `set()`으로 등판만 ② 폴백 글자와 버튼 상태만 손댑니다.

**실측**: 눌렀을 때 등판 `9 → 10` · `mounts = 1`(다시 안 그림) · 세이브에 `S.shirtNo = 10`.

## 7. 🖼️ 접히는 선 — **78번의 배치를 그대로 지켰습니다**

조율자 지시: *"접히는 선 배치를 유지하세요 — 무대 `sticky top` + 🎲 줄 `sticky bottom`"*.
지켰고, 🔢 등번호 줄이 그 사이에 **한 칸 들어갔습니다.**

```
🧬 선수 만들기                  32px
🎲는 몇 번이든 눌러도 돼요…      50px
┌────────────────────────┐
│ 🧒 김하늘                │  ← 무대 위 이름표 — **한 줄만** (아래 §7 상자)
│         👕 유니폼        │  240px · position: sticky (top)
│         (등에 이름·번호)  │
│           ⚽             │      ← 공은 가운데 (좌우에 뜻 없음)
│         🦶 오른발         │
├────────────────────────┤
│ 🎂 17세 · 🦶 오른발       │   ← 🔒 잠긴 사실 줄 (무대 밖으로 내렸어요)
│ 🔢 등번호  [9][10][19]   │   ← 새 칸. 자기 안에서 끝납니다
├────────────────────────┤
│ 🌱 출발점 — 등급 여섯 줄  │   ← 🎲가 바꾸는 것을 가장 곧게 읽는 자리
├────────────────────────┤
│ 📈 지금 실력 (레이더)     │   ← 접히는 선 아래
│ 🎁 타고난 것              │
└────────────────────────┘
🎲 다시 뽑기 · 📊 표준과 견주기   ← position: sticky (bottom)
```

**실측 (844px 접히는 선):**

| | 320px | 390px |
|---|---|---|
| 🔢 등번호 줄 끝 | 430px | 454px |
| 🌱 등급 여섯 줄 끝 | **666px** ✅ | **656px** ✅ |
| 가로 넘침 | 0px | 0px |
| 탭 칸 (🎲·📊·시작·뒤로) | 46 / 46 / 50 / 54px | 같음 |
| 🔢 등번호 칸 | 44 / 44 / 44px | 같음 |
| 420px 스크롤 뒤 무대·🎲 공존 | ✅ 무대 −2~188 · 🎲 752~812 | ✅ 무대 −2~238 · 🎲 751~811 |

### 🔴 이름이 **두 번 겹쳐 보이던 자리** — 렌더가 아니면 못 봤습니다

무대 위 이름표(`.pc-id`)에 `🧒 이름 / 🎂 17세 · 🦶 오른발 · 🔢 9번`을 얹었더니,
**320px에서 그 줄이 접히면서 유니폼 등의 이름을 그대로 덮었어요.** 이름이 두 개 겹쳐 보입니다.

**고친 방법 셋:**

| | 무엇 |
|---|---|
| ① | 이름표는 **이름 한 줄만.** 🎂 나이·🦶 주발은 **무대 밖 아래로** 내렸습니다 |
| ② | `.pc-name`에 `nowrap` + `ellipsis` — **두 줄이 되는 길을 아예 막습니다.** 긴 이름이 와도 세로로 안 자라요 (전체 이름은 등판이 보여 줍니다) |
| ③ | 렌더 검사가 **이름표와 등판의 화면 사각형이 안 겹치는지**를 잽니다 — N절 + **폭마다**(E절) |

**실측**: 390px 이름표 y2.5~11.5 · 등판 y17.5~48 / 320px 이름표 y3.2~13.7 · 등판 y17.4~47.8 — 안 겹칩니다.

## 8. ♿ `prefers-reduced-motion` — 축약 대상이 아닙니다

| | 기본 | reduce |
|---|---|---|
| 👕 3D | 옷걸이 흔들림 · 소매 스윙 · 숨 · 느린 좌우 · 공 회전 | **정지 한 장** (바뀔 때만 그림) |
| 🎲 `nudge()` | 0.62초 감쇠 진동 | **아무 일도 안 함** |
| ✨ 새겨지는 순간 | 0.42초 페이드인 | **바로 켜짐** (정보는 그대로) |
| `.pb-slot` 3칸 등장 | 0.22초씩 순서대로 | 그 자리에서 바로 |

**실측 (reduce 판)**: 회전 `3.142 → 3.142`(0.7초 뒤에도 그대로) · `nudge()` 눌러도 `3.142` ·
등급 여섯 줄 `opacity` 전부 **1** · 등판 `facing 0.991` `opacity 1` — **정보를 하나도 안 잃습니다.**

⚠️ `animation: none`만 쓰면 `both`의 시작 상태 `opacity: 0`에 갇힙니다. 끝 상태를 직접 적었어요(그대로 유지).
