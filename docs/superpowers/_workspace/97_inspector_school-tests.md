const STAGES = [ { id: "e", n: 2, … }, { id: "m", n: 3, … }, { id: "h", n: 3, … } ];

## 9-2. 📮 요청하신 판정 — **M-N은 폐기가 맞습니다. 검사는 「위로」 올렸습니다**

**engineer 말이 맞습니다.** `deal()`이 `n`을 읽게 되면서 **선언과 실제가 한 소스가 됐고**,
옛 S-6b(*"선언 ↔ 실제가 **어긋나지 않는다**"*)는 **원리적으로 깨질 수가 없어졌습니다.**
M-N(표만 1/1/1)은 표와 덱을 같이 움직이니 **초록불이 맞아요.**

🔴 **그런데 「못 뜨는 변이」를 그대로 두는 게 더 나쁩니다.** 그건 초록불로 죽어 있으면서
*"이 자리는 검사가 있다"*고 말하는 상태예요 — 이 저장소가 여덟 번 데인 바로 그 형태입니다.
그래서 **지우되, 지운 자리를 파일에 적었습니다.**

**S-6b를 「종속값을 관계로」로 올렸습니다** (CLAUDE.md의 세 번째 축 · engineer 제안 그대로):

```
옛  S-6b : 선언(STAGES.n) === 실제 덱          ← 배선이 끊겨 있을 때만 의미가 있었음
새  S-6b : n을 바꾸면 덱이 「따라 움직인다」      ← 배선 자체가 계약
```

실측 (검사가 스스로 찍습니다):

```
카-A 선언 e:2 · m:3 · h:3 → 실제 e:2 · m:3 · h:3 · 아크 8장 ✔
카-B 선언 e:2 · m:2 · h:2 → 실제 e:2 · m:2 · h:2 · 아크 6장 [eemmhh] ✔
```

- 🧭 카-B(2/2/2)는 **변이가 아니라 탐침**입니다 — 설계가 *"아크가 길어지면 여기를 2/2/2로"*라고
  적어 둔 **실제 운영 손잡이**라, 「고장을 심는 것」이 아니라 **「다음 배치가 진짜로 도는지」**를 봅니다.
  0번이 이 정규식도 함께 대조해요(안 걸리면 💥가 아니라 ❌).
- 🔒 두 배치(2/3/3 · 2/2/2)는 **검사에 박았습니다.** `_t.STAGES`에서 읽으면 배선이 끊겨도 따라갑니다.
- 🔑 새 S-6b를 깨는 건 **배선 끊기**이고 그게 **M-DECK**입니다 — 실제로 빨간불 확인했어요.
  그리고 배선이 다시 끊기면 M-N도 되살아납니다. 즉 M-N은 **「배선이 끊겨 있을 때만 유효한 변이」**였어요.

> 🌍 **이 판정이 성립하는 세계:** `deal()`이 `stage.n`을 읽는 세계입니다.
> 누가 다시 카드 수를 `deal()` 안에 하드코딩하면 **S-6b가 먼저 빨간불**이 되고,
> 그때는 옛 S-6b(정적 일치)를 되살리는 게 맞습니다. 파일 주석에 그렇게 적어 뒀어요.
