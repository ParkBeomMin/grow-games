## 1. ✅ 통과 — 기계가 확인함

> 모든 새 검사는 **게임 입구**(타이틀 → 이어하기/새 게임 → 진짜 버튼 `pointerdown → pointerup → click`)로 들어간다. 페이지 주소는 `/soccer/`(engineer 요령).
> 난수원은 셋으로 가른다 — 게임 `Math.random`(시드) · 이벤트 `WingerEvents._rng`(seed ^ 0x9E3779B9) · 드라이버 정책(seed ^ 0x85EBCA6B).
> 연출(`fx.js`)은 꽃가루 자리를 `Math.random`으로 정해 **게임 난수를 먹으므로** 비트 대조에서는 난수 없는 빈 연출로 바꿨다(분포엔 영향 없음).
> 페이지 안 예외는 jsdom이 node로 안 올려서 VirtualConsole로 모아 **「예외 0」**을 따로 단언했다.
> 문턱은 스펙·실측 문서 숫자를 검사에 박았다(소스에서 안 읽음). 식은 소스에서 뜯거나 진짜 페이지에서 불렀다.

### ❌-1 (코드 · 중간 · engineer) 📖 `book.js` — 다른 기기 장부의 `"__proto__"` 키가 **Object.prototype을 더럽힌다**
- **자리**: `beta/soccer/book.js:26` `const ID_RE = /^[a-z0-9_:]{1,40}$/i;` — `"__proto__"`·`"constructor"`가 통과 · `:55` `const had = out[k][id];` — id가 `"__proto__"`면 `had`가 **Object.prototype** · 바로 아래 합치기가 거기에 `n`·`at`을 씀 · `:69` `mark()`의 같은 줄
- **어긋난 것**: 파일 주석(:23-25)은 「장부는 클라우드를 타고 다른 기기에서 올 수 있어서, 모양이 다른 키(`__proto__` 같은 것)는 받지 않아요」라고 **약속**하는데 정규식이 받는다. `JSON.parse`는 `"__proto__"`를 **자기 칸**으로 만들고 `Object.keys`가 그 칸을 내놓는다 → `load()`가 `Object.prototype.n = NaN` · `Object.prototype.at = …`을 쓴다 → 그 페이지의 **모든 객체**가 `.n`·`.at`을 물려받음. `mark("ev", "__proto__")`도 `true`
- **재현**: `localStorage["winger-save-v1-book"] = '{"v":1,"ev":{"__proto__":{"n":9,"at":1}},"end":{},"ach":{},"pend":[]}'` → `WingerBook.load()` → `({}).n` → **NaN** · `({}).at` → **1** (node에서 book.js 그대로 + 진짜 페이지 둘 다 재현)
- **고칠 길(제안)**: 합칠 때 `Object.prototype.hasOwnProperty.call(out[k], id)`로 `had`를 보거나 · `out[k]`를 `Object.create(null)`로 · 또는 `ID_RE`에 `(?!__proto__$|constructor$|prototype$)`
