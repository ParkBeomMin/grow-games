                 │        └──▶ B 업적(🎖️ 분류) · 필름(병역 장) · 도감(병역 이야기)                 │
                 │                                                                               │

| 누가 | 무엇에 기대나 | 왜 순서가 강제되나 |
|---|---|---|
| B 업적의 📖 이야기 분류 | A의 이야기 결말 | 결말이 없으면 칸이 빈다 |
| B 필름의 🎲 선택의 기록 | A의 `S.evLog` | 판정 기록이 쌓여야 성향·최고의 한 수가 나온다(옛 세이브는 이 장을 건너뜀) |
| C 전부 | A의 선택 이벤트 틀(확률 조각 · 얼린 % · 오버레이 · 도감) | 입영 통지·군 팀 지원·차출 협상이 **그 틀 그대로**다 — 따로 만들면 "% 표시 규칙"이 둘이 된다 |
| C 업적·필름 | B의 업적 목록·필름 모델 | 🎖️ 분류와 병역 장을 끼울 자리 |
| D 서버 최초 기록 | B의 업적 id | 업적 id가 서버 키다 |
| D 영구결번 | B에서 들이는 **등번호**(`S.no`) + 기존 `hof` | 지금 게임엔 **내 등번호가 없다**(판단 지점 9) |
| D 공유 링크 | B의 필름 요약 + 기존 `hof` | 링크가 보여줄 내용이 필름이다 |

## 단계 나눔 — ① A+B → ② C → ③ D

오케스트레이터가 정한 순서를 **유지하는 쪽을 추천**합니다(판단 지점 1에 대안). 근거:

1. **큰 밸런스 변경을 겹치지 않는다** — [[백로그 — 미룬 결정]]의 *"둘을 겹치면 어디서 틀어졌는지 못 찾는다"*.
   A는 작게 흔들고(프로 이벤트) C는 크게 흔든다(나이 축·복무 시즌·U-23). 둘을 한 번에 재면 곡선이 움직였을 때 원인을 못 가른다.
2. **C는 A의 엔진 위에 선다** — A가 실기기에서 한 번 검증된 뒤라야 C의 이벤트가 "새 틀의 버그"와 "병역 규칙의 버그"로 갈린다.
3. **D는 밸런스가 아니라 운영·보안 단계다** — SQL 적용에 사용자 승인이 필요하고, 영구결번은 등번호를 단
   커리어가 **은퇴까지 쌓여야** 의미가 생긴다. ①에서 등번호를 먼저 들이면(판단 지점 9) ③ 시점엔 결번 후보가 있다.

### ① 안의 순서 (한 단계지만 세 조각으로 굴린다)

| 조각 | 내용 | 실측 필요 | 끝났다고 말하는 기준 |
|---|---|---|---|
| ①-a | 이벤트 엔진 + 유스 4종 전환 + 프로 이벤트 18종 + 신뢰(`S.trustEv`) + 약속 + 도감 | **예** (M-A0~A6) | 아래 ① 완료 기준의 A 항목 |
| ①-b | 이야기 4편(🌍 낯선 땅 · 📍 자리 전쟁 · 🕯️ 선배의 마지막 시즌 · 🔥 한 끗 레이스) + (판단 5가 (b)면) 🩹 재활 | **예** (M-A7) | 결말 도달·닫힘 |
| ①-c | 업적 55 · 희귀도 · 대표 업적 · 필름 · 공유 이미지 · 등번호 | **예** (M-B1~B3, 희귀도 배정용) | 아래 ① 완료 기준의 B 항목 |

①-a → ①-b는 순차(이야기가 엔진 위), ①-c는 ①-a와 **파일이 겹치지 않아** engineer/director가 나눠 병렬로 굴릴 수 있다
(단, 필름의 🎲 장은 ①-a의 `S.evLog` 모양이 확정된 뒤).

### 각 단계의 완료 기준 (기계 ✅ / 👁️ 실기기)

**① A+B**
- ✅ **"늘 안전" 커리어가 현행과 같다** — 유스 엔딩 7종 분포·프로 도전 통과율, 프로 리그MVP 곡선·`careerScore` 분포가
  현행 표본과 **통계적으로 구별되지 않는다**(M-A1·M-A2). 이게 빨간불이면 아래는 볼 것도 없다
- ✅ **보이는 %가 판정 %다** — 이벤트마다 화면 숫자 == 판정에 쓴 숫자(독립 재계산 어긋남 0건) + 대량 표본의 실제 성공률이
  구간별로 표시 %와 맞는다(이항 검정). **숨은 보정 0**
- ✅ **지배 전략이 없다** — 확률을 읽는 정책 ≥ 늘 안전·늘 도전(모든 격자 칸), 늘 도전이 "사실상 정답"인 칸이 절반 이하(M-A2)
- ✅ **선택이 육성을 대체하지 않는다** — 읽기 정책의 이득이 종합 70 칸에서 ≈0, 130 칸에서도 한 시즌 훈련량의 일부(M-A3)
- ✅ **흐름을 안 끊는다** — 시즌당 이벤트 평균·최대가 밴드 안, 컵·월드컵 중 0건(M-A4)
- ✅ 이야기 4편이 **은퇴 전에 전부 닫힌다**(흐지부지 결말 포함), 결말마다 도달 가능(M-A7)
- ✅ 업적은 경기력에 **0** — B를 켠 커리어와 끈 커리어의 `careerScore`·수상 분포가 같다(M-B3)
- ✅ 옛 세이브(시즌 중·결산 중·유스 중·은퇴 직전 픽스처)가 **한 칸도 안 움직이고** 이어진다
- ✅ 기존 `tests/soccer/` 63종 전부 초록 + 새 검사(%-진실 · 중립 · 닫힘 · 업적 멱등 · 필름-옛세이브 · 도감 합집합)
- 👁️ 오버레이·도감·필름 스크롤·공유 이미지(글꼴·이모지·줄바꿈)·등번호 고르기 — **사용자 실기기 확인이 이 단계의 관문**

**② C**
- ✅ 비(非)한국 커리어가 **현행과 같다**(몸 나이 축 도입이 중립 — M-C5)
- ✅ 병역 경로 다섯 중 **어느 것도 모든 칸에서 지배하지 않는다**, 강제 현역도 파국은 아니다(M-C1)
- ✅ 기한을 넘긴 옛 세이브가 **갑자기 입대하지 않는다**(`legacy`)
- ✅ U-23 대회가 어떤 경로로 끝나든(탈락·승부차기·메달·차출 거부) **후반기로 돌아오고** `S.u23 = null`(월드컵 계약 ①② 그대로) ·
  `S.u23`과 `S.wc`가 동시에 살아 있는 순간 0 · 월드컵 검사 5종 초록
- 👁️ 복무 장면·U-23 소집·결과 카드·차출 협상 카드(U-23은 화면 테마를 안 바꾼다)

**③ D**
- ✅ SQL이 **파일로만** 준비됐고(적용 전 확인 쿼리 포함) — **운영 DB 적용은 사용자 승인 뒤**
- ✅ 모든 서버 문자열이 받는 길(scrub)·그리는 자리(esc)·서버(CHECK) **세 겹**에서 막힌다 — 변이 검증: 그리는 길에서 esc를 빼면 태그가 DOM에 들어가는 걸 검사가 잡는다
- ✅ 서버가 꺼져도(오프라인·베타·RPC 실패) 게임이 **한 줄도 안 막힌다**(기존 HOF `sent:false` 방식)
- 👁️ 라이브 현황 카드·공유 링크 보기 화면·결번 벽

### A · 이벤트

**2. "안전한 선택"의 모양**
| | 선택지 | 트레이드오프 |
|---|---|---|
| (a) | 유스 = **옛 자동 이벤트 효과 그대로**, 프로 = **효과 0(넘긴다)** | "늘 안전" 커리어가 **구성상** 현행과 같다 — 중립이 우연이 아니라 정의다. 대신 프로의 안전 버튼은 "아무 일 없음"이라 보상 욕심이 없는 사람만 누른다 |
| (b) | 유스·프로 모두 **작은 확정 보상**(오프사이드식) | 누르는 맛은 있지만 프로 커리어가 **평균적으로 부푼다**(원칙 ④). 보상 크기를 실측으로 깎아도 "늘 안전"이 현행과 같다는 보장이 사라진다 |
| (c) | 유스·프로 모두 효과 0 | 가장 단순하지만 유스의 옛 이벤트(평균 +)가 사라져 **유스 통과율이 떨어진다** — 되메우려면 다른 손잡이를 만져야 한다(원칙 ⑪) |

→ **추천 (a).** 도전은 "기본 효과 + 판돈(성공 +W / 실패 −L)"으로 통일해, 판돈의 기댓값이 표시 %에서 정확히 0이 되는 점(p\*)을 문서에 적을 수 있게 한다.

**3. 약속형 이벤트(판정이 다음 경기 기록에서 나오는 것)**
| | 선택지 | 트레이드오프 |
|---|---|---|
| (a) | **넣는다 — 소수(18종 중 6종)**, 화면엔 %가 아니라 "최근 10경기 중 N번"이라는 **사실**을 적는다 | 우리만 가능한 것(판정에 승부처 미니게임의 손이 들어간다). 대신 "화면 % = 판정 %" 규칙의 예외라 **% 기호를 절대 안 쓴다**는 규칙이 하나 더 생긴다 |
| (b) | 확률형만 | 규칙이 하나라 가장 깨끗하다. 오프사이드와 같은 판이 된다 |
| (c) | 약속형 위주 | 경기와 이벤트가 강하게 엮이지만, 벤치가 잦은 시기엔 이벤트가 계속 미뤄진다 |

→ **추천 (a).** "이벤트의 주사위 절반은 네 발"이 오프사이드와 갈리는 지점이다.

**4. 프로 이벤트가 뜨는 자리와 빈도**

## 네 문서가 공통으로 지키는 규칙 [2차 수정]

1. **중립은 우연이 아니라 정의로** — "늘 안전"이 현행과 같은 것은 **구성으로** 보장한다(유스 = 옛 효과, 프로 = 0). 실측은 그것을 **확인**할 뿐이다
2. **보이는 % = 판정 %** — 정수 %를 한 번 계산해 얼리고, 화면과 판정이 **같은 필드**를 읽는다. 반올림·보정·연속 실패 보호 같은 숨은 손은 0
3. **재료는 이미 있는 상태값** — 새로 만드는 상태는 🤝 `S.trustEv` 하나(+판단 5의 `S.inj`와 그 거울 `S.xiLock`). 모두 **손잡이(선택)가 있고 화면에 보인다**(원칙 ③).
   **[2차 수정]** 그 밖의 새 칸은 게임 상태가 아니라 셈의 도구다 — `S.condUsual`(평소 컨디션 — 확률 조각의 가운데) · `S.buffX`(옛 칸 `S.buff`를 건드리지 않고 ×2.0을 싣는 칸) · `S.betaAt`(운영판이 끼었는지 알아보는 도장)
4. **이벤트는 문턱을 안 만진다** — 월드컵 소집 문턱·이적 제안 문턱(`PROMOTE_HYPE`)·수상 판정·클래스 문턱은 이벤트 효과 대상이 아니다. 월드컵 D1의 *"78인데 왜 안 뽑혀"* 약속을 지킨다
5. **다른 축의 손잡이로 고치지 않는다(원칙 ⑪)** — `curve-test`의 🚧 미달 곡선을 이벤트로 메우지 않는다
6. **마이그레이션 없음 · `id` 불변 · `hof` UPDATE 없음** — 새 필드는 읽는 쪽 기본값, 명전 항목은 한 번의 INSERT
7. **공유 파일은 짧게** — 새 기능은 전용 파일. 공유 파일 수정은 `cloud.js` 한 줄(①), `stats/index.html` 관리 절(③)뿐
8. **남이 올린 값은 세 겹** — 서버 CHECK · 받는 길 `Match.scrub` · 그리는 자리 `esc`
9. **상태는 한 객체 안에, 해제 코드 없이** — `S.ev`·`S.u23`·`S.trustEv`는 시즌 번호나 null로 **저절로** 무효가 된다(월드컵 `S.wc.ready` 선례)
10. **갈래마다 따로 심지 않는다** — 이벤트는 `renderPrep` 한 곳에서 굴리고, 이야기의 라운드 집계는 `recordRound` 한 곳(뛴 주·벤치 주가 둘 다 지난다)에서 센다(v2.48.0 교훈)
11. **[2차 수정] 기존 필드의 뜻·타입·범위·null의 뜻을 바꾸지 않는다 — 새 뜻은 새 필드로.** 베타(`beta/soccer/`)와 운영판(`soccer/`)은 같은 세이브 칸
    (`SAVE_KEY = "winger-save-v1"`, `game.js:409` · 슬롯 `-slots` · 유산 `-legacy` · 공유 명전 `grow-hof-v1`)을 한 도메인의 localStorage에서 함께 쓴다 —
    베타에서 이어 한 커리어를 운영판에서 열 수 있고 그 반대도 된다. **운영판(현행 코드)이 베타 세이브를 열어도** 모르는 칸을 무시할 뿐 아는 칸을 틀리게 읽지 않아야 하고
    (예: `S.buff`를 숫자로 바꾸면 운영판 `S.buff ? 1.5 : 1.0`이 베타의 `1.0`을 참으로 읽어 공짜 1.5배), **베타가 운영판이 만진 세이브를 열면** `S.betaAt !== S.savedAt`으로 알아보고
    다음 경기에 걸린 진행 중 상태를 없던 일로 정리한다(11번 저장 데이터). ②·③도 같은 규칙을 따른다(23번 §2 ⑤ 「②·③ 단계에 넘길 것」 — 군 팀 복무 중의 `S.group` 등)
