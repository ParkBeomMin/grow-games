## 4. 🔥 부탁 2 — `_load.js`의 픽스처 아티팩트

engineer 진단이 정확했습니다. **코드는 멀쩡했고 검사가 틀렸습니다.**

고정 `SPREAD = [-11, 7, -3, 13, …]`가 `fw fw wg wg mf…` 순서로 붙어서 mateBase 70이면
**언제나** 이렇게 나옵니다:

```
fw 59 · 77    wg 67 · **83**    mf 62 · 72 · 80 · 56    df 75 · 64 · 79
```

`ACE_POOL.goal`이 `["fw","wg"]`가 된 뒤 `aceOf`는 능력치 최대 한 명을 고르니
**골 에이스가 100% 윙어**입니다. 실제 게임은 **50.1%**예요 — 픽스처가 그 최악만 봤습니다.
(`goal: ["fw"]`일 땐 에이스 위치가 spread와 무관해서 없던 함정입니다.)

### 고친 방법 — `spin`

```js
xiOf(pos, ability, mateBase, spin)
```

- **`spin`을 안 주면 예전 그대로**입니다(고정 SPREAD) — 기존 검사의 기준선이 안 흔들려요
- `spin`이 숫자면 그 시드로 SPREAD를 **섞습니다**(mulberry32 + Fisher-Yates).
  경기마다 다른 spin을 주면 명단 폭의 **앙상블**이 됩니다

**검증**: 앙상블 400벌에서 골 에이스가 **fw 204 / wg 196 → wg 49.0%**.
실제 게임 50.1%와 같은 자리입니다(고정 한 벌은 100%).

`award-test.js`의 B 절 전부를 앙상블로 바꿨습니다. 결과:

```
❌ 전  B-2. 득점자[fw 33.9% wg 40.1% …] → 뒤집힘
✅ 후  B-2. ① create 득점자[fw 38.9% wg 34.0% mf 21.8% df 5.3%]
           ② auto   득점자[fw 39.6% wg 33.5% mf 21.4% df 5.4%]
```

**B-1 · B-1b · B-3의 변이 셋도 전부 그대로 잡힙니다** (도움비 Δ −27%p · 득점자 Δ 17~19%p).

> ⚠️ **fw 38.9% vs wg 34.0% — 여유가 4.9%p뿐입니다.** engineer가 실제 명단으로 잰
> 42.6% vs 30.8%보다 붙어 있어요(제 앙상블은 같은 11개 값을 섞기만 해서 폭이 좁습니다).
> G-9에서 `NPC_SPOT`이나 `GOAL_W`가 또 움직이면 **여기가 먼저 빨간불**이 될 수 있습니다.
> 그때는 *"검사가 잡음을 잡았나 / 순서가 진짜 뒤집혔나"*를 engineer 표(실제 폭 ±14 무작위)와
> 대조해 주세요.
