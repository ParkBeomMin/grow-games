## 3. 🎚️ `youth-card-test.js` — 중심의 중립성 (§7 검사 5)

### 🔒 값을 베껴 적지 않았습니다

`YOUTH_CARD_P`를 **읽지도, 베끼지도 않습니다.** 그 값이 **무엇을 위한 자리인지**를 씁니다:

```
🎯 s = 0.5(중립 조작 · 🤖 자동 진행이 쓰는 값)에서
   perfect 빈도 = miss 빈도    ⇔    등급 ±1칸 기댓값 0
```

⚽🅰️는 `miss = (1−p)/2`라 p = ⅓에서, 🧱은 이분이라 p = 0.5에서 그렇게 됩니다 —
**두 조건이 하나의 문장으로 모이고**, 계수를 어디로 옮겨도 이 문장은 살아남아요.

진짜 `playYouthMoment`를 **🤖 자동 진행 갈래**(`cb(judge(0.5), T)`)로 부릅니다.
산식 사본을 안 지었어요.

### 실측 (칸마다 60,000회 · 시드 3 × 카드 3종 × 능력치 4단 = 36칸)

```
최대 |Δ| = 0.0091  (문턱 0.025)
⚽ 결정·능력치40 : p0.3311 o0.3358 m0.3330  Δ−0.0019
⚽ 결정·능력치206: p0.3345 o0.3328 m0.3327  Δ+0.0018
🧱 수비·능력치40 : p0.4975 o0.0000 m0.5025  Δ−0.0049
🧱 수비·능력치206: p0.5035 o0.0000 m0.4965  Δ+0.0071
```

### 📏 문턱과 기준선 사이의 여유를 **눈에 보이게** 뒀습니다

| | 값 |
|---|---|
| 잡음 1σ | **0.0041** (🧱 기준 · N=60,000) |
| 문턱 | **0.025** = **6.1σ** |
| 실측 최대 | 0.0091 = 2.2σ |
| 변이(M-P1/P2) | 0.179 / 0.307 = 문턱의 **7~12배** |

`A-2`가 **문턱이 1σ의 4배 이상인지를 스스로 검사**합니다. `fatigue` 때처럼 여유가
0.4%까지 좁아지는 일이 여기서는 검사 자체에 걸려요.

### 🧪 측정 조건을 검사가 스스로 찍습니다

```
A-3. 능력치 축을 실제로 훑었다 (40 → 46 → 103 → 206 · 5.2배)
```

🔴 **처음에는 여기가 빨간불이었고, 그게 맞았습니다.** `S.stats`를 30/55/80/110으로
채웠더니 엔진이 본 능력치가 **40 → 40 → 41 → 57**이었어요 — `nowStats`가 🎂 17세 곡선
(≈0.5)을 곱하고 `blendOf`가 40에서 자릅니다. **능력치 축을 거의 안 타고 있었는데
값만으로는 정상으로 보였습니다.** 그래서 `S.stats`를 30/90/200/400으로 밀어
`half(a)`가 움직이는 40~120 구간을 덮게 했습니다.

> 🏠 참고: **유스에서 엔진이 실제로 보는 능력치는 40 언저리~60**이에요. 위쪽은
> `half(a)` 구간을 덮으려고 일부러 민 것이고, 파일에 그렇게 적어 뒀습니다.

### 🌍 이 검사가 성립하는 세계 (파일 머리말에 적었습니다)

> · 유스 평가전은 `stageScore`가 **이미 능력치로 등급을 정하고**, 카드는 ±1칸만 움직인다
> · 그래서 카드의 중심 `autoP`는 **상수**다 — 프로의 `pFinish`/`pConcede`를 쓰면 **이중 계상**
> · 능력치는 사라진 게 아니라 **`half(a)`(폭)에 남는다**
>
> 🔴 **"유스도 프로와 같은 중심을 써야 한다"고 우기지 않습니다.** 되살아나면 M-P3이 잡습니다.

## 4. 🔌 `wiring-test` — 배선 세 갈래를 **서로 다른 자로**

### 무엇이 문제였나

director 진단이 정확했습니다. **배선이 아니라 검사의 모형**이었어요.
옛 정규식은 `<script src="…"></script>` 하나만 봤는데, 지금 `index.html`에는 세 갈래가 있습니다.

| | 갈래 | 예 | 왜 그 모양인가 |
|---|---|---|---|
| ⓐ | 고전 스크립트 | `<script src="game.js">` | — |
| ⓑ | **모듈 스크립트** | `<script type="module" src="char3d.js">` | 그래야 **jsdom이 실행 안 해서** 나머지 12종이 안 죽어요 |
| ⓒ | **동적 import** | `char3d.js` 안의 `import("./vendor/three.module.min.js")` | 691KB — 🧬 조립대에 **처음 들어올 때만** |

### 어떻게 고쳤나 — **넓히지 않고 나눴습니다**

```
A-②-0  세 갈래를 다 읽었다   — 고전 21 · 모듈 1 · 동적 import 1
        (셋 중 하나가 0이면 그 갈래를 아예 안 재는 겁니다 → 그 자체가 빨간불)
A-②    앞으로: 페이지가 받는 것 → ASSETS에 다 있나   (오프라인에서만 깨짐)
A-③    뒤로:   ASSETS의 스크립트 → 페이지가 다 받나  (그 기능만 조용히 사라짐)
A-④    디스크: 폴더의 .js 중 어디에도 없는 고아
```

`import()`는 **모듈 파일 안에서만** 찾고, 거기서 나온 모듈을 한 겹 더 따라갑니다.
그래서 `focus.js`를 `<script>`로 싣고 ASSETS에 안 넣는 **진짜 미등록**(M5)은 그대로 잡혀요 —
**정규식을 넓히기만 했으면 놓쳤을 자리**입니다.

### 🚧 `focus.js` — 알려진 미달로 **상한을 박았습니다**

```
✅ A-④.  폴더의 .js 15개 중 새 고아가 없다 (알려진 것: focus.js)
🚧 A-④.  focus.js 는 아직 index.html·sw.js 어디에도 없습니다 — 알려진 미달이에요
🚧        등록하면 이 줄이 ❌로 바뀌어 "KNOWN_ORPHANS에서 빼세요"라고 말합니다 (승격 알림)
✅ A-④b. KNOWN_ORPHANS가 현실과 맞는다 (1개)
```

- **A-②/A-③과 묶지 않았습니다.** 묶으면 고친 뒤에도 빨간불이라 사람이
  *"저건 원래 빨간불이야"*로 배웁니다.
- **양방향입니다.** `focus.js`가 등록되는 순간 A-④b가 ❌로 바뀌어
  *"이제 목록에서 빼세요"*라고 말해요 — `tests/soccer/curve-test.js`와 같은 모양입니다.
- **새 고아가 생기면 그건 ❌**입니다. 회귀는 잡히고 현상은 기록됩니다.

### ⚠️ 3D 자체는 안 잽니다

**jsdom엔 WebGL이 없습니다.** 검사가 보는 것은 **배선뿐**이에요 —
스크립트 태그가 있나 · ASSETS에 있나 · `import()` 대상이 캐시되나.
`bootPage`는 `type="module"`을 **일부러 안 실행합니다**(그래야 나머지가 안 죽어요).
**3D가 실제로 그려지는지는 이 검사가 손대지 않습니다** — §6 「검증 불가」로 넘깁니다.
