## 3. 타임라인 규칙 — `n`에서 전부 나옵니다

### 3-1. 산식 (engineer가 그대로 옮길 형태)

```js
/* ⏱️ 90분 대본 — 🔒 **새 굴림 0.** n장의 순간 카드에서 결정적으로 나옵니다.
 *   순간 카드   M[i] = minAt(i, n)                                  ← 이미 있는 함수. 안 고칩니다
 *   구간 필러   F[j] = round((M[j] + (M[j+1] ?? 90)) / 2)   j = 0 … n-1
 *   🔑 F[j]는 「카드 j 다음 구간의 한가운데」예요 — 마지막(j = n-1)은 90'까지의 꼬리입니다.
 *   🔒 첫 구간 [0, M[0]) 에는 필러를 **안 놓습니다** (§3-3 — 계약 D). */
const HALF_MIN = 45;                                   // 🥅 전반 종료. 🔒 축구의 값이지 손잡이가 아니에요
const fillerMins = (n) => {
  const M = Array.from({ length: n }, (_, i) => minAt(i, n));
  return M.map((m, j) => Math.round((m + (M[j + 1] != null ? M[j + 1] : 90)) / 2));
};
```

| n | 🔥 순간 카드 `M` | ⏱️ 필러 슬롯 `F` |
|---|---|---|
| **2** (🏫 초5) | `[30, 60]` | `[45, 75]` |
| **3** (🏫 중등 · 고등) | `[23, 45, 68]` | `[34, 57, 79]` |

*(`Math.round(56.5) = 57` — JS는 반올림이 위쪽입니다. 「57」이 맞는 값이에요.)*

### 3-2. 🥅 하프타임 놓는 자리 — 한 줄 규칙

> **하프타임은 45'에 한 장. `분 ≤ 45`인 모든 줄 「뒤」, `분 > 45`인 첫 줄 「앞」에 놓습니다.**
> **그리고 필러 슬롯이 정확히 45'면 그 필러를 안 놓습니다 — 하프타임이 그 자리를 씁니다.**

🔑 이 한 줄이 두 경우를 다 냅니다:

| n | 45'에 무엇이 | 결과 |
|---|---|---|
| **2** | 필러 슬롯 `F[0] = 45` | 🔒 **하프타임이 그 필러를 대신합니다** (필러 1장이 줄어요) |
| **3** | 순간 카드 `M[1] = 45` | 🔒 **그 카드 「뒤」**에 놓입니다 (전반 종료 직전의 장면 → 휘슬) |

🔒 **`engine.js`의 `next()`와 같은 규칙입니다**(`engine.js:709` — `mins[k] > 45`).
🏟️ 프로 경기와 학교가 **다른 규칙으로 전반을 끝내면** 다음 사람이 둘 중 하나를 버립니다.

🔴 **`45`를 손잡이로 만지지 마세요.** 이건 **축구의 값**이지 밸런스 계수가 아닙니다.
전반이 짧아 보이면 만질 곳은 `minAt`이지 여기가 아니에요.

### 3-3. 🔒 첫 구간에 필러를 안 놓는 이유 — 계약 D

계약 D는 **첫 순간 카드까지 ≤ 90초**이고, 재추정이 **~88초 · 여유 ~2초**입니다
(141번 §4-3 · 142번 §6 ⓖ가 designer 판정 대기로 올려 둔 그 자리).

143번 §3-4가 **「지금 가장 가까운 위험」**으로 찍어 둔 항목이 정확히 이것입니다:

> *🟡 🏁 킥오프의 대기·애니메이션·타이핑을 늘리기 — **깨질 수 있습니다.** 화면이 안 늘어도 초가 늘어요*

필러 한 장은 `delayOf()`(0~1점 차에서 **900ms** · `match-scene.js:170`)를 먹습니다.
초5의 첫 카드 앞에 한 장만 놓아도 **88 → 88.9초**, 여유가 1.1초로 얇아져요.

👉 🔒 **첫 구간의 유료 줄은 0장.** 그리고 이건 **초5만의 예외가 아니라 모든 단계 공통 규칙**입니다
(⑤ — 단계마다 대본이 갈리면 *"초5만 짧은 경기"*로 읽힙니다).

📌 **판단이 바뀔 조건**: I-10(실기기에서 A·B·D 한 번)이 D를 **여유 10초 이상**으로 재면,
첫 구간에 한 장을 더합니다. 🔴 **추정치로는 안 늘립니다** — 143번 §3-3이 못 박은 자리예요.

### 3-4. 🏁 0' 킥오프 줄이 **무료인** 자리

🔒 **`kickoff()`가 힌트 줄을 쓰는 그 자리에서(`town.js:811`) 큐에 넣습니다 —
[🏁 경기 시작]을 누르기 「전」입니다.**

| | |
|---|---|
| 왜 무료인가 | 900ms가 **사람이 힌트를 읽고 버튼을 누르는 5~8초**(141번 §4-3의 확인 탭) 안에 묻힙니다 |
| 최악의 경우 | 사람이 900ms 안에 누르면 **+0.9초** — 그래도 88.9초 < 90 |
| 실제 | **~0초** |
| 🔴 왜 「킥오프 휘슬」이라고 안 쓰나 | 버튼이 이미 **「🏁 경기 시작」**입니다. 누른 뒤에 *"경기가 시작됩니다"*를 또 쓰면 **같은 말을 두 번** — `match-scene.js:536`가 그 사고를 이미 기록해 뒀어요 |
| 그래서 무슨 말을 하나 | **대진**입니다 (§4-2) — *"{상대}와 마주 섰어요"*. 아직 안 시작했다는 게 문장에 들어 있어요 |

🔴 **버튼이 없으면(마크업이 낡았으면) 이 줄도 안 놓습니다** — `kickoff()`의 `if (!btn)` 폴백
갈래는 바로 `playCard()`로 갑니다. 그 갈래에 킥오프 줄을 넣으면 **거기서만 D가 +0.9초**예요.

## 5. `flow` 배정 — 왜 그 순서인가

### 5-1. 산식

```js
/* 🔁 흐름 — 🔒 **연출 축입니다. 트레이드오프 손잡이도, 중립화 상수도 아니에요**(원칙 ⑨).
 *    값이 `d`·`spotMul`·`state`에 한 톨도 안 갑니다.
 *
 * 🔑 **기본은 교대입니다** — 슬롯 번호 j와 단계 번호 sIdx의 합으로 갈라요.
 *    ⚠️ **한쪽으로만 쏠리면 경기가 아니라 슬라이드쇼입니다.** 그리고 `sIdx`를 섞는 것은
 *       중등과 고등이 **같은 n(3)**이라 안 섞으면 34'·57'의 흐름이 두 경기 내내 같아서예요.
 *
 * 🔑 **꼬리(j === n-1)만 스코어를 봅니다.** 90분 직전은 흐름이 스코어와 어긋나면
 *    가장 크게 읽히는 자리예요 — 3점을 앞서는데 *"완전히 밀어붙입니다"*는 거짓말입니다.
 *    🔒 **읽기만 합니다. 새 굴림 0** — `hg`/`ag`는 이미 `GOAL_BY`가 만든 값이에요. */
const flowOf = (j, n, sIdx, hg, ag) =>
  j < n - 1 ? ((j + sIdx) % 2 === 0 ? "a" : "h")
    : hg < ag ? "a" : hg > ag ? "h" : "mid";
```

### 5-2. 나오는 순서

| 단계 | `sIdx` | j=0 | j=1 | 꼬리 |
|---|---|---|---|---|
| 🏫 초5 (n=2) | 0 | *(45' — 하프타임이 대신)* | — | 🎯 스코어 |
| 🏫 중등 (n=3) | 1 | `h` (34') | `a` (57') | 🎯 스코어 (79') |
| 🏫 고등 (n=3) | 2 | `a` (34') | `h` (57') | 🎯 스코어 (79') |

🔑 **한 경기 안에서 `a`와 `h`가 반드시 한 번씩** 나오고, **중등과 고등이 서로 뒤집혀** 있습니다.
🔑 그리고 **꼬리만 사람이 만든 결과를 탑니다** — 지고 있으면 우리가 몰아붙이고,
이기고 있으면 상대가 달려듭니다. 🟢 그게 *"내가 한 일이 경기에 남았다"*는 유일한 흐름 줄이에요.

### 5-3. 🟢 **`flow`의 배선은 이미 있습니다** — 남은 것은 **공의 `x` 하나**

⚠️ **이 절은 2026-09-05에 다시 썼습니다.** 처음 쓸 때는 *"`setPitch`가 `flow`를 안 봅니다"*였는데,

🔒 초5의 첫 순간 카드 **앞**에 놓이는 유료 줄이 **0장**입니다(§3-3).

### 11-1. 🔴 `school-scene-test` B-1이 빨간불이 됩니다 (**반드시 같이 고칩니다**)

const OWN = {

### 11-2. 🟡 B-1의 **판별력이 얇아집니다**
