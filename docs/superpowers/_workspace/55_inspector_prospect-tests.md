## 2. 🔴 찾은 결함 ① — **옛 세이브가 한 시즌에 두 살을 먹습니다**

```
❌ D-2. 🎂 age 칸이 없는 옛 세이브도 한 시즌에 한 살만 먹는다 (21 → 23)
     🔴 **한 시즌에 2살을 먹습니다.**
        재현: {year:3, proYear:1} → ageOf 21 → proYear+1 후 birthday → **23**
```

### 왜 그런가

```js
// career.js startPrep()
S.proYear += 1;
WingerProspect.birthday(S);      // S.age = ageOf(S) + 1

// prospect.js ageOf() — age 칸이 없으면 되짚습니다
return START_AGE + (year - 1) + proYear;   // ← 방금 올린 proYear를 **다시** 셉니다
```

`proYear`를 올린 **뒤에** `birthday`를 부르는데, `ageOf`의 되짚기가 그 `proYear`를 또 셉니다.
**+1이어야 할 자리가 +2**가 돼요.

| 세이브 | 첫 전환 | 그 뒤 |
|---|---|---|
| `age` 있음 (새 게임) | 21 → 22 ✅ | +1 ✅ |
| **`age` 없음 (옛 세이브)** | **21 → 23** ❌ | +1 (그때 `S.age`가 생겨서) |

**한 번뿐이지만 영구적입니다** — 그 커리어는 끝까지 한 살 많은 채로 갑니다.
노쇠가 한 해 일찍 오고 은퇴도 한 해 일찍 와요.

### 🔁 **같은 형태가 유스 해넘이에도 있습니다**

```js
// game.js — 해넘이
S.year += 1;
WingerProspect.birthday(S);      // 같은 모양
```

실측: `{year:1, proYear:0}` → 18세 → 해넘이 한 번 → **20세**.

### 고치는 방향 (engineer 판단)

- `birthday`를 **먼저** 부르고 `proYear`/`year`를 올리거나
- `birthday`가 되짚기를 안 타게 (`S.age = (S0.age != null ? S0.age : ageOf(S0)) + 1`)

> 🎯 **이 자리가 검사 사각지대였던 이유**: `ageOf`만 보면 되짚기가 맞고(F-1~4 전부 초록),
> `birthday`만 보면 +1이 맞아요. **둘을 이어 붙였을 때만** 틀립니다 —
> 경계면 결함의 전형이라 한쪽만 보는 검사로는 영영 안 잡혔을 겁니다.
