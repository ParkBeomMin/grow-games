### 2-2. `s` — 넷과 같은 자

```js
const sOne = (err, mul) => sBar(err, ONE.win * mul);
const cellS = (c, a) => sOne(Math.abs(c.x - a.best), a.tight * c.mul);
```

* `c.x` = 누른 칸의 중심 · `a.best` = 그 순간의 **빈 곳 한가운데** (연속으로 움직여요)
* `a.tight` = 각이 좁아진 정도 (기다리면 창만 좁아집니다)
* `c.mul` = 🦶 주발 × 🫀 컨디션 × ♿ 확대

🔴 **옛 `sOne(margin, mul)`은 형태째 죽었습니다** — *"여유가 클수록 좋다 · 키퍼 몸 안이면 0"*.
넷 중 혼자 **오차의 방향이 반대**였고, 그게 112번 §1-3이 짚은 자리예요.
이름은 남았지만 **받는 것이 「여유」에서 「오차」로 바뀌었습니다.** 🏃 `sCut`과 같은 모양이에요.

🔴 같이 죽은 것: `ONE.need` · 골대 기둥까지 오차에 넣던 `margin`의 3항 `Math.min`
(규칙이 둘이었어요 — 격자의 바깥 칸이 곧 골문 구석이라 기둥은 **그림만** 남습니다).
✅ 산 것: **골문이라는 공간** · 키퍼가 각을 좁힌다는 장면 · `ONE.grow`(다 나오기까지의 시간).

## 3. 🚨 설계가 성립 안 하던 자리 — **격자에는 「오차의 바닥」이 필요합니다**

설계 §11-4/§11-5는 이렇게 적었어요:

> 🥅 1대1 · 방해 = **🧤 키퍼가 나옴** · 좋은 지점 = **키퍼에서 가장 먼 골문 지점**
> `s = sBar(|누른 칸의 중심 − 그 순간의 좋은 지점|, 판정 창)`

**그대로 만들어서 재 봤더니 이렇게 나왔습니다** (같은 조작자·같은 판, 판 200개):

| | 옛 🥅 | 새 🥅 (첫 판) |
|---|---|---|
| 서툰 | 0.398 | **0.291** |
| 보통 | 0.563 | 0.586 |
| 능숙 | 0.702 | **0.903** |

🔴 **능숙이 0.90입니다.** 원인은 하나예요 —

> 「좋은 지점」이 시간에 따라 **한 칸 폭(20%)을 훑으면**, 언젠가 **칸 한가운데에 딱 맞는 순간**이
> 옵니다. 그때 오차가 **정확히 0**이고 `sBar(0, 창) = 1`이에요. 🔑 **창을 아무리 좁혀도
> 오차가 0이면 `s = 1`입니다.** 잘하는 사람은 그 순간까지 기다리기만 하면 돼요.
> 키퍼가 얼마나 빨리 나오게 해도 이 성질은 안 없어집니다 — 실측으로 확인했어요
> (지우는 속도를 15%/s → 66%/s까지 올려도 능숙은 0.68~0.80이었고, 그 대가로 서툰이 0.20까지 내려갔습니다).

🔑 **옛 판에는 천장이 있었습니다.** *완벽하게 조준해도* 남는 여유가 최대 17.25%인데
`ONE.need`가 26이라 `s`가 0.66에서 멈췄어요. **그 천장이 격자에는 없습니다.**

### ★ 그래서 「오차의 바닥」을 구조로 만들었습니다

**「좋은 지점」이 거의 안 움직이게 하고, 대신 「창」만 좁아지게** 했어요.

```js
cov   = cov0 + (cov1-cov0)·p      // 키퍼가 덮는 반폭 10 → 17  (좋은 지점은 그 절반인 3.5%만 밀립니다)
best  = 넓은 쪽 빈 곳의 한가운데
tight = 1 − close·p               // 창은 62% 좁아집니다
```

| | |
|---|---|
| ✅ `best`가 **한 칸 폭의 5분의 1**만 움직이니 **칸 중심에 앉는 일이 거의 없습니다** |
| ✅ `|칸 중심 − best|`가 판마다 0~10% 사이에 **깔립니다** — 그게 옛 판의 천장을 대신해요 |
| ✅ **기다리면 창만 좁아집니다** — «빨리 차라»가 그대로 살아요 |
| ✅ 화면이 그대로 말합니다 — 키퍼 몸이 벌어지고, **밝은 칸이 좁아집니다** |

> 🚨 **`close`와 `cov1`을 맞바꾸지 마세요.** 둘의 몫 나누기가 이 판이 서는 이유예요 —
> `cov1`을 키워 「좋은 지점」이 한 칸을 훑게 만드는 순간 **능숙이 0.90으로 돌아갑니다.**
> 소스 주석에 그 근거를 적어 뒀어요.
> 🔴 **난이도 손잡이는 `ONE.win` 하나입니다.** `cells`는 「읽힘」의 손잡이예요(설계 §11-5).

## 4. 📏 `E[s]` — **짝지은 차이** (옛 🥅 ↔ 새 🥅, 같은 모델·같은 판)

### 4-1. 어떻게 쟀나

🔒 **게임은 진짜 코드를 그대로 굴립니다.** jsdom 위에 `winger-moment.js`를 싣고,
`requestAnimationFrame`·`performance.now`·`setTimeout`을 **가상 시계**로 갈아 판을
밀리초 단위로 밀면서 **실제 탭 이벤트**를 보냅니다. 산식을 베껴 적지 않았어요.
(하네스: `scratchpad/eng-mini/es-harness.js` — 🔴 **커밋 안 했습니다**)

🎲 **난수원 셋을 서로 다른 시드로 갈랐습니다** (lockstep 방지):

```
엔진    W.WingerEngine._t.seed(n)
무대    W.Math.random = mulberry32(n ^ 0x85EBCA6B)
조작자  mulberry32(n ^ 0x9E3779B9)
```

**조작자 모델 — 옛·새가 같은 파라미터를 씁니다.**
반응 지연 `L` 안에서 못 움직이고, `[L, L+H]`를 내다봐 「그 순간의 최선」이 가장 큰 때 `t*`와
그 자리 `x*`를 고른 뒤, `t* + N(0,σt)`에 `x* + N(0,σx)`를 누릅니다.
옛 판은 그 좌표를 그대로, 새 판은 **그 좌표가 든 칸**을 눌러요.

| | L | H | σx (골문 폭 %) | σt |
|---|---|---|---|---|
| 서툰 | 380 | 420 | 14 | 230 |
| 보통 | 300 | 950 | 8 | 130 |
| 능숙 | 240 | 2200 | 4 | 70 |

🫀 컨디션 60~94 · 🦶 왼발 4분의 1도 판마다 흔들었습니다.

> 🔑 *"좋은 지점이 안 움직이면 어느 칸을 누를지가 고정되고, **격자가 버튼 하나가 됩니다**"* —

## 11. ★ 고친 것 — **바닥을 바닥으로**

```js
const CELL_FLOOR = 0.30;                                   // 🏔️ s의 천장
const cellFloorErr = (err, cellW) => Math.max(err, cellW * CELL_FLOOR);
const oneErr = (cx, best) => cellFloorErr(Math.abs(cx - best), 100 / ONE.cells);
```

> **물리적으로 정직합니다** — *"칸을 눌렀다"*는 ***"이 칸 어딘가"***이지 *"정확히 중심"*이 아니에요.
> 🔑 **바닥이 속도와 무관해서 몫을 자유롭게 나눌 수 있습니다.**

**그래서 몫을 되돌렸습니다:**

| | 몫으로 풀던 때 | ★ 지금 |
|---|---|---|
| `cov0 → cov1` | 10 → 17 (좋은 지점이 **3.5%**만 밀림) | **10 → 34** (좋은 지점이 **12%** — 한 칸 폭의 0.6배를 훑어요) |
| `close` | 0.62 (창으로 천장까지 만들려 함) | **`ONE_CLOSE` 0.45** — **지분만** 정합니다 |
| 천장 | 🔴 몫이 만듦 (= 격자가 버튼 하나) | ✅ **`CELL_FLOOR`가 만듦** |

✅ **어느 칸을 누를지가 판 안에서 바뀝니다** — 좋은 지점이 칸 경계를 넘어가요. 격자가 삽니다.

### 🔒 손잡이 셋을 **세 자리로** 갈랐습니다 (`BLK_WIN` ↔ `BLK_READ`와 같은 구조)

| 이름 | 무엇 | 어디 |
|---|---|---|
| **`ONE_WIN`** = 23 | **`속도 ÷ 창`의 창 쪽 — 난이도**(중립화 비) | `const ONE_WIN` 단독 |
| **`ONE_CLOSE`** = 0.45 | **몫 나누기 — 공간 ↔ 시간 지분** | `const ONE_CLOSE` 단독 |
| **`CELL_FLOOR`** = 0.30 | **`s`의 천장** · 🔒 **넷이 공유** | 판정 창 절 (`FOOT_WIN` 옆) |

🔴 **셋을 같은 표에 두지 않았습니다.** `K`로 내보낼 때도 따로예요 —
`K: { CUT, ONE, ONE_WIN, ONE_CLOSE, CELL_FLOOR, KP, … }`.
주석에 *"난이도를 `ONE_CLOSE`나 `CELL_FLOOR`로 맞추지 마세요"*를 못 박아 뒀습니다.

## 15. 🚧 JS ↔ CSS 경계면 — **director에게 넘기는 클래스 계약**

inspector 지적이 맞습니다. `classList.toggle`로 켜는데 **`style.css`에 규칙이 하나도 없어요.**
`style.css`는 director 영역이라 저는 **이름과 「무엇을 알려야 하는지」만** 적습니다.

> 🔴 **`soon`/`rise`는 ♿ 자리입니다.** 제가 소스 주석에 *"색으로만 알리면 색약에서 안 읽혀요"*라고
> 적고 **클래스만 켜 뒀습니다** — 지금 화면은 **밝기(색)로만** 알리고 있어요.
> 🔑 **주석이 지키라고 한 것을 코드가 안 지키는 상태**입니다. 제 잘못이에요.

### 15-1. 🔮 미래 흘리기 넷 — **한 자리입니다. 한 번에 정해 주세요**
