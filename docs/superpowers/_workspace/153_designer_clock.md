### 1-2. 🔴 149번이 자동 진행을 잠근 근거가 틀렸습니다

> 149번 §9: *"🤖 `setInterval` 자동 진행 — 🔴 학교는 **카드마다 미니게임**이라 타이머가
> 사람의 조작과 부딪힙니다. 윙어1은 경기당 승부처가 **한 번**이라 성립하는 구조예요.
> 🔴 **열지 않습니다** — 미니게임을 경기당 한 번으로 줄이면 그건 이 게임이 아닙니다"*

🔑 **「타이머가 조작과 부딪힌다」는 `setInterval`의 성질이지 시계의 성질이 아닙니다.**

`setInterval`은 **자기 시간축을 따로** 갖습니다. 그래서 미니게임이 떠 있는 동안에도 계속 째깍여
`clearInterval`로 껐다 켜야 하고, 그 껐다 켜는 자리가 조작과 부딪힙니다.

**`await` 루프는 시간축이 하나뿐입니다.** 카드에 닿으면 루프가 그 자리에서 멈춰 서고,
판정이 끝나 프라미스가 풀리면 **거기서부터** 이어 갑니다. 끌 것도, 켤 것도 없어요.

👉 149번은 **「자동 진행」을 `setInterval`과 같은 것으로 보고** 통째로 잠갔습니다.
그게 얇았던 두 번째 이유입니다.

## 3. ⏱️ 시계 규칙 — 이번 설계의 본체

### 3-1. 흐르는 속도 — **경기 1분 = 90ms**

```js
/* ⏱️ **경기 1분이 실제로 걸리는 시간** — 🔒 **트레이드오프 손잡이입니다** (원칙 ⑨).
 *    ⬆️ 올리면 경기가 길어지고 시계 숫자가 읽히기 쉬워집니다
 *    ⬇️ 내리면 짧아지고 숫자가 흐려집니다 (60ms = 16.7 tick/s면 눈이 못 따라가요)
 * 🔴 **`FLOW_MS`(620)와 같은 표에 두지 마세요** — 그건 514ms에 **종속된 값**이고
 *    이건 **맞바꾸는 손잡이**입니다. 성격이 달라서 나란히 두면 다음 사람이 구분을 못 합니다. */
const MIN_MS = 90;
```

⚠️ **90ms는 실기기 실측 전까지 「제안」입니다.** 근거 셋:

| # | 견주는 것 | 값 |
|---|---|---|
| **①** | 🧠 **사람이 「세고 있다」로 읽는 카운터의 상한** — 대략 10~12 tick/s. 그 위는 흐려집니다 | 90ms = **11.1 tick/s** — 경계 **안쪽** |
| **②** | 🌊 **줄 하나가 서 있는 동안 시계가 몇 분어치 안 가는가** — `FLOW_MS / MIN_MS` | 620 / 90 = **6.9분**. 「멈췄다」가 느껴질 만큼 길고, 답답할 만큼 길진 않아요 |
| **③** | ⚽ **윙어1이 「보는 시간」으로 쓰는 초** — `evs` 4~8줄 × 780ms | 3.1~6.2초 ↔ 우리 **8.1초**. **같은 자릿수** |

🔴 **총 90분 = 8.1초입니다.** 90 × 90ms.

### 3-2. 🔴 `setInterval`이 아니라 `await` 루프 — 149번 기각의 답

```js
const wait = (ms) => new Promise((r) => setTimeout(r, ms));
const minMs = () => (Scene && Scene.isFast && Scene.isFast() ? 0 : MIN_MS);

let clockMin = 0;
/* ⏱️ 시계를 `target` 분까지 **한 칸씩** 올립니다.
 * 🔒 **틱의 「개수」는 속도와 무관합니다 — 언제나 1분에 한 번.** ⏩·🤖는 **간격만 0**이 돼요.
 *    🔴 `if (fast) { clockMin = target; return; }`로 건너뛰지 마세요 — 그 순간
 *       검사(§6 C-1)가 재는 수열이 무너지고, ⏩에서만 다른 세계가 됩니다.
 * 🎬 **세대 가드는 여기 하나뿐입니다** — 화면이 「안 썼다」(`false`)고 하면 루프를 끊어요.
 *    🔴 town 쪽에 `Scene.gen() !== myGen`을 또 넣지 마세요: 같은 결과를 내는 줄이 둘이면
 *       한쪽을 지워도 증상이 0장이라 변이가 아무것도 안 잡습니다. */
async function tickTo(target) {
  while (clockMin < target) {
    clockMin += 1;
    if (!Scene.clock(clockMin, myGen)) return false;
    const ms = minMs();
    if (ms > 0) await wait(ms);
  }
  return true;
}
```

🔑 **`setInterval`을 안 쓰는 이유 셋** (149번이 기각한 그 자리의 답):

| | `setInterval` | `await` 루프 |
|---|---|---|
| 시간축 | 🔴 **둘** — 타이머 하나 + `draw()`의 프라미스 큐 하나. 순서가 갈립니다 | 🟢 **하나** — 루프가 `draw()`를 `await`합니다 |
| 미니게임 중 | 🔴 계속 째깍임 → `clearInterval`/재시작. **여기가 조작과 부딪히는 자리** | 🟢 `await`에서 **그냥 서 있습니다** |
| 세대 교체 | 🔴 끄는 자리를 따로 둬야 함 (좀비 타이머) | 🟢 `clock()`이 `false` → 루프가 스스로 끝 |

### 3-3. 시계가 멈추는 자리 · 이어지는 자리

| 자리 | 시계 | 얼마나 | 왜 |
|---|---|---|---|
| 🏁 `0'` 킥오프 두 줄 | **0'에 서 있음** | 2 × 620ms | 🔒 [경기 시작]을 누르기 **전**입니다. 시계는 아직 안 돕니다 |
| 🏁 [경기 시작] 누름 | **여기서부터 흐릅니다** | — | 🔑 「누르면 경기가 시작된다」가 이제 **글자 그대로** 참이에요 |
| 🌊 흐름 줄 | **그 분에 멈춤** | `FLOW_MS` 620ms | 읽는 줄입니다 |
| 🥅 하프타임 `45'` | **45'에 멈춤** | `delayOf()` 900ms | 스코어보드가 갱신되는 자리 |
| 🔥 순간 카드 | 🔴 **완전히 멈춤** | open 900 + **사람** + close 900 | 🔒 사람이 조작하는 동안 시계가 돌면 **조작이 시간에 쫓깁니다** — 원칙 ①의 자리예요 |
| 🔥 판정 뒤 | **스스로 이어 갑니다** | — | 🔴 **[다음 판] 버튼이 없어졌기 때문**입니다 (§4-1) |
| 🔚 `90'` 종료 | **90'에서 멈추고 끝** | 620ms | 🔒 `90+`는 안 씁니다 (`setClock`이 지원하지만 학교 대본은 90에서 끝) |

🔴 **🥅 하프타임에 「15분 휴식」을 흉내내지 않습니다.** 45'에서 900ms 멈추고 **46'부터 이어 갑니다.**
빈 시간을 화면에 넣으면 그건 흐름이 아니라 정지예요.

### 3-4. 🔒 첫 구간 상한을 폅니다 — `head.slice(0, 1)` → `head`

const minMs = () => (Scene && Scene.isFast && Scene.isFast() ? 0 : MIN_MS);

let clockMin = 0;
/* 🔒 **틱의 「개수」는 속도와 무관합니다 — 언제나 1분에 한 번.** ⏩·🤖는 **간격만** 0이에요.

async function tickTo(target) {

    if (!Scene.clock(clockMin, myGen)) return false;

    if (ms > 0) await wait(ms);

  return true;
}

 *    `land()`가 판정을 끝내고 이 함수를 **다시** 부르면 그 자리에서 이어 갑니다.
 * 🔴 `draw()`가 프라미스를 돌려줘야 합니다 — 안 그러면 시계가 줄을 **추월**해서
 *    84' 줄이 뜨기 전에 90'이 떠요. */
async function runClock() {
  while (sp < script.length) {
    const s = script[sp];
    if (!(await tickTo(s.min))) return;          // 🎬 세대가 갈렸어요
    sp += 1;
    if (s.t === "card") { playCard(s.i); return; }
