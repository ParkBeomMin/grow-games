## 1. 🎮 검사 44 — 31b는 **코드 + 플레이어**를 잽니다

지적하신 대로입니다. 31b가 재는 실점 비대칭에는 **조작 실력이 실려 있어요** —
내 🧱 수비 카드의 성공이 곧 우리 클럽의 실점을 줄이니까요.

그래서 **둘로 갈랐습니다. 같은 축을 재는 것 같지만 묻는 게 다릅니다.**

| | 명단 | 무엇을 묻나 | skill |
|---|---|---|---|
| **31b** | **me 없음**(`xiAll`) | **순수 산식 대칭** — 조작이 개입할 자리가 없어요 | 안 탑니다 |
| **44** | **me 있음**(df110) | **실제 플레이** — 내 카드가 실점에 직접 걸려요 | 탑니다 |

### 44가 보는 것 — **절대값을 안 박고 관계 셋만**

balancer가 준 밴드 창 `E[s] ∈ [0.44, 0.58]` 안에서만 봅니다.

```
   🎮 내가 df110일 때 실점 비대칭 — skill 0.44 -2.63% · 0.5 -0.64% · 0.58 3.17%
      시드별 0.44 [-2.04 -3.49 -2.44 -2.53] · 0.5 [0.23 -1.45 -0.36 -0.98] · 0.58 [3.16 3.30 3.60 2.63]

✅ 44-1. 🎮 **잘할수록 덜 먹힌다** — -2.63% < -0.64% < 3.17% (단조)
✅ 44-2. 🎮 그 폭이 실제로 있다 — 창 양 끝이 **5.79%p** 벌어진다 (≥3%p)
     👉 이 폭이 0이면 **검사가 조작을 아예 안 보고 있다**는 뜻이에요
✅ 44-3. 🎮 밴드 창 [0.44, 0.58] 전체 · 시드 4개에서 |비대칭| ≤ 8% (최악 3.60%)
✅ 44-4. 🔗 측정 조건이 코드에 명시돼 있다 — 31b는 _t.skill = 0.5 · 44는 0.44/0.58를 직접 설정
✅ 44-변이. _t.skill을 무시하고 늘 0.5로 굴리면 → 빨간불 (폭 5.79%p → **0.00%p**)
```

> 🚨 **창 밖(0.35 · 0.65)에는 문턱을 안 박았습니다.** 거기서 문턱을 박으면
> **코드가 아니라 가상 플레이어를 재게** 됩니다 — 52번 §3에서 데인 그 자리예요.
> 창 밖은 balancer 몫으로 남깁니다.

### 🔗 측정 조건을 **메시지에 찍습니다**

*"나중에 누가 기본값을 바꾸면 검사가 왜 빨간불인지 아무도 모른다"*를 이렇게 막았어요:

```
✅ 31. 여섯 클럽이 같은 산식으로 득점한다 — 시드 4개 평균 +0.12% (±15%)
     측정 조건: _t.skill = 0.5 · 명단에 me 없음(순수 산식) · 전력 70:70 · N=20000 · 시드 11/202/5150/31337
     시드별 [-0.51 -0.24 0.29 0.95]
✅ 31b-상한. 실점 비대칭이 더 나빠지지 않았다 — 시드 평균 |-14.56%| ≤ 17%
     시드별 [-14.70 -14.62 -14.31 -14.63] · _t.skill = 0.5 · me 없음
```

`SKILL = 0.5`를 파일 상수로 뽑고 *"🤖 자동 진행과 같은 값 · balancer가 곡선을 잰 값"*이라고
적었습니다. 44-4가 그 상수가 그대로인지 매번 확인해요.

## 2. 🔎 재다가 나온 것 — **제 31b는 skill을 안 탑니다**

*"당신 픽스처 그대로"*라고 하셔서 먼저 재현해 봤는데, **skill을 흔들어도 소수점 하나
안 움직였습니다:**

| `_t.skill` | 0.35 | 0.44 | 0.50 | 0.58 | 0.65 |
|---|---|---|---|---|---|
| 31b 실점 비대칭 (시드 넷 평균) | −14.56 | −14.56 | −14.56 | −14.56 | −14.56 |

**이유: 제 31b 명단(`xiAll`)에는 `me`가 없습니다.** 내 카드가 하나도 안 열리니
`autoJudge`가 아예 안 불려요 — `skill`이 걸릴 자리가 없습니다.

그래서 `me`를 넣고 다시 쟀습니다:

| `_t.skill` | 내가 df110 | 내가 mf110 |
|---|---|---|
| 0.35 | −6.69% | −9.45% |
| 0.50 | −0.73% | −5.17% |
| 0.65 | **+7.07%** | −0.67% |

**부호까지 갈립니다.** balancer가 본 것과 크기는 다르지만(픽스처의 `me`가 누구냐로 달라져요)
**방향과 성질은 같습니다** — 잘할수록 덜 먹힙니다.

> ### 🚨 그래서 둘 다 필요합니다
> 하나로 합치면 *"산식이 비대칭인가"*와 *"플레이어가 잘하나"*가 섞여서
> **빨간불이 떴을 때 어느 쪽인지 못 가립니다.** 31b는 계수를 지키고, 44는 조작을 지켜요.
> 그리고 이 결과는 **승격을 두 번 보류한 세 번째 근거**이기도 합니다 —
> 밴드 가장자리(−14.6%, 여유 0.44%p)에 있는 값이 **재는 조건에 따라 이만큼 흔들립니다.**

## 3. 🆕 clamp — 22번 ①-K를 정정합니다 (`neutral-test` ⑤)

말씀하신 대로 확인했습니다. **지금까지 어떤 검사도 clamp를 볼 수 없었습니다** —
중립 검사 넷이 **전부 `s = 0.5`**에서 보고, 거기서는 둘째 항이 0이라 정의상 안 닿거든요.

`s`를 극단(0·1)에 놓고 리그 여섯 클럽 전력(78·74·72·70·68·66)과 최약체(52)를
**서로 다 맞붙여** 셌습니다. 산식은 소스에서 뜯은 `pFinish`·`pConcede`·`half(a)`를 씁니다.

```
✅ ⑤-1. 능력치 110까지는 **리그 전 상대 · s 극단(0·1)에서도** clamp에 안 닿는다
✅ ⑤-2. 🚧 능력치 130에서 clamp가 닿는 칸 5개 ≤ 8 (상한이지 목표가 아니에요)
     예: atk 78:52 s=1 → 1.012 — **잘 해도 더 못 올라가는 칸**입니다
✅ ⑤-2. 🚧 능력치 150에서 clamp가 닿는 칸 14개 ≤ 20
     예: def 78:68 s=1 → 1.000
✅ ⑤-변이. half(a)를 두 배로 키우면 능력치 110에서도 clamp가 닿는다 (21칸)
```

**말씀하신 그대로 재현됩니다** — 110까지는 전 상대 안전, **130부터 최대 전력차(78:52)에서
상단이 잘립니다.**

### 🚧 양방향입니다

- 닿는 칸이 **늘면** → 빨간불 (회귀)
- **0이 되면** → *"🎉 해소됐어요! `CLAMP_KNOWN`에서 지우고 ⑤-1의 안전 구간을 넓히세요"* 빨간불

처방도 파일에 옮겨 적었습니다 — engine.js §2-6 주석의
*"**중심을 옮기지 말고 `half(a)`를 줄이세요** — 중립이 중심에 걸려 있습니다."*
