## 1. 🚨 **무엇이 안 읽히나** — 소스에서 찾았습니다

> 🔴 **우리는 §101부터 「재미」로 보고 조작 폭·`E[s]`·판정 창을 팠습니다.**
> 범민 님 낱말은 *"**이해하기도 어렵고**"*였어요. **다른 축이었습니다.**
> ⚠️ 제가 §12-2(c)에서 *"손잡이에 이름을 붙이기 전에 상한을 계산하라"*고 적었는데,
> **이번엔 「무엇을 고치는지」를 정하기 전에 「무엇이 문제인지」를 확인 안 했습니다.**

### 1-1. 넷이 요구하는 규칙 — 준비 화면에서 그대로 셌습니다

| | 규칙 | 개수 |
|---|---|---|
| 🏃 **컷인** | ① 갭이 좌우로 열렸다 닫힌다 ② 코스 칸이 여럿 ③ **갭이 내 코스 칸 위일 때** 누른다 ④ 주발 쪽 칸이 넓다 | **4** |
| 🥅 **1대1** | ① 키퍼가 달려나온다 ② 기다릴수록 빈 곳이 준다 ③ **골문에서 지점을 직접 누른다** ④ 주발 쪽 절반이 넓다 | **4** |
| 🎯 **킬패스** | ① 동료 셋이 **서로 다른 속도**로 뛴다 ② 오프사이드 라인이 있다 ③ **넘기 직전**이 최고 ④ 넘은 동료는 잠긴다 | **4** |
| 🧱 **차단** | ① 1단계는 안 움직인다 ② 주발을 읽는다 ③ 몸 방향을 읽는다 ④ **세기에 따라 정답이 뒤집힌다** ⑤ 2단계는 움직인다 ⑥ 창 폭은 1단계가 정한다 | **6** |

**범민 님이 보신 건 초·중·고 8판입니다. 8판에서 18개 규칙을 처음 배웁니다.**

### 1-2. 🚨 그리고 **「무엇을 누르는가」가 넷 다 다릅니다**

| | 무엇을 누르나 | 입력의 종류 |
|---|---|---|
| 🏃 컷인 | ⬅️ / ➡️ **코스 버튼** | **방향** |
| 🥅 1대1 | **골문 위 지점** | 🔴 **자유 좌표** (넷 중 유일) |
| 🎯 킬패스 | ① ② ③ **동료 버튼** | **대상** |
| 🧱 차단 | ⬅️⬆️➡️ **방향** → 🛡️ **막기** | **방향 + 시점** |

> 🔑 **네 게임이 「입력의 뜻」을 매번 새로 배우게 합니다.**
> 방향 · 좌표 · 대상 · 시점 — **네 종류의 입력이 여덟 판 안에 다 나옵니다.**

### 1-3. 🚨 **가장 결정적인 것 — 「좋은 순간」의 뜻이 넷 다 다릅니다**

`sBar(err, win) = 1 − 오차/판정창`이 **공통 자**인데, **`오차`의 뜻이 넷 다 다릅니다:**

| | `s` 함수 | 오차가 뜻하는 것 | 좋은 쪽 |
|---|---|---|---|
| 🏃 컷인 | `sCut` | 갭 **중심에서 벗어난 거리** | 🔵 **가까울수록** |
| 🥅 1대1 | `sOne` | **빈 곳의 여유** (`margin < 0`이면 0) | 🔴 **클수록** |
| 🎯 킬패스 | `sKp` | 라인까지 **남은 거리** | 🟡 **작을수록** (넘으면 0) |
| 🧱 차단 | `sBar` | 타이밍 오차 | 🔵 가까울수록 |

> 🚨 **셋이 서로 반대 방향입니다.** 컷인·차단은 *"가운데로"*, 1대1은 *"많이 남겨"*,
> 킬패스는 *"아슬아슬하게"*.
>
> 🔑 **공통 자는 코드에만 있고 화면에는 없습니다.**
> 플레이어가 보는 것은 **일치 / 여유 / 경계 / 중심** 넷이고, **서로 아무 공통점이 없습니다.**
> 소스 주석이 *"넷이 같은 모양을 씁니다 — 모양이 같아야 난이도를 한자리에서 견줄 수 있어요"*라
> 적었는데, **그건 밸런서의 편의였지 플레이어의 이해가 아니었습니다.**

### 1-4. 🔑 그래서 준비 화면이 매 판 떠도 안 통합니다

준비 화면은 **처음 3번 전문 → 그 뒤 한 줄**입니다(`FULL_SHOWS = 3`).
**넷이 각각 3번이면 12판**인데, **범민 님은 8판을 보셨습니다.**
🔴 **넷 다 「처음 3번」 구간을 못 벗어난 채 끝났습니다.**

> ★ **즉 지금 구조는 「12판 이상 뛴 사람」에게만 설명이 줄어듭니다.**
> **첫 커리어의 8판은 설계상 계속 배우는 구간입니다.**

## 3. ★ 리-B 설계 — **한 문법**

### 3-1. 🖼️ 공통 문법 — **움직이는 것 하나 · 목표 띠 하나 · 버튼 하나**

```
┌──────────────────────────────────────┐
│  🏃 컷인 돌파                         │
│                                      │
│  수비 둘 사이가 벌어질 때 파고들어요   │  ← 한 줄. 늘 뜹니다
│                                      │
│  ├──────[███ 목표 띠 ███]──────────┤  │  🔑 보이는 폭 = 판정 창
│         ⚽ ──────▶                    │  🔑 움직이는 것 하나
│                                      │
│            [  지금!  ]                │  🔑 버튼 하나
└──────────────────────────────────────┘
```

| | 넷이 공유하는 것 |
|---|---|
| **입력** | 🔒 **버튼 하나.** 고를 게 없고 **「언제」만** 남습니다 |
| **좋은 순간** | 🔒 **띠 한가운데.** 넷 다 같습니다 |
| **오차** | 🔒 **띠 중심에서 벗어난 거리.** `sBar` 하나 |
| **판정 창** | 🔒 **보이는 띠의 폭이 그대로.** 원칙 ③ |

> ★ **첫 판에 배우면 나머지 셋은 배울 게 없습니다. 규칙이 하나예요.**

### 3-2. 🔑 그럼 넷의 개성은 어디로 — **「띠가 왜 그 폭인가」입니다**

| | 움직이는 것 | 🔑 띠가 그렇게 되는 이유 (설명 없이 화면으로 보입니다) |
|---|---|---|
| 🏃 **컷인** | 수비 둘 사이의 공 | **주발 쪽으로 갈 때 띠가 넓습니다** — 몸이 열려 있으니까요 |
| 🥅 **1대1** | 골문으로 가는 공 | 🔑 **키퍼가 나올수록 띠가 좁아집니다** — 기다리면 사라져요 |
| 🎯 **킬패스** | 라인으로 뛰는 동료 | 🔑 **띠가 라인 바로 앞에 있습니다** — 넘으면 오프사이드라 띠가 끝나요 |
| 🧱 **차단** | 지나가는 상대 | 🔑 **1단계 읽기가 폭을 정합니다** (이미 구현됨) |

> 🔑 **규칙은 하나이고, 그 하나가 왜 다른가가 개성이 됩니다.**
> 그리고 **그건 설명이 아니라 화면이 말합니다** — 띠가 좁아지는 걸 보면 알아요.
> ★ **이게 원칙 ①입니다** — *화면이 만드는 기대와 메커닉의 핵심이 같아집니다.*

### 3-3. 🔴 무엇을 버리는가 — **명시합니다**

| 버림 | 왜 |
|---|---|
| 🔴 **🥅 자유 좌표 입력** (골문을 직접 누르기) | 넷 중 유일한 입력 종류. **가장 크게 배워야 하는 것** |
| 🔴 **🎯 대상 선택** (동료 ①②③) | *"셋을 동시에 추적"*이 8판 안에 안 들어옵니다 |
| 🔴 **🏃 코스 칸 여러 개** (⬅️/➡️) | *"움직이는 것과 고정된 칸의 일치"*가 두 물체를 봐야 합니다 |
| 🔴 `sCut` · `sOne` · `sKp` | **오차의 뜻 셋** → `sBar` 하나로 |
| 🔴 `CUT` · `ONE` · `KP` 계수 표 | 대체 |

> 🟡 **개성이 줄어드는 건 맞습니다.** 다만 **지금 그 개성이 이해를 막고 있습니다.**
> 🔑 **그리고 잃은 개성은 「띠의 거동」으로 돌아옵니다**(§3-2) — 키퍼가 좁히는 띠,
> 라인 앞에서 끝나는 띠는 **자유 좌표·대상 선택보다 오히려 그 장면을 더 잘 말합니다.**

### 3-4. ★★ **게임 전체의 문법을 둘로 줄입니다**

| 문법 | 어디에 | 무엇 |
|---|---|---|
| 📝 **고르는 화면** | 🧒 초1~3 선택지 · 🧱 차단 1단계 읽기 · 📨 제안 승낙/거절 · 🎯 자리 | **텍스트 선택지 2~3개.** 한 줄 설명. **움직이는 것 없음 · 시간 무제한** |
| 👆 **누르는 화면** | 🎮 순간 카드 넷 | **띠 하나 + 버튼 하나.** 움직임 있음 · 시간 있음 |

> 🔑 **「고르는 것」과 「누르는 것」을 화면으로 가릅니다.**
> §104 §2-3에서 차단의 두 국면을 화면으로 가른 그 판정을 **게임 전체로 넓히는 것**이에요.
> 🔑 **그리고 리-A(텍스트 3택)가 여기서 삽니다** — 버리는 게 아니라 **제자리를 찾아 줍니다.**

> 🔴 **못 박습니다: 고르는 화면에 초읽기를 붙이지 마세요.** 🧊 볼카운트가 죽은 자리입니다.
> **누르는 화면에는 반드시 시간이 있어야 하고, 고르는 화면에는 절대 없어야 합니다.**

## 5. ③ 👀 스카우터

### 5-1. ★ 「눈에 띈다」는 **이미 있습니다 — 안 보일 뿐입니다**

`fit`(🇯🇵 패스 · 🇧🇷 골 · 🇮🇹 수비 · 🇬🇧 총점)이 정확히 *"누가 나를 원하는가"*입니다.
🔴 **문제는 그 판정이 제안 화면에서야 보인다는 것**이에요.

> ★ **경기 중에 스카우터가 반응하게 합니다.**
> `perfect` 카드가 나오면 그 자리에 한 줄:
> *"🧾 라인 밖에서 누가 수첩에 뭘 적었어요"*

| | |
|---|---|
| 🔒 **밸런스 무변** | **이미 정해진 `fit` 결과를 미리 보여주는 것**뿐입니다. **새 굴림 0** |
| ✅ **원칙 ③** | 손잡이(카드)의 효과가 **그 자리에서** 보입니다 |
| 🔒 **원칙 ⑧** | 🔴 **누가 보고 있는지는 안 알려줍니다.** *"낯선 어른"*까지만 — **어느 나라인지는 제안 화면에서** |

🔑 **§101에서 고등 머리글에 넣은 *"라인 밖에 낯선 어른들이 서 있어요"*가 살아 있는 장치가 됩니다.**
앞당기는 게 아니라 **카드 결과에 반응하게** 만드는 것이에요.

### 5-2. 🔴 그리고 제안 시점이 앞당겨집니다

범민 님 — *"초4? 초5부터 축구대항전 나가서 (…) 스카우터 눈에 띄면 스카웃 제의"*.
**지금 구조와 같습니다** (초등 뒤 제안). 🔑 **바뀌는 건 「자동으로 뜬다」 → 「보고 있던 사람이 온다」**예요.

⚠️ 🔒 **`fit`·`FIT_EDGE`·`SIGN_SHAKE`·`OFFER`·`BAND_EDGE`는 한 칸도 안 건드립니다.**
**balancer가 전수 열거로 닫은 자리입니다**(§13-7 · 네 줄이 한 벌).

### 6-1. 🔒 **안 건드리는 것 — 곡선의 뼈대**

> 🔑 **`s`를 만드는 쪽만 바꿉니다. 그러면 곡선의 뼈대가 삽니다.**

### 6-2. 🚨 **그런데 `E[s]` 짝짓기가 이번엔 안 됩니다**

§12-1에서 세운 계약 —
> 🔒 *"같은 조작자 모델·같은 판으로 잰 **옛 매핑 ↔ 새 매핑의 `E[s]` 차이 ≤ 0.005**"*

🔴 **이번엔 못 씁니다. 입력이 바뀌면 조작자 모델도 바뀌니까요.**
**「골문 좌표를 겨누는 모델」과 「띠 타이밍 모델」은 짝지을 수가 없습니다.**

★ **그래서 계약을 한 층 위로 올립니다:**

| | |
|---|---|
| 🔴 **못 씀** | `E[s]` 짝지은 차이 |
| ✅ **새 계약** | 🔒 **「같은 조작 실력(서툰·보통·능숙 세 벌)에서 개편 전후의 20시즌 결과 분포가 같은가」** — ⚽ 골·🅰️ 도움·🛡️ 무실점·부문상 수상률·36턴 종합 |

> 🔑 **§14-2에서 배운 것과 같은 이동입니다** — *"비율도 대리 지표다. 원칙의 문장을 그대로 쓰라."*
> **`E[s]`는 대리 지표이고, 진짜 지표는 「게임의 결과」입니다.**
> 🔴 **그리고 이번엔 대리 지표가 아예 짝지어지지 않으니, 진짜 지표로 갈 수밖에 없습니다.**

⚠️ **그러면 `YOUTH_CARD_P`·`PEER_REF`를 새 `E[s]`에 맞춰 다시 잡아야 할 수 있습니다.**
🔒 **다만 그건 「값 재계산」이지 「구조 변경」이 아닙니다** — `PEER_REF`는 원래 **종속값**이고,
주석에 *"넷 중 하나가 바뀌면 표 전체를 다시 돌리세요"*라고 이미 적혀 있습니다. **이번이 그 경우예요.**

## 11-2. 🚨 **§3을 개정합니다 — 제가 버리자고 한 것이 정답이었습니다**

§3-3에서 이렇게 적었습니다:
> 🔴 **🥅 자유 좌표 입력**(골문을 직접 누르기) — *"넷 중 유일한 입력 종류. 가장 크게 배워야 하는 것"*

**틀렸습니다. 🥅 1대1이 넷 중 유일하게 「축구 장면 위에서 노는」 게임입니다.**

| | 🥅 1대1이 이미 갖고 있는 것 |
|---|---|
| 🟢 **공간** | **골문**을 그립니다 — 참고작의 골대 격자와 같은 자리 |
| 🟢 **고를 것이 보임** | 빈 곳이 **화면에** 있습니다 |
| 🟢 **한 탭이 「어디 + 언제」를 동시에** | 지점을 누르면 **그 순간의 키퍼 위치**로 `s`가 납니다 |
| 🟢 **`s`가 연속** | 여유가 연속값이에요 |

> 🔑 **제가 「입력 종류가 다르다」는 규칙층 이유로 의미층의 유일한 성공작을 버리려 했습니다.**
> ⚠️ **§12-2(c)에서 배운 것을 또 어겼습니다** — *"손잡이에 이름 붙이기 전에 상한을 계산하라."*
> 이번엔 **버리기 전에 「그게 왜 거기 있었는지」를 확인 안 했습니다.**
> 🔴 **폐기는 이름이 아니라 형태**인데, 저는 **형태를 안 보고 「입력 종류」라는 이름으로 버렸어요.**

### 🔴 그럼 1대1의 진짜 약점은 무엇이었나 — **자유 좌표입니다. 격자가 아니라서요**

참고작이 **격자**를 쓰는 이유가 여기 있습니다:
> **「어디를 누를 수 있는지」가 칸으로 서 있습니다.** 자유 좌표는 *"아무 데나 눌러도 되나?"*가 남아요.

★ **자유 좌표 → 격자.** 버릴 것은 **공간이 아니라 「경계 없음」**이었습니다.

## 11-3. ⓒ 🔴 **「정지 ↔ 움직임」이 아닙니다**

조율자님이 짚으신 모순 — 저는 🧱 차단을 **움직이는 쪽**으로 맞췄는데 참고작은 **정지 격자**다.

**따져보니 물음이 잘못 세워졌습니다:**

| | 참고작이 나은 이유 | 정지여서인가 |
|---|---|---|
| ① | **골대가 있어 「골을 넣는다」가 자명** | 🔴 아니요 — **공간** 때문입니다 |
| ② | **격자가 「고를 것」을 보여줌** | 🔴 아니요 — **선택지가 눈에 보이는 것** 때문입니다 |
| ③ | 세 줄 위계 | 🔴 아니요 — **낱말** 때문입니다 |

> 🔑 **셋 다 「시간이 흐르는가」와 무관합니다.**
> 참고작 화면에도 *"오른쪽 위 두 칸이 밝게 강조"* — **강조가 바뀌면 그건 시간 게임입니다.**
> ★ **우리가 배울 것은 「멈추는 것」이 아니라 「보이게 하는 것」입니다.**

### 🔒 그리고 🧱 차단 판정은 **안 뒤집힙니다**

§104의 판정은 *"1단계는 정지·무제한, 2단계는 움직임"*이었고, 그건 **국면을 화면으로 가른 것**입니다.
🔑 **참고작의 교훈은 「2단계 화면을 무엇으로 그리는가」에 걸립니다** — 띠 대신 **내 앞 공간**으로요.
**국면 분리는 그대로입니다.**

## 11-4. ★ 개정된 공통 문법 — **장면 위의 격자, 한 번 탭**

> 🔒 **축구 장면 하나 · 그 위에 격자(노릴 곳) · 방해하는 것이 시간에 따라 움직임 ·
> 한 번 탭이 「어디 + 언제」를 동시에 정합니다.**

```
┌────────────────────────────────────┐
│  goal chance                       │  ← 상황 분류 (작게)
│  🥅 1대1 마무리                     │  ← 무엇 (크게)
│  키퍼가 나오기 전에 빈 곳을 노려요    │  ← 왜/어떻게 (한 줄)
│  ┌──────────────────────────────┐  │
│  │  ▓▓▓ │ ▓▓▓ │     │     │     │  │  🔑 밝은 칸 = 지금 좋은 곳
│  │──────┼─────┼─────┼─────┼─────│  │     (키퍼가 나오면 줄어듭니다)
│  │      │  🧤 │     │     │     │  │  🧤 키퍼 — 움직이는 것 하나
│  │──────┼─────┼─────┼─────┼─────│  │
│  │      │     │  ⚪ │     │     │  │  ⚪ 공 — 내가 어디서 차는지
│  └──────────────────────────────┘  │
│         (칸을 누르세요)              │  ← 버튼 없음. 장면이 곧 버튼
└────────────────────────────────────┘
```

### 넷이 공유하는 것

| | |
|---|---|
| **장면** | 🔒 **축구의 한 장면.** 추상 도형 금지 |
| **격자** | 🔒 **노릴 수 있는 칸이 눈에 보입니다.** 3~5칸 — 한눈에 세어지는 수 |
| **강조** | 🔒 **지금 좋은 칸이 밝습니다.** 그게 **판정 창의 시각화**예요(원칙 ③) |
| **방해** | 🔒 **움직이는 것 하나.** 시간이 흐르면 강조가 바뀝니다 |
| **입력** | 🔒 **칸 하나 탭. 버튼 없음** — 장면이 곧 버튼입니다 |

### 넷의 개성 — **장면과 방해가 다릅니다**

| | 장면 | 격자 | 방해(움직이는 것) | 창이 넓어지는 이유 |
|---|---|---|---|---|
| 🥅 **1대1** | **골문 앞** | 골문 5칸 | 🧤 키퍼가 나옴 | 🦶 주발 쪽 절반 |
| 🏃 **컷인** | **수비 둘 사이** | 지나갈 길 3~4칸 | 🧍🧍 수비가 좁혔다 벌어짐 | 🦶 주발 쪽 |
| 🎯 **킬패스** | **오프사이드 라인 앞** | 동료가 뛰는 길 3칸 | 🏃 동료가 라인으로 뜀 | 동료마다 속도 |
| 🧱 **차단** | **내 골문 앞** | 상대가 올 길 3칸 | 🏃 상대가 다가옴 | 1단계 읽기 |

> 🔑 **규칙은 하나(「밝은 칸을 지금 누르세요」)이고, 왜 밝기가 다른가가 개성입니다.**
> **그리고 그건 설명이 아니라 화면이 말합니다.**

## 12-1. 🔴 ① **§11-5를 정정합니다 — 격자는 조준 오차를 지웁니다**

### (a) 무엇이 틀렸나

§11-5에 이렇게 적었습니다:
> *"칸은 이산이지만 「좋은 지점」이 연속으로 움직이므로 **오차가 연속입니다**."*

**절반만 맞았습니다. 조율자님 요약이 정확해요 — 연속이면 0도 지나갑니다.**

### (b) 🔑 왜 그런지 — **구조로 적어 둡니다**

| | 탭 지점 | 오차 |
|---|---|---|
| **자유 좌표** (옛 🥅) | 🔑 **손이 정한 연속값** — 노린 곳에 못 맞습니다 | 조준 오차 **+** 타이밍 오차 |
| **격자** (새 🥅) | 🔴 **칸 중심에 스냅** — **정확히 아는 지점**입니다 | **타이밍 오차만** |

```
격자에서:  오차 = 좋은지점의 속도 × 타이밍오차
          s   = 1 − (속도 × Δt) ÷ 창
```

> 🚨 **`속도`와 `창`이 따로 있는 두 손잡이가 아니라 「하나의 비」입니다.**
> engineer가 실측으로 확인한 그대로예요 — *"`cov1`과 `close`를 맞바꾸면 0.90으로 되돌아갑니다."*
>
> 🔑 **그리고 조준 오차가 사라졌으니 `Δt = 0`인 순간에 `s = 1`입니다.**
> **창을 아무리 좁혀도 안 잡힙니다** — `sBar(0, 창) = 1`은 창과 무관하니까요.
> ★ **자유 좌표에는 「손이 만드는 바닥」이 있었고, 격자가 그걸 지웠습니다.**

### (c) ★ 그래서 손잡이가 **셋**으로 갈립니다 — 🔒 **같은 표에 두지 마세요**

| 이름 | 성격 | 무엇을 정하나 |
|---|---|---|
| **`속도 ÷ 창`** | 🔗 **중립화 비** | 🔑 **난이도.** `E[s]` 평균이 여기서 나옵니다. **둘을 따로 잡으면 서로 상쇄합니다** |
| **몫 나누기** (속도↕ ↔ 창↕) | 🎯 **트레이드오프 손잡이** | 🔑 **공간 읽기 ↔ 타이밍의 지분.** 비가 같아도 게임의 성격이 달라집니다 |
| **`CELL_FLOOR`** | 🔗 **구조적 바닥** (칸 폭에 종속) | 🔑 **`s`의 천장.** 격자의 이산화가 만드는 불확실성 |

> 🔑 **§12-2(`BLK_WIN` ↔ `BLK_READ`)와 정확히 같은 구조입니다** — **비는 난이도, 몫은 지분.**
> 🔴 **그때 제가 이름을 잘못 붙여 데인 자리예요.** 이번엔 먼저 나눕니다.

### (d) 🚨 **바닥을 「몫 나누기」로 만들면 격자가 죽습니다**

engineer 처방: *"「좋은 지점」은 거의 안 움직이게 하고 창만 62% 좁아지게 몫을 나눴습니다."*

**`E[s]`는 맞습니다. 그런데 그건 「몫 나누기」로 「바닥」 문제를 푼 것입니다 — 원칙 ⑪.**

> 🔴 **좋은 지점이 거의 안 움직이면 「어느 칸을 누를지」가 사실상 고정됩니다.**
> **그러면 격자가 눈금이 아니라 「버튼 하나」가 됩니다** —
> 🔑 **제가 §11-4에서 폐기한 「띠 + 버튼 하나」로 되돌아간 것입니다.**
> 격자를 넣은 이유(§11-3 ②: *"고를 것이 화면에 보인다"*)가 사라져요.

### (e) ★ 바닥을 **바닥으로** 만듭니다 — 갈래 둘

| | 안 | 판정 |
|---|---|---|
| **바닥-A** | **격자는 눈금으로만.** 탭 좌표를 스냅 안 함 | 🟢 손의 바닥이 그대로 돌아옵니다 · 🔴 **390px에서 손가락 정밀도**가 문제 · 🔴 *"칸을 눌렀다"*는 감각이 약해짐 |
| **바닥-C** ⭐ | 🔒 **칸 폭만큼의 불확실성을 오차에 더합니다** | 🟢 **물리적으로 정직합니다** — *"칸을 눌렀다"*는 *"이 칸 어딘가"*이지 *"정확히 중심"*이 아니에요 · 🟢 격자 감각 유지 · 🟢 **바닥이 속도와 무관**해서 몫을 어떻게 나누든 남습니다 |

```js
/* 🔒 **칸 바닥** — 격자의 이산화가 만드는 불확실성입니다.
 * 🔗 **칸 폭에 종속**됩니다. 난이도 손잡이가 아니에요 — 난이도는 `속도 ÷ 창`이 잡습니다.
 * 🔴 이게 없으면 「좋은 지점」이 칸 중심을 지나는 순간 s = 1이 되고, 창을 아무리
 *    좁혀도 안 잡힙니다(113번 실측: 능숙 0.903). 자유 좌표에는 손이 만드는 바닥이
 *    있었는데 격자가 그걸 지웠어요. */
const CELL_FLOOR = 0.30;                       // 칸 폭의 30% (제안 · balancer 실측)
err = Math.max(Math.abs(칸중심 − 좋은지점), 칸폭 * CELL_FLOOR);
```

**★ 바닥-C를 권합니다.** 그러면 `s`의 천장이 `1 − (칸폭×0.30)/창`이 되어 **1에 안 닿습니다.**
🔑 **그리고 engineer는 몫을 자유롭게 나눌 수 있게 됩니다** — 좋은 지점을 **다시 움직이게** 해도 돼요.

> ⚠️ 🔴 **§11-5의 「칸 수는 난이도 손잡이가 아니다」를 정정합니다.**
> **칸이 좁을수록 바닥이 낮아지므로 칸 수가 난이도에 닿습니다.**
> 🔒 **그래도 칸 수로 난이도를 잡지 마세요** — **읽힘(3~5칸)으로 먼저 정하고,
> 그 칸 폭에서 `속도 ÷ 창`으로 난이도를 맞춥니다.** 순서가 있습니다.

## 12-2. ④ 나머지 셋 — **둘은 같은 함정, 하나는 다른 성질**

### 🎯 킬패스는 **절벽**입니다

최적이 *"라인 넘기 직전"*이고 **넘으면 오프사이드(0점)**입니다 (`sKp`의 `gap < 0 ? 0`).
🔑 **최적점 바로 옆이 0이라, 바닥을 깔면 오히려 「아슬아슬함」이 죽습니다.**

★ **킬패스는 `CELL_FLOOR`를 **한쪽에만** 겁니다:**
```
라인 쪽(아직 안 넘음)  → 바닥 있음 (칸 폭 불확실성)
라인 너머(넘음)        → 🔒 0 그대로. 절벽 유지
```
> 🔑 **고위험 고수익이 이 게임의 성격입니다.** 넷 중 **하나쯤은 그런 게 있어야** 반복(H3)이 덜해요.
> ⚠️ 🔴 다만 **절벽 때문에 `E[s]` 분포가 넷 중 혼자 다릅니다** — balancer가 따로 봐야 합니다.

> 🔒 **`CELL_FLOOR` 자체는 넷이 같은 값을 씁니다** — 격자의 이산화가 만드는 것이라
> **게임과 무관**하니까요. **거는 방식만 킬패스가 한쪽**입니다.

격자는 **칸이 넓어 대략만 맞으면 되니까** 그 이득이 **그대로 드러납니다.**

> ★ **새 축을 만든 게 아니라, 원래 있던 축을 가리던 노이즈를 걷은 것입니다.**

### (b) 🔴 그런데 위험이 하나 있습니다 — **「알면 끝」인 계단**

| | 늘어나는 방식 |
|---|---|

| 🔴 **내다보는 폭** | *"아, 미리 눌러야 하는구나"*를 **한 번 깨달으면 끝** — **계단** |

> 🚨 **그러면 「숙련도 폭」이 아니라 「안다 / 모른다 폭」이 됩니다.**
> 🔴 첫 커리어와 두 번째 커리어 사이에 **큰 계단**이 생기고,
> 🔴 **범민 님 지적(*"이해하기 어렵다"*)과 정확히 같은 축**입니다 — 모르면 못 해요.
