## 3. 밀도 규칙 — **분에서 나옵니다**

### 3-1. 격자 (engineer가 그대로 옮길 형태)

```js
/* ⏱️ **90분 격자** — 🔒 흐름 줄의 수는 「분」에서 나옵니다. 카드 수 `n`에 안 묶여요.
 *    🔴 144번은 `F[j] = 두 카드의 중점`이라 필러가 `n`장이었고, 그중 하나가 하프타임에
 *       먹혀 🏫 초5는 흐름 줄이 **딱 한 줄(75')**, 그것도 마지막 결정 「뒤」였습니다.
 *
 * 🔒 **`GRID_NEAR`는 종속값입니다 — 손잡이가 아니에요.** 「가장 가까운 눈금이 카드면 뺀다」의
 *    다른 표현일 뿐이라 `GRID`가 바뀌면 **따라 재계산**됩니다. 따로 만지지 마세요.
 *    같은 값(정확히 6분)이면 **남깁니다** — 눈금이 카드와 6분 떨어지면 다른 장면이에요. */
const GRID = 12;                 // 🔒 12분 눈금 → 12·24·36·48·60·72·84 (7칸)
const GRID_NEAR = GRID / 2;      // 🔒 종속값 (GRID의 절반)
const HALF_MIN = 45;             // 🔒 축구의 값. `engine.js`의 `next()`와 같은 자리

const flowMins = (cardMins) => {
  const busy = cardMins.concat([HALF_MIN, 90]);          // 🥅 하프·🔚 종료도 이미 찬 자리예요
  const g = [];
  for (let m = GRID; m < 90; m += GRID) {
    if (busy.some((b) => Math.abs(m - b) < GRID_NEAR)) continue;
    g.push(m);
  }
  /* 🔒 **첫 순간 카드 「앞」은 한 줄이 상한입니다** — 계약 D의 추정 여유가 1초대예요(§4-3).
   *    둘 이상 나오면 **가장 이른 것**만 남깁니다 — 시계가 일찍 움직이는 게 더 중요합니다.
   * 🔴 격자가 첫 구간에 **매번 두 칸을 준다면 그건 격자가 잘못 잡힌 것**입니다 (§3-2 표). */
  const head = g.filter((m) => m < cardMins[0]);
  return head.slice(0, 1).concat(g.filter((m) => m >= cardMins[0]));
};
```

### 3-2. 🔴 왜 12분인가 — 다른 눈금은 실제로 이렇게 나옵니다

```
GRID= 9   n=2:[9,18,36,54,72,81] 첫구간 2칸   n=3:[9,18,36,54,63,81] 첫구간 2칸
GRID=10   n=2:[10,20,40,50,70,80] 첫구간 2칸  n=3:[10,30,40,50,60,80] 첫구간 1칸
GRID=12   n=2:[12,24,36,72,84]  첫구간 2칸    n=3:[12,36,60,84]      첫구간 1칸   ← 이것
GRID=15   n=2:[15,75]           첫구간 1칸    n=3:[15,60]            첫구간 1칸
GRID=18   n=2:[18,72]           첫구간 1칸    n=3:[36,54]            첫구간 0칸
```

| 눈금 | 왜 아닌가 |
|---|---|
| **9 · 10** | 흐름 줄이 6칸이 되고 **첫 구간이 매번 2칸**이라, 상한 규칙이 **매 경기 발동**합니다. 규칙이 격자를 이기면 격자가 아무 말도 안 하는 거예요 |
| **15** | 🔴 **`minAt`과 공명합니다.** `minAt(i,2)`가 정확히 `30·60`이고 15의 배수라 셋이 충돌로 날아가 **초5가 다시 2줄**이 됩니다 |
| **18** | n=3의 첫 구간이 **0칸** — 범민 님이 짚은 그 구멍이 그대로 남습니다 |
| **✅ 12** | 카드 분(30·60 / 23·45·68) 어디에도 안 맞습니다(60 하나만 충돌). **두 단계가 똑같이 4줄**이고 첫 구간이 각각 2칸·1칸 |

🔑 **일반 규칙**: `minAt(i,n) = 90(i+1)/(n+1)`이라 카드 분은 **90의 약수 구조**를 탑니다.
👉 **격자는 90과 잘 안 맞물리는 값**이어야 해요. 12는 90의 약수가 아닙니다(15·18·10·9는 전부 약수).

### 3-3. `flow` 배정 — `n` 대신 `K`(흐름 줄 수)

```js
/* 🔁 흐름 — 🔒 **연출 축입니다. 트레이드오프 손잡이도 중립화 상수도 아니에요**(원칙 ⑨).
 *    `d`·`spotMul`·`state`에 한 톨도 안 갑니다.
 * 🔴 **144번의 `n`을 `K`로 바꿉니다** — 이제 흐름 줄 수가 카드 수와 무관해요.
 *    `n`을 그대로 두면 n=2에서 `j < 1`이 되어 **넷 중 셋이 전부 꼬리 취급**을 받습니다. */
const flowOf = (j, K, sIdx, hg, ag) => (j < K - 1
  ? ((j + sIdx) % 2 === 0 ? "a" : "h")
  : hg < ag ? "a" : hg > ag ? "h" : "mid");
```

| 단계 | `sIdx` | j=0 | j=1 | j=2 | j=3 (꼬리) |
|---|---|---|---|---|---|
| 🏫 초5 | 0 | `a` | `h` | `a` | 🎯 스코어 |
| 🏫 중등 | 1 | `h` | `a` | `h` | 🎯 스코어 |
| 🏫 고등 | 2 | `a` | `h` | `a` | 🎯 스코어 |

🟡 **초5와 고등이 같은 순서입니다** (`sIdx` 0·2가 둘 다 짝수). 🟢 **그대로 둡니다** —
문구 표가 단계마다 다르니(§3-4) **같은 흐름 순서여도 같은 줄이 안 나옵니다.**
그리고 검사 `flow90-test` F-5의 계약(*"중등과 고등이 서로 뒤집혀 있다"*)은 **그대로 참**입니다.

### 3-4. 🗣️ 대본 — **흐름마다 세 줄**, 세 줄이 서로 다른 「모양」

## 4. ⏱️ 딜레이 판정과 시간 예산

### 4-1. 🌊 흐름 줄과 🔥 결정 줄을 가릅니다

> ⚠️ **여기 값은 실기기 실측 전까지 「제안」입니다.** 다만 **바닥(514ms)은 실측값**이에요
> (145번 §11 — 헤드리스에서 `transform`이 네 프레임 연속 같아질 때까지 폴링).

```js
/* ⏱️ **흐름 줄이 화면에 서 있는 최소 시간** — 🔒 **종속값입니다. 손잡이가 아니에요.**
 *    바닥은 **점이 다 서는 데 걸리는 514ms**입니다 (`.w2-slot`의 `transition .42s`
 *    + 인라인 최대 `transition-delay` 78ms = 계산 498 · 브라우저 실측 514 · 145번 §11).
 *    🔴 `.w2-slot`의 값이 바뀌면 **여기도 따라 재계산**하세요 — 세기를 여기서 잡지 마세요.
 * 🔑 620 = 514 + 106 (여유 21%). 그리고 결정 줄 900ms와 **31% 벌어져** 리듬이 갈립니다
 *    (900 대 780은 13%라 사람 눈에 안 갈려요).
 * 🔑 ⚽ 윙어1의 `MatchSim`은 **780ms**입니다(`beta/soccer/game.js:2211`). 더 짧게 잡는 이유는
 *    윙어1이 **한 줄씩** 흘리는 데 비해 학교는 카드 사이에 **2~3줄을 뭉쳐서** 흘리기 때문이에요. */
const FLOW_MS = 620;

/* 🔴 `delayOf`는 `match-scene.js`에 있습니다 — **director 파일**이에요. 값은 제안입니다. */
function delayOf(card) {
  if (S.fast) return 90;
  const d = Math.abs(S.h - S.a);
  const base = d <= 1 ? 900 : d === 2 ? 600 : 350;
  const flowish = card && (card.kind === "filler" || card.kind === "kick" || card.kind === "end");
  /* 🔒 `Math.min`인 이유: 3점 차(350ms)에서 흐름 줄만 620으로 **느려지면 거꾸로**예요.
   *    흐름 줄은 결정 줄보다 **절대 느리지 않습니다**. */
  return flowish ? Math.min(FLOW_MS, base) : base;
}
```

| 줄 | 딜레이 | 왜 |
|---|---|---|
| 🌊 `filler` · 🏁 `kick` · 🔚 `end` | **`min(620, delayOf)`** | **읽는 줄**입니다. 뜸을 들일 반전이 없어요 |
| 🥅 `half` | **`delayOf()` 그대로 (900)** | **스코어보드가 갱신되는 자리**라 그 순간만은 뜸을 들입니다 |
| 🔥 순간 카드 open/close | **`delayOf()` 그대로** | 🔒 결정과 반전의 자리. 안 건드립니다 |
| ⏩ `fast()` | 90 | 그대로 |

🔒 **514ms 바닥을 지키는 법**: 값을 베껴 적지 말고 **관계로 검사하세요** —
`style.css`의 `.w2-slot` `transition` + `match-scene.js`의 인라인 최대 `transition-delay`를
소스에서 뜯어 `FLOW_MS`와 견줍니다 (§6 I-D).

> 카드가 둘이면 필러도 둘인데 그중 하나가 하프타임에 먹혀 **한 줄만** 남았습니다.
> 이제 흐름 줄은 **90분을 12분으로 자른 격자**에서 나옵니다. 카드 수와 무관해요.
>
> 🏫 **초5도 중·고도 흐름 줄이 정확히 넷**이 되고, 시계가 `0' · 12' · 30' · 36' · 45' · 60' · 72' · 84' · 90'`으로
> **끊긴 데 없이** 갑니다. 그리고 **줄마다 준호의 이름이 나옵니다** — 더 윙어 1의 중계가 그랬듯이요.
>
> 🟢 **그런데도 기다리는 시간은 안 늘었습니다** — 흐름 줄은 결정 줄보다 **31% 빨리** 넘어가서,
> 줄이 13장 → 18장으로 느는데 아크 전체는 11.7초 → **12.0초**입니다.
> 🟡 **다만 「첫 카드까지 90초」 계약의 여유가 1.4초로 얇아요.** 폰으로 한 번 재 봐야 압니다.
