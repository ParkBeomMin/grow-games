## 1. 🚨 진단 — **문제는 이산이 아니라 「난수 한 겹」입니다**

### 1-1. 제가 §101에서 적은 진단을 한 단계 더 파고들었습니다

§101에서 *"`s`가 3단 이산이라 폭이 0.05"*라고 적었는데, **이산은 증상이지 원인이 아닙니다.**

`winger-moment.js:501-585`을 읽고 원인을 찾았습니다:

```
읽기(내 조작)  →  🎲 tell 의 신뢰도  →  맞음/틀림  →  s = 1 / 0.24 / 0
                  ↑ 여기가 문제입니다
```

| 세기 | 최적 전략 | **그 전략이 맞을 확률** |
|---|---|---|
| 확실히 틀었어요 (`hi`) | 몸 방향을 따라감 | `tellHi` = **0.58** |
| 살짝 흔들었어요 (`lo`) | 🦶 주발 쪽 | `favor(1−tellLo)/2` = **0.608** |

> 🔴 **완벽하게 읽어도 60%만 맞습니다. 나머지 40%는 `s = 0.24` 또는 `0`입니다.**
> 🔑 **그래서 「잘 읽은 판」과 「대충 찍은 판」이 결과에서 구분이 안 됩니다.**
> 소스가 적어 둔 *"순수 찍기 0.46 ~ 완벽한 읽기 0.60"*이 정확히 그 뜻이에요 —
> **읽기를 완벽하게 해도 얻는 게 0.14뿐**입니다.

### 1-2. 나머지 셋과 무엇이 다른가 — **난수의 자리**

| | 조작 → 결과 사이 |
|---|---|
| 🏃 컷인 | 갭 위치를 정확히 맞추면 🔑 **`s = 1`이 결정적으로** 나옵니다 |
| 🥅 마무리 | 빈 곳을 정확히 노리면 **결정적** |
| 🎯 킬패스 | 라인을 정확히 맞추면 **결정적** |
| 🧱 **차단** | 🔴 **잘 읽어도 42%는 실패합니다** |

**셋은 「난수가 판을 만들고, 조작이 결과를 만듭니다」.**
**차단은 「난수가 판을 만들고, 조작을 거친 뒤 난수가 결과를 다시 만듭니다」.**

> 🔑 **이건 원칙 ③입니다** — *"통제할 수 없는 효과는 영향이 아니라 노이즈로 읽힌다."*
> 손잡이(읽기)를 돌렸는데 효과가 **40%의 확률로 사라집니다.**
>
> 🔑 **그리고 원칙 ①이기도 합니다** — 화면이 *"읽으면 맞출 수 있다"*고 약속하는데
> 실제로는 **58%**예요. **약속과 메커닉이 어긋납니다.**

### 1-3. 🔴 그런데 그 난수 겹은 **일부러 넣은 것**입니다

`BLK` 주석이 그 이유를 정확히 적어 뒀습니다:

> *"세기가 하나면 사후확률의 크기 순서가 판마다 안 바뀌어서 **늘 같은 쪽을 고르는 게 정답**이
> 됩니다 — 신호가 둘인 척하는 신호 하나짜리 판이 돼요."*

**맞는 말이고, 그래서 `tellHi`/`tellLo` 두 세기가 있어야 합니다.**
🔒 **버릴 것은 「신뢰도가 둘인 것」이 아니라 「맞으면 1, 틀리면 0」이라는 결과 매핑입니다.**

## 2. ★ 설계 — **2단 국면**

### 2-1. 흐름

```
┌─ 1단계 · 읽기 ───────────────────────────────┐
│  🧱 어디로 파고들까요?                        │
│                                              │
│  🦶 주발      오른발잡이                      │   🔒 지금 그대로입니다
│  ⬅️ 몸 방향   왼쪽으로 · 확실히 틀었어요       │   🔒 움직이는 것 없음
│                                              │   🔒 시간 무제한
│      [ ⬅️ 왼쪽 ] [ ⬆️ 가운데 ] [ ➡️ 오른쪽 ]   │
└──────────────────────────────────────────────┘
                    ↓  고른 순간
┌─ 2단계 · 손 ─────────────────────────────────┐
│  🧱 지금이에요!                               │
│                                              │
│   🏃‍♂️ ──────────▶            🛡️              │   🔑 상대가 내 앞을 지나갑니다
│   ├────[    판정 창    ]────┤                 │   🔑 창의 폭 = 읽기가 정합니다
│                                              │
│              [ 🛡️ 막기 ]                      │   ⏱️ 1.6초
└──────────────────────────────────────────────┘
```

### 2-2. 🔑 **읽기가 판정 창을 정합니다** — 이게 설계의 전부입니다

```js
s = sBar( 타이밍 오차, BLK_WIN × BLK_READ[읽기결과] × mul )
```

| 읽기 | `BLK_READ` | 읽히는 말 |
|---|---|---|
| **정확** (`pick === truth`) | **1.00** | *"방향을 완벽히 읽고 그 자리에 서 있었어요"* |
| **인접** (한 칸 옆) | **0.45** | *"반 박자 늦었지만 몸을 걸쳤어요"* |
| **반대** | **0.15** | 🔑 *"역동작에 걸렸는데 **발을 뻗어 걷어냈어요**"* |

**셋이 지켜집니다:**

| | | |
|---|---|---|
| ✅ | 🔑 **`s`가 연속이 됩니다** | 타이밍이 연속값이니까요. **이산이 사라집니다** |
| ✅ | 🔑 **읽기가 결과에 직접 실립니다** | 잘 읽으면 창이 **6.7배** 넓습니다 — 난수 한 겹이 **판정 창**으로 바뀌었어요 |
| ✅ | 🔑 **반대로 읽어도 0이 아닙니다** | 손이 완벽하면 건집니다. **원칙 ③** — 손잡이가 항상 뭔가를 합니다 |

> 🔑 **그리고 이건 이미 있는 문법입니다.**
> 🏃 컷인의 준비 화면이 *"🦶 **주발 쪽 칸이 더 넓어요** — 화면에 보이는 폭이 그대로 판정 창"*이라고
> 적어 뒀어요. **차단도 「잘 읽은 쪽이 더 넓다」가 됩니다.** 새 문법이 아니라 **같은 문법의 확장**이에요.

### 2-3. 🔒 **원칙 ①을 지키는 방식 — 두 국면을 「화면」으로 가릅니다**

`runBlock` 주석의 이 문장이 이 설계의 가장 큰 위험입니다:

> *"🚨 **움직이는 것이 하나도 없어요.** (…) 이건 취향이 아니라 이 메커닉의 존재 이유예요 —
> 🧊 볼카운트가 「타이밍처럼 생겼는데 핵심이 안 누르기」라 세 번 고치고도 죽은 자리입니다."*

**그 경고는 여전히 유효합니다. 그래서 국면을 섞지 않습니다:**

| | 1단계 | 2단계 |
|---|---|---|
| 움직이는 것 | 🔒 **없음** | ✅ 상대 한 명 |
| 시간 | 🔒 **무제한** | ⏱️ **1.6초** |
| 화면이 약속하는 것 | *"읽어라"* | *"지금 눌러라"* |
| 재촉하는 연출 | 🔒 **금지** (반짝임·카운트다운·색 전환) | ✅ 있어야 합니다 |

> 🔑 **볼카운트가 죽은 이유는 「타이밍처럼 보이는데 타이밍이 아니어서」였습니다.**
> 여기서는 **타이밍처럼 보이는 국면이 진짜 타이밍**이고, **읽기 국면은 타이밍처럼 안 보입니다.**
> 🔴 **1단계에 초읽기를 붙이는 순간 정확히 볼카운트가 됩니다.** 이 문장을 주석에 남기세요.

### 2-4. ⚠️ 2단계가 「또 하나의 컷인」이 되면 안 됩니다

🏃 컷인·🥅 마무리·🎯 킬패스는 전부 **「움직이는 것을 겨눠 맞추기」**입니다.
2단계도 그러면 **넷이 다 같은 게임**이 되고 H3(반복)이 나빠집니다.

★ **그래서 2단계는 「겨냥」이 아니라 「순간」입니다** — 방향은 이미 1단계에서 정했어요.
**고를 게 없고 「언제」만 남습니다.** 버튼도 **하나**입니다(`🛡️ 막기`).

| | 조작 | 고르는 것 |
|---|---|---|
| 🏃 🥅 🎯 | **어디를** 겨눠 **언제** | 방향 + 시점 |
| 🧱 **2단계** | 🔑 **언제만** | **시점 하나** |

> 🟢 **버튼 하나 · 1.6초**라 **탭이 안 늘어납니다**(1단계 1탭 → 2단계 1탭 = 지금과 같은 2탭 구조).
> ⏱️ 판당 **+1.6~2.0초.** 나머지 셋이 2.5~6초라 **차단이 그 범위 안으로 들어옵니다** —
> 지금은 무제한이라 **혼자만 길이가 정의되지 않았습니다.**

## 3. ④ 판정 — **3택 읽기를 살립니다**

조율자님 물음: *"읽기 자체가 재미없는 건지, 읽기인데 손이 안 먹혀서인지"*

★ **후자입니다.** 근거 셋:

| | |
|---|---|
| ① | 🔑 **겹쳐 읽기 설계가 정교합니다.** 부등호가 양쪽에서 뒤집히도록 계수를 맞췄고(`0.58 > 0.336` · `0.24 < 0.608`), *"세기가 하나면 s가 0.540에서 한 걸음도 안 움직인다"*까지 **실측으로 확인**했어요. **이건 좋은 설계이고 버리면 아깝습니다** |
| ② | 🔑 소스가 *"`beta/soccer/cup.js`의 승부차기 문법 — **이 저장소에서 유일하게 성공한 축구 조작**"*이라고 적어 뒀습니다. **문법 자체는 통합니다** |
| ③ | 🔴 **문제는 읽기가 아니라 「읽은 것이 결과에 안 실리는 것」**입니다(§1) |

### 🟡 참고작의 텍스트 3택은 왜 성립하나 — 그리고 왜 우리는 다른가

조율자님이 짚으신 대로 **텍스트 3택도 그것대로 성립합니다.**
🔑 **다만 거기는 「읽기」가 게임의 **전부**이고, 우리는 **넷 중 하나**입니다.**

> 🔴 **한 게임 안에 장르가 둘이면 어긋남으로 읽힙니다** — 그게 §101이 짚은 것이고,
> 범민 님이 *"미니게임 별로"*라고 **통째로** 말씀하신 이유일 수 있어요.
> ★ **그래서 「읽기를 버려서」가 아니라 「읽기에 손을 얹어서」 장르를 맞춥니다.**

## 4. 수치와 그 근거

> ⚠️ **아래 값은 balancer의 실측 전까지 전부 「제안」입니다.**

### 4-1. 🔴 계수 둘 — **성격이 다르니 표를 나눕니다** (원칙 ⑨)

```js
/* 📏 **중립화 값입니다. 난이도 손잡이가 아니에요.**
 * 🔗 종속값 — `BLK_READ`·상대 속도·1.6초 중 하나라도 바뀌면 **따라 재계산**하세요.
 * 이 값이 하는 일은 하나뿐입니다: 🔑 **E[s] 평균을 0.537에 붙들어 두는 것.**
 * (넷의 평균이 0.521~0.537로 폭 0.017인 게 원칙 ④를 만듭니다) */
const BLK_WIN = 0.30;        // 상대가 내 앞을 지나는 구간 대비 판정 창 (제안)
```

```js
/* 🎯 **읽기 보상 — 이건 트레이드오프 손잡이입니다.**
 * 「읽기를 얼마나 결과에 실을 것인가 ↔ 손을 얼마나 실을 것인가」를 맞바꿉니다.
 * 🔴 키우면 읽기 게임이 되고, 줄이면 타이밍 게임이 됩니다. **숙련도 폭(§4-2)이 여기서 나와요.** */
const BLK_READ = { exact: 1.00, near: 0.45, opp: 0.15 };
```

> 🔴 **둘을 같은 표에 나란히 두지 마세요.** 하나는 **평균을 붙드는 종속값**이고
> 하나는 **폭을 정하는 손잡이**입니다. 「훈련 계단 보정」에서 데인 자리와 같은 형태예요.

### 4-2. ⑤ **숙련도 폭 목표 — 8~12%p**

| | 🏃 컷인 | 🥅 | 🎯 | 🧱 지금 | 🧱 **목표** |
|---|---|---|---|---|---|
| `E[s]` 폭 | 0.43 | 0.28 | 0.29 | 0.05 | **0.21 ~ 0.32** |
| `Δperfect = 2·half(70)·ΔE[s]` | 16%p | 11%p | 11%p | 🔴 **2%p** | **8 ~ 12%p** |

**★ 넷 중 「가장 좁은 쪽」으로 겨눕니다.** 근거 둘:

| | |
|---|---|
| ① | 🔑 **`defend` 카드는 df가 가장 자주 봅니다.** `MINI` 표에서 네 포지션 모두 `block` 하나뿐이고, df는 그 카드가 오는 빈도가 가장 높아요. **같은 폭이면 df 커리어가 조작에 가장 크게 좌우됩니다** — 🔴 **원칙 ⑦(포지션 형평)의 자리**입니다 |
| ② | 🔑 **🛡️ 철벽상이 「무실점 경기 수」**입니다(§①-G). 수비 카드의 조작 폭이 커지면 **부문상이 조작으로 결정**돼요. 🔴 **원칙 ⑥** — *"덜 키운 쪽은 +0"* |

> ⚠️ **①은 제 추정입니다.** balancer가 **포지션별 `defend` 카드 빈도**를 먼저 재세요 (실측 19).
> **빈도가 고르면 폭을 12%p 쪽으로 올려도 됩니다.**

### 4-3. 🔒 **`E[s]` 평균 0.537은 그대로입니다**

```
지금:  E[s] = P(정확)·1 + P(인접)·0.24 + P(반대)·0        ≈ 0.537
새로:  E[s] = E[ sBar(오차, BLK_WIN · BLK_READ[읽기]) ]   ← 0.537 에 맞춥니다
```

🔴 **평균이 움직이면 그건 미니게임 개선이 아니라 밸런스 변경입니다** (원칙 ④).
`BLK_WIN` **하나로만** 맞추세요 — `BLK_READ`를 만져서 평균을 맞추면 **폭이 같이 움직여
무엇을 고쳤는지 못 가립니다.**

> 🔑 **손잡이를 나눈 이유가 이것입니다: `BLK_WIN`은 평균, `BLK_READ`는 폭.**

## 12-3. ★ 반박 ③ — **받아들입니다. 그리고 근거가 하나 결정적입니다**

```
읽기 전략 값어치:  옛 0.143  →  새 0.052   (BLK_READ 극단까지 밀어도 4.6%p)
판 하나 안의 읽기:  정확 0.719  vs  반대 0.175   (Δ 0.544)
```

### (a) 🔑 **둘은 모순이 아니라 같은 거래의 양면입니다**

| | 옛 차단 | 새 차단 |
|---|---|---|
| 읽기의 **기댓값** | **0.143** (높음) | 0.052 |
| 읽기가 **판 하나에서 보이나** | 🔴 **안 보임** — 완벽히 읽어도 42%가 실패 | ✅ **0.719 vs 0.175** |

**옛 것은 「기댓값은 큰데 어느 판에서도 안 보이는」 상태였습니다.**
새 것은 **「기댓값은 작은데 매 판 또렷하게 보이는」** 상태입니다.

### (b) ★★ 결정적 근거 — **옛 것이 2.75배였는데, 그게 「별로」라고 불렸습니다**

> 🔑 **범민 님이 「미니게임 별로」라고 하신 그 차단이 전략 값어치 0.143짜리입니다.**
> **전략 값어치가 지금의 2.75배였는데도 별로였어요.**
>
> ★ **그러니 전략 값어치는 애초에 없던 문제입니다.**
> 그걸 3분의 1로 줄이고 **판 안의 가독성을 3.6배(0.544)로 바꾼 것**이
> **정확히 이 개편의 내용**이고, 🔑 **없던 문제를 팔아 있던 문제를 산 것**입니다.

그리고 §1의 제 진단이 그대로였습니다 —
> *"완벽히 읽어도 58%만 맞습니다. 그래서 **잘 읽은 판과 대충 찍은 판이 결과에서 구분이 안 됩니다.**"*

**0.143은 그 구분 안 되는 판들에 얇게 흩어져 있던 값입니다.** 모아서 보이게 한 거예요.

### (c) 🔴 다만 진짜 위험 하나 — **읽기가 「탭하고 넘기는 화면」이 되는 것**

`Δperfect = 2 × half(70) × 0.052` ≈ **2.0%p.**
**읽기를 통째로 무시하고 늘 같은 방향을 눌러도 2.0%p만 손해입니다.**

| | |
|---|---|
| 🟢 **왜 괜찮다고 보나** | 🔑 **플레이어는 기댓값을 계산하지 않습니다. 눈앞의 0.719 ↔ 0.175를 봅니다.** *체감되는* 읽기의 값어치는 판 안의 격차예요. 2.0%p는 **최적화하는 사람만** 계산하는 값이고, 30초짜리 육성 미니게임의 관객이 아닙니다 |

## 13-2. ★ **원인 재진단 — 「폭」이 아니라 「이중 계상」입니다**

balancer가 짚은 구조:

```
🧱 조작 ─┬─→ 내 카드 miss ↓ → 팀 실점 ↓ → 무실점 경기 수 ↑ ──┐
         │                                                  ├→ 🛡️ 철벽상
         └─→ 내 차단 수 ↑ ─────────────── 타이브레이커 ─────┘
```

> 🔑 **같은 조작이 본선과 타이브레이커를 **동시에** 밉니다. 그게 증폭기입니다.**
> **한 성적을 두 번 세는 것**이고, 제가 §101 §3-3에서
> *"승패를 `spotMul`에 걸면 한 성적을 두 번 세는 것이고 그건 원칙 ⑪"*이라 적은 것과 **같은 형태**예요.

### 🚨 그리고 더 깊은 것 하나 — **①-G의 축 개편이 절반만 끝나 있었습니다**

①-G가 「차단 횟수」를 버린 근거는 이랬습니다:
> *"1위가 「가장 잘 막는 수비수」가 아니라 **「가장 자주 두들겨 맞는 팀의 수비수」**가 됐다."*

그래서 **「무실점 경기 수」**로 갈았는데 — 🔴 **무실점은 클럽 값이라 동료 11명이 전부 동점**입니다.
**본선의 변별력이 0이면 실제로 상을 정하는 건 타이브레이커입니다.**

> 🚨 **즉 축은 「무실점 경기 수」로 갈았지만, 실판정자는 여전히 「차단 횟수」였습니다.**
> **버린 축이 「타이브레이커」라는 이름으로 뒷문으로 돌아온 것입니다.**
>
> 🔑 **CLAUDE.md 2026-08-28 — *"폐기는 이름이 아니라 형태"*.**
> `ACE_W`를 폐기해 놓고 **같은 형태의 계단을 다른 이름으로 되살린** 그 자리와 같습니다.
> 이번엔 되살린 이름이 **「타이브레이커」**였어요.

### 🔑 그래서 ⓑ에 대한 답 — **"두 번째로 가는 게 맞나"가 아닙니다**

> ★ **축은 안 바꿉니다. 「첫 번째가 절반만 끝난 것」을 마저 끝냅니다.**
> **①-G의 판정(무실점 경기 수)은 그대로 삽니다.** 고칠 것은 **타이브레이커**입니다.

### 🔴 그리고 비대칭 하나가 여기서 드러납니다

| 상 | 조작이 닿는 경로 |
|---|---|
| 🥇 골든부츠 · 🎯 플레이메이커 · 📈 | ⚽🅰️ 카드 `perfect` → **골·도움 (개인·누적)**. 🔑 **한 겹** |
| 🛡️ **철벽상** | 🧱 카드 → **팀 무실점 + 내 차단**. 🔴 **두 겹** |

> 🔑 **공격 3상은 조작이 「한 겹」으로 닿고 수비 1상만 「두 겹」입니다.**
> 그래서 폭을 똑같이 넓혀도 **df만 튑니다.** 미니게임이 이상한 게 아니라 **상의 배선이 이상합니다.**

## 13-3. ★ 판정 — **ⓒ + ⓓ. 그리고 폭 목표 자체를 폐기합니다**

### (a) 🔴 **`8~12%p`는 제가 잘못 세운 목표입니다**

§4-2에 제가 이렇게 적었습니다:
> *"나머지 셋이 11~16%p입니다. **넷 중 가장 좁은 쪽으로 겨눕니다.**"*

**그건 「형평」 논거였지 「범민 님 피드백」 논거가 아니었습니다.**
그리고 실측이 말합니다 — **df에서는 그 형평을 맞추는 순간 부문상이 무너집니다.**

> 🔑 **형평을 위해 부문상을 부수는 건 순서가 거꾸로입니다.**
>
> ★ **목표를 「대리 지표」에서 「진짜 지표」로 바꿉니다** (§2-2에서 「결정 탭 4」를
> 「첫 카드 앞 결정 3」으로 고친 것과 **같은 수정**입니다):
>
> | | |
> |---|---|
> | 🔴 **옛 목표 (폐기)** | 🧱 숙련도 폭 **8~12%p** |
> | ✅ **새 목표** | 🔒 **「🛡️ 철벽상의 서툰↔능숙 격차가 개편 전(Δ3.2%p) 대비 +3%p를 안 넘는 최대 폭」** |

**폭은 이제 결과값이지 목표값이 아닙니다.** 실측 23이 그 자리를 맡습니다.

⚠️ balancer 선형 추정으로는 **폭 3%p 안팎**이 될 것 같습니다(2%p→3.2 · 8%p→19.3).
**그러면 개편 전과 거의 같습니다. 정직하게 적습니다 — 폭은 사실상 포기입니다.**

### (b) 🟢 **그래도 개편의 값어치는 거의 안 깎입니다** — 둘은 다른 것입니다

| | 무엇 | 범민 님이 지적한 것인가 |
|---|---|---|
| **폭 (숙련도)** | **서툰 손 ↔ 능숙한 손**의 `E[s]` 차이 | 🔴 **아닙니다.** 한 번 해보시고 *"별로"*라 하셨어요 — **숙련도 곡선을 체감하실 시간이 없었습니다** |
| **가독성 (판 안)** | 정확 **0.719** ↔ 반대 **0.175** | ✅ **이것입니다.** §1의 진단 — *"잘 읽은 판과 대충 찍은 판이 결과에서 구분이 안 됩니다"* |

> 🔑 **폭을 3%p로 낮춰도 판 안의 0.719 ↔ 0.175는 그대로입니다.**
> **한 판 안에서 읽고 누른 것이 결과에 보이는 것** — 그게 개편의 내용이었고, 남습니다.
>
> ★ **§12-3(b)와 정확히 같은 구조입니다** — 그때는 *"없던 문제(전략 값어치)를 팔아
> 있던 문제(가독성)를 샀다"*였고, 이번엔 *"없던 문제(숙련도 폭)를 팔아 부문상을 지킵니다."*
> **두 번 다 파는 쪽이 「지적받지 않은 것」입니다.**

**그리고 부수로 얻은 것도 남습니다** — 🔑 **차단이 처음으로 컨디션을 탑니다**(50번 §5의 열린 항목),
**2단계 1.67~1.73초로 길이가 정의됩니다**(전에는 무제한이라 혼자만 정의가 없었어요),
**`sBar` 공통 자에 합류**(§10).

> 🔴 **그러니 ⓐ(개편 전으로 되돌리기)는 하지 않습니다.** 폭만 좁히면 되고,
> 되돌리면 **가독성·컨디션·길이·공통 자 넷을 함께 잃습니다.**

### (c) ★ ⓓ — **타이브레이커를 「조작이 안 닿는 값」으로**

**이게 폭을 다시 열 수 있는 유일한 길입니다.**

```
지금:  무실점 경기 수 (동점)  →  타이브레이커 = 내 차단 수   🔴 조작이 두 겹
바꾼 뒤: 무실점 경기 수 (동점)  →  타이브레이커 = 🔒 조작이 안 닿는 값
```

**타이브레이커 후보 — 셋 다 「육성이 정하는 값」입니다:**

| 후보 | 좋은 점 | 걸리는 점 |
|---|---|---|
| ⭐ **수비 능력치** | 🟢 **가장 곧습니다** — *"팀에서 가장 좋은 수비수가 클린시트 상을 받는다"* · 🟢 원칙 ⑥ 정면 통과 | 🟡 시즌 안에서 안 변해 **한 팀의 임자가 고정**됩니다 |
| **출전 경기 수** | 🟢 누적·무상한(원칙 ⑤) · 🟢 조작 무관 | 🔴 **부상·로테이션 축이 상을 정하게** 됩니다 |
| **종합 능력치** | 🟢 육성 총량 | 🔴 공격 스탯이 수비상에 실립니다 |

**★ 「수비 능력치」를 권합니다.** ⚠️ *"임자가 고정된다"*는 🔑 **의도한 것**입니다 —
**육성 축이니까요.** 그리고 상은 시즌마다 **내가 키운 만큼** 옮겨 갑니다.

> 🔴 **그러면 조작이 상에서 거의 사라집니다. 그게 맞습니다.**
> 조작은 이미 **`spotMul`·경기 평점·⭐ 명성**에 닿아 있어요.
> 🔑 **원칙 ⑥ — 상은 육성이 정하고, 조작은 경기 안에서 보이면 됩니다.**

⚠️ **이건 곡선 변경입니다.** 🔴 **폭 조정(ⓒ)과 같이 내보내지 마세요** — 둘 다 철벽상에 닿습니다.
**ⓒ 먼저(싸고 급함), ⓓ는 실측 22의 값을 보고.**

### (d) 🔴 그리고 ⓓ를 하기 전에 물어야 할 것

> **「공격 3상은 조작이 한 겹인데, 수비상만 조작을 뺀다」가 비대칭 아닌가?**
