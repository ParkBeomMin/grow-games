## 1. ① D-2 — **재현본을 버리고 진짜 경로로**

지적이 정확했습니다. 제 D-2는 옛 순서를 **손으로 재현**하고 있었어요:

```js
oldSave.proYear += 1; P.birthday(oldSave);   // ❌ 제가 옛 순서를 흉내 냄
```

고침이 *"순서 바꾸기"*라 **고친 뒤에도 재현본은 옛 순서를 그대로 돌립니다** —
검사가 코드가 아니라 **제 재현본**을 재게 돼요. 영영 빨간불입니다.

### 고친 것 — 진짜 `startPrep`을 두 번 부릅니다

```
✅ D-2. 🎂 age 칸이 없는 옛 세이브도 진짜 startPrep에서 한 시즌에 한 살만 먹는다 (21 → 22 → 23)
✅ D-2-변이. birthday를 proYear 뒤로 되돌리면 → 빨간불 (21 → **23**, 한 시즌에 2살)
```

변이는 `career.js`의 **두 줄 순서를 실제로 뒤집습니다**(`MUT.OLD_ORDER`).
재현이 아니라 **소스를 되돌려** 확인해요.

### 🔁 그리고 순서에 안 기대는 형태를 하나 더

```
✅ D-3. 🎂 birthday가 나이 칸을 확정한 뒤에는 **시즌 번호가 나이에 안 닿는다**
        (21 → 22 → 시즌+1·연차+1 뒤에도 22)
```

이 불변식이 서 있으면 **`birthday`를 어느 순서로 불러도 안전**합니다.
`game.js`의 유스 해넘이(`S.year += 1` · `birthday`)도 같은 자리인데,
유스 화면을 12개월 몰아 돌리는 건 비싸서 **형태로 덮었습니다.**

## 2. ② 32-0 — **벤치는 정상입니다. 제 계약이 틀렸습니다**

제가 *"`clubRows()`에 내 줄이 있다"*를 회귀로 걸었는데 **그건 틀린 계약이었습니다.**
벤치는 게임이 원래 하는 일이고, 밸런스가 움직이면 언제든 다시 그렇게 됩니다.

> engineer 확인: 곡선을 판정 자리 전부에 걸면서 픽스처의 21세 신인이
> 종합 49.4 → **41.3**이 되어 벤치로 밀렸습니다.

**검사가 밸런스 변경을 못 견디면 그 검사가 잘못된 겁니다.**

### 계약을 바꿨습니다

```
✅ 32-0.  🔗 clubRows()가 leagueXI와 맞는다 — 선발이면 me 줄이 있고 벤치면 없다
          (전체 66줄 · me 0줄 · isStarter false)
✅ 32-0b. 🪑 벤치였으면 **선발로 세워** 아래 검사를 돌린다 (벤치였음 → 선발로 · me 1줄)
```

- 지키는 것은 **정합성**(`leagueXI` ↔ `clubRows`)이지 *"내가 선발이다"*가 아닙니다
- 그리고 **벤치라서 건너뛰지 않습니다** — 스탯을 올려 선발 상태를 만들고 32-4~8 · 34를 다 돌려요.
  건너뛰면 *"안 돈 것"*이 초록으로 섞이니까요. 스탯을 올리는 건 **검사 쪽 준비**이지
  소스를 고치는 게 아닙니다

**결과: 32-4~8 · 34-1~7이 다시 다 돕니다** (14개 검사가 살아났어요).

## 3. ③ 검사 38 — **만들자마자 제 검사가 틀렸습니다**

### 무슨 일이 있었나

코디가 넘겨주신 형태로 만들었습니다:

```js
trainMul(조숙, 22세) === trainMul(보통, 26세)     // 정점에서 같아야 한다
```

**그 자리에서 빨간불이 떴습니다** — 조숙 1.226 / 보통 1 / 만성 0.839.

```
❌ 38-1. 세 타입의 정점에서 훈련 효율이 같다 — 조숙 22세 1.226 · 보통 26세 1 · 만성 30세 0.839
```

**소스를 먼저 읽었습니다.** 제 지침이 *"검사가 빨간불인데 코드가 맞아 보이면,
검사를 고치기 전에 코드를 한 번 더"*라서요. 읽어 보니 **회귀가 아니라 판단**이었습니다:

```
지운 것 : "조숙은 훈련이 빠르다" 라는 **세기 손잡이** (`train`)
되살린 것: 계단의 **짝** — 손으로 고른 값이 아니라 계단에서 **역산한 종속값**
           TRAIN_NEUTRAL[t] = Σ trainStep(a, peak(보통)) ÷ Σ trainStep(a, peak(t))
```

**같은 숫자인데 다른 물건입니다.** 계단(1.1/1.0/0.7/0.45)이 **정점 기준**이라
정점이 이른 타입은 계단을 일찍 내려가요 — 짝이 없으면 훈련 총량이
**81.5 / 100 / 119.2**로 갈립니다. *"상쇄되고 있던 게 아니라 상쇄하고 있던 것"*이 맞습니다.

> ### 🆕 이게 새 유형입니다 — **설계가 뒤집히면 검사가 옛 계약을 지킵니다**
> 문법은 멀쩡하고 변이도 걸리는데 **지키는 문장이 이제 틀린 것**이에요.
> *"초록불인데 아무것도 안 지키는 검사"*의 거울상입니다 —
> **빨간불인데 지키면 안 되는 것을 지키는 검사.**
> 둘 다 결과는 같아요: 사람이 그 검사를 안 믿게 됩니다.

### 다시 쓴 것 — `58_engineer_train-neutral.md` 규격 그대로

| # | 무엇 | 실측 |
|---|---|---|
| **38-1** | 🏋️ **커리어 훈련 총량이 세 타입에서 같다** (20~37세) | 13.547 / 13.550 / 13.550 · **1.0002배** (≤1.03) |
| **38-2** | 🏋️ **계단은 거리만 본다** — 등식이 아니라 **비가 일정한가** | 거리 12칸에서 조숙 1.226 · 만성 0.839 **각각 한 값** |
| **38-3** | 🔗 상수가 **살아 있는 `trainStep`에서 역산한 값**과 맞는다 | 1.226 vs **1.2262** (차 0.00024 ≤ 0.005) |

**변이 넷 전부 잡힙니다:**

```
✅ 38-변이①. 계단의 짝을 지우면 → 빨간불 (총량 [11.05 13.55 16.15] · 비 1.462배)
✅ 38-변이②. 세기 배수를 **이름만 바꿔**(bloom) 부활시키면 → 빨간불 (비 1.372배)
✅ 38-3-변이. **계단만 고치고 상수를 안 고치면** → 빨간불 (조숙 1.226 vs 1.2180)
```

- **38-1은 상수를 안 읽습니다** — *"세 값이 서로 같은가"*만 봐요
- **38-2가 타입별 상수는 허용하고 계단이 타입을 보는 것만** 잡습니다.
  등식으로 잡았다면 상수가 되살아난 지금 세계에서 **성립할 수 없었어요**
- **38-3은 `_t.TRAIN_NEUTRAL`을 읽습니다.** 그런데 *"문턱을 코드에서 읽는"* 함정이 아니에요 —
  **살아 있는 `trainStep`에서 계산한 값과 대조**하니 둘 중 하나만 바뀌면 잡힙니다.
  소스 주석의 *"계단을 바꾸면 여기를 다시 역산해야 해요"*를 검사가 지키는 자리입니다
- 변이 이름도 `BLOOM` → **`NEUTRAL_OFF`**로 갈았고, 정규식에 **값을 안 적었습니다**
  (`/const TRAIN_NEUTRAL = \{[^}]*\};/`) — balancer가 재조정해도 안 죽어요

> 📏 재는 자가 다릅니다 — 저는 **최대 ÷ 최소**, engineer 58번은 다른 눈금으로 0.01% / 18.90%.
> **가리키는 현상은 같습니다.** 검사 주석에 그렇게 적어 뒀어요.
