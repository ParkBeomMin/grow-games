### 🔴 함께 고친 것 — 대회(월드컵) 모드

**`body.wc-mode`가 이미 "밤 경기장 네이비 + 골드"였습니다** (`style.css:478`, 옛 주석 그대로).

## 2. 순간 카드 경기 화면 — `beta/winger2/match-scene.js`

### 2-1. 화면 구조 (설계 §5-5 그대로)

```
┌─ .w2-top  position: sticky; top: 0 ────────┐
│  청록 유나이티드   1 : 1   잿빛 시티        │
│  ⏱ 45'                      🔥 내 순간 1회  │
│  ▓▓▓▓▓░░░░░░░░░  ← 흐름 막대               │
└────────────────────────────────────────────┘
   12'  🟨 상대 압박이 거세요           ← 아래에서 위로 push-in
   27'  ⚽ 골!! 박스트, 그물을 흔듭니다!
   41'  😣 뚫렸어요… 실점
   ── 🥅 하프타임 · 점유 48% · 슛 6 · 내 평점 6.8 ──   ← 세 값은 아직 엔진이 안 줘요 (§4)
   58'  🔥 골문 앞! 이걸 넣으면 역전입니다   ← 여기만 타이핑
        [ 미니게임 ]
   58'  ⚽ 골!! 김윙어, 그물을 흔듭니다!
        ⚽ G O A L !!
   90+3' 삐— 경기 종료 휘슬
   🏆 결승골!!                               ← 결승골은 휘슬에만 알 수 있어요
   🔥 이 경기의 내 순간 1회 (성공 1)
```

**흐름 막대**는 옛 미니 필드를 대신합니다. 현행 더 윙어의 공은
`b.style.top = (26 + Math.random() * 46) + "%"` (`game.js:2066`) — **흐름과 무관하게 무작위로 튀고**,
`left`/`top`을 애니메이션해서 프레임마다 레이아웃을 다시 돌렸어요.
새 막대는 카드의 주인(우리 공격 / 상대 공격 / 중립)만 `transform: translateX`로 보여줍니다.
**정직한 한 줄**이고, 레이아웃을 안 건드립니다.

### 2-2. 밀도의 차이 — 이게 핵심입니다

| | 값 | 왜 |
|---|---|---|
| 카드 간 딜레이 | **1점 차 이내 900ms · 2점 차 600ms · 3점 차 이상 350ms** | 0-0이면 뜸을 들이고, 기운 경기는 빨리 넘깁니다. `setTimeout` 값 하나가 서스펜스예요 |
| 타이핑 | **🔥 내 순간 카드만** · 40~60ms/자 | 전부 타이핑하면 지루해집니다. 다른 카드는 즉시 |
| ⏩ 빨리감기 | 딜레이 90ms · 타이핑 끔 | **개입은 유지합니다.** 현행처럼 승부처를 확률 굴림으로 대체하면(`game.js:1891`) 게임이 사라져요 |
| 추가시간 | `end` 카드의 분이 `90+1~4` | 설계 §5-5의 *"1점 차일 때 카드가 하나 더"*는 **엔진이 안 넣었습니다** — 카드가 9장이 되면 balancer가 방금 잡은 곡선이 움직여서요. 화면은 **분 표시로만** 추가시간을 냅니다 (`90+3'`). 실측 게이트에서 designer·balancer가 판단할 항목이에요 |

### 2-3. 무엇이 걸렸는지 — 첫 줄 (설계 §5-1)

같은 미니게임이 결정으로도 전개로도 열립니다. **결과가 다른 건 괜찮지만 무엇이 걸렸는지
모르는 것이 문제**라, 순간 카드의 첫 줄이 반드시 그걸 밝힙니다.

```
⚽ 결정  🔥 골문 앞! 이걸 넣으면 역전입니다
🅰️ 전개  🎯 동료가 뒷공간으로 뛰어요 — 이 패스가 통하면 동점입니다
🧱 수비  🧱 상대 에이스가 달려듭니다 — 여기서 막으면 리드를 지킵니다
```

꼬리말은 `card.stake`에서 옵니다(`동점`·`역전`·`리드`·`만회`·`동점 저지`).
**엔진이 안 주면 그 시점 스코어차로 만들되, 없는 말을 하지 않습니다** —
`역전`은 화면이 못 알아내는 값이라 자체 계산에서는 안 씁니다.

### 2-4. 사후에 셉니다 (설계 §5-2)

**사전에 "경기당 2회"를 약속하지 않습니다.** 능력치 70은 실제로 0.72~0.88회라 거짓말이 됩니다.

```
🔥 이 경기의 내 순간 2회 (성공 1)
🔥 이 경기엔 내 순간이 오지 않았어요 — 능력치가 오르면 더 자주 옵니다   ← 0회일 때
```

0회 문구를 따로 둔 이유: 0회는 **버그가 아니라 정상**인데, 아무 말도 안 하면
플레이어는 화면이 고장 난 줄 압니다. 그리고 이 줄이 **"능력치를 올리면 이 숫자가 는다"를
가르치는 자리**예요 — 그게 §5-2가 말한 성장의 체감입니다.

## 3. 골 연출 — 배선을 이었습니다 (설계 §5-4)

`fx.js`는 처음부터 `confetti`/`burst`/`flash`/`celebrate`를 갖고 있었는데
**더 윙어의 `Fx` 호출 20곳 중 골에 붙은 게 하나도 없었습니다.**

| 사건 | 붙인 것 |
|---|---|
| ⚽ **내 골** | 앰버 풀스크린 플래시 · 셰이크 0.3s · `⚽ G O A L !!` 배너 스케일업 · `Fx.burst(스코어보드, "⚽")` · **진동 40ms 한 번** |
| ⚽ 동료 골 | 초록 플래시만 (0.3s · 약하게). 배너·셰이크·진동 없음 |
| 🅰️ **내 도움** (동료 골 + 내 도움) | 내 골과 같은 등급. `🅰️ 도움!!` 배너 — **내 순간**이라 크게 갑니다 |
| 😣 실점 | 회색 플래시 + **좌우** 흔들림 (0.24s) |
| 🏆 결승골 | **`end` 카드에서** `🏆 결승골!!` + `Fx.confetti({ level: "big" })` |

> 🔴 **결승골은 카드가 열리는 순간에 축하할 수 없습니다.** 1-0 뒤에 2-2가 되면
> 그 골은 결승골이 아니거든요. 엔진의 `markDecisive()`도 경기가 끝나야 채웁니다.
> 그래서 화면도 **휘슬에** 터뜨립니다. 카드 시점에 쓸 수 있는 건 `goAhead`뿐이라,
> 골 배너를 `⚽ 앞서 나갑니다!!`로 바꾸는 데까지만 씁니다.
>
> **엔진이 따로 뭘 넘기지 않아도 됩니다.** `markDecisive()`가 `end` 카드를 내기 **직전에**
> 이미 그린 카드 객체를 되채우므로, 화면이 기억해 둔 내 골 카드를 휘슬 때 다시 보면 압니다.
> `summary()`에 `decisive`를 넘기실 필요가 없어요.

### 지킨 것

- **`transform`·`opacity`만 애니메이션합니다.** 옛 `.pitch.goal-h`는 `box-shadow`를 애니메이션해서
  프레임마다 페인트를 다시 돌렸어요 — `opacity`만 움직이는 `::after` 레이어로 바꿨습니다.
- **셰이크는 `body`가 아니라 `.w2-scene`에 겁니다.** `body`에 `transform`이 붙으면
  `position: fixed`의 기준이 바뀌어 **`fx.js`의 색종이 레이어(`.fx-layer`)가 엉뚱한 데 뜹니다.**
  설계는 "`body` 셰이크"라고 적었지만 그대로 하면 색종이가 깨져요.
- **소리 없음.** 저장소 전체 오디오 호출 0건 — 무음 기대를 깨지 않습니다.
- 진동은 **우리 골에만**. 실점·동료 골에는 안 울려요.

### ♿ `prefers-reduced-motion` — 축약 대상이 아닙니다

```css
@media (prefers-reduced-motion: reduce) {
  .w2-card, .w2-half, .w2-goal, .w2-score.bump,
  .w2-scene.shake, .w2-scene.shake-x, .pitch.goal-h::after, .pitch.goal-a::after
    { animation: none !important; }
  .w2-flow-mark { transition: none !important; }
  .w2-flash { display: none !important; }
}
```

**끄더라도 정보는 전부 남습니다.**

| 정보 | 켰을 때 | 껐을 때 |
|---|---|---|
| 골이 들어갔다 | 배너 + 플래시 + 셰이크 | **배너 텍스트가 그대로 DOM에 남습니다** (움직임만 없음) |
| 스코어 | 숫자가 튕김 | 숫자만 바뀜 |
| 무엇이 걸렸는지 | 한 자씩 타이핑 | 통째로 즉시 |

> 🔴 **`Fx.flash`를 정보에 쓰지 않았습니다.** `fx.js:123`이 `if (reduced() || !text) return;`이라
> reduced-motion에서 **문구가 통째로 안 뜹니다.** 골 배너를 `Fx.flash`에 맡겼으면
> 어지럼증 옵션을 켠 사람은 골이 들어간 걸 모르게 돼요. 그래서 배너는 피드에 직접 그립니다.
> **`Fx`는 장식(색종이·이모지)만 맡깁니다.**

## 4. 엔진 경계면 — engineer가 맞춰 주셔야 하는 것

화면이 읽는 필드입니다. 이름이 다르면 **화면은 조용히 아무것도 안 그립니다** (이 저장소 단골 버그).

```js
// 카드 1장
{
  min: 27,                 // 표시 분. 추가시간은 91~95 (화면이 90+N'으로 씁니다)
  kind: "kick" | "goal" | "assist" | "defend" | "filler" | "half" | "end",
  mine: true,              // 내가 주인공인가 → 화면이 미니게임 자리를 엽니다
  moment: "cutin" | "oneone" | "killpass" | "block" | null,
  stakeKey: "equalize",    // ← 화면이 **이걸** 봅니다 (한국어 문자열 비교를 안 하려고)
  stake: "동점",           // 사람이 읽는 이름. 화면은 안 씁니다
  result: "goal" | "assist" | "shot" | "save" | "concede" | "none",
  by: "김윙어",            // 그 장면의 주인공
  goalBy: "박스트",        // 넣은 사람 · assistBy: 찔러 준 사람
  assistBy: "김윙어",
  text: "…",               // 없으면 화면이 kind/result로 만듭니다
  score: [1, 1],           // ⚠️ 이 카드 해결 **직후**의 [우리, 상대]
  goAhead: true,           // 이 골로 앞서 나갔나 (카드가 열리는 그 순간에 참)
  decisive: false,         // 결승골 — 🔴 markDecisive()가 **경기 끝에** 채웁니다
  poss: 48, shots: 6, rating: 6.8,   // kind: "half"일 때 (⚠️ 아직 안 옵니다 — 아래)
}

`stakeKey` 8종 → 화면 문구:

| key | 화면이 붙이는 꼬리말 |
|---|---|
| `comeback` · `equalize` · `lead` · `clincher` | 한 점이라도 따라갑니다 · 동점입니다 · 앞서 나갑니다 · 쐐기를 박습니다 |
| `holdBig` · `holdLead` · `holdDraw` · `holdGap` | 추격을 끊습니다 · 리드를 지킵니다 · 균형을 지킵니다 · 더 벌어지는 걸 막습니다 |
```

> ✅ **engine.js와 실제로 붙여서 40경기를 돌렸습니다** (jsdom · `autoJudge`로 자동 판정).
> 스코어보드와 `result()`의 스코어가 40경기 전부 일치 · 피드에 `undefined`/`NaN` 0건 ·
> 순간 카드 36장 전부 첫 줄이 무엇이 걸렸는지 밝힘. 내 순간 빈도 0.90회/경기로
> 설계 §5-2의 wg·능력치 70 (0.78) 밴드 안입니다.

### 화면이 요구하는 다섯 가지

1. **`score`는 카드마다 그 시점의 확정 스코어를 담아 주세요.** 화면이 자체로 누적하지 않습니다 —
   그러면 엔진과 어긋나고, 어긋난 걸 아무도 못 봐요.
2. `mine === true`면 화면이 미니게임 자리를 열고, **판정을 엔진에 되돌린 뒤 `result`가 정해지는**
   순서입니다. 화면은 결과를 만들지 않습니다.
3. `stakeKey`를 계속 주세요. 없으면 화면이 스코어차로 만들지만, 그건 엔진이 아는 걸
   화면이 다시 추측하는 것이라 카드가 뒤집힐 때 틀립니다.
4. `summary({ mineCards, mineSuccess })` — 지금 넘기는 그대로면 충분합니다.
   **결승골은 따로 안 넘기셔도 됩니다** — 아래 §3 참고.
5. **한 장씩** 해결해 주세요. 배열을 한 번에 다 주면 §2의 "마지막 카드 전까지 스코어 미확정"이
   무너지고, v2가 현행처럼 "결과를 정해 놓고 재생"으로 되돌아갑니다.

### 호출 모양

**`career.js`의 `runV2Match`가 이미 부르는 이름 그대로 맞췄습니다.** 드라이버를 고칠 것 없어요.

```js
W2Scene.mount(host, { home, away, myName })
W2Scene.momentSlot()      // 🔥 미니게임이 들어갈 자리
W2Scene.push(card)        // → Promise. 드라이버가 thenable로 기다립니다
W2Scene.summary({ mineCards, mineSuccess })
W2Scene.fast()            // ⏩ 빨리감기 (연출만 짧아지고 순간 카드는 그대로 열려요)
```

| 드라이버가 이렇게 부르면 | 화면은 이렇게 |
|---|---|
| `momentSlot()` → `push(card)` (판정 전) | 미니게임 자리를 만들고, 그 **위에** `🔥 무엇이 걸렸는지` 줄을 타이핑 |
| 판정 뒤 **같은 카드 객체로** `push(card)` | "이제 결과를 그려라"로 알아듣고 결과 줄 + 골 연출. 미니게임 자리는 치웁니다 |
| 미니게임이 없어 `autoJudge`로 온 카드 (`push` 한 번) | 두 줄을 이어서 한 번에 그립니다 |

- **킥오프·하프타임·종료 휘슬도 전부 엔진 카드입니다** (`kind: "kick"/"half"/"end"`).
  화면이 따로 만들지 않아요 — 처음에 양쪽이 다 만들어서 `"킥오프!"` 다음 줄에
  `"경기가 시작됩니다"`가 또 떴습니다. **화면 쪽을 지웠어요.**
- `push()`가 Promise를 돌려주니 `CARD_DELAY`(900/350) 갈래는 안 지나갑니다 —
  딜레이·타이핑을 화면이 온전히 제어합니다.

### ⚠️ 아직 안 오는 값 — 🥅 하프타임 통계

설계 §5-5는 하프타임 카드에 **점유 · 슛 · 내 평점 3개**를 요구합니다. 지금 `blankCard`에는
그 세 값이 없어서 화면은 `🥅 하프타임` 한 줄만 그려요.

**빈 칸을 늘어놓지는 않습니다** — `점유 —% · 슛 — · 내 평점 —`이면 화면이 고장 난 것처럼
보이거든요. 값이 있는 것만 이어 붙입니다. `card.poss` · `card.shots` · `card.rating`을
채워 주시면 그대로 뜹니다.
