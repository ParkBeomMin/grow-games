## 2. 🚨🔑 판정 — **「가리는 줄」은 잡을 수 있습니다. 다만 「동작 검사」로는 못 잡아요**

### 2-1. 먼저 성질을 정확히 재 봤습니다

```
무변이            showOffers() 직접 → hidden=false      최종 hidden=true
M-RESET 단독      showOffers() 직접 → hidden=false      최종 hidden=true   ← 🔴 증상 0장
M-BACK 단독       showOffers() 직접 → hidden=false      최종 hidden=**false** ← ✅ 잡힘
M-RESET + M-BACK  showOffers() 직접 → hidden=**true**   최종 hidden=**true**  ← 🔴 가려짐
```

🔑 **`remove("hidden")`은 무변이 코드에서 하는 일이 전혀 없습니다** —
바로 아래 `toggle("hidden", false)`가 이미 되돌려 주거든요.
그리고 `playedStage("m")`은 **단조**(false → true)라, 「감춰졌다가 다시 보여야 하는」 경로 자체가 없습니다.

> **★ 그래서 이건 「동작하는 줄」이 아니라 「다른 검사의 감도를 떠받치는 줄」입니다.**
> 동작이 없으니 **동작 검사로는 원리적으로 못 잡습니다.** 검사가 부족한 게 아니에요.

### 2-2. 그래서 **감도 자체를 검사**했습니다 — `town-test.js` **T-6d**

```
✅ T-6d. 🚨🔑 감도 검사 — 「끄는 줄」이 T-6b를 떠받치고 있다
     ⒜ M-BACK 단독            → hidden false (T-6b 빨간불 ✔ 감도 있음)
     ⒝ M-RESET + M-BACK 한 벌 → hidden true  (🔴 가려짐 — 그래서 ①이 필요합니다)
```

🔴 **이 검사는 「기준선」이 무변이 소스가 아니라 「M-BACK을 넣은 소스」**입니다 —
재는 것이 게임 동작이 아니라 **다른 검사의 감도**라서요. 그 점을 파일에 크게 적었습니다.

**`remove()` 줄이 사라지면 세 겹이 잡습니다:**

| | 무엇이 | 언제 |
|---|---|---|
| ① | **0번 검사** — `M_RESET` 정규식이 소스에 안 걸려 ❌ 한 줄 | 가장 먼저 (죽지 않고 빨간불) |
| ② | **T-6d** — ⒜⒝가 뒤집힙니다 | 구조가 바뀌면 |
| ③ | 사람 — 파일 주석 | 읽을 때 |

🔑 **①이 핵심입니다.** 이 저장소의 「0번 검사」(변이 정규식 건강 검사)가 원래는
*"변이가 안 도는 걸 죽지 않고 알리는"* 장치인데, **여기서는 「이 줄이 존재해야 한다」는
계약 그 자체**로 두 몫을 합니다. 줄을 지우면 그 순간 빨간불이에요.

### 2-3. ⚠️ 「⒝(가려짐)를 단언하는 것」이 「결함을 정답으로 단언」인가 — 아닙니다

⒝가 단언하는 건 *"①이 ②를 떠받치고 있다"*는 **참인 구조적 성질**입니다.
누가 구조를 바꿔 «①이 없어도 ②가 잡히게» 만들면 이 줄이 빨간불이 되고,
**그때 사람이 이 파일을 엽니다.** 그게 노리는 마찰이에요.

### 2-4. 🔴 engineer의 대안 ②(한 줄로 합치기)는 **반대합니다**

`toggle("hidden", !!early || playedStage("m"))`로 합치면 ⒜⒝ 문제는 사라지지만,
**최종의 계약과 조기의 계약이 한 줄에 묶입니다.** 그러면
*"자리가 앞으로 새는 것"*과 *"뒤로 새는 것"*의 신호가 하나로 합쳐져요 —
designer가 **별개 검사로 두라**고 한 그 자리이고, 이 저장소가 *"성질이 다른 것을 한 검사에
묶지 마라"*로 이미 데인 형태입니다. **①을 남기고 감도를 검사하는 쪽(대안 ①)이 맞습니다.**

### 2-5. 🔑 이 형태를 **두 번 만났습니다 — 이름을 붙여 둡니다**

| | 무엇이 겹쳤나 | 증상 |
|---|---|---|
| 96번 ⓔ | 재도전 **가드 셋** | 하나를 빼도 증상 0장 → 검사가 통째로 죽음 |
| 98번 §5 | 📨 조기 화면이 남긴 **화면 상태** | M-BACK이 초록불로 통과 |

> **★ 형태:** *여러 자리가 같은 상태를 쓰는데 **뒤 자리가 앞 자리의 흔적을 못 지우면**,
> 앞 자리가 뒤 자리의 검사를 가립니다.*
> **방어 둘:** ⒜ 「켜는 줄마다 끄는 줄」 ⒝ **감도 검사**(그 「끄는 줄」이 없으면 무엇이 안 잡히는지를 못 박기).

## 4. 🔑 RNG 질문에 답합니다 — **O-8이 잡습니다** (직접·확정적으로)

## 6. 🆕 발견 — **「← 자리 다시 고르기」는 게임 전체에서 한 번도 안 보입니다**

`btn-back-first`가 서는 자리를 전부 훑었습니다 (거절 판 · 승낙 판):

```
조기e  screen-agency  hidden=true      ← add("hidden")이 감춤
중등뒤 screen-agency  hidden=true      ← playedStage("m")이 이미 true
아크끝 screen-agency  hidden=true
취소뒤 screen-agency  hidden=true      ← 최종 모드라 또 감춤
```

🔑 **`playedStage("m")`이 단조(false → true)이고, 그게 false인 유일한 화면(조기)은 무조건
감추기 때문**입니다. 즉 지금 이 버튼은 **DOM 노드 하나와 세 줄의 로직을 쓰면서 사용자에게는
한 번도 안 보이는 죽은 UI**예요 — 그리고 **그 세 줄이 §2의 「가리는 버그」를 만들었습니다.**

📮 **engineer/designer 판정을 부탁드립니다** — 둘 중 하나입니다:

  있고 ①-D에서 X 경로가 보이게 한다"*를 주석에 적어 주세요 (지금 주석은 *"조기 제안이 그
  자리를 씁니다"*인데, 조기 제안은 **감추는** 쪽이었어요)

  **통째로 사라집니다.** 🔴 다만 그때는 **T-6b · T-6c · T-6d · O-6 네 검사가 옛 계약**이 되니
  같이 지워 주세요 — 저에게 알려 주시면 제가 정리합니다.

⚠️ **T-6b·O-6이 「공허한 검사」인가 — 아닙니다.** 계약이 *"보이면 안 된다"*이고
변이(M-BACK · M-EARLYBACK)가 **보이게 만들어 실제로 잡힙니다.** 다만 «지키는 것의 값어치»가
