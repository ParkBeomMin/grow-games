# 🌏 월드투어 개편과 결산 표 정리

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development

**Goal:** 실기기 확인에서 나온 네 가지를 고친다 — 축구 결산의 이적 이력 표시, 월드투어 버튼 넘침, 투어 로그 버그, 그리고 월드투어가 시시한 문제.

**Tech Stack:** 바닐라 JS classic script. 빌드 없음. 테스트는 node (`tests/idol/` 12종, `tests/soccer/` 15종).

## Global Constraints

- **`beta/` 안에서만 작업한다.** 상용(루트)은 건드리지 않는다.
- **기존 저장 데이터를 마이그레이션하지 않는다.** 읽는 쪽에서 기본값을 준다.
- 성장 곡선·리그·컨셉 상수를 건드리지 않는다.
- 테스트는 **소스에서 추출**하거나 **게임 입구를 통해** 실행한다. 값을 복사해 적은 테스트는 반려 대상이다.
- **`eval("const x = …")`을 쓰지 마라.** `new Function(...)` + `return`을 쓴다.
- 기존 테스트 전부 초록이어야 한다. `node tests/smoke-test.js beta`와 `root`도 통과해야 한다.
- 주석·문구는 한국어 존댓말(`~해요`).
- **CSS는 절대색이 아니라 테마 변수를 쓴다.** 각 게임의 `style.css` 관례를 따른다.

### Task 1: 축구 결산 표에 소속 칼럼

**Files:**
- Modify: `beta/soccer/career.js` (`yearReport()` — 이적 이력 줄과 시즌 표)

**지금 무엇이 문제인가**

결산 화면에 이적 이력이 **텍스트로 한 줄에 나열**된다. 이적을 네 번 하면 세 줄로 접히면서 화면을 잡아먹는다.

```
🔁 이적 이력 — 2시즌 블랙이글스→머드독스(K리그3) · 3시즌 머드독스→파인힐스 ·
4시즌 파인힐스→머드독스 · 5시즌 머드독스→스톤워커스
```

**⚾ 더 드래프트가 같은 문제를 이미 풀었다.** 2.21.1에서 "연도별 기록 — 소속팀을 소속 칸에 합쳐 성적 칸 폭 회복". `beta/rookie/career.js`의 연도별 표를 보고 **같은 방식을 따르라.**

- [ ] **Step 1: 실패하는 테스트 작성**

게임 입구를 통해 검사한다. `tests/soccer/promote-test.js`의 부트스트랩을 재사용하라.

1. 시즌 표에 **소속 칼럼**이 있다 (헤더 텍스트로 확인).
2. 각 행의 소속 칸에 **그 시즌의 클럽 이름**이 들어 있다. 이적한 시즌은 바뀐 게 보인다.
3. **`🔁 이적 이력` 텍스트 줄이 없다.** 표로 옮겼으니 중복이다.
4. 이적을 한 번도 안 한 커리어에서도 표가 정상이다 (소속 칸이 계속 같은 이름).
5. **옛 세이브 방어** — `S.career.years[]`에 클럽 정보가 없는 옛 항목은 `-`로 그린다. 던지지 않는다.
6. 리그가 바뀐 시즌은 소속 칸에서 **리그도 알 수 있다** (짧게).

- [ ] **Step 2: 빨간불 확인** → **Step 3: 구현**

`S.career.years[]`에 클럽·리그를 남겨야 한다. **새 필드이므로 옛 항목에는 없다.**
`S.moves`에서 역산하려 하지 마라 — 복잡하고 틀리기 쉽다. 시즌 결산 시점에 그냥 적어라.

칸이 좁으니 **클럽 이름이 길면 줄여야 한다.** rookie가 어떻게 했는지 보고 맞추라.

### Task 3: 월드투어를 실제 도전으로

**Files:**
- Modify: `beta/idol/career.js` (`playTourCity`, `renderTourCity`, `finishTour`, `TOUR_PLACES`)
- Modify: `beta/idol/index.html`·`style.css` (필요하면)
- Create: `tests/idol/tour-depth-test.js`

**지금 무엇이 문제인가**

사용자 평가: "월드투어가 그냥 너무 시시하게 진행되는 것 같아. 뭔가 특별하거나 조금 더 어렵거나 그런 게 있어야 하겠는데"

구조를 보면 그렇다.

- 도시마다 **미니게임 한 번**. 그게 전부다
- 판정이 `perfect` 0.95~1.0 / `ok` 0.72~0.90 / `miss` 0.42~0.62
- **위험이 없다.** 주석에 "투어가 망해도 팬덤·자금·기록이 줄지 않아요"라고 적혀 있다
- 4~8번 클릭하면 끝난다. 결정이 하나도 없다

**넣을 것 세 가지**

#### 3-1. 강행군 — 컨디션이 깎인다

투어는 실제로 체력전이다. 도시마다 컨디션이 깎이고, **컨디션이 낮으면 판정이 나빠진다.**
뒤로 갈수록 어려워져서 후반 도시가 진짜 고비가 된다.

#### 3-2. 기세 — 연속 만석이 눈덩이가 된다

연속으로 객석을 채우면 화제성이 붙어 다음 도시가 더 잘 차고, **한 번 망하면 리셋된다.**
이러면 초반 실수가 아프고 연승이 짜릿해진다.

#### 3-3. 결정 — 강행할까, 하루 쉴까

**이게 핵심이다.** 컨디션이 낮을 때 도시 앞에서 고르게 한다.

- **강행** — 미니게임을 하지만 컨디션이 낮아 판정이 불리하다. 아주 낮으면 **공연 취소** 위험까지
- **하루 쉬기** — 컨디션을 회복하지만 그 도시 객석은 낮게 확정되고 기세가 끊긴다

취소된 공연은 객석 0으로 남는다. **다만 커리어가 끝나는 벌은 주지 않는다** — 투어 등급이 낮아질 뿐이다.

**수치는 구현자가 실측해서 정하라.** 목표:

| 상황 | 결과 |
|---|---|
| 능력치·컨디션 좋고 미니게임 잘함 | S등급 도달 가능 |
| 능력치 좋지만 후반에 컨디션 관리 실패 | B~C등급 |
| 조건만 겨우 채우고 떠남 | C등급 또는 취소 발생 |

**지금은 사실상 전원 S~A다.** 그게 시시한 이유다. **등급이 실제로 갈려야 한다.**

`tourGrade(fillRate)`의 등급 컷도 새 분포에 맞게 다시 잡아라.

- [ ] **Step 1: 실패하는 테스트 작성** — `tests/idol/tour-depth-test.js`

**게임 입구를 통해 검사한다.** `tests/idol/tour-run-test.js`가 투어를 실제로 도는 부트스트랩을 갖고 있다. 재사용하라.

1. 도시를 돌 때마다 **컨디션이 깎인다.**
2. 컨디션이 낮으면 **같은 미니게임 결과에서도 객석이 낮다.**
3. **기세** — 연속 만석 뒤 객석이 더 높고, 실패 뒤에는 리셋된다.
4. 컨디션이 낮을 때 **"쉬어가기" 선택지가 화면에 뜬다.**
5. 쉬면 컨디션이 회복되고 그 도시 객석은 낮게 확정된다.
6. **등급이 실제로 갈린다** — 미니게임을 전부 `perfect`로 처리한 경우와 전부 `miss`로 처리한 경우의 등급이 다르다. 각 200회.
7. **전원 S가 아니다** — 무작위 플레이 500회에서 S등급 비율이 40% 미만이다.
8. **투어가 망해도 팬덤·자금·기록이 줄지 않는다** (기존 원칙 유지). 취소가 나도 마찬가지다.
9. 옛 세이브 방어 — 새 필드 없이 투어를 시작해도 던지지 않는다.

- [ ] **Step 2: 빨간불 확인**

- [ ] **Step 3: 구현**

`TOUR_PLACES`에 도시별 규모를 붙일지는 구현자가 판단하라.
붙이면 "뒤로 갈수록 큰 시장"이라는 상승 곡선을 만들 수 있다. **안 붙여도 3-1~3-3만으로 목표는 달성 가능하다.**
욕심내지 말고 검사 6·7번을 만족하는 최소 범위로 가라.

- **Task 3이 `tour-run-test.js`를 깨뜨릴 수 있다.** 그 테스트가 투어를 끝까지 도는데, 쉬어가기 선택지가 생기면 클릭 흐름이 달라진다. **깨지면 새 흐름을 지나가도록 고쳐라. 우회하지 마라.**

- **CSS는 러너 사각지대다.** 쉬어가기 선택지가 생기면 버튼이 늘어난다. 실기기 확인이 필요하다.
