# ⚽ 축구 성장 곡선 설계

작성 2026-07-29 · 대상 `beta/soccer/`

## 결론 먼저

**축구의 천장은 축이 아니라 경기 평점이었다.** 아이돌과 증상은 같은데 원인이 다르다.

```js
const rating = clamp(myScore / 10, 1, 10);   // 능력치 60이면 이미 10.0
```

능력치 60부터 평점이 상한에 붙는다. 그 위로는 아무리 키워도 평점도, MOM도, 성적도 같다.

| 능력치 | MOM(주간 1위) 확률 |
|---|---|
| 40 | 3% |
| 60 | 36% |
| 80 | 88% |
| 100 | **98%** |
| 120 | **98%** |
| 130 | **98%** |

축을 아무리 잘 만들어도 이걸 안 고치면 같은 자리에 선다. **셋을 함께 고쳐야 한다.**

## 고칠 것 1 — 경기 평점 (뿌리)

`myScore`에 붙은 상수 `+20`과 상한 없는 팬덤 항이 원인이다.

```js
// 지금
const myScore = (…) * clutch(…) + S.condition / 8 + (S.fandom || 0) / 45 + rand(-5, 5) + 20;
const rating = clamp(myScore / 10, 1, 10);

// 바꿈
const myScore = (…) * clutch(…) + S.condition / 8 + Math.min((S.fandom || 0) / 45, FAN_CAP) + rand(-5, 5) + 20;
const rating = clamp(myScore / RATING_DIV, 1, 10);
```

`FAN_CAP = 12`, `RATING_DIV = 14`.

측정값:

| 능력치 | 평점 (전) | 평점 (후) | MOM (전) | MOM (후) |
|---|---|---|---|---|
| 40 | 7.8 | 5.0 | 3% | 0% |
| 60 | 10.0 | 6.1 | 36% | 1% |
| 80 | 10.0 | 7.1 | 88% | 11% |
| 100 | 10.0 | 8.2 | 98% | 44% |
| 120 | 10.0 | 9.3 | 98% | 84% |
| 130 | 10.0 | 9.8 | 98% | 94% |

**부수 효과가 크다.** `matchContribution`의 성능 계수 `perf`가 전원 최대치(1.6)로 죽어 있었는데
살아난다. 체력(`stamina`)도 `myScore`를 통해서만 작용하는데, 평점이 상한이라 무의미했다.
이제 의미가 생긴다.

> 평점은 MOM 순위표에 그대로 표시된다. 지금은 사용자 화면에 **거의 항상 10.0**이 찍힌다.
> 눈에 보이는 버그이기도 하다.

## 고칠 것 2 — 윙어의 드리블이 성적에 안 닿는다

`matchContribution`이 골은 슛, 어시는 패스, 수비는 수비로만 굴린다.
**드리블은 어디에도 안 들어간다.** 그런데 드리블은 윙어의 주 스탯이다.

도달 가능 범위(상한 130, 초월 5단계 160)에서 잰 결과:

| 포지션 | 전부 130 | 주 스탯 160 + 나머지 90 |
|---|---|---|
| 공격수 | 84% | 92% |
| 미드필더 | 83% | 85% |
| 수비수 | 84% | 92% |
| **윙어** | 85% | **32%** |

윙어만 자기 주 스탯에 투자할수록 나빠진다. 구조적 결함이다.

```js
// 윙어는 돌파로 기회를 만들어요. 골·어시 판정에 드리블이 함께 작용합니다.
const gStat = S.pos === "wg" ? S.stats.shoot * 0.6 + S.stats.dribble * 0.4 : S.stats.shoot;
const aStat = S.pos === "wg" ? S.stats.pass  * 0.6 + S.stats.dribble * 0.4 : S.stats.pass;
```

윙어 32% → **69%**. 다른 포지션은 변화 없다(±1%p).

여전히 공격수 몰빵(92%)보다 낮은데, 이건 의도한 대로다.
윙어는 슛·패스·드리블을 고루 써서 **고르게 키우는 게 유리한 포지션**이 된다.

## 고칠 것 3 — 축을 연말 평가에 연결

축구는 **이미 골·어시스트·수비 성공·출전 수를 시즌·통산 모두 집계하고 있다.**
`hype`만 여전히 순위 기반이라 안 쓰일 뿐이다. 새로 만들 게 없다.

```js
// 지금 — 순위가 전부
const hype = clamp(act.hypeSum / 2.2 - agePen, -1.5, 12);

// 바꿈 — 순위는 연출로 남기고, 연말 평가는 축이 한다
const hype = clamp(Math.log(Math.max(1, posAxis(act))) * AXIS_K - AXIS_OFF - agePen, -1.5, 12);
```

### 포지션별 축

| 포지션 | 골 | 어시 | 수비 | 정규화 |
|---|---|---|---|---|
| 공격수 `fw` | 1.0 | 0.5 | 0.15 | 1.00 |
| 윙어 `wg` | 0.8 | 0.8 | 0.15 | 1.05 |
| 미드필더 `mf` | 0.5 | 1.0 | 0.30 | 0.96 |
| 수비수 `df` | **2.0** | 1.0 | 0.55 | 0.72 |

수비수의 골 가중치가 높은 건 세트피스 득점이 실제로 희소하고 가치가 크기 때문이다.
정규화 계수는 네 포지션의 산출량 차이를 메운다 — 수비수는 시즌 수비 성공이 70회인데
공격수는 골이 38개다. 그대로 더하면 포지션이 곧 유불리가 된다.

`AXIS_K = 3.00`, `AXIS_OFF = 4.19`. 그리드 탐색으로 잡았다.

#### 정규화 계수 재보정 (승부처 극장골 누락)

`wg`·`mf`·`df`의 정규화 계수와 `AXIS_OFF`는 **처음 값에서 한 번 고쳐졌어요.**
첫 캘리브레이션의 시뮬레이션에 **승부처(결정적 순간) 극장골이 빠져 있었어요.**

`MatchSim.finish`는 `myGoals: goals + (momentRes === "perfect" ? 1 : 0)`으로
승부처를 완벽하게 처리하면 한 골을 내 골에 얹어요. 그 값이 그대로 `act.goals`에
들어가서 `POS_AXIS[pos].g`를 먹어요. 승부처 성공률은 능력치 110에서 약 48%라
시즌 12경기면 극장골이 5~6개예요. 그런데 **수비수의 골 가중치는 2.0**이라,
이 5~6골이 수비수에게만 10~12점의 축을 얹어줬어요.

그래서 극장골을 뺀 시뮬레이션으로 잡은 계수를 실제 게임에 적용하면 수비수가
과보상됐어요 — 능력치 90에서 미드필더 21% 대 수비수 44%까지 벌어졌어요.
`tests/soccer/curve-test.js`가 이걸 잡았고, 극장골을 포함해 다시 잡은 값이 위 표예요.

| 상수 | 재보정 전 | 재보정 후 |
|---|---|---|
| `POS_AXIS.wg.n` | 1.02 | **1.05** |
| `POS_AXIS.mf.n` | 0.88 | **0.96** |
| `POS_AXIS.df.n` | 0.76 | **0.72** |
| `AXIS_OFF` | 3.80 | **4.19** |

`AXIS_OFF`가 오른 건 극장골이 축 자체를 통째로 밀어 올렸기 때문이에요. 축이 커진
만큼 `log(축) * AXIS_K`도 커져서, 같은 곡선을 유지하려면 상수를 더 빼야 해요.

교훈은 하나예요. **캘리브레이션 시뮬레이션은 실제 경기 사슬을 한 칸도 빠뜨리면
안 돼요.** `tests/soccer/axis-test.js`도 같은 이유로 극장골이 빠져 있어서
`curve-test.js`와 모순되는 계수를 요구했고, 같이 고쳤어요.

## 곡선 검증

세 수정을 전부 적용한 뒤, 능력치를 전부 같은 값으로 두고 5년차 기준:

| 능력치 | 공격수 | 윙어 | 미드필더 | 수비수 | 목표 |
|---|---|---|---|---|---|
| 70 | 2.0% | 2.0% | 1.6% | 2.2% | 5% |
| 90 | 17.2% | 15.2% | 17.4% | 17.9% | 25% |
| 110 | 62.0% | 61.1% | 62.4% | 61.8% | 60% |
| 130 | 86.4% | 87.1% | 89.0% | 86.7% | 85% |
| 150 | 95.3% | 96.0% | 97.5% | 95.8% | 계속 오름 |

위 값은 `tests/soccer/curve-test.js`가 칸당 6000시즌으로 실측한 값이에요.
승부처 극장골까지 포함한 뒤의 값이라, 재보정 전 표보다 전 구간이 조금씩 높아요.

**포지션 간 편차가 모든 구간에서 3%p 이내다.** 이 작업에서 가장 중요한 성질이다.

110·130·150은 목표와 맞는다. **저연차가 목표보다 빡빡하다.**
평점 천장을 없애면 약한 선수는 실제로 약해지므로 당연한 결과다.
아이돌에서 저연차가 목표보다 후했던 것과 반대 방향이다.

### 중간 등급이 받쳐준다

위 표는 **리그MVP만** 잰 것이다. 이탈 위험은 중간 등급으로 확인해야 한다.

| 능력치 | 리그MVP | 베스트11 | 무관 |
|---|---|---|---|
| 50 | 0.0% | 12.3% | 87.7% |
| 70 | 2.0% | **63.8%** | 36.2% |
| 90 | 17.2% | **97.2%** | 2.8% |
| 110 | 61.5% | 100% | 0% |
| 130 | 86.8% | 100% | 0% |

베스트11이 성장 피드백을 주고 리그MVP가 목표로 남는다. 사다리가 잘 서 있다.

## 기존 저장 데이터

**마이그레이션하지 않는다.** 읽는 쪽에서 기본값을 준다.

- `act.goals`/`assists`/`defense`/`apps`는 **이미 있다.** 없으면 `|| 0`으로 이미 방어돼 있다.
- 평점 재조정은 저장 필드를 안 건드린다. 진행 중인 캐릭터는 다음 경기부터 새 평점을 받는다.
- 시즌 도중 업데이트가 걸리면 그 시즌 앞부분은 옛 평점으로 쌓인 기록이다.
  축은 골·어시 **개수**를 세므로 평점 변화가 소급되지 않는다. 성적이 튀지 않는다.

## 하지 않는 것

- **`matchScoreline`의 승부 판정은 안 건드린다.** 평점을 쓰지만 `strength`가
  `(rating-5)/5`로 완만해서, 평점이 내려가도 승률이 무너지지 않는다.
  건드리면 팀 성적까지 흔들려서 이번 범위를 벗어난다.
- **컴백 컨셉 같은 선택 시스템은 이번에 안 넣는다.** 축구는 포지션이 이미 그 역할을 한다.
  천장부터 없애고, 통하는지 보고 판단한다.
- **유스 경기(`renderStageSim`)의 평점은 안 건드린다.** 등급(S/A/B/C/D)에서 역산하는
  별도 경로라 이번 문제와 무관하다.

## 위험

- **평점 재조정이 이 작업에서 가장 위험하다.** `rating`은 `matchContribution`,
  `matchScoreline`, MOM 순위표, `deriveOppGoals` 네 곳이 쓴다. 하나라도 놓치면
  경기 결과가 어긋난다.
- **저연차 1%가 너무 빡빡할 수 있다.** 베스트11이 받쳐주지만 실기기 확인이 필요하다.
- **포지션 정규화 계수가 감이 아니라 측정값이라는 걸 테스트가 지켜야 한다.**
  아이돌에서 "초록불인데 아무것도 검증하지 않는 테스트"가 여섯 번 나왔다.
  포지션 간 편차를 재는 테스트가 반드시 있어야 한다.
