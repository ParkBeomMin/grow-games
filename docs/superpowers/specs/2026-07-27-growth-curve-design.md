# 성장 곡선 — 순위 천장 제거와 후반 목표

작성일: 2026-07-27
대상: `idol` · `stock` · `dev` · `chef` · `stream` · `soccer` 6종의 `career.js`, 그리고 아이돌 후반 콘텐츠
배포: **베타 먼저**. 상용 반영은 검증 후 별도 판단.

## 1. 배경

플레이어 제보 — 아이돌에서 "본상 건너뛰고 3년차부터 대상으로 씹어 먹는 중",
"각성 한 번도 안 함". 능력치를 더 올릴 이유가 없다는 뜻이다.

측정해보니 사실이다. 5년차 기준 대상 수상률:

| 능력치 | 대상 확률 | 연간 hype |
|---|---|---|
| 50 | 0% | -1.0 |
| 70 | 6% | 4.4 |
| 90 | **75%** | 7.8 |
| 110 | **76%** | 7.8 |
| 130 | **76%** | 7.8 |
| 150 | **77%** | 7.8 |

**90을 넘는 순간 천장에 붙고, 그 뒤로는 아무리 키워도 같다.**

### 원인

6종이 같은 식을 쓴다.

```js
act.hypeSum += (5 - rank) * 0.35 + miniHype;          // 주(회차)마다
const hype = clamp(act.hypeSum / 2.2 - agePen, -1.5, 12);   // 연말
```

`rank`는 1~6의 순위다. **간신히 1위를 하든 압도적으로 하든 `+1.4`로 같다.**
12회차를 전부 1위 하면 `hypeSum` 약 17, `hype` 7.7에서 멈춘다. 능력치가 그 위로
올라가도 순위가 이미 1위라 더 얻을 것이 없다.

라이벌은 `rand(52, 88)`로 매년 새로 굴리는데 **분포가 고정**이라, 플레이어만
성장하고 상대는 제자리다.

**루키는 이 문제가 없다.** 타율·홈런·도루로 WAR을 계산해 연속적이다. 이번 작업에서 건드리지 않는다.

## 2. 목표와 비목표

**목표**
- 능력치를 올린 만큼 결과가 좋아지게 한다. 특히 실제로 플레이가 지나는 구간(70~120)에서.
- 멈춰 있으면 뒤처지게 해서, 후반에도 육성할 이유를 남긴다.
- 정상에 오른 플레이어에게 새 목표를 준다.

**비목표**
- 루키 수정. 이미 연속식이다.
- 게임을 어렵게 만드는 것 자체. 목표는 **기울기**이지 난이도 상향이 아니다.
- 기존 저장 데이터 소급. 지나간 시즌 기록은 그대로 둔다.
- 6종 전부에 후반 콘텐츠. 이번엔 아이돌 하나만 만들고, 통하면 넓힌다.

## 3. 결정 사항 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| 접근 | **게임마다 고유 축을 하나씩** 두고 hype를 거기서 뽑는다 | 순위는 모든 테마가 공유할 수 있는 유일한 지표라 공통 엔진이 골랐지만, 순위는 본질적으로 천장이 있다(1위 위가 없다) |
| 공통 뼈대 | 유지 | 6종을 각각 새로 설계하는 건 6배 작업이다. 축 하나만 갈아 끼운다 |
| 순위 | 회차 연출용으로 남긴다 | 매주 1위 다툼은 그대로 재미있다. 다만 **연말 평가는 축이 정한다** |
| 축의 성질 | **상한이 없어야 한다** | 판매량·구독자·자산은 계속 커진다. 여기서 천장이 사라진다 |
| 격차 보너스 | **버린다** | 축을 갈면 필요 없어진다. 공통 엔진을 유지한 채 천장만 뚫는 미봉책이었다 |
| 라이벌 성장 | 해마다 3% | 멈춰 있으면 뒤처지게 (축 변경과 무관하게 유효) |
| 루키 | 제외 | 이미 타율·홈런이라는 고유 축을 쓴다. **이 게임에 벽이 없는 이유이자, 가장 깊고 인기 있는 이유이기도 하다** |
| 후반 콘텐츠 | 아이돌 월드투어 하나 | 통하는지 보고 넓힌다 |

## 4. B — 테마별 고유 축

### 4.1 왜 축을 갈아야 하나

지금 6종은 **이름표만 다른 같은 게임**이다. 다섯은 `sales`·`wins`·`week` 셋만
추적하고, `sales`조차 `hype`와 `wins`에서 파생된다. 독립적인 축이 하나도 없다.

```js
// 5종이 글자 그대로 동일
const cbSales = Math.max(1, Math.round(S.fandom * 0.05 + act.cbWins * 6 + act.cbHype * 4 + rand(-4, 4)));
```

축구만 `goals`·`assists`·`defense`를 따로 세는데 **hype에 반영하지 않는다.**
이미 있는 걸 안 쓰고 있다.

### 4.2 게임별 축

| 게임 | 축 | 무엇에서 자라나 | 상한 |
|---|---|---|---|
| 🎤 아이돌 | **초동 판매량** | 매력 + 무대 완성도(보컬·댄스·랩) + 팬덤 | 없음 |
| 📈 주식 | **누적 수익률** | 분석 + 정보 + 자본, 멘탈이 손실을 줄임 | 없음 |
| 💻 개발자 | **사용자 수** | 알고리즘 + 코딩, 협업이 유지율을 올림 | 없음 |
| 👨‍🍳 셰프 | **예약 대기 인원** | 맛 + 창의, 칼솜씨·속도가 회전율을 올림 | 없음 |
| 📹 스트리머 | **구독자 수** | 입담 + 리액션, 기획이 이탈을 줄임 | 없음 |
| ⚽ 축구 | **공격포인트(골+어시)** | 슛 + 패스 + 드리블 | 없음 |

모두 **누적되고 상한이 없다.** 능력치를 올린 만큼 계속 커진다.

### 4.3 hype를 축에서 뽑는다

```js
// 지금 — 순위가 전부
act.hypeSum += (5 - rank) * 0.35 + miniHype;
const hype = clamp(act.hypeSum / 2.2 - agePen, -1.5, 12);

// 바꿈 — 순위는 연출, 평가는 축이 한다
const hype = clamp(axisScore(S) - agePen, -1.5, 12);
```

`axisScore`는 게임마다 다르되, **그 해에 축이 얼마나 늘었는지**를 로그 스케일로 잰다.
로그를 쓰는 이유는 축이 후반에 기하급수로 커지기 때문이다. 선형으로 재면
10년차에 hype가 수백이 된다.

축구는 이미 세고 있는 값을 연결하기만 하면 된다.

### 4.4 각 게임이 달라지는 지점

같은 능력치라도 **어디에 투자했느냐가 결과를 가른다.**

- 아이돌 — 매력만 키우면 판매량은 오르지만 무대 완성도가 낮아 1위를 못 한다
- 주식 — 자본이 없으면 수익률이 좋아도 절대 금액이 안 늘고, 멘탈이 낮으면 손실 구간에서 무너진다
- 셰프 — 맛만 좋고 속도가 느리면 대기가 길어져도 회전이 안 돼 매출이 안 는다
- 축구 — 수비수는 공격포인트가 적게 나오므로 포지션별 기준이 필요하다

**축구는 포지션마다 축을 나눈다.** 공격포인트 하나로 재면 수비수가 구조적으로
불리해진다. 이미 `goals`·`assists`·`defense`를 따로 세고 있으므로 재료는 있다.

| 포지션 | 축 |
|---|---|
| 공격수 | 골 + 어시스트 |
| 미드필더 | 어시스트 + 경기 관여(골+어시+수비) |
| 수비수 | 수비 성공 + 팀 실점 억제 |

포지션별로 상을 따로 두는 게 아니라, **같은 상을 각자 다른 축으로 겨룬다.**
실제 축구 시상이 그렇다.

### 4.5 검증 없이는 못 정한다

계수는 전부 시뮬레이션으로 맞춘다. 목표 곡선은 이렇다.

| 능력치 | 대상 확률 |
|---|---|
| 70 | 5% 안팎 |
| 90 | 25% 안팎 |
| 110 | 60% 안팎 |
| 130 | 85% 안팎 |
| 150 | 계속 오름 |

**150에서도 오르는 게 핵심이다.** 지금은 90부터 76%로 평평하다.

### 4.6 짚어둘 것

- **6종을 한꺼번에 하지 않는다.** 아이돌 하나를 먼저 끝내고 곡선을 확인한 뒤,
  같은 방법을 나머지에 옮긴다. 여섯을 동시에 바꾸면 어디서 틀어졌는지 못 찾는다.
- **기존 저장 데이터 — 새로 만들 필드가 없다.** `S.career.sales`가 이미 누적되고
  있고 `S.career.years[]`에도 연차별 `sales`가 남는다. 축을 새 필드로 만들지 말고
  **이미 있는 이 값을 그대로 쓴다.** 진행 중인 캐릭터도 축이 0에서 시작하지 않으므로
  갑자기 무명이 되는 일이 없다. 영향도가 가장 적은 길이다.
  나머지 5종도 같은 필드를 갖고 있는지 구현 전에 확인한다.
- 순위는 남기지만 hype에는 안 쓴다. 회차 화면의 긴장감은 그대로 두고
  연말 평가만 축이 맡는다.

## 5. C — 아이돌 월드투어

### 5.1 왜 월드투어인가

B가 만든 "더 잘할 여지"의 도착점이 필요하다. 대상을 몇 번 타고 나면 국내에서는
더 오를 곳이 없다. 월드투어는 그 위에 층을 하나 얹는다.

### 5.2 열리는 조건

```
대상 3회 이상  또는  팬덤 8000 이상
```

둘 중 하나면 된다. 상을 노린 육성과 팬덤을 노린 육성 둘 다 길이 되게 한다.

처음엔 `대상 2회 또는 팬덤 5000`으로 잡았다가 올렸다. **너무 쉽게 열리면
후반 목표가 아니라 그냥 다음 단계가 되고, 다 본 뒤에 할 게 없어진다.**

**단, 이 숫자는 임시다.** 현행 규칙으로 시뮬레이션하면 대상 2회가 8~9년차에
나오는데, 제보자는 4년차에 이미 2회였다. 제보자가 최적화해서 키웠기 때문이고,
내 성장 모델이 보수적이라는 뜻이다. **4절의 축 변경을 실제로 넣은 뒤 다시 재서
강하게 키운 플레이어 기준 6~8년차에 열리도록 맞춘다.**

### 5.3 구조

연차 활동(컴백 2회) 뒤에 **월드투어 단계**가 붙는다. 도시를 하나씩 도는 방식이다.

```
🌏 월드투어 — 3/6번째 도시 · 도쿄

  관객 4.2만 / 5만 · 현지 반응 ★★★☆☆

  [ 공연하기 ]
```

- 도시 수는 팬덤에 따라 4~8곳
- 도시마다 미니게임 1회. 결과가 관객 동원과 현지 반응을 정한다
- 전 도시를 마치면 **월드투어 등급**(S/A/B/C)이 남고 명예의 전당 점수에 들어간다
- 실패해도 커리어가 끝나지 않는다. 다음 해에 다시 도전할 수 있다

### 5.4 보상

| | |
|---|---|
| 팬덤 | 도시마다 관객 수에 비례해 증가 |
| 수익 | 국내 활동보다 크게 |
| 기록 | `S.career.tours` — 명예의 전당과 은퇴 화면에 표시 |
| 명전 점수 | 투어 등급에 따라 가산 |

### 5.5 이번에 하지 않는 것

- 다른 5종의 후반 콘텐츠. 아이돌이 통하는지 보고 정한다.
- 월드투어 전용 화면 디자인. 기존 활동 화면 구조를 재사용한다.

## 6. 검증

테스트 러너가 없다. `tests/cloud/`와 같은 방식으로 node 스크립트를 쓴다.

| 대상 | 방법 |
|---|---|
| 성장 곡선 | 능력치·연차를 훑어 대상/본상 확률표를 뽑고 4.5의 목표 곡선과 대조 |
| 축이 자라는지 | 능력치를 올리면 축이 실제로 커지는지, 150에서도 계속 오르는지 |
| 기존 저장 데이터 | 진행 중인 캐릭터가 축 도입 후 갑자기 나빠지지 않는지 |
| 회귀 | 루키가 안 바뀌었는지, 기존 저장 데이터가 그대로 열리는지 |
| 월드투어 | 열림 조건, 도시 수, 등급 산출, 재도전, 명전 반영 |
| 화면 | jsdom으로 월드투어 진입·진행·종료 |

CSS 렌더링은 확인할 수 없다. 배포 후 실기기 확인이 필요하다.

## 7. 작업 순서

1. **아이돌 하나만** — 초동 판매량을 축으로 세우고 hype를 거기서 뽑는다
2. 곡선 검증 스크립트로 4.5 목표와 대조, 계수 조정. 기존 저장 데이터 처리도 여기서 결정
3. 아이돌 월드투어 — 상태·진행·등급·화면
4. 베타 배포 후 실기기 확인. **여기서 통하는지 판단한다**
5. 통하면 나머지 5종에 같은 방법 적용 (축구는 포지션 문제를 따로 풀어야 한다)
