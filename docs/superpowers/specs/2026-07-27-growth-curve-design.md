# 성장 곡선 — 순위 천장 제거와 후반 목표

작성일: 2026-07-27
대상: `idol` · `stock` · `dev` · `chef` · `stream` · `soccer` 6종의 `career.js`, 그리고 아이돌 후반 콘텐츠
배포: **베타 먼저**. 상용 반영은 검증 후 별도 판단.

## 1. 배경

플레이어 제보 — 아이돌에서 "본상 건너뛰고 3년차부터 대상으로 씹어 먹는 중",
"각성 한 번도 안 함". 능력치를 더 올릴 이유가 없다는 뜻이다.

측정해보니 사실이다. 5년차 기준 대상 수상률:

| 능력치 | 대상 확률 | 연간 hype |
|---|---|---|
| 50 | 0% | -1.0 |
| 70 | 6% | 4.4 |
| 90 | **75%** | 7.8 |
| 110 | **76%** | 7.8 |
| 130 | **76%** | 7.8 |
| 150 | **77%** | 7.8 |

**90을 넘는 순간 천장에 붙고, 그 뒤로는 아무리 키워도 같다.**

### 원인

6종이 같은 식을 쓴다.

```js
act.hypeSum += (5 - rank) * 0.35 + miniHype;          // 주(회차)마다
const hype = clamp(act.hypeSum / 2.2 - agePen, -1.5, 12);   // 연말
```

`rank`는 1~6의 순위다. **간신히 1위를 하든 압도적으로 하든 `+1.4`로 같다.**
12회차를 전부 1위 하면 `hypeSum` 약 17, `hype` 7.7에서 멈춘다. 능력치가 그 위로
올라가도 순위가 이미 1위라 더 얻을 것이 없다.

라이벌은 `rand(52, 88)`로 매년 새로 굴리는데 **분포가 고정**이라, 플레이어만
성장하고 상대는 제자리다.

**루키는 이 문제가 없다.** 타율·홈런·도루로 WAR을 계산해 연속적이다. 이번 작업에서 건드리지 않는다.

## 2. 목표와 비목표

**목표**
- 능력치를 올린 만큼 결과가 좋아지게 한다. 특히 실제로 플레이가 지나는 구간(70~120)에서.
- 멈춰 있으면 뒤처지게 해서, 후반에도 육성할 이유를 남긴다.
- 정상에 오른 플레이어에게 새 목표를 준다.

**비목표**
- 루키 수정. 이미 연속식이다.
- 게임을 어렵게 만드는 것 자체. 목표는 **기울기**이지 난이도 상향이 아니다.
- 기존 저장 데이터 소급. 지나간 시즌 기록은 그대로 둔다.
- 6종 전부에 후반 콘텐츠. 이번엔 아이돌 하나만 만들고, 통하면 넓힌다.

## 3. 결정 사항 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| hype 산식 | 순위 + **1위일 때 격차 보너스** | 압도할수록 더 받아야 계속 키울 이유가 생김 |
| 격차 상한 | 2배 (`clamp(gap/25, 0, 2)`) | 무제한이면 clamp(12)에 즉시 붙어 다시 천장이 생김 |
| 나누는 값 | `2.2` → `3.2` | 격차분이 더해져 총합이 커진 만큼 되돌림 |
| 라이벌 성장 | 해마다 **3%** | 5%는 9년차에 중위권이 1%로 무너짐(시뮬 확인) |
| 수상 컷 | **안 건드림** | 산식이 바뀌면 컷을 옮기지 않아도 분포가 벌어짐 |
| 루키 | 제외 | 이미 연속식 |
| 후반 콘텐츠 | 아이돌 **월드투어** 하나 | 통하는지 보고 넓힘 |

## 4. B — 성장 곡선

### 4.1 산식

```js
// 회차마다 (1위일 때만 격차 보너스)
const topRival = Math.max(...others.map((r) => r.score));
const gap = rank === 1 ? clamp((myScore - topRival) / 25, 0, 2) : 0;
act.hypeSum += (5 - rank) * 0.35 + gap * 0.35 + miniHype;

// 연말
const hype = clamp(act.hypeSum / 3.2 - agePen, -1.5, 12);
```

`25`는 "2위보다 25점 앞서면 1배 더"라는 뜻이다. 라이벌 점수 폭이 `52~88`(36점)이므로
그 3분의 2쯤 앞서면 보너스가 최대에 가까워진다.

### 4.2 라이벌 성장

```js
function rollRivals() {
  const grow = 1 + Math.max(0, (S.proYear || 1) - 1) * 0.03;
  return RIVAL_GROUPS.map((name) => ({ name, pop: rand(52, 88) * grow }));
}
```

9년차면 라이벌이 약 24% 강해진다. 멈춰 있으면 밀리지만, 성실히 키우면 계속 앞선다.

### 4.3 축구는 구조가 다르다

5종(`idol`·`stock`·`dev`·`chef`·`stream`)은 `act.hypeSum += (5 - rank) * 0.35 + miniHype;`
한 줄이 같다. **축구만** 그 값을 `hypeDelta`로 따로 계산해 두 곳에서 쓴다
(`beta/soccer/career.js:286`, `:297-298`). 축구는 `hypeDelta` 계산부에 격차분을 더한다.

### 4.4 기대 결과 (5년차, 시뮬레이션)

| 능력치 | 대상 (현행 → 변경) | 본상 (현행 → 변경) |
|---|---|---|
| 70 | 6% → 0% | 35% → 1% |
| 90 | 75% → **21%** | 100% → 96% |
| 110 | 76% → **90%** | 100% → 100% |
| 130 | 76% → 90% | 100% → 100% |

90과 110이 21% 대 90%로 갈린다. 지금은 둘 다 76%다.

**110 위로는 다시 평평해진다.** 이건 의도한 것이고, 그 구간을 C가 받는다.

### 4.5 짚어둘 것

- **초반이 어려워진다.** 능력치 70의 본상이 35% → 1%로 떨어진다. 이건 기울기를 만드는
  대가다. 다만 1~2년차는 원래 상을 못 받는 구간이라 체감 차이는 작을 것으로 본다.
  베타에서 확인이 필요하다.
- 라이벌 성장은 `S.proYear`를 읽는다. 6종 모두 이 필드를 쓰는 것을 확인했다(각 15곳).

## 5. C — 아이돌 월드투어

### 5.1 왜 월드투어인가

B가 만든 "더 잘할 여지"의 도착점이 필요하다. 대상을 몇 번 타고 나면 국내에서는
더 오를 곳이 없다. 월드투어는 그 위에 층을 하나 얹는다.

### 5.2 열리는 조건

```
대상 2회 이상  또는  팬덤 5000 이상
```

둘 중 하나면 된다. 상을 노린 육성과 팬덤을 노린 육성 둘 다 길이 되게 한다.

### 5.3 구조

연차 활동(컴백 2회) 뒤에 **월드투어 단계**가 붙는다. 도시를 하나씩 도는 방식이다.

```
🌏 월드투어 — 3/6번째 도시 · 도쿄

  관객 4.2만 / 5만 · 현지 반응 ★★★☆☆

  [ 공연하기 ]
```

- 도시 수는 팬덤에 따라 4~8곳
- 도시마다 미니게임 1회. 결과가 관객 동원과 현지 반응을 정한다
- 전 도시를 마치면 **월드투어 등급**(S/A/B/C)이 남고 명예의 전당 점수에 들어간다
- 실패해도 커리어가 끝나지 않는다. 다음 해에 다시 도전할 수 있다

### 5.4 보상

| | |
|---|---|
| 팬덤 | 도시마다 관객 수에 비례해 증가 |
| 수익 | 국내 활동보다 크게 |
| 기록 | `S.career.tours` — 명예의 전당과 은퇴 화면에 표시 |
| 명전 점수 | 투어 등급에 따라 가산 |

### 5.5 이번에 하지 않는 것

- 다른 5종의 후반 콘텐츠. 아이돌이 통하는지 보고 정한다.
- 월드투어 전용 화면 디자인. 기존 활동 화면 구조를 재사용한다.

## 6. 검증

테스트 러너가 없다. `tests/cloud/`와 같은 방식으로 node 스크립트를 쓴다.

| 대상 | 방법 |
|---|---|
| 성장 곡선 | 능력치·연차를 훑어 대상/본상 확률표를 뽑고 4.4의 기대치와 대조 |
| 6종 동일성 | 여섯 파일의 산식이 같은 모양인지 (축구는 `hypeDelta` 경유) |
| 회귀 | 루키가 안 바뀌었는지, 기존 저장 데이터가 그대로 열리는지 |
| 월드투어 | 열림 조건, 도시 수, 등급 산출, 재도전, 명전 반영 |
| 화면 | jsdom으로 월드투어 진입·진행·종료 |

CSS 렌더링은 확인할 수 없다. 배포 후 실기기 확인이 필요하다.
