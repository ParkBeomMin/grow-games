작성일: 2026-07-26

## 1. 배경

플레이어 의견으로 이적 · 메이저리그 · 팀 순위 · 가을야구/한국시리즈 · 포스팅이 들어왔다.
이 중 **팀 순위 · 가을야구 · 한국시리즈** 셋을 1단계로 묶는다. 이적/FA는 2단계,
메이저리그/포스팅은 3단계로 각각 별도 사이클을 돈다.

코드를 대조한 현재 상태:

| 요청 | 현재 |
|---|---|
| 팀 순위 | `standingsHTML()`이 `career.js:259`에 있으나 **어디서도 호출되지 않는 죽은 함수**. 화면엔 `G 12/144 · 3위` 텍스트만 |
| 한국시리즈 | 결과만 존재. `career.js:522`가 `1위 60% / 2~3위 22%` **주사위 한 번**으로 우승을 정함 |
| 가을야구 | 없음 |

리그는 10팀(`rookie/game.js:5` `REGIONS`)으로 실제 KBO와 같고, 정규시즌도 144경기로 실제와 같다.
가을야구도 실제 KBO 구조를 그대로 따른다.

### 범위 밖 (명시)

- **정규시즌 경기 수(144), 경기당 클릭 수, 훈련 횟수는 바꾸지 않는다.** 별개 아이디어로 보류됨.
- 다른 6개 게임은 건드리지 않는다. 이 게임들은 프로 단계가 `CB_PER_YEAR(2) × WEEKS_PER_CB(6)` = 연 12단위 구조라 구조가 다르고, 가을야구는 야구 전용이다.
- 이적 / FA / 메이저리그 / 포스팅.

## 2. 순위표 노출

`standingsHTML()`을 그대로 살려 두 곳에 붙인다. 함수 자체는 수정하지 않는다.

### 프로 화면 (`screen-pro`)

`.gauges` 블록 바로 아래에 접이식(`<details>`) 순위표를 넣는다. **기본은 접힘.**

```
▸ 📊 3위 · 42승 30패          ← 접힘 (기본)

▾ 📊 3위 · 42승 30패          ← 펼침
   #  팀          승-패
   1  LG 트윈스    48-24
   2  삼성 라이온즈 45-27
   3  한화 이글스   42-30     ← .me 클래스로 강조 (기존 CSS)
   ...
```

접어두는 이유: 펼친 채로 두면 표 10줄이 훈련 버튼(`#pro-actions`)을 화면 밖으로 밀어낸다.
요약 줄에 순위와 승패가 이미 있어 대부분은 펼칠 필요가 없다.

`S.season`이 없을 때(스프링캠프 중)는 순위표 블록 자체를 숨긴다.

### 시즌 결산

`seasonReport()`(`career.js:565`)에 최종 순위표를 **펼친 채로** 한 번 보여준다.
가을야구 진출 여부를 납득시키는 화면이 되어야 하므로 접지 않는다.

## 3. 가을야구 진출과 대진

정규시즌 144경기가 끝나면 최종 순위로 갈린다.

- **6위 이하** → 포스트시즌 없음. 지금처럼 바로 시즌 결산 (문구: "가을야구 진출 실패")
- **1~5위** → 포스트시즌 진입

```
4위 ─┐
     ├─ 와일드카드 (2전 1승제, 4위는 1승 안고 시작)
5위 ─┘   │
3위 ──────┴─ 준PO (5전 3선승)
                │
2위 ────────────┴─ PO (5전 3선승)
                      │
1위 ──────────────────┴─ 한국시리즈 (7전 4선승)
```

### 시리즈별 승리 조건

| 라운드 | 형식 | 상위 팀(4위·3위·2위·1위) | 하위 팀 |
|---|---|---|---|
| 와일드카드 | 2전 1승제 | **2경기 중 1승이면 진출.** 2경기를 모두 져야 탈락 | **2연승해야** 진출 |
| 준PO | 5전 3선승 | 3승 | 3승 |
| PO | 5전 3선승 | 3승 | 3승 |
| 한국시리즈 | 7전 4선승 | 4승 | 4승 |

와일드카드의 어드밴티지는 구현상 **4위의 승수를 1에서 시작**시켜 표현한다.
`need = 2`이고 4위는 `aw = 1`, 5위는 `bw = 0`으로 출발한다.

여기서 나오는 결과를 못박아 둔다:

- 4위가 1차전을 이기면 `2-0`이 되어 **1경기 만에 시리즈가 끝난다.** 정상이다.
- 4위가 1차전을 지면 `1-1`, 2차전을 이기면 `2-1`로 4위 진출.
- 5위가 2연승하면 `1-2`로 5위 진출.

### 내가 없는 라운드는 자동 시뮬

1위로 직행하면 아래에서 누가 올라오는지 보여주는 것이 재미의 일부다.
플레이어가 끼지 않은 라운드는 팀 강도(`initSeason`이 팀마다 부여하는 `str`)로 자동 판정하고,
기존 `playFeeds()`(`career.js:474`) 연출로 흘려보낸다.

```
🍂 가을야구가 시작됐어요
   와일드카드  두산 1-0 롯데      → 두산 진출
   준PO        KIA 3-1 두산       → KIA 진출
   PO          삼성 3-2 KIA       → 삼성 진출
   🏆 한국시리즈 상대는 삼성이에요
```

## 4. 포스트시즌 경기 진행

정규시즌과 **같은 연출과 미니게임**을 그대로 쓴다(`proBatterGame` / `proPitcherGame` / `quickGame`).
바뀌는 것은 화면 상단 표기와 투수 등판 빈도뿐이다.

```
🍂 준PO 3차전 · 시리즈 1-1
한화 이글스 vs 두산 베어스
```

### 투수 단축 로테이션

짧은 시리즈에 총력전을 붙이는 실제 관행을 따른다. 7전 4선승제에서 선발이 7경기를
모두 던지는 일은 없으므로, "매 경기 등판"은 채택하지 않는다.

| 보직 | 정규시즌 | 포스트시즌 |
|---|---|---|
| 선발 투수 | 5경기마다 등판 (`sn.game % 5 === 0`) | **4경기마다** |
| 중간계투 | 45% 확률 등판 | **60%** |
| 마무리 투수 | 55% 확률 등판 | **70%** |

타자는 정규시즌과 동일하게 매 경기 출전하므로 영향이 없다.

### 기록 분리

포스트시즌 기록은 정규시즌 기록에 **합산하지 않는다.** 실제 야구도 그렇고,
`.312`로 마친 타율이 가을야구 부진으로 `.298`이 되면 이상하다.
`S.post.stats`에 따로 쌓고 시즌 결산에 한 줄로 보여준다.

WAR·MVP·골든글러브·신인왕은 지금처럼 정규시즌 성적만으로 계산한다(KBO도 동일).

### 훈련과 컨디션

**시리즈 안에는 훈련이 없다.** 실제로도 시리즈 중엔 경기만 있다.
대신 **라운드와 라운드 사이에 컨디션이 자동 회복된다**(이동일·휴식일, `+15`).
클릭을 추가로 요구하지 않는다. 정규시즌 144경기의 훈련 횟수는 그대로다.

## 5. 저장 구조와 이어하기

포스트시즌은 여러 경기에 걸치므로 새로고침을 견뎌야 한다. `S.season`과 나란히 `S.post`를 둔다.

```js
S.post = {
  bracket: [                    // 라운드별 진행 상황 (자동 시뮬 결과 포함)
    { round: "wc",   a: "두산", b: "롯데", aw: 1, bw: 0, need: 2, done: true,  winner: "두산" },
    { round: "semi", a: "한화", b: "두산", aw: 1, bw: 1, need: 3, done: false, winner: null },
  ],
  myTeam: "한화 이글스",
  myRound: "semi",              // 내가 지금 치르는 라운드. null이면 탈락 또는 종료
  gameNo: 3,                    // 현재 시리즈의 몇 차전인지 (1부터)
  eliminated: false,
  wonKS: false,
  stats: { ab: 0, hits: 0, hr: 0, sb: 0 },   // 투수면 { ip, k, er, wins, saves, g }
};
```

`career.js:977`의 이어하기 분기에 `S.post`를 추가한다.

```js
showPro: () => {
  if (S.post && !S.post.eliminated && S.post.myRound) { renderPost(); show("screen-pro"); }
  else if ((S.season && S.pendingGame) || S.camp > 0) { renderPro(); show("screen-pro"); }
  else if (S.season) runSeason();
  else seasonReport();
},
```

## 6. 우승 판정 교체

`career.js:522`의 주사위를 지운다.

```js
// 삭제
const champ = (rank === 1 && Math.random() < 0.6) || (rank > 1 && rank <= 3 && Math.random() < 0.22);
// 대체 — 한국시리즈를 실제로 이겼을 때만
const champ = !!(S.post && S.post.wonKS);
```

`finishSeason()`은 포스트시즌이 **끝난 뒤에** 호출되도록 순서를 바꾼다.
현재 `finishProGame`이 `sn.game >= sn.total`일 때 `nextFn: finishSeason`을 돌려주는데,
이를 `nextFn: enterPostseason`으로 바꾸고, 포스트시즌이 끝나면(우승·탈락·미진출)
`finishSeason()`을 부른다. 6위 이하면 `enterPostseason`이 곧바로 `finishSeason()`으로 넘긴다.

**호출 순서가 중요하다.** `finishSeason()`이 `S.post.wonKS`와 `S.post.stats`를 읽으므로,
`S.post = null`은 `finishSeason()`이 값을 다 쓴 뒤에 해야 한다. 현재 `finishSeason()`이
`S.season = null`을 하는 자리에서 `S.post = null`도 함께 처리한다.

새 렌더 함수 `renderPost()`가 포스트시즌 중의 `screen-pro`를 그린다. `renderPro()`와
같은 화면을 쓰되 훈련 버튼 대신 시리즈 상태와 경기 시작 버튼만 보여준다.

### 밸런스 영향

우승이 지금보다 귀해진다. 1위는 60%였으나 이제 7전 4선승을 실제로 이겨야 하고,
2~3위는 22%였던 것이 PO와 KS를 연달아 뚫어야 한다. 4~5위는 와일드카드부터 올라와야 해
사실상 희박하다.

명예의 전당 점수가 `rings * 25`(`career.js:630`)를 쓰므로 앞으로 쌓이는 기록은
우승 하나의 무게가 커진다. **기존 명전 데이터는 그대로 둔다** — `S.career.rings`는
이미 있는 필드라 마이그레이션이 필요 없고, 과거 기록이 상대적으로 후해 보이는 것은 감수한다.

## 7. 코드 구조 — 순수 함수로 분리

판정 로직을 화면과 분리해 순수 함수로 만든다. 설계상으로도 옳고, 브라우저 없이 검증할 수 있다.

```js
// 하나의 시리즈. a는 항상 상위 시드, b는 하위 시드.
// aw/bw는 각 팀의 승수, need는 시리즈 승리에 필요한 승수.
// Series = { round, a, b, aw, bw, need, done, winner }
//   round : "wc" | "semi" | "po" | "ks"
//   a, b  : 팀 이름 문자열
//   winner: 팀 이름 문자열, 미결이면 null

// 최종 순위 → 대진표. 내 팀이 6위 이하면 null.
// 반환: { series: Series[], myTeam, myRound }
buildBracket(standings: {name, w, l}[], myTeam: string): Bracket | null

// 시리즈에 한 경기 결과를 반영해 새 객체를 돌려준다(원본 불변).
// aWon이 true면 상위 시드가 이긴 것.
advanceSeries(series: Series, aWon: boolean): Series

// NPC끼리의 시리즈를 팀 강도로 끝까지 시뮬해 done 상태의 Series를 돌려준다.
// strA/strB는 initSeason이 팀에 부여한 str 값.
simSeries(round, aName, bName, strA, strB, need, aHead): Series
```

`aHead`는 와일드카드에서 4위가 안고 시작하는 승수(1), 그 외 라운드는 0.

## 8. 검증

이 저장소에는 테스트 러너가 없고 넣지 않는다(기존 결정). node로 순수 함수를 직접 돌려 검증한다.

| 대상 | 확인 |
|---|---|
| `buildBracket` | 1·2·3·4·5위 각 경우의 대진이 KBO 규칙과 일치. 6위 이하는 `null`. 내 팀이 대진에 정확히 한 번 등장 |
| `advanceSeries` — 와일드카드 | **4위는 1승만 하면 진출, 5위는 2연승해야 진출.** 4위가 1차전을 져도 2차전을 이기면 진출. 5위가 1차전을 이기고 2차전을 지면 탈락 |
| `advanceSeries` — 5전 3선승 | 3승에서 종료. 3-0, 3-1, 3-2 모두 정상 종료. 4승째가 나오지 않음 |
| `advanceSeries` — 7전 4선승 | 4승에서 종료. 4-0 ~ 4-3 정상 종료 |
| `simSeries` | 강한 팀이 유의미하게 자주 이김(1000회 반복). 무한루프 없음. 항상 `done: true`로 끝남 |
| 진출 확률 | 1000시즌 시뮬로 순위별 우승 확률을 뽑아, 1위가 가장 높고 5위가 가장 낮은지 확인 |

순위표 UI(접이식 동작, `.me` 강조, 캠프 중 숨김)와 포스트시즌 화면 표기는 브라우저가 필요하므로
사용자가 `/beta/rookie/`에서 확인한다.
