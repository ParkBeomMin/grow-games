## 2. 지킬 것 — 모든 파일에 걸리는 규칙

1. **중립은 정의로** — 유스의 확정 = 옛 `maybeEvent` 효과 그대로, 프로의 확정 = 효과 0. 그래서 「늘 확정만 고르는 커리어 == 현행 커리어」가 구성으로 선다(실측 비트 동일 — 20·22·24번)
2. **보이는 % = 판정 %** — 정수 `pct`를 **한 번** 계산해 얼리고, 화면과 판정이 그 필드 하나를 읽는다. 판정 난수 `u`도 뜰 때 한 번 굴려 얼린다(`u × 100 < pct`면 성공). 연속 실패 보호·행운 보정·"뜻밖의 반전" 같은 **숨은 손 0**
3. **판돈은 한 축, W = L** — 얻는 것과 잃는 것이 같은 종류·같은 크기 → **p\* = 50%**가 구성으로 선다. 컨디션은 판돈이 아니다(확률 조각이다)
4. **잘리는 판돈은 내놓지 않는다** — 적용하면 칩과 다른 값이 되는 도전(상한·바닥)은 무작위 이벤트면 후보에서 빼고, 이야기 장이면 판돈을 명성 ±25로 바꾼다(§3-8)
5. **이벤트는 문턱을 안 만진다** — 월드컵 소집 문턱 · 이적 문턱(`PROMOTE_HYPE`) · 수상 판정 · 클래스 문턱은 효과 대상이 아니다. 경기력 버프(골 +6% 같은 것)도 없다(`BUFF_CAP` 비대칭)
6. **B는 경기력에 0** — 업적 버프 없음 · 점수는 `careerScore()` 그대로(내역만 펼친다) · 판정 함수는 세이브를 **읽기만** 한다(난수 0)
7. **마이그레이션 없음 · `id` 불변 · `hof` UPDATE 없음** — 새 필드는 전부 읽는 쪽 기본값. 명전 항목은 한 번의 INSERT. 이 문서의 id(이벤트·이야기·결말·업적·성향)는 출하 뒤 바꾸지 않는다
8. **기존 필드의 뜻·타입·범위·null의 뜻을 바꾸지 않는다 — 새 뜻은 새 필드로** — 베타(`beta/soccer/`)와 운영판(`soccer/`)은 같은 세이브 칸을 한 도메인의 localStorage에서 쓴다
   (`SAVE_KEY = "winger-save-v1"`, `game.js:409` · 슬롯 `winger-save-v1-slots` · 유산 `-legacy` · 공유 명전 `grow-hof-v1`). 운영판은 모르는 칸을 무시할 뿐 틀리게 읽지 않아야 하고,
   베타는 운영판이 끼었는지 `S.betaAt`으로 알아보고 진행 중 상태를 정리한다(§6-1 · §9-D)
9. **갈래마다 따로 심지 않는다** — 이벤트는 `renderPrep` 한 곳에서 굴리고, 📍 라운드 집계는 라운드마다 한 곳에서 센다(뛴 주·벤치 주 둘 다)
10. **남의 값은 `esc`로 그린다** — 🏛️ 헌액자 이름처럼 로컬 명전에서 오는 글자도(로컬에도 씻기 전 값이 있을 수 있다 — `career.js:215-217`). 캔버스 `fillText`는 태그를 해석하지 않는다
11. **문구는 우리 말로, 오프사이드 문구·사건 구성을 쓰지 않는다** — 이 문서의 제목·선택지 이름을 쓰고, 본문을 쓸 때 `00_input/02_offside.md`의 목록과 한 번 대조해 겹치는 제목은 바꾼다. 사용자 문구는 `~해요`

## 3. ①-a 선택 이벤트

### 3-1. 선택지 네 종류

| 종류 `k` | 판정 | 화면 |
|---|---|---|
| `safe` 확정 | 없음 | 효과 칩(없으면 「아무 일 없이 지나가요」). 프로는 효과 0 |
| `try` 도전 | 얼린 `pct`와 얼린 `u` — `u × 100 < pct`면 성공 | 「성공 62%」 + 조각(기본 50 · 약발 +4 · 컨디션 +8 (평소 64 · 오늘 74)) + 성공/실패 칩. **도전 = 기본 효과 + 판돈**(성공 +W / 실패 −L) |
| `deal` 거래 | 없음 — 확정으로 주고받는다 | 받는 칩 + 내는 칩. ①에서는 📍 1장 「🔀 옆 칸으로 비킨다」 하나 |
| `promise` 약속 | 다음 출전 리그 경기의 기록(§3-6) — 새 난수 없음 | 「📋 약속: 골 1 — 그리고 승리」 + **사실** 「최근 10경기 중 4번」. **% 기호를 쓰지 않는다** |

- 도전이 둘인 선택(🌍 1장)은 **같은 `u`**를 쓴다 — 선택지마다 성공 확률은 정확히 제 `pct`다
- 답한 직후 저장한다 — 앱을 닫았다 열어도 같은 `u`, 「될 때까지 새로고침」이 구조적으로 불가능하다

### 3-2. 확률 식

**프로(도전 전부 — 이벤트 17종의 도전 · 이야기 1장의 도전)**

```
pct    = clamp( 50 + 실력 + 컨디션 , 10, 90 )        ← 정수. 화면 조각의 합과 같다(아래)
실력   = clamp( k·X − Mₑ , −10, +10 )                X·k는 이벤트마다(§3-5 · §4) · Mₑ는 §7-3
컨디션 = clamp( (지금 컨디션 − 평소 − Cδₑ) × 0.8 , −15, +15 )
         평소 = S.condUsual의 **이 블록 갱신 전** 값(없으면 이 블록의 컨디션) · Cδₑ는 §7-3(대부분 0)
```

- **조각을 각각 정수로 반올림한 뒤 더한다** — `parts = [{기본 50}, {재료 이름: 실력}, {컨디션: 조각, usual, now}]`의 `v` 합이 곧 `pct`다(프로는 구성상 25~75라 자르기가 안 걸린다)
- 실력 조각은 **재료 이름**으로 적는다(「약발 +5」「종합 +8」「명성 −3」) · 컨디션 조각은 평소와 오늘을 같이(「컨디션 −6 (평소 71 · 오늘 63)」)
- 공통 재료: **리그 기준** = `raceStr(70, leagueOf(S).prestige)`(K3 52.9 · K1 68.6 · 챔십 94.9 · PL 117.6) · **주 스탯** = `POS_INFO[S.pos].stat` · **종합** = `overall()` ·
  **재능 ★** = `talentStars(S.talents[k])`(1~5) · **명성** = `S.fandom` · **프로 시즌 수** = `S.proYear` · **이 클럽 시즌 수** = `seasonsAtClub(S, S.group)`

**유스(4종 — 옛 식에 기본값만 확정)**: `pct = clamp(Σ round(조각), 10, 90)` — 조각은 §3-4 표. 프로와 같이 **조각마다 정수로 반올림한 뒤 더한다**(화면 조각의 합 = pct, 잘린 경우만 다름)

**블록 하나에서 하는 일(순서대로)**

3. **평소 컨디션 갱신** — 이 블록의 조각에 쓸 값으로 지금 `S.condUsual`을 잡아 두고(없으면 지금 컨디션), `S.condUsual += (지금 컨디션 − S.condUsual) ÷ 8`. 이벤트를 굴리든 안 굴리든 한다
4. 시즌이 바뀌었으면 `S.evSeason = { y, n: 0, ids: [] }`. `mid`면 `S.evMem.n += 1` · 그 블록의 `classUp` 값을 쓰고 끈다
5. `S.evSeason.n ≥ 5`(시즌 상한)면 멈춘다
6. **이야기 장이 이 블록 차례면 그 장을 띄우고 멈춘다**(§4 — 한 블록에 한 장, 무작위 이벤트보다 먼저). `n += 1`
7. `n + 열린 이야기의 이번 시즌 남은 장 수 ≥ 5`면 멈춘다 — **장 자리를 먼저 잡는다**

9. 후보: 이 `kind`에 뜨는 이벤트 중 — 이번 시즌 아직 안 뜬 것 · (약속형이면) 걸린 약속이 없을 때 · 뜨는 조건이 참 · 판돈이 안 잘림(§3-8). 없으면 멈춘다

> · 성공 확률은 화면에 적힌 숫자 그대로예요. 이벤트가 뜰 때 0~99 중 숫자 하나를 뽑아 두고, 도전을 고르면 그 숫자가 적힌 확률보다 작을 때 성공해요. 숨은 보정은 없어요.
> · 확률은 적힌 조각을 더한 값이에요. 프로에서는 기본 50에 실력(±10까지)과 컨디션(±15까지)을 더해요 — 아무리 강해도 확실한 도전은 없어요. 컨디션 조각은 **평소보다** 생생한지·지쳤는지를 봐요 — 늘 쉬는 선수도, 꾸준히 훈련하는 선수도 좋은 날과 나쁜 날을 똑같이 만나요.
> · 도전은 "받는 것 + 판돈"이에요. 판돈은 늘 한 가지라 얻는 것과 잃는 것이 같은 크기예요 — 성공 확률이 50%를 넘으면 걸 만해요.
> · 📋 약속은 확률이 아니라 **다음 경기**가 정해요. 적힌 숫자는 "최근 경기에서 이만큼 해냈다"는 기록이에요. 상대가 정해진 약속은 그 팀과 만나는 경기에서 정해요. 벤치면 다음 출전 경기로 넘어가고, 시즌이 끝나면 없던 일이 돼요.
> · 같은 이벤트는 한 시즌에 한 번까지예요. 자주 본 이벤트일수록 덜 나와요.
> · 월드컵·컵 대회 중에는 이벤트가 뜨지 않아요.

## 4. ①-b 이야기 4편

### 4-1. 공통 규칙

1. **장은 블록 자리에서만** 뜬다 — 무작위 이벤트보다 먼저, **한 블록에 한 장**. 확인 순서 **🌍 → 📍 → 🕯️ → 🔥** — 먼저 맞는 한 편의 장만 뜨고 그 블록은 끝난다
   (그래서 🌍 1장이 차지한 `pre`에는 🕯️이 안 열리고, 🕯️은 `pre`에만 열리니 그 시즌엔 안 열린다).
   밀린 장은 조건이 「이상」인 것(🌍 2장 · 📍 2장 · 🔥 2장)이면 다음 블록에 뜬다. **🕯️ 2장은 `h2` 한 자리뿐**이라 같은 `h2`에서 📍 ⓑ가 열리면 그 시즌 🕯️ 2장은 없고,
   결말은 1장으로 정한다 — 시뮬레이터가 이렇게 굴렀고 §4-4 분포가 이것을 포함한다
2. 동시에 열린 이야기는 **최대 2편**
3. **은퇴·환생 때 열린 이야기는 흐지부지로 닫는다**(방어). 🌍·📍·🕯️의 흐지부지는 규칙상 거의 안 닿아 **도달률 문턱(결말마다 ≥ 3%)에서 뺀다** — 닫힘 100% 검사의 대상일 뿐
4. 결말은 **그동안의 선택·판정·실제 기록**에서 규칙으로 — 숨은 굴림 없음 · **규칙표는 빈칸 없이**(모든 경우가 정확히 한 결말)
5. **장 자리** — 시즌 상한 5 안에서 열린 이야기의 이번 시즌 남은 장만큼 자리를 비워 둔다(§3-3 7번) · **📍·🔥은 여는 블록에서 「뜬 수 + 남은 장 + 2 ≤ 5」일 때만 연다**(자리가 없으면 그 블록의 여는 조건은 없던 일)
6. **1장의 「참음」과 「걸었다가 실패」는 다른 결말이다**
- 이야기 장의 도전 판돈이 잘리면 명성 ±25로(§3-8)
- 이야기의 약속 장이 오면 걸려 있던 무작위 약속은 없던 일(§3-6)
- 운영판이 끼면(`S.betaAt !== S.savedAt`) 열린 이야기는 흐지부지(방어)로 닫는다 — 🔥은 흐지부지 결말이 없어 **결말 없이 없앤다**(도감·`S.story.done`에 안 남고 `end1`·`end5`에 안 센다).
  방어로 닫을 일이 달리 생겨도(규칙상 없는 「은퇴 때 열린 🔥」) 같다
- 이야기 장의 이벤트 id는 `s_{sid}{장}` — `s_abroad1` · `s_abroad2` · `s_slot1` · `s_slot2` · `s_senior1` · `s_senior2` · `s_race1` · `s_race2`

```js
  parts: [ { k: "ballon", label: "🏅 발롱도르", n: 2, v: 440 } ],
  ach:  [ { id, y } ],                                              // 이 커리어에서 딴 업적 — 마지막 장의 대표 업적 고르기
  word: null,
}
```

### 5-7. 📤 공유 이미지 — 1080×1350, 자산 0장

| 내용(위→아래) | 로고 줄 · 커리어 등급 · 이름 · `#번호` · 포지션 · 유스 국기 · 커리어 점수 · 리그 여정(🇰🇷 K3 → 🇬🇧 PL) · 숫자 네 칸(시즌 · 경기 · ⚽ · 🅰️ — 수비수는 🛡️) · 수상 한 줄 · 대표 업적 배지(희귀도 색) · 🧭 성향 · 🎯 최고의 한 수 · 🖊️ 한마디(있으면) · 하단 주소 |

| 텍스트 복사 | 유스 엔딩의 「📋 결과 복사」는 그대로 |

### 5-8. 🏅 대표 업적(결정 7)
- 한 커리어에 하나. 기본값 = 딴 것 중 **가장 드문 것**(같으면 가장 최근) — `WingerAch.repOf(S)`
- 고르는 곳: 📊 기록 → 🏅 업적 탭(진행 중 — `WingerAch.setRep(id)`) · 필름 마지막 장(은퇴 때 — `WingerCareer.leave`)
- 보이는 곳: 📊 기록 화면 머리 줄 · 명전 카드(이름 옆, 희귀도 색 테) · 필름 표지 · 공유 이미지
- 명전 항목에는 `rep`(id)만 — 그리는 쪽이 업적 표에서 이름·희귀도를 찾는다. **모르는 id면 그리지 않는다**
- 「대표 업적」은 효과가 없다 — 도움말에 「🎖️ 시즌 칭호와 다른 물건이에요」 한 줄

### 5-9. 등번호(결정 9)
- **고르는 때**: 프로 데뷔(`enterCareer`) 뒤 첫 준비 화면에서 오버레이 한 번 — 포지션별 추천 셋(공격수 9·19·20 · 윙어 7·11·17 · 미드필더 8·10·6 · 수비수 4·5·3) + 🎲 + 직접 입력(1~99 정수). 건너뛰면 추천 첫 번호
- **옛 세이브**(`S.no` 없음 — 데뷔 때 고르기 전에 닫은 세이브도): 다음 `pre` 블록에서 한 번 묻는다 — **그 블록의 무작위 이벤트 대신**(블록 굴림 없이 · 시즌 상한 `S.evSeason.n`에는 안 센다).
  그 `pre`를 이야기 장(🌍·🕯️ 1장)이 차지하면 무작위 이벤트처럼 그 블록엔 안 묻고 다음 `pre`로 미룬다(모달 동시 둘 0)
- 커리어 내내 유지(이적해도 그대로). 바꾸는 길은 🕯️ 결말의 「선배 번호 물려받기」 하나 · 동료에겐 번호가 없다(충돌을 안 본다)
- 보이는 곳: 준비 화면 이름 줄 `#10` · 스쿼드 레이어 내 줄 · 필름 · 공유 이미지 · 명전 카드

## 9. inspector 검사 목록

**문턱은 이 문서의 숫자를 검사에 박고(소스에서 읽지 말 것), 식은 소스에서 뜯어 쓴다.**

### 9-A. 규칙·회귀

1. **늘 안전 == 현행** — 유스: 칸 뽑기를 옛 순서로 쓰고 이벤트 난수를 `WingerEvents._rng`로 갈라 끼우면 **비트 대조**, 아니면 **분포 대조**(3년차 통과율 · 엔딩 7종 · 20,000판 · 구별 안 됨). 프로·커리어도 같은 방식.
   변이: 유스 확정 효과 +3 → +4면 빨간불
2. **B 켠 것 == 끈 것** — 같은 시드 시즌·커리어의 `careerScore`·수상 비트 동일. 변이: 업적 판정 안에서 `Math.random()` 한 번 → 빨간불
3. **옛 세이브** — 새 필드가 하나도 없는 픽스처(시즌 중 · 결산 중 · 유스 중 · 은퇴 직전)를 늘 안전으로 끝까지 == 현행
4. **옛 `careerScore()` === Σ `careerScoreParts().v`** — 옛 식(지금 코드 — 검사에 사본을 박는다)과 전 격자에서 비교. 새 `careerScore()`가 parts의 합을 돌려주므로 새 것끼리 견주면 늘 같다 — 반드시 옛 식과. 변이: parts에서 항 하나를 빼면 빨간불(`hof-test`·`title-test` 초록 유지)
5. **보이는 % = 판정 %** — 얼린 `pct`를 화면 문자열과 판정이 둘 다 읽는지(독립 재계산 어긋남 0) + 대량 표본 이항 검정(구간별). 변이: 판정에 +5 → 빨간불
6. **조각 합 = pct** — `parts`의 `v` 합이 `pct`(유스는 10~90에서 잘린 경우만 다름)
7. **새는 판돈 0** — 적용한 변화 == 칩의 ±W·L. 변이: 🎖️ `p_marked`에서 주 스탯 상한 거르기를 지우면 빨간불
8. **🤝** — `myLine().odds`가 격차 0에서 신뢰 +2로 +13.7%p 안팎 · **컨디션 보정을 친 |격차| ≥ 12**에서 ±0.5%p 이하(명단 1,000벌) · 합 ±4
   *(2026-09-29 inspector 정정: 처음 문구 「|격차| ≥ 10」은 컨디션 보정을 뺀 격차 −10 에서 실측 +6.38%p 가 나와 성립하지 않는다 — 20번 §7 표와 같은 값. 검사는 보정을 친 |g| ≥ 12 로 박았다)*
9. **빈도** — 실제 버튼으로 시즌 완주: 시즌 평균 2.5~4.0 · 최대 5 · 컵·월드컵·특훈 중 0 · 블록마다 굴림 1회 이하 · 모달 동시 둘 0
