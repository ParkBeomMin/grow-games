# 🌏 월드투어 전용 미니게임

작성 2026-07-30 · 대상 `beta/idol/`

## 왜 만드나

투어를 3무대 세트로 만들었더니 사용자 반응이 이랬다.

> "월드투어 미니게임 여러 개 넣은 건 괜찮은데, 미니게임 종류가 일반하고 같은 게 좀 걸려.
> 좀 특별한 미니게임을 새로 만들어서 하면 좋을 것 같은데"

맞다. 기존 8종(`play`·`hold`·`sequence`·`reaction`·`duel`·`target`·`drop`·`odd`)을
세 번 이어붙인 것뿐이라 **종류 자체는 컴백 무대와 똑같다.** 투어라는 느낌이 안 난다.

## 어디에 둘 것인가

**`beta/tour-stage.js`를 새로 만들어 아이돌만 싣는다.**

`timing.js`는 402줄에 8종이고 **8개 게임이 전부 내려받는다.** 투어 전용 메커닉을 거기 넣으면
쓰지 않는 7개 게임까지 무게를 진다. 그리고 이 메커닉들은 범용 타이밍 원시함수가 아니라
**콘서트장이라는 무대에서만 성립하는 것**이다. 소유가 분명한 게 낫다.

인터페이스는 `timing.js`와 똑같이 맞춘다 — `fn(container, opts, cb)`이고 `cb(res)`의
`res`는 `"perfect"` / `"ok"` / `"miss"`. 그래야 기존 투어 코드가 그대로 받는다.

## 세 메커닉

기존 8종과 **무엇이 다른지**가 설계의 핵심이다. 비슷하면 만든 의미가 없다.

### 🎬 오프닝 — 함성 웨이브

관객석 구역이 가로로 늘어서 있고 빛이 **왼쪽에서 오른쪽으로 흐른다.**
각 구역이 최고조일 때 탭한다. **3번 연속** 잡아야 완벽하다.

- 기존 `sequence`와 다르다 — 그건 정해진 순서를 **기억해서** 누르는 것이다.
  이건 타이밍 창이 **이동한다.**
- 놓치면 파도가 끊긴다. 3번 중 몇 번 잡았는지가 결과를 정한다

### ✨ 킬링파트 — 싱크로

두 개의 바가 **서로 다른 속도로 왕복한다.** 둘이 겹치는 순간에 탭한다.

- 기존 `play`와 다르다 — 그건 고정된 초록 존에 움직이는 커서를 맞추는 것이다.
  이건 **두 움직이는 대상의 교차**를 기다린다
- 주기가 어긋나서 겹침이 드물게 온다. **기다리는 긴장**이 이 메커닉의 맛이다

### 🔥 앵콜 — 함성 유지

관객 함성 게이지가 **계속 떨어진다.** 연타로 올리면서 목표선 위에서 버틴다.

- 기존 `hold`와 다르다 — 그건 꾹 눌러 모았다가 한 번 떼는 것이다.
  이건 **연타로 유지**하는 것이다
- **과하게 치면 삑사리 구간**이 있다. 위로도 한계가 있어서 세게만 치면 안 된다
- 목표선 위에서 머문 시간이 결과를 정한다

## 능력치 연동

기존 미니게임은 `miniZone(stat)`으로 능력치가 높으면 판정 창이 넓어진다.
**새 메커닉도 같은 방식으로 능력치를 봐야 한다.** 안 그러면 육성이 투어에 안 닿는다.

| 무대 | 보는 능력치 | 근거 |
|---|---|---|
| 🎬 오프닝 | 댄스 | 무대 장악·동선 |
| ✨ 킬링파트 | 포지션 주 스탯 | 하이라이트는 자기 파트 |
| 🔥 앵콜 | 체력 | 끝까지 버티는 것 |

## 지켜야 할 것

- **자동 플레이(`autoMiniOn()`) 경로가 있어야 한다.** 기존 미니게임 전부가 갖고 있고
  테스트와 확인 페이지가 그 경로로 돈다. 없으면 투어가 막힌다
- **합산 가중치는 그대로다** — 오프닝 0.10 / 킬링파트 0.15 / **앵콜 0.75**.
  앵콜 하나가 객석 39pp를 흔든다
- **등급 분포가 유지돼야 한다** — S 11% / A 30% / B 44% / C 16%.
  넷 다 5% 이상, 어느 등급도 절반 이하. 새 메커닉의 난이도가 다르면 여기가 먼저 깨진다
- **컨디션 소모·기세 보너스·취소 문턱 상수는 건드리지 않는다**
- 투어가 망해도 팬덤·자금·기록은 줄지 않는다

## 하지 않는 것

- **기존 8종을 고치지 않는다.** 컴백 무대는 그대로다
- **`timing.js`를 건드리지 않는다.** 8개 게임이 공유한다
- **새 판정 등급을 만들지 않는다.** `perfect`/`ok`/`miss` 셋을 쓴다

## 위험

- **모바일 터치.** 연타(앵콜)와 이동 타이밍(오프닝)은 포인터 이벤트 처리가 까다롭다.
  기존 `hold`가 `pointerdown`/`pointerup`을 쓰는 방식을 보고 맞춰야 한다
- **투어가 더 길어진다.** 도시 8곳 × 3무대면 24판이다. 각 메커닉이 3~5초에 끝나야 한다
- **CSS가 사각지대다.** 관객석 구역·두 바·게이지 셋 다 새 화면 요소다.
  실기기 확인이 반드시 필요하다
