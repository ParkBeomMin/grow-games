# 시즌 중 트레이드 요청 (⚾ 더 루키)

작성일: 2026-07-27
대상: `rookie/career.js` 한 파일. 다른 게임에는 트레이드가 없어요.

## 1. 배경

지금 트레이드 요청은 시즌 결산 화면에서만 열려요. 현실의 야구는 시즌 도중에도
트레이드가 일어나고, 오히려 그쪽이 더 극적이에요 — 순위 싸움 중인 팀이 보강하고,
가망이 없는 팀이 주축을 팝니다.

플레이어가 신청하는 방식만 다뤄요. 구단이 일방적으로 통보하는 트레이드는 범위 밖입니다.

## 2. 창구

`S.season.game`이 **30 이상 100 이하**일 때 신청할 수 있어요.

| 값 | 근거 |
|---|---|
| 하한 30경기 | 시즌 초반에는 실제로도 트레이드가 거의 없어요. 개막하자마자 팀을 갈아타는 것도 이상하고요 |
| 상한 100경기 | KBO 트레이드 마감 시한(7월 31일)을 144경기의 약 70% 지점으로 옮긴 값이에요. 마감이 있어야 "지금 아니면 못 한다"가 생겨요 |

기존 제약은 그대로 씁니다.

- `S.proYear >= TRADE_MIN_YEAR` (2년차 이상)
- `S.tradeYear !== S.proYear` — **연 1회.** 시즌 중에 쓰면 그 해 오프시즌에는 못 써요.
  `finishTrade()`가 성공·실패와 무관하게 `S.tradeYear = S.proYear`를 찍기 때문에 추가 코드가 없어요.

## 3. 팀 교체

`S.season`은 내 팀 성적(`teamW`/`teamL`)과 나머지 9팀(`others`)을 나눠 들고 있어요.
그래서 트레이드는 **그 둘을 맞바꾸는 것**으로 끝나요.

```js
const i = sn.others.findIndex((o) => o.name === team);
const nt = sn.others[i];
sn.others[i] = { name: S.team, w: sn.teamW, l: sn.teamL, str: teamStrOf(S.team) };
sn.teamW = nt.w;
sn.teamL = nt.l;
```

이 한 조각으로 아래가 전부 따라와요. 순위표·상대팀·가을야구 코드는 건드리지 않아요.

| 기존 코드 | 스왑 후 |
|---|---|
| `myRank()` — `others`에서 나보다 승수 많은 팀을 셈 | 새 팀 기준으로 자동으로 맞아요 |
| `standingsHTML()` — `{내 팀} + others` | 옛 팀이 정확한 성적으로 표에 남아요 |
| `nextOpp()` — `others[floor(game/3) % 9]` | 옛 소속팀과 맞대결하는 일이 자연히 생겨요 |
| `enterPostseason()` — `teamW/teamL + others`로 순위표 | 새 팀 성적으로 대진이 짜여요 |
| `teamWinP()` — `teamStrOf(S.team)` | `moveTo`가 `S.team`을 바꾸므로 새 팀 전력이 반영돼요 |

리그 전체 승수는 보존돼요 — 두 팀의 성적을 지우지 않고 자리만 바꾸니까요.

**내 개인 성적(`S.season.stats`)은 그대로 이어져요.** 실제 야구도 시즌 통산 기록은
소속팀이 바뀌어도 합산해요. 팀별로 쪼개 보여주지는 않아요 — 결산 화면이 한 줄짜리라
쪼개면 오히려 읽기 나빠집니다.

### 어디에 넣는가

`moveTo(team, type, bonus)` 안에서 `S.team`을 바꾸기 **전에** 스왑해요.
`if (S.season)` 하나로 분기가 끝나요 — `finishSeason()`이 `S.season = null`을 찍으므로
오프시즌 트레이드와 FA는 이 경로를 타지 않아요.

## 4. 대가

시즌 중 이적은 오프시즌보다 훨씬 강력해요. 리빌딩 팀에서 우승 후보로 옮기면
그 시즌 가을야구를 갈 수 있으니까요. 값을 매기지 않으면 오프시즌 트레이드를 쓸 이유가 없어져요.

| 항목 | 값 | 이유 |
|---|---|---|
| 협상 라운드마다 컨디션 | **−8** (3라운드 = −24) | 경기에 집중이 안 되는 걸 나타내요. 훈련 한 번이 −12~18이니 그보다 가벼워요 |
| 구단 태도 시작값 | **−12** | 시즌 중 전력 이탈이라 구단이 더 꺼려요. 승낙 확률이 그만큼 낮아져요. 기존 계산식의 결과에서 12를 뺀 뒤 `clamp(…, 8, 76)`을 걸어요 |
| 실패 시 컨디션 | **−20** 추가 | 오프시즌 실패는 다음 캠프에 영향이 오지만, 시즌 중엔 당장 남은 경기를 뛰어야 해요 |

`startTrade()`가 쓰는 팀 순위도 시즌 중에는 바꿔요. 지금은 `S.career.seasons`의 마지막
항목, 즉 **작년 순위**를 봐요. 시즌 중이라면 지금 순위(`myRank()`)가 맞아요 — 올해
하위권이라 팔 이유가 생긴 건데 작년 성적으로 판정하면 어긋납니다.

실패 시 `S.tradeSour = true`는 그대로 둬요. 다음 시즌 캠프 분위기가 어색해지는 기존 효과예요.

성공 시 이적료는 없어요(`bonus = 0`). 오프시즌 트레이드와 같아요.

## 5. 화면

협상 화면(`screen-move`)과 `startTrade` / `renderTrade` / `playTradeCard` / `finishTrade`를
그대로 재사용해요. 새 화면은 없어요.

### 진입 버튼

`renderPro()`의 `pro-actions` 맨 아래에 붙여요. 경기일에 훈련 버튼을 잠그는 루프가
끝난 뒤에 추가하므로 경기일에도 눌러요 — 협상은 턴을 쓰지 않으니 막을 이유가 없어요.

```
🔁 트레이드 요청
   마감까지 N경기 · 컨디션을 씁니다
```

새 CSS는 만들지 않고 기존 `action-btn`을 씁니다.

### 복귀 지점

`S.season`이 있으면 시즌 중이에요. **플래그를 저장하지 않고 그때그때 `!!S.season`으로
판단해요** — 저장본에 남은 낡은 플래그와 실제 상태가 어긋날 일이 없어집니다.

| 상황 | 협상 종료 후 |
|---|---|
| 시즌 중 | `renderPro(); show("screen-pro")` |
| 오프시즌 | `seasonReport()` (기존) |

### 협상 이어하기

지금은 협상 도중 화면을 벗어났다 오면 `startTrade()`가 상태를 새로 만들어 진행분이
사라져요. `S.trade`가 남아 있으면 그 상태로 이어가게 고쳐요. 오프시즌 트레이드도
같은 문제라 함께 고쳐집니다.

## 6. 범위 밖

- **구단이 나를 일방적으로 트레이드하는 것** — 사용자가 "내가 신청하는 것만"으로 정했어요.
- **다른 6개 게임** — 트레이드 기능 자체가 없어요.
- **시즌 중 FA** — 현실에 없어요. FA는 오프시즌 그대로예요.
- **팀별 성적 분리 표시** — 결산 한 줄에 담기지 않아요.
- **트레이드 상대 선수 / 지명권** — 이 게임은 선수 한 명만 다뤄요.

## 7. 검증

테스트 러너가 없으므로 node VM으로 배포되는 코드를 직접 실행해 검증해요.
스왑이 가장 위험한 지점이라 거기에 집중합니다.

| 대상 | 확인 |
|---|---|
| 스왑 | 리그 총 승수 불변 · 팀이 10개 유지되고 중복 없음 · 내 성적 = 새 팀의 성적 · 옛 팀이 정확한 성적과 전력으로 `others`에 편입 · `S.team`이 새 팀 |
| 창구 | 29·30·100·101경기에서 버튼 노출 여부. `S.season`이 없을 때(오프시즌) 시즌 창구 판정이 안 걸리는지 |
| 연 1회 | 시즌 중 실패 후 같은 해 오프시즌에 다시 못 여는지 |
| 대가 | 라운드마다 컨디션 −8, 실패 시 −20 추가, 오프시즌에는 하나도 안 깎이는지 |
| 승낙 확률 | 같은 조건에서 시즌 중 시작값이 오프시즌보다 12 낮은지. 시즌 중에는 작년 순위가 아니라 현재 순위를 보는지 |
| 가을야구 | 스왑 후 `enterPostseason()`이 새 팀 순위로 대진을 짜는지 |
| 복귀 | 시즌 중 종료는 `screen-pro`, 오프시즌 종료는 결산으로 가는지 |
| 이어하기 | `S.trade`가 있으면 라운드·게이지가 유지되는지 |
| 회귀 | 가을야구·환생·은퇴확인·경제 스위트가 그대로 통과하는지 |

## 8. 배포

`beta/rookie/`에 먼저 반영하고 사용자가 `/beta/rookie/`에서 확인한 뒤 상용으로 옮겨요.

`beta/`에는 다른 세션의 작업이 얹혀 있을 수 있어요. `promote.sh`는 대상을 지정해서
부르고, 넘기기 전에 `diff -u`로 내용을 확인합니다.
